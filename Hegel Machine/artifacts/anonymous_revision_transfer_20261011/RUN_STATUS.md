# Frozen predictor transfer to new apparatuses

All six registered source runs are retained. This follow-up used zero new model calls. It copied each submitted predictor and its source fitting context, then tested new seeded apparatuses of the same nominal family on 512 independent rows with 48-step trajectories.

| Condition | Ordinary Code | Hegel |
|---|---:|---:|
| Original source code and parameters | 0/3 pass | 0/3 pass |
| Same code with target data supplied to an existing fit | 3/3 unavailable | 3/3 unavailable |

Every final source predictor exposes `predict`, but none exposes `fit`. The second condition preserves this fact instead of injecting a fitting algorithm. The fixed attempted target prefixes still cost 432 rows across six programs; no target refit or scoring occurred in that condition. Frozen prediction scored 3,072 terminal rows; all executions completed normally. Raw outcomes and per-source MSE are in `outcomes.json`.

This does not show that the full executable archive is useless: it retains self-authored exploratory scripts and experiments that a future LLM or consolidated procedure may adapt. It shows that the **submitted predictor alone** has not packaged a reusable parameter-identification operation. Reusing the historical method-edit, paid-practice and frozen-transfer machinery is the next step. A later strong control must give ordinary Code the same nonempty archive; the completed source pilot started both arms with empty archives.

Source development costs remain reported once in `summary.json` (74 calls, 2,058,865 reported tokens, 1,986 observations). The separate interrupted startup is retained in the source cohort documentation. These six programs come from three development apparatuses, not six independent mechanism families.
