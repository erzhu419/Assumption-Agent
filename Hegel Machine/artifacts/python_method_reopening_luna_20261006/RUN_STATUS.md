# Response-reopening study

Three registered Luna authors started from the adopted historical program and the same paid source counterexample. Original five source conditions and ten targets were preserved; one late-response-change condition added a sixth source case and two targets.

| Author | Outcome | Current-source confirmation | Paid practices |
|---|---|---|---|
| 0 | 12-call limit; no submission | 0/6 | 0 |
| 1 | 12-call limit; no submission | 0/6 | 0 |
| 2 | Provider capacity error on call 12 | 3/6 | 3 |

No method was published; all 36 author-target slots were skipped, not executed failures. The unchanged program passes 10/12 targets with no false confirmations: the original ten are reused, and both newly executed late-change targets stop unresolved.

The supplied source trace shows response validation MSE 4.30e-20 followed by fresh-confirmation MSE 0.645 after the response changes. All authors edited source, but none practiced this added case. The first two spent their full calls editing or inspecting old evidence; the third preserved reuse, refit and instrument repair on three original cases before the service interruption. The interruption was capacity-related, not a timeout.

New work: 36 attempted model calls; 1,098,325 known tokens plus one call with unknown usage; 31.23% of reported input cached. Costs are 789 observations, 639 measurement units and 20,445 computation units, including the two new controls. Prior diagnostic and source-acquisition costs are retained separately in [summary.json](summary.json).

## Limitations and next step

This is development evidence in known apparatus families with an announced 167-row checkpoint. It does not demonstrate successful mismatch-driven LLM method revision. Next, reuse the existing paid practice path immediately after a source edit, so the author receives actual execution feedback before more editing. Keep this new feedback condition separate from these frozen failed/interrupted attempts.
