# Hegel Machine V13 系统审计与主目标判定

审计提交：`c71e65f7f10863ea68f2ccecac2cd5a86e1e1ba4`。对照基线：`6e963206fd2822476c894fd2d0f09db4be70223c`。审计日期：2026-11-18（北京时间）。

## 1. 总体结论

**V13 有真实且重要的工程进步；用户最关心的完整科学主张仍未闭合。**

本轮已经有直接证据支持：普通研究入口在历史假设和当前候选均失败时，生成子问题，调用既有机制研究能力，得到不同的父程序，并通过新的确认数据。上一轮“子问题只生成而没有返回执行”的批评，不能原样沿用。

当前尚不能据此宣称：一个在这条失败递归链中形成的新假设，经过完整的范围和历史分支检验后，在允许强普通方法重建同一知识的条件下，已被证明提高了后继未见问题的研究效率。主要原因有三类：

1. **主对照仍有实质混杂。**普通组开启 H* 家族优先搜索，最佳路由组关闭它。18.92% 的目标计算成本差是真实组间结果，但同时包含搜索策略变化。相同 H* 开关下，已有的预组织组反而比普通组更贵、少完成一题。
2. **局部机制与普通消费路径尚未完全接通。**同协议证据复用的数据形状不匹配；持久延期问题没有跨轮恢复入口；新增边界探针只在控制脚本及测试中调用；额外调和证据被保存给普通组，但没有被重放进入其知识重建。
3. **科学反驳的对象与条件仍有错误。**无预算或有限搜索未找到参数，可以被标为整个家族被反驳；固定参数实例的失败可能限制可重新拟合的模板；部分“路由后置”候选实际上不再被消费。

**建议下一轮继续使用现有任务和函数，完成一次接口贯通与公平对照修订。暂不新增物理家族、通用框架或方法自改写层。H* 的当前默认前置搜索可以关闭，保留其结构表达和以后检验的资格。**

## 4. 实测结果：数值可信，解释必须收窄

### 4.1 四臂结果独立重算

这里的“严格通过”指内部完成且确认损失不高于 `1e-7`、另外 48 行外部评价 MSE 不高于 `1e-7`，并满足预定预算。它是本实验的有限样本门槛，不是对所有世界状态的数学证明。计算成本是项目计费单位，不是硬件 FLOPs；墙钟包含执行脚本中的外部评价时间。[S4][S5]

| 条件 | H* 前置调度 | 严格通过 | 假确认 | 目标计算成本均值 | 观测行均值 | 墙钟均值秒 |
|---|---|---:|---:|---:|---:|---:|
| `K_cold` | 仅共同起点，无新增源库 | 23/24 | 1 | 226,253.33 | 287.33 | 25.31 |
| `R_ordinary_optimized_lazy` | 开启 | 21/24 | 2 | 226,943.08 | 278.92 | 34.44 |
| `K_routing_no_H_star` | 关闭 | 22/24 | 2 | 184,004.29 | 276.29 | 23.59 |
| `K_routing_plus_H_star` | 开启 | 20/24 | 2 | 249,564.33 | 276.75 | 39.84 |

`K_cold` 有共同校准锚点，并非完全没有任何先验。目标阶段冻结源库；每题使用源快照，普通组跨目标保留来源重建缓存。因此这组实验主要测冻结知识迁移，不是目标反馈持续入库后的在线自我改进。

源任务需要更正一处报告标签：32 个普通源任务均内部确认，但**严格通过为 31/32**。`1021000/S_left_dpg_N4` 的内部 loss 约 `1.12e-18`，外部 MSE 为 `8.5874e-4`。脚本的 `source_episodes_confirmed_exact` 实际统计 `internally_confirmed`，报告误称“32/32 严格确认”。原始失败仍保留在数据中，应保留而非删除。另有 8 个共同校准锚点，均严格通过。[S4][S5]

### 4.2 最重要的混杂：普通组与最佳知识组并非相同搜索策略

`_build_four_arm_libraries()` 明确设置：

```python
lib_r._prioritize_generalized_families = True
lib_no_h._prioritize_generalized_families = False
lib_plus_h._prioritize_generalized_families = True
```

该开关不是展示字段。dispatcher 仅在开关开启时调度家族，普通研究先尝试这些家族，再尝试普通 commitment。因此它改变真实候选顺序、拟合路径和有限预算占用。[S4，函数 `_build_four_arm_libraries`][S2，函数 `dispatch_branches_and_families_for_target`][S1，家族实例化入口]

已有数据能给出两个不同的判断：

- 同一预组织库中，关闭 H* 的组相对开启组多完成 2 题，平均少用 **65,560.04** 计算单位。它支持“当前 H* 前置调用策略没有增量效用，并存在具体伤害”。
- 同样开启 H* 时，预组织组相对普通组是 **20/24 对 21/24**，平均 **249,564.33 对 226,943.08**，预组织组反而贵 **9.97%**。该比较仍有重建细节差异，但已经足以否定“预组织在本数据中必然节省”这种解释。

主结果中的 **18.92%** 是当前不同处理组之间的真实成本差，不能直接称为“自主路由知识的净贡献”。缺失的关键对照是使用相同 H* 调度策略的 `R_lazy_noH`。不能靠从旧账单机械扣掉某一项费用来补出这条没有运行过的结果。

### 4.3 唯一成功率增益案例，显示的是哪一种作用

对 `1024000/T1_unseen_family`：

| 条件 | 严格结果 | 计算成本 | 外部 MSE |
|---|---|---:|---:|
| 普通 R，H* 开 | 未决 | 679,993 | 0.0016421421 |
| 预组织 K，H* 开 | 未决 | 679,995 | 0.0016421421 |
| 预组织 K，H* 关 | 通过 | 254,538 | 1.688e-18 |
| cold | 通过 | 265,600 | 1.688e-18 |

两个 H* 开启组选中了相同的错误家族绑定 `theta_0_0.273:r_0.937`。关闭组成功，cold 也成功。这个个案有价值：它定位了有害搜索路径，同时显示预组织关闭组比 cold 少用 11,062 计算单位。它尚未回答关闭同一有害路径的普通档案组会怎样。[S5，链 `1024000` 的 T1 记录]

此外，应并列解释负结果：

- `1023000/T3`：三个知识组均内部确认，外部 MSE 约 `4.244e-5`；cold 严格通过。这是实际知识使用条件下的额外失败，不能把更快输出错误预测计为有效研究提速。
- `1026000/T3`：四组都假确认，外部 MSE 约 `1.011e-4`，说明共同确认协议仍不足。
- `1025000/T2`：只有 H* 开启的预组织组新增未决，耗 678,528 计算单位；普通组和 H* 关闭组都通过。[S5]

### 4.4 成本优势不能全部解释为“源期前移摊销”

R 对 K-noH 的 8 个源簇目标均值成本差都为正；双方都成功的 21 个目标配对中，K-noH 仍平均少用 **29,629.10** 计算单位。所以组间成本差并非完全由唯一未决案例造成。但“双方都成功”是结果后的筛选，只能作描述，不能取代全部任务主比较；H* 混杂也依然存在。

24 目标的总计算差为 **1,030,531**，R 记录的直接重建费为 **336,803**，只占该差的 **32.68%**。其余差异包含候选搜索和预算路径等作用，不能全部命名为重建费用前移。

报告的 `43,733.875 / 42,938.792 = 1.0185` 算术成立，但“约 1.02 题回本”只是两个均值之比：任务固定按 T1→T2→T3 运行，普通缓存后两题变暖，单题节省不是恒定值。即使沿用这组混杂数据，仅按维护计算费作前缀核算，`1026000、1027000、1028000` 三个簇在 3 题后仍未回本。应改为逐链、逐前缀报告全部成本。[S5；本包 `recomputed_results.json`]

源四任务均值计算费为 702,412.625，其中维护子集 43,733.875；共同校准锚点另为 86,581.75。排除共同费用作增量分析可以，但必须同时给出全账和口径。

完成率符号翻转 `p=1` 复算无误，含义是这 8 个源簇不足以识别成功率差异，**不是等效或非劣证明**。V12 的 19/24 与 V13 的 21/24 还使用了不同源链和整体代码，不能作为缓存修复导致完成率上升的单因子证据。缓存正确性和目前差距缩小可分别报告，不能混成因果结论。

## 5. 科学语义仍有三处需要优先修复

### 5.1 无预算或未找到拟合，不等于整个家族被反驳

`_cross_evaluate_refittable_family_on_neighbor()` 在家族实例化返回空列表时，直接返回 `evaluated=True、cross_mse=inf、empirically_refuted=True`。而实例化函数可以因为预算不足、槽位不支持或证据缺失返回空列表。非空列表中有限网格最优误差高于门槛，也不能一般性证明连续参数域中不存在可行实例。[S2，`_cross_evaluate_refittable_family_on_neighbor`]

本次最小复现调用真实搜索函数和真实 wrapper，使用真实 `SearchBudget(0)`：计费 0、拒付 1 次，仍得到 `empirically_refuted=True`。这条结论随后能参与生成硬作用域 guard。固定实例交叉检验及另一条 adjudication 路径也存在忽略 `budget.spend()` 返回值、拒付后仍执行计算的问题。

应保留以下差别：

| 事实 | 可以更新什么 | 不能直接更新什么 |
|---|---|---|
| 固定实例实际执行后错误 | 该程序版本、该绑定在该证据上的有效性 | 所有合法重绑实例组成的整个族 |
| 有限拟合未找到可行实例 | 此搜索过程的失败记录、路由效率估计 | 家族不可行结论 |
| 无预算/无数据/实现不支持 | unknown、deferred 或 unsupported | 科学反驳 |
| 在声明参数域内完成穷尽/不可行检查 | 该数据与参数域下的家族不可行性 | 无限制的所有世界不成立 |

这里不需要追加通用定理证明框架。当前阈值族若能用已有区间信息完整排除可行绑定，可以记录该有限结论；否则保留未知。

### 5.2 实例失败与模板取消资格，仍可能错层

交叉检验固定源半径和边条件，只重新拟合线性系数；失败后收缩 branch scope。dispatcher 又用这个 scope 排除对应 commitment，而下游 commitment 实例化原本允许目标半径等合法重拟合。[S2，`instantiate_aligned_claim_program`、`_refine_coexisting_branch_scopes_and_routing`][S1，普通 commitment 实例化入口]

隔离示例中，旧门函数 `1[x<0.5]` 对新环境 `1[x<0.75]` 的误差为 0.1333，合法改绑 0.75 后误差为 0，但前者生成的 guard 可以使可重绑模板也不进入搜索。此示例用了显式简化的对齐和拟合替身，证明对象层级与控制流风险，不是对当前 96 个物理目标的全程重放。

需要明确三种对象：固定绑定假设实例、允许重拟合的机制模板、经验路由策略。反例必须传播到实际被检验的对象及依赖，不能仅按同一 source id 扩散到所有模板。

### 5.3 “仅影响排序”的路由拒绝，实际可能丢候选

两处消费问题已确认：[S2，`dispatch_branches_and_families_for_target`][S1，家族消费入口]

1. aggregate commitment 被放入尾队列前就加入 `seen`，重新拼接尾队列时因已见而跳过。某些 branch commitment 仍保留，但原 aggregate 模板不再返回。
2. 路由不匹配的家族放入 `deferred_router_families`，普通入口只读取 `scheduled_families`，没有消费 deferred 列表的路径。

因此这里不能保证“只是排序”。应该先完整形成可尝试集合，再按优先级排序和统一去重；预算没有走到尾部与科学上被排除必须分别记账。

## 6. 生产—消费接口尚未闭合的四处

### 6.1 exact-protocol 复用读取了测试形状，而非生产形状

真实 `acquire` 保存的是：

```python
{"probe": asdict(probe), "observations": [asdict(row), ...], ...}
```

复用 callback 却读取 batch 顶层的 `sequence/reset/probe_id`，并直接把 observations 当作对象列表。单测造的是平铺字段和对象列表，所以能够通过。真实生产形状的最小复现会再尝试一次 acquisition，拒付后返回 unavailable；平铺测试形状则成功 reused。[S1，`acquire` 与 `_exec_reconcile_probe`][S8]

修复要同时处理 nested probe 路径、Observation 反序列化、原执行 ID 和协议指纹。另有 `new_measurements` 从不存在的 batch 字段取 0 的元数据错误；主测量预算仍由 acquire 正确计费，不能把它误说成整个实验成本未计费。

PR-A 选择点 2 的报告也应更正：原回执第一条比较真实执行成功、第二条 unavailable，`paid_probes_executed` 长度为 1。脚本把“没有假执行”误写成“没有任何执行”，因此 `zero_fake_executed_probes=false`。正确验收是 unavailable 对应请求不能出现在 executed 集合，而非要求整个 episode 的执行列表为空。[S6][S7]

### 6.2 延期子问题被保存，但没有后续恢复入口

当前 run 的 `response_questions` 从空列表开始，只接入本次 `rec_action.pending_questions`；持久 `_pending_reconciliation_questions` 在随包源码中只有追加和按 ID 更新，没有下一次 run 的读取调度。PR-A funded/unfunded 使用两个独立的 deepcopy，因此验证了预算分支，未验证先延期、再续跑同一父研究。[S1][S2][S7]

同时，handler 只处理 `both_competing_branches_refuted`，`scope_boundary_unidentified_after_refutation` 会被跳过。后者已经出现在真实选择点回执，不能当作纯理论边缘情况。问题 ID 还缺少完整父版本/独立 episode 身份，可能使历史同名问题被一起回填。

### 6.3 普通组可访问的原始 archive，没有进入实际重建

`_raw_reconciliation_evidence_archive` 的写入增加了公平性的必要基础。但重建函数对它的唯一读取是 `len()`，用于缓存键；没有重放额外 probe 的行和反例。archive 本身只有 rows、source/task/probe id 和 transition 数量，缺少完整 transitions、动作/reset、schema/绑定等重建 scope 所需信息。[S2，`reconstruct_parametric_families_from_ordinary_archive`、`_recording_probe_fn`]

所以“普通组拿到了一个容器”成立，“已从相同全部历史构造出语义等价的范围/路由”尚未成立。下一步应统一原始 EvidenceBatch，再让两组调用同一重放函数；比较预测、guard 判定、反例归属和合法绑定是否一致，不要求内部 ID 或存储字节完全一样。

### 6.4 新边界探针尚止于生成器

新增 `propose_threshold_interval_boundary_probe()` 仅由 PR-AB 控制脚本和单测调用。普通入口没有调用。PR-B 传入手工区间 `[0.34,0.43]` 和半径 `0.89`，回执只检查能够提出有分歧的探针，没有购测、更新可行区间、修订候选和重新独立确认。[S2][S7][S8]

可以说边界生成能力已实现，不能说这条新增能力已经修好主线误确认。这不代表项目旧代码完全没有其他主动阈值测试；缺的是合同要求的这条残留版本空间→付费区别实验→新确认通路。

## 7. 用户的完整主线，现在走到了哪里

### 7.1 已有一个真实的当前任务修复

PR-A 的 `focal_memory, seed=9315` 中，旧马尔可夫分支和初始候选失败后，子研究使父程序新增 `accumulate` 结构，候选从 `answer:residual_0:combined` 变为 `world_commitment:0000:world_commitment_scientific_revision:4`。新确认 24 行 loss 为 **2.5386e-17**，外部 48 行 MSE 为 **1.6120e-17**。[S6]

它支持“普通入口确实能根据失败调用已有研究能力、形成新可执行假设并修好父问题”。固定语言和已有 latent 搜索器不妨碍这个有限意义的自主发现，不能把标准抬成必须发明新原语或改写全部代码。

### 7.2 还缺同一个新假设的后续闭环

成功后调用 `remember_confirmed_selection`，但没有再次调用分支调和；第一个问题 answered 后 break，另一个问题仍 pending。新概念可以进入普通记忆，并不意味着绝对不能复用，但本轮没有完整展示它如何再与历史分支检验、形成新的范围关系，并使后继未见任务受益。[S1][S6]

PR-C 另有阈值家族、路由组织和目标实验。把 PR-A 的递归修复与 PR-C 的迁移均值放在同一报告中，不能代替同一个对象的连续证据。

| 用户要求 | 当前证据等级 |
|---|---|
| 从普通经历产生新可执行假设 | 已有有限语言内的真实实例 |
| 真实冲突改变声明 | 已实现，但需修正反驳层级、预算与范围语义 |
| 子研究改变父问题 | 有具体同次 run 成功 |
| 延期继续、修复后再与历史分支调和 | 尚未完整接通 |
| 强普通法能够从同历史重建 | 缓存进步明确，额外证据重放未闭合 |
| 同一新假设改善具体未见问题 | 尚无干净的连续对象因果证据 |
| 整体递归机制稳定优于使用前/强普通方法 | 当前不支持；有成本差、有负迁移、有策略混杂 |

本轮任务的“未见”主要是已定义机制族中的新阈值、半径、命名/布线及 N4→N5 实例；T1 阈值位于源阈值范围内。它们是有效的未见实例测试，但不能扩写成新物理机制族或开放研究问题的成功。

## 8. 与 AWM、近期自改进研究的关系

AWM 的最新版原文强调两项与此处直接相关的区分：结构简化应保留已测试的区分；模型内证明与模型是否匹配真实环境要分别验证。对 Hegel 当前最有用的是落实合并/范围修订的证据语义，并非立刻扩充 Lean 覆盖。[L1]

AIDE² 将研究代理的修改放入固定预算和隐藏评价中检验，并在未参与选择的任务上检查迁移。Hegel 当前可以先完成知识层的改进证据，不必立刻加入代码自改写，但同能力、同调度、公平后继评价是必要的对照原则。[L2]

PAST-Bench 同时评价后继任务收益及存储—检索—更新的实际路径，指出相同总分改善可以由不同机制支持。这与本轮诊断相吻合：有保存、队列、缓存字段，还需要证明下游实际使用及其作用。[L3]

这些论文提供实验与证据设计参考，不替 Hegel 自身证明效果。此处只提取直接相关的原则，没有把不同任务域的分数作横向排名。

## 9. 下一轮方向及对上一轮合同的修正

建议交付三项有限工作：

1. **修复事实与执行语义。**真实 batch 复用、预算拒付、实例/模板反驳层级、routing 尾队列、持久 pending 恢复和修复后的局部再调和。
2. **统一实际历史与搜索策略。**补可重放原始证据；在两组同样关闭 H* 前置调用的条件下比较 lazy 与预组织；普通组只在需要时重建，能缓存等价知识，不付永不消费的强制构造费。
3. **做一条连续对象实验。**同一个普通循环形成的修复对象，在未来新实例上与强普通重试/重建比较，并做对象移除或替换干预。先用已曝光案例修接口，再冻结新样本作科学评价。

具体函数、验收回放、对照配置、成本和停止规则在 `02_下一轮最小施工与实验合同.md`。

我上一轮合同也有需要修正的地方：虽然要求同工具和三组对照，却没有把普通组的 H* 调度开关逐字段冻结，也没有明确“共享原始证据”必须通过同一重建函数的行为等价检查。这使实现容易满足字面上的“允许重建”，却留下实际路径差异。本轮将这两项写成具体配置和生产者—消费者回放，属于对实验合同自身的补正。

**当前最稳妥的项目定位是：可执行假设与分支维护已具备部分真实闭环，失败驱动修复已有实例，递归知识对未见研究的独立效用仍待公平且连续的证据。**若补齐对照后普通方法打平，应接受知识组织与审计价值的贡献边界；若成本优势仍稳定存在，再以具体工作负载和完整成本报告它。
