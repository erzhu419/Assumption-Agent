## 1. 本轮唯一主目标

让**同一个**在普通研究中形成或修复的可执行假设，携带其真实来源、被测版本和范围依据，完成：

> 普通经历 → 真实冲突 → 子研究/修订 → 新确认 → 与历史分支再检查 → 后继未见任务调用 → 与同能力、同历史、同调度的普通方法比较。

允许最终结论是打平、负迁移、只有可审计性改善、只在指定工作负载节省成本。不得通过禁用普通方法的已有能力、不给原始证据、强迫其支付无用构造费或改变确认门槛来获得正结果。

继续使用既有物理实验室、合法 probe 接口和研究器。优先原位修改现有函数及数据字典。新模块数量、日志数量、hash 数量、测试数量均不作为科学目标指标。

## 3. 第一项交付：使证据取得、科学裁决和真实消费一致

### 3.1 统一生产 EvidenceBatch 的读取，修复 exact reuse

修改位置：`unified_research.py` 的 `acquire`、`_exec_reconcile_probe`；`branch_reconciliation.py` 的证据记录与重放。

复用真实生产形状，至少保留：

```python
{
    "evidence_id": ...,
    "episode_uid": ...,                 # 公开的任务实例身份，不是隐藏机制标签
    "actual_probe_id": ...,
    "probe": {"sequence": ..., "reset": ..., "history_preparation": ...},
    "channels": ..., "schema_version": ..., "bindings": ...,
    "observations": ..., "transitions": ...,
    "cost_ref": ...,                    # 来自真实 acquisition 计费结果
}
```

字段可以映射到已有结构，不要求另建通用执行器。

规则：

- 从 `batch['probe']` 读取协议，使用现有反序列化器恢复 Observation；不要让测试继续构造与生产不同的平铺形状。
- 同协议复用需核对任务/世界实例、动作、reset、历史准备、读出通道、角色绑定和 schema 语义。相同动作字符串不足以证明同一实验。
- reused 保留原 evidence/probe ID，独立样本增量为 0；再次分析旧行不记为新确认。
- `executed_new` 的成本引用来自真实 acquisition action 或计费增量；修正从不存在字段取 0 的元数据。
- unavailable 不签发新证据、不修改请求干预的支持/反驳。已存在的其他真实 probe 保留。
- archive 保存可重放的完整必要信息，不能只存 `transitions_count`。

**验收回放 A：**调用真实 acquire 取得一次 batch；同请求再经过真实 callback，必须复用原 ID、不新增 acquisition。随后改动作或 reset，必须拒绝“同协议复用”；预算不足则 unavailable。该测试以生产者实际输出直接喂给消费者，不再单独手填 fixture。

- `budget.spend` 拒绝后立即返回 deferred，不继续预测、拟合或改写知识。

- 每次 scope 修订保存触发它的 cross-check 回执：被测版本、固定/可变参数、邻居身份、证据引用、协议、结果。不能仅保存几个 regime 摘要而丢失“为什么改”。

## 4. 第二项交付：同一原始历史能够被普通方法实际重建

修改位置：`_recording_probe_fn`、`reconstruct_parametric_families_from_ordinary_archive`、`OrdinaryPersistentCommitmentCache`、PR-C 分组配置。

### 4.1 共享可重放历史，再比较构建时机

使用第 3 节的 EvidenceBatch，把源研究数据、真实反例、调和时新增探针统一关联到各程序版本与来源。让预组织组与普通组调用同一个建分支/范围/路由的核心函数：

- 预组织组在来源阶段提前执行并保存结果；
- 普通组在实际需要时从相同证据重放，保存所需结果，后续复用；
- 内部 ID 和存储表示可以不同，但程序预测、scope 三态判定、反例归属、合法绑定和独立支持关系应一致。

这样比较的是构建和消费时机。若输出本来不等价，就要将差异明确列为算法处理，而不能只叫“缓存实现不同”。

三层缓存保留现有实现，补足原始证据内容指纹：同数量但内容或 schema/绑定/反例版本变化必须失效；与本次产物无关的来源变化可以局部保留。不要仅以 archive 的 `len()` 作语义版本。

H* 调度关闭时，普通组不应被强迫为永不消费的家族做昂贵反统一；允许它形成相同知识，实际是否形成由共同策略决定。来源阶段预组织过但未来不用的工作，也要进入预组织组自己的维护账。

**验收回放 D：**从空派生缓存开始，用同一冻结原始历史分别构建两组对象；比较实际预测、guard 判定与支持/反例关系。第二次未变输入应复用。保持 archive 长度不变，只修订一个有影响的观测/协议，相关结果必须重建。不得再只断言“缓存 hit=True”。

### 4.2 用明确的配置矩阵消除 H* 调度混杂

主对照只需三组：

| 项目 | `R_lazy_noH` | `K_eager_noH` | `K_cold` |
|---|---|---|---|
| 初始研究器与合法研究 API | 相同 | 相同 | 相同 |
| 当前目标预算与确认规则 | 相同 | 相同 | 相同 |
| 完整原始来源/调和证据 | 可访问且实际重放 | 可访问且提前构建 | 仅共同起点，作为转移锚点 |
| H* 前置调用 | 关闭 | 关闭 | 关闭或无可用 H* |
| 普通机制/参数重新研究 | 允许 | 允许 | 允许 |
| source 派生结果缓存 | 按需构建并持久复用 | 提前构建并持久复用 | 无 source 派生结果 |
| scope/routing 算法 | 同一算法 | 同一算法 | 同一研究器自身生成能力 |
| 跨目标新增学习 | 两组共同冻结，或两组共同开放；本主试验选冻结 | 同左 | 同口径 |

如还要研究 H* 策略，另列 R/K × H* 开关的 2×2。不要用 R-H*ON 对 K-H*OFF 给出纯知识组织结论。H*OFF 的精确定义要以真实消费者行为为准，不能把“完全不调度”写成“只是稍后调度”。

在已曝光的 `1024000/T1` 先补 R-noH，确认其是否从错误家族路径恢复。该题只用于诊断与回归，不算新泛化成功。不要预言 R-noH 必然打平，必须实际运行。

## 5. 第三项交付：闭合一条持久的递归修订与后继复用链

### 5.1 让延期问题真正能够继续

修改位置：`UnifiedResearchAgent.run()` 的问题加载、当前 handler 和成功记忆之后的调用；现有 library 队列字段。

- run 开始读取可执行的持久 pending，而不是只接收当前 rec_action 的新问题。
- 问题身份绑定 `episode_uid + parent_semantic_version + evidence_refs + question_kind`，不能只依赖通用 `anonymous_process` 和可复用 claim id。
- 恢复前核对父版本与依赖；已变化的问题重新定位或标 stale，不把新答案写回旧父版本。
- 旧父环境若需要继续购测，必须恢复对应合法实验上下文/任务检查点。不能把新环境的观测悄悄当成旧父环境证据。
- 延期后重启不重置累计研究成本、不重复计独立证据；如果只有历史数据可用，明确限制研究范围。
- `scope_boundary_unidentified_after_refutation` 必须接入已有边界研究路径，或保留明确可执行的阻塞原因与下一动作。不能进入队列后因 kind 过滤永久无消费者。

**验收回放 E：**同一个真实 library 在预算不足时保存问题；保存/恢复后补充明确预算，在同一合法父环境继续。检查是恢复原问题和原证据，不是 deepcopy 初始库再跑一个新的成功例。若父版本变化，不能更新旧问题。

### 5.2 子问题答案需要返回到假设库的修订入口

子研究给出新程序并通过新确认后：

1. 保存新版本与实际确认批次；旧失败版本保留历史状态。
2. 重新进入同一分支调和入口，仅检查受此次变更影响的历史邻居与依赖，不必全库重新研究。
3. 分别决定重新标定、局部修订、分支共存、合并或撤回。
4. 预算不够继续调和时，保存 `pending_reconciliation`，不要把“父任务已修好”扩写为“整个库已一致”。
5. 给父用途返回经过验证的答案，保留未解决的兄弟问题；不要无差别全部标 answered。
6. 新证据、版本或候选均未改变时，不重复产生同一个递归任务。以现有语义版本/证据指纹去重，避免无限重入。

### 5.3 将残留阈值区间探针接到真实循环

调用现有 `propose_threshold_interval_boundary_probe`，其输入来自当前已付数据的相容参数区间，不再由脚本手工指定。顺序必须完整：

1. 从当前证据产生仍相容的参数/程序版本。
2. 冻结被测版本及允许绑定，寻找其预测不一致的合法 probe。
3. 真实 acquisition 成功后才更新证据与相容区间。
4. 根据结果重新标定或修订候选。
5. 使用新的、未被本次候选选择消费的确认批。
6. 预算不足或关键分歧尚未研究时，记录未知/未决或有明确限域的经验结论，不声称整个范围已识别。

已有主动阈值研究器能完成的步骤直接复用。不能通过给算法真实阈值、改变精度门槛、扩大某一组预算来修复假确认。

**验收回放 F：**把已曝光 `1021000/S_left`、`1023000/T3`、`1026000/T3` 的边界失败用于开发。检查新增 probe 是否实际执行、它如何改变区间/候选，以及新确认是否独立。允许正确输出未决；不要以全部回归题必须完成作为修改科学真值门槛的理由。

## 6. 分支冲突、修订、融合与消除的实际决策规则

下面规则沿用已有 branch/family 字段即可，不必增加一套通用理论对象框架。

| 观察到的情况 | 本轮应采取的动作 | 保留的理由/证据 |
|---|---|---|
| 同一实例在真实新数据上错误，允许参数重绑后能解释 | 新实例/参数修订；保留模板 | 原绑定反例、新绑定证据、允许重绑范围 |
| 两条声明范围不重叠 | 分支共存 | 各自来源与范围，不能仅因不同而消除一支 |
| 重叠范围存在实际预测冲突，只有一支通过 | 限制失败支在该范围的资格；研究边界 | 固定版本、真实 probe、局部范围依据 |
| 重叠范围双方都失败 | 限制两支的具体声明，提出遗漏机制/表示子问题 | 父用途、共同反例与待研究返回类型 |
| 不同表达在当前已付数据上暂时相同 | 保留可能等价关系；必要时做区分实验 | 未找到区别不等于永久等价 |
| 有共享结构，广义表达保持旧支持与已测试拒绝 | 可合并/反统一为新候选，保留来源分支 | 旧证据保持、独立区分测试、支持根 |
| 合并后丢失旧反例或损害某一来源 | 回退合并，保留分支或缩小合并范围 | 被丢失的具体区别 |
| 某个来源撤回，其他来源仍独立有效 | 局部更新支持；不全删共同结构 | 支持根与依赖图 |
| 只因路由特征不典型 | 降优先级，有预算时后置尝试 | 经验调度理由，不伪装为科学反驳 |
| 没预算、未找到拟合、协议不匹配 | unknown/deferred | 不新增肯定或反驳的科学事实 |

规模扩大时可以用结构签名/索引筛选需要比较的邻居；签名只决定“先比较谁”，不直接决定“谁正确”。当前库很小，先保证上述语义，不另开全库优化工程。

## 7. 一条真正回答用户问题的连续对象实验

### 7.1 使用现有 focal_memory 链，避免另造新领域

可以沿用当前 C1 成功作为已曝光开发模板：普通来源形成马尔可夫候选；某次真实研究产生无法解释的历史依赖；子问题调用现有 latent 研究器，形成含 `accumulate` 的新程序；新确认后重新与历史分支调和。

此处“新假设”应明确到实际程序、固定参数、自由参数、状态表示和版本。无需宣称系统发明了 latent 搜索算法。既有语法中的新机制组合、状态表示或可执行实例可以成为合法学习成果。

主试验使用冻结后的新来源实例，记录全体尝试，包括没产生合格新对象的源链。冻结源知识后测试现有实验室支持的新 latent 参数、对象命名和布线；加入返回旧马尔可夫域的任务及与新假设范围相关的相近反例。不得把当前旧 seed 的修复包装成未见收益。

### 7.2 两个问题分开测，防止重新引入能力不公平

**问题 A：父任务修复是否值得？**普通失败重试与父子问题驱动调度必须拥有相同 latent 搜索 API、总预算和原始经历。比较怎样分配研究、是否完成、错误确认、总成本。C1 的 195 行与 560 行对照继续用作预算路径测试，不用于宣称递归净增益。

**问题 B：修复所得知识是否改善未来研究？**对同一个修复对象使用 R-lazy-noH、K-eager-noH 与 cold。允许 R 从相同原始证据重建并缓存等价知识；删除 K 中该对象的干预仍保留同样原始经历和普通重建权限。如果普通方法迅速重建并打平，按真实结果报告。

可用最小对象移除干预定位影响：只去掉本次修复版本及由它独占支持的派生关系，保持其他来源和合法工具一致。不得同时删除全部历史、关闭潜变量能力或改变任务预算。

### 7.3 每个主案例必须能直接回答的七句事实

1. 在哪些普通经历后，产生了哪个具体 `hypothesis_id/version`？
2. 哪个真实证据使哪个版本在什么范围失败？
3. 为什么选择重新标定、修订、分支共存或合并？
4. 哪个子答案实际改变了父程序或下一实验？
5. 修复对象经过了哪些新确认与历史分支检查？
6. 哪个未见目标实际调用该对象，改变了什么研究动作？
7. 同历史、同能力、同策略普通方法的结果及全部成本是什么？

这七句应该由同一条对象/证据账本生成，不能从 PR-A 与另一套 PR-C 成绩中各摘一段拼接。

## 8. 评价与成本合同

### 8.1 冻结和样本单位

- 当前 `1021000–1028000` 已曝光，用于诊断回归。
- 先完成上述 A–F 生产路径回放，再固定代码、M0、合法机制目录、预算、H* 开关、候选调度、确认规则和统计口径。
- 然后一次性生成新的来源链和后继任务。隐藏世界参数仅用于独立评价，不进入策略路由。
- 源链是统计簇。同一来源的多个目标不能被当作互相独立的重复实验。
- 8 簇适合发现具体反例和估计方向，不能保证足以证明小幅非劣或优越。若资源不足，保持个案和描述性结论；若要强统计主张，先据已曝光变异估算所需簇数，不边看新测试成绩边加样本直到显著。
- 外部评价不参与本轮候选选择。失败若用于下一版调试，则该实例进入曝光集。

### 8.2 同时报告质量、误确认和资源

至少给出每个任务与每个源簇的：

- 内部完成、外部严格通过、内部确认但外部失败、未决。
- 新知识错误迁移、旧域保留、错误硬排除、scope unknown。
- 观测、测量、计费计算、墙钟；标明墙钟是否含外部评价。
- 源形成、额外区分实验、维护、重建、目标拟合与确认的成本来源。
- 冷缓存首次调用与暖缓存后续调用，固定或平衡后的任务次序。

不用单一平均 MSE 或一个加权总分掩盖错误确认。若声称“质量不降而更省”，先定义可接受的质量差及配对分析方法；`p>0.05` 不能直接充当等价/非劣证据。双方都成功子集中的成本只作描述性补充。

### 8.3 用逐链前缀全成本替代通用回本题数

在共同原始历史已经付费、两组获取相同信息的比较中，定义：

\[
\Delta C_c(k)=C^{R}_{\mathrm{maintenance},c}+\sum_{t\le k}C^{R}_{c,t}
-C^{K}_{\mathrm{maintenance},c}-\sum_{t\le k}C^{K}_{c,t}.
\]

R 的按需构建已经计入相应目标成本时，不重复计费。共同来源数据成本可以在差值中相消，但全账仍列出。如果两组实际取得的信息不同，另做端到端成本比较，不继续声称“相同历史”。

逐源链展示 k=1、2、3 及预先规定的后续长度；失败和误确认仍留在分母。收益依赖目标次序、缓存状态和未来任务分布，不能将均值比值扩展成所有库的固定回本阈值。

## 9. 三层结论与停止规则

| 可写的结论 | 所需证据 |
|---|---|
| 机制已接通 | A–F 真实生产路径回放，预算/身份/未知语义正确 |
| 某个自主修复对象帮助了具体未见问题 | 连续对象账本、同策略普通对照、实际消费与对象干预 |
| 在给定工作负载上系统性改善研究 | 冻结新源簇、质量与全部成本并列、簇配对不确定性、负例完整 |

停止规则：

1. 同策略普通方法打平或更好，接受当前主张收缩，不削弱它、不换成更弱普通对照。
2. H* 无增量，不强求其成为默认搜索入口；不从此断言数学抽象永远无用。
3. 学得路由若只有更低成本但增加假确认，不写整体研究更有效；先改善确认或明确质量—资源取舍。
4. 科学评价本身允许失败；验收不要求所有新任务100%通过。
5. 生产路径与有限公平试验完成后收口，不因每个可能边界不断增加新框架或追加无关测试。
6. 只有在现有语义和评价稳定后，才考虑更复杂的机制组合、开放语言提案或方法层 RSI。它们是后续新研究，不用来掩盖当前证据缺口。

## 10. 下一轮应交回的材料

只需一套可审查结果：修改的核心函数与差异；A–F 回放日志；同原始历史重建的行为比对；公平配置矩阵；连续对象账本；冻结新实验的所有成功、失败和成本；一段明确允许负结论的研究判断。

不必再增加新的总览层级或十几个同义完成标签。完成时首先回答：**哪个新假设，因为什么经历而改变，怎样改变了哪个未见问题，以及同样强的普通方法究竟做得怎样。**
