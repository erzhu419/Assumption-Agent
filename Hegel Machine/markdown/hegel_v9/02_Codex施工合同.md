## 3. 语义参数组适配

### 3.1 不新增一套模型存储

在现有拟合图／关系参数合同旁建立可再生的薄视图。必须能定位到原字段，而不是复制整个程序库。

每组需表达：

```text
group_ref：实际参数／坐标／组合引用
kind：readout / relation / temporal / role / aggregate_scope / composition
occurrences：受该组控制的实际节点及列
legal_domain：公开合同允许的范围，或unknown
source_application：源版本和适用范围
target_identification：固定 / 重识别 / 重绑 / 未决
use_sites：变化后需要重算哪些现有结果
```

这是最低语义要求，不要求逐字新建这些字段；现有字段能表达就直接复用。

### 3.2 分组算法

1. 用`research_program_fit_contract`读取全部声明列；零列不丢。
2. 用真实关系绑定找出同一参数的所有出现；不得以浮点相等作为唯一依据。
3. 对时间算子和角色映射读取其公开合同，不从参数数值猜物理意义。
4. 源旧文件缺失零列时，只保留可恢复的旧计算，不声称恢复完整源族。
5. 一个组改变后，使用既有依赖失效→refit／实验重建路径。

### 3.3 必须覆盖的三种不一致

- **源点不一致：** 保存后预测已变，属于表示／保存错误；先修复再科学评价。
- **族自由度不一致：** 源点相同，但合法目标参数变化无法表达；属于合同保持失败。
- **世界迁移不一致：** 源点及族都保持，目标仍不适用；是科学问题，不再归咎保存。

## 4. 划分候选生成

### 4.1 初始有限前沿

按实际反例依赖召回候选组；每代最多释放一个语义组或改变一个局部结构。保留至少原方法候选及一个若有依据的联合变体。

候选必须说明：

- 哪部分与源共享；
- 哪部分由目标资料识别；
- 哪部分仅在声明范围可用；
- 实际执行哪一个现有研究器；
- 什么结果反驳该共享方式。

### 4.2 禁止的默认

不得默认所有源关系参数永远共享；不得默认新目标全部参数都必须放开；不得默认源全对象聚合可以无证据扩到任意对象数；不得默认更高维模型比简单模型更接近正确理论。

允许源参数作初始化，允许泛化候选暂时未经证实，但必须按候选而非事实使用。

### 4.3 两个因素相互补偿时

一个因素单改无益不能直接永久删除该因素。若现有联合成功、残差形态或程序依赖提供依据，可提出一个有限的双组变体。使用同一资料和预算比较；无证据时不全面生成所有组合。

## 5. 参数、结构、表示与观测的竞争诊断

### 5.1 每个诊断的最低内容

```text
diagnosis：一个可证伪的原因候选
answers：至少两种可能结果，或明确解关系
witnesses：真实反例／不确定参数／失败计算引用
test：当前合法、可执行、完整报价的研究
parent_effect：不同结果改变哪里
scope：检验涉及哪些模型和条件
```

若诊断不能产生不同可测后果，则先保留为IDEA，不计作已执行子研究。

### 5.2 判断优先级

1. 先消费已经存在且适用于当前题义的答案；
2. 修正让试验没有真正发生的执行错配；
3. 在合法完整单位中，优先处理会改变当前父用途的区别；
4. 利用真实配对结果排序已有可比方法；
5. 无可信收益估计时允许有界探索，保留未决；
6. 与任务无关的理论问题进入原理论使命，不抢占未获授权的任务资源。

这不是固定参数→结构→表示的必经阶梯。已有强表示反例时可以直接研究表示；已有相同实例失败时不必重试。

### 5.3 数值与族否定

现有稳定求解已经修好，不再建设另一套求解器。对固定列族，报告最小残差、秩及有限范围；若要声称逐点不可行，要满足相应有效下界或可行性检查。只返回一个拟合不佳实例时，状态是该实例失败。

`search_incomplete`不生成世界反驳；完整有限搜索的负结果只覆盖声明的有限空间。候选代表不能冒充后验抽样。

## 6. 新程序的生成与实际消费者

### 6.1 载体

- 原生拟合图：继续由原`research_program`重放器消费；
- 研究控制程序：继续由`select_actions`与`ProcedureConsumerAgent / execute_procedure`消费；
- 一项方法可以调用上述两者，但必须有明确适配，不将Python源码塞进无人消费的字段。

### 6.2 可编辑位置

允许改变一个真实调用的参数组自由度、一个合法局部结构、一个数据读出／选择、一个已有区分实验、或者一个基于实际返回的后继分支。

不允许删掉普通全池比较、预算检查、证据版本核对或确认来取得虚假的效率提升；不允许改hidden任务类别分支。

### 6.3 生成器预算建议

首版建议：父beam≤4、不同候选≤12、初始编辑深度1、条件候选≤8、初始科学选择段≤2。原协议已冻结更小界限的运行保持不变。

满足真实依赖超界、旧方法对照保留、完整报价及预先冻结的条件时，可在新版本把科学选择段上限扩到4；不自动扩到任意长度。实际代码／结构复杂度、拟合与观测预算单独约束。

### 6.4 来源差异怎样约束后继生成

| 观测 | 生成器应改变 | 不应改变 |
|---|---|---|
| 某参数域未被消费 | 重新绑定该候选实际输入 | 不反驳整个结构 |
| 保存丢掉合法列 | 修复族合同再比较 | 不把修复冒充学得规律 |
| 当前表示可靠冲突 | 生成使用公开遗漏区别的候选或随机解释 | 不继续同表示换无数拟合器 |
| 特定绑定失败 | 保留其他合法映射，重开该绑定 | 不全删源知识 |
| 实例新预测失败 | 撤回该实例在范围内支持，提出可区分修订 | 不无条件排除所有参数 |
| 完整方法配对无益 | 限制该条件和编辑族的优先级 | 不从未执行替代推导最优策略 |

## 7. 最小开发单位

### 7.1 当前联合稿的任务确认

复用现有冻结／确认出口；读当前原额度及时间授权，不推断算术余额等于许可。原已解源的765余额不转给目标。新确认失败后保留原预测并更新原方法题；未确认不发布新世界支持。

### 7.2 学习划分的同资料配对

选当前明确未决的一项共享假设，固定一个真实调用前状态。两臂共同资料、工具、旧池、语义组和完整资源；只改变该共享／释放／绑定内容。

可引用既有匹配回执；版本或资料不匹配时不能强行拼成配对。需要新增计算时先报价。所有195行均已曝光，仅作为开发诊断。

### 7.3 可选的数据×方法四格

仅当确有不同且合法的新证据D1时，比较：

```text
M0,D0；M1,D0；M0,D0+D1；M1,D0+D1。
```

没有D1就做两格，不购占位数据。所有最终候选先冻结，再共同评价新面板。四格是一个来源的局部机制试验，不是四个独立任务。

### 7.4 条件学习

使用同内容方法在不同调用前状态下的完整配对偏好。没有配对结果，不给替代方法伪正标签。一个方法只在一个来源有正偏好时，允许局部探索规则，不发布一般condition。当前`insufficient_paired_preferences`允许并且必须保留。
