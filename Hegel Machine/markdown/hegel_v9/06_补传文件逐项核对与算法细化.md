## 1. A的操作细化：共享事实，不自动共享结论

附件A明确要求跨方法版本保留共同证据而不继承错误支持。上轮§8已有继承表；现在把表收紧为实际判定规则。

### 1.1 保留三种不同对象

| 对象 | 版本变化后怎样处理 |
|---|---|
| 原始事实：物理命令、实测响应、轨迹、时间和原始仪器读数 | 保留原记录及取得条件；换方法不会把历史事实删除 |
| 条件化计算结果：特征列、拟合、预测、评分、区间 | 输入与全部相关依赖保持时才复用；否则按现有失效机制重算 |
| 科学／方法结论：适用、预测支持、研究策略优越 | 只对实际受检对象、范围、评价和来源成立；新程序体不自动继承 |

若原记录含有由旧校准推导的“物理量”，它不是未解释原始读数；校准变化时，原始读数可留，推导量需要重算。

### 1.2 依赖规则

设旧结论c实际依赖集合为Dep(c)，本次改变的语义对象为Δ。执行如下规则，而不是只看方法ID：

```text
原始记录：保留。

计算缓存：
  原调用输入、版本、绑定、资料顺序、参数域和评价完全一致 → 可复用。
  任一实际依赖改变 → 使依赖该项的计算失效，按原消费者重算。

局部支持：
  Δ与Dep(c)不相交，并且范围、命题和评价仍相同 → 保留该局部支持。
  Δ与Dep(c)相交 → 保存历史结论，但不作为新对象的有效支持。
  依赖不全，无法确认 → 保留历史，当前支持为未决。

整段方法效用：
  方法体、条件策略、执行语义或资源合同改变 → 新的效用主张需要新检验。
```

依赖“完全一致”不是要求另造证书系统；读取现有真实引用即可。内容指纹可以检出字节变化，但不能自动证明任意Python语义等价。对允许的纯路径迁移或已有可验证透明变换，可以沿用相应有限等价检查；无法证明时按新计算处理。

### 1.3 对本项目的具体后果

将来源关系参数从固定改为目标识别后：

- 来源原始资料、未改变的角色校准和仍独立成立的局部子结论可以保留；
- 用旧半径生成的目标特征列、其依赖拟合与评分不能直接复用为新半径的结果；
- 原@3/@4在原48行上的结果仍是原方法的冻结历史；
- 新联合稿在195行上的结果是开发拟合，不能借用旧确认身份；
- 同一origin追加后效仍是一条配对，不按方法版本号增加样本。

“相同预测”也不自动允许继承成本结论：若代码实现或缓存策略改变，新的实际运行成本需要测量。

### 1.4 最小验收

一个局部参数组改变，实际依赖它的列和拟合必须重算；无关且依赖完整的局部支持可以保留；新方法的整体支持从未测开始。用这三种行为验收，不以新增字段数量验收。

## 2. B的操作细化：研究收益如何算，数据不足时如何行动

本节是新增实施建议。它不声称当前已经能准确预测任意研究行动的价值。

### 2.1 先定义在比较哪两项完整行动

对调用前公开状态x，比较当前候选完整研究a与参照研究b。只有满足下列条件的历史配对进入直接估计：

```text
同一调用前起点、共同已有资料与旧候选池；
工具和资源权限可比；
被比较的方法体／参数化合同相同；
评价尺度和资料角色相同；
条件筛选规则只读取行动前公开信息；
两臂结果真正执行，不由另一臂的失败臆造。
```

“状态相似”应使用先冻结的有限公开条件，不能看到哪个动作赢了再定义相似。跨版本、不等起点或不等预算的资料仍可作为候选生成经验，但不直接合并成同一种策略的配对收益标签。

### 2.2 先在每个物理来源内汇总，再在来源间汇总

令g为物理来源／donor簇，J_g为该来源中符合上述合同的配对。对两臂都具有共同冻结评价的配对，计算：

\[
\Delta^R_j = R_j(b)-R_j(a),\qquad
\Delta C_{j,k}=C_{j,k}(a)-C_{j,k}(b).
\]

正的ΔR表示a风险更低；正的ΔC表示a消耗该资源更多。R严格沿用原评价定义，不自行将按行、按轨迹、最坏误差混合。

每个来源先求局部平均，再按事前声明的来源权重聚合。无其他目标分布信息时，可使用等来源权重：

\[
\widehat\Delta R=\frac1G\sum_{g=1}^{G}
  \frac1{|J_g|}\sum_{j\in J_g}\Delta^R_j.
\]

这只是匹配历史配对的经验汇总。它不是自动得到当前x下的真实条件期望，更不是因果效果已经跨任务识别。

同一装置的100次续修不能当成100个独立来源。用于条件搜索的这些结果也不能再冒充条件的独立验证。

### 2.3 未完成不能用缺失风险偷偷排除

另外报告每臂在同预算下的完整交付指示I，以及交付差异I(a)−I(b)。

- 一臂没有交付预测器时，风险差为缺失，不能填0、无穷大或虚构惩罚；
- 完成率和费用仍按真实尝试记录；
- 同时报告“全部尝试的交付率”和“共同完成配对上的风险差”，不能只用后一项评价不可靠方法；
- 行政暂停／外部资料缺失标明受干扰，不能当作世界模型反例；已付成本不删除。

具体首版排序可采用：先满足原任务质量和交付要求，再比较同质量资源；不能用低开发MSE抵消大量不交付。更一般的资源偏好须来自已有任务合同，而不是新造权重。

### 2.4 当前数据不足时的返回

| 可比材料 | 返回 | 不得输出 |
|---|---|---|
| 没有同内容、同状态配对 | `return_estimate=unknown`，附合法计划和完整报价 | 收益0或任意成功概率 |
| 只有一个真实物理来源 | 该来源的局部观察差异、费用、范围 | 稳定跨来源均值、置信度或一般条件 |
| 有多个来源且合同可比 | 分来源结果、经验汇总、交付率、适用条件 | 将其当成自动校准的未来效果 |
| 效果与资源互有优势 | 保留权衡 | 未经解释的“综合最优分” |

附件报告的当前@4只有一个真实配对，因此这一步目前能返回局部后效，不足以训练可信的一般“最优下一研究”函数。

### 2.5 没有可靠收益估计，不等于不能研究

在未知收益下，允许一次预登记的有界探索：

```text
先消费已有答案并排除执行错配；
→ 检查至少两个答案是否改变当前父用途；
→ 检查已有执行器是否能实施一项区分或修订；
→ 检查完整交付报价是否在权限和预算内；
→ 在合法候选中按事先声明的操作规则选择一次；
→ 实际返回后更新经验，不回填事前“预测收益”。
```

候选分歧用于提出有辨别意义的研究，不转成概率。不得因为复制同一候选增加次数就提高其价值；不同族的参数维数也不作为概率质量。

若多个研究资源不可比较且没有偏好，保留并列，并用预登记顺序完成一次合法探索。该顺序是工程决策，不是学得的科学最优性。

### 2.6 每次返回要明确否定的层次

| 返回 | 可以更新的结论 |
|---|---|
| 保存／绑定有错 | 执行合同有问题，相关科学检验未按意图发生 |
| 一个拟合实例失败 | 此实例在这份资料及范围失败 |
| 完整有限空间均不满足，且数值／覆盖前提合格 | 此次明确有限空间被排除 |
| 预算结束、仍有未处理空间 | 搜索未完成；方法在当前预算的交付表现受损 |
| 多个已测相容解释对任务无区别 | 当前任务可以暂不辨明机制，不是机制已经唯一 |
| 所有当前代表均被新响应反驳 | 当前代表均失败；是否排除全族仍需覆盖依据 |

上述规则沿用旧求解器和残差；不会要求穷尽整个可表达程序空间才能换方向。

## 3. C的操作细化：从一段经历产生真正不同的程序

### 3.1 上轮哪里还不够具体

上轮§14.1已经给了生成伪代码，但`anchor_to_current_parent_and_semantic_groups`、`existing_legal_edits_from_contracts`、`apply_one_edit`等仍是抽象步骤。

对于方案说明，这些名称有用；对于直接施工，仅写“实现该函数”会再次把关键算法交回开发者。本节选定一个有限实例补足，不承诺一般程序发现已经解决。

### 3.2 固定输入，只提取真实差异

输入仍是附件列明的材料：源成功研究图、参数绑定、目标反例、失败的系数重拟合、成功的联合修订。步骤如下：

**第一步：对齐两个实际计算。** 使用已有节点／绑定引用寻找可比较部分；仅做受类型、角色和参数身份约束的有限匹配。不根据半径数值相同、变量名字相同就认定语义相同。匹配不唯一时保留有界候选或未决。

**第二步：提取“改了什么”，不要提取“答案是什么”。** 比较旧稿与联合稿，列出改变的关系绑定组、独立读出组、对象范围或局部组合子图。来源旧数值、新目标拟合数值仍保留为历史事实，但不成为通用方法中的目标常量。

**第三步：回溯实际消费者。** 对每个变化组，取使用它的特征列、拟合、候选比较、区间分析和实验读出的依赖闭包。这个闭包决定必须重算哪些结果，不给该组自动分配整段改善信用。

**第四步：建立最小可试变换。** 对一个在旧稿固定、在修订中重新识别的关系组g，构造“在目标资料上重新识别g”的候选。若同时有结构变化，保留联合变换，并把“只改g”和“只改结构”作为可选诊断；不能从联合成功断言只改g一定成功。

**第五步：参数化研究而非复制目标解。** 新程序保存的是合法域、需要读取的列与真实依赖、目标拟合器入口，以及研究返回后的分支。它不保存“下一目标半径应为0.9746124”。

### 3.3 一个明确的可执行改写

将旧方法片段概括为：

```text
旧片段：
  读取源关系绑定ηs；
  在该绑定产生的完整列上，用目标资料D识别β；
  与旧池比较，输出当前候选。
```

对应候选改写是：

```text
新片段：
  读取当前公开合法关系域I，不把源窄区间当作目标真边界；
  对I内现有研究器实际选择的η，重新计算依赖该组的目标列；
  在每个η下用D识别β，并依照原研究器比较；
  返回当前候选、实际搜索覆盖以及剩余任务相关分歧；
  与完整合法旧池比较，保留原候选；
  后续是否区分实验、确认或停止，遵守原任务合同。
```

这项改写改变了目标端能研究的自由度和计算，不只是把“structure”动作优先级调高。

**实现限制：** 如果某个现有高层入口只能同时改变关系和结构，不能把它标成“只释放关系”。应在已有拟合器的真实可配置边界限制搜索；不能实现该限制时，返回“联合变体”，单因素格为未实现／未测。不要靠改标签伪造消融。

### 3.4 如何归纳“什么条件下追加哪段研究”

从真实经历抽取可用分支特征：旧研究是否完整、当前仍有哪些已付反例、哪些关系组确为源固定、相容候选是否对合法完整轨迹产生任务相关分歧、仪器绑定是否已有支持、完整研究预算是否足够。

这些字段只表示公开研究状态，不编码case身份、隐藏机制、最终赢家或未来结果。

生成器可以由真实依赖提出：

```text
系数重拟合完成，但仍有未解释反例
  → 试验关系组重识别或保留真实联合变体。

重新识别后已解释开发资料，但相容关系仍产生任务相关预测分歧
  → 提出已有合法区分实验及其分析。

原任务允许确认，且当前没有阻止确认的义务
  → 冻结后执行原确认。

确认失败
  → 同一版本的失败保留，后效返回；下一版本再修订。
```

**这些是候选分支，不是从一个来源就学成的一般规则。** 相同方法内容的真实正／负配对由原条件器比较；材料不足时不发布一般条件。一个条件在前一段执行后才变得可见，可以用于下一段选择，但不能冒充整段调用前已知信息。

当前这条195行修复是开发者选定入口，适合提供候选生成材料；它不能被改名成系统自主学得并执行的完整方法。

### 3.5 原生成伪代码的一处实际修正

原代码在达到`max_candidates`后只跳出最内层编辑循环。在扩到多个父前沿／多代时，后续父候选仍可能继续追加，导致超过候选上限。例如，4个父、每个至少12项编辑、上限12，原片段可返回15个候选。

此外，限制成功候选数不能限制全部无效／重复提案的生成耗费。必须同时约束“尝试数”和“成功保留数”，提案生成、匹配、编译检查也受独立计算／时间额度约束。

以下伪代码给出修正后的控制流程。它是设计说明，未声称这些助手函数已经在仓库实现：

```python

        return unresolved("missing_actual_dependencies", materials)

    if not deltas:
        return unresolved("no_executable_semantic_change", materials)

    accepted, attempts = [], 0
    frontier = [parent_method]
    for depth in range(limits.edit_depth):
        next_frontier = []
        for parent in frontier:
            while True:
                if len(accepted) >= limits.max_candidates:
                    return proposals(accepted, attempts, "candidate_cap")
                if attempts >= limits.max_attempts or meter.exhausted():
                    return proposals(accepted, attempts, "generation_budget")

                # 提案枚举本身也必须能够被meter中止。
                edit = next_bounded_edit(parent, deltas, limits, meter)
                if edit is None:
                    break
                attempts += 1  # 失败、重复、权限不符都计入尝试
                child = edit_existing_method(parent, edit, meter)

                if not actual_dependencies_and_information_are_valid(child):
                    retain_failed_attempt(child)
                    continue
                if not executable_by_existing_consumer(child):
                    retain_failed_attempt(child)
                    continue
                if exact_execution_duplicate(child, accepted):
                    retain_duplicate_origin(child)
                    continue

                # 有限面板上的同预测不是永久语义等价；不因此删去其他机制。
                accepted.append(child)
                next_frontier.append(child)

        frontier = bounded_frontier(next_frontier, limits.beam_width)
        if not frontier:
            break
    return proposals(accepted, attempts, "bounded_search_finished")
```

`next_bounded_edit`的候选顺序由真实差异位置、六类合法编辑和冻结的轮转规则确定；不按隐藏任务标签排序。`edit_existing_method`在本窄实例中具体执行§3.3的“固定关系→目标识别”替换，并保留§3.2的依赖闭包。后续结构编辑同样必须有实际局部子图与对应消费者。

### 3.6 首轮边界

保留上轮建议：父前沿≤4、成功候选≤12、初始编辑深度1、条件候选≤8、科学选择段≤2。**新增建议：一次生成最多48次编辑尝试**，并独立限制资料召回、匹配、程序检查的计算和墙钟。

### 4.1 D：8格不是唯一最小，更不保证出现正负偏好

上轮给了参数P、组合S、测量／角色M三因素2×2×2完整开发试点，并给出公开信息、冻结与按物理来源留出。它满足“分别变化三类因素”的设计要求，但不是任何目标的最小样本定理。

**设计必须保证可区分某项科学后果，而不能保证某种方法必胜。** 即使P/S/M不同，两个研究策略仍可能都成功、都失败或成本打平。那就是有效结果，条件器应保留“无可辨偏好”。

当前已有材料不能保证形成一般使用条件，正是附件要求保留`insufficient_paired_preferences`的原因。
