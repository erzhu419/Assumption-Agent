# 二、当前真正的核心缺口：复用一个答案，还是复用一种可重新学习的模型族？

这是我认为需要补进主方案最明确的一层。

假设来源程序是：

\[
f_s(x)=\sum_{j=1}^{k}\beta_{sj}\phi_j(x;\eta_s).
\]

这里至少有三种完全不同的“复用”。

### 第一种：保存完整源响应，再调整偏置和缩放

\[
a+c\,f_s(x).
\]

它可以逐值还原源程序，但目标端能够调整的方向很少。

### 第二种：保存独立拟合列，在目标重新拟合读出

\[
a+\sum_j b_j\phi_j(x;\eta_s).
\]

这保留了更多自由度，但关系参数\(\eta_s\)仍然固定。

### 第三种：保留结构关系，让目标重新识别关系参数、绑定或部分结构

\[
F_s\bigl(\phi_{\mu_t,\eta_t}(x);\beta_t\bigr).
\]

它比第二种更灵活，但也可能更贵、更容易在小样本中过拟合，而且不保证正确。

所以，项目必须分别检查：

\[
\boxed{
\text{源点重构}
\neq
\text{模型族自由度保持}
\neq
\text{跨任务适用性}.
}
\]

此前8列变1列，主要是第二项出了问题；恢复8列后，第三项仍然可能失败。第79节恰好给出了这个真实负结果：多列工作误差下降约8.22%，新48行误差却上升约40.61%。hegel_machine_next_construction…

**因此，下一项知识对象不能只叫“这个结构能复用”，而应明确声明：这个结构的哪些部分可暂时共享，哪些部分要由目标数据重新识别。**

# 四、问题A：怎样学习“不变结构／可变参数／可重绑角色”？

## 4.1 建议的学习对象

将一个任务的预测写成：

\[
\widehat y_\tau
=
F_{s_\tau}\left(
\phi_{\mu_\tau,\eta_\tau}(x_{0:t});
\beta_\tau
\right).
\]

其中：

| 分量 | 含义 |
|---|---|
| \(s_\tau\) | 窗口、事件、聚合、条件等组合结构 |
| \(\eta_\tau\) | 半径、阈值、窗口长度等关系或时间参数 |
| \(\mu_\tau\) | 角色、单位、仪器、对象集合等绑定 |
| \(\beta_\tau\) | 读出系数与截距 |
| \(\Omega_\tau\) | 适用范围 |

这不是要求新建一个巨大模型类，而是给现有程序、拟合合同和参数绑定一个统一的研究含义。

系统要生成的假设是一个划分\(\Pi\)：

> 哪些组共享，哪些按目标重新识别，哪些需要重新绑定，哪些仍然未知。

## 4.2 首个有限候选集合

建议先生成四类候选，但**不是规定所有任务必须按这个顺序走完**。

| 候选 | 暂时保留 | 目标端研究 |
|---|---|---|
| \(\Pi_0\) | 当前结构与已核实绑定 | 独立读出系数 |
| \(\Pi_1\) | 组合结构与角色 | 读出＋一个关系参数组 |
| \(\Pi_2\) | 未被挑战的结构子图 | 一项合法角色／测量绑定及必要参数 |
| \(\Pi_3\) | 未受反例影响的计算 | 一项局部结构改写及其参数 |

如果\(\Pi_0\)在同一状态已经失败，应直接使用原证据；不必为了流程完整再拟合一次。若有直接的表示冲突，也不需要先穷尽所有系数再换表示。

## 4.3 参数组必须从真实绑定抽取

这是施工中的关键。

不能因为两个节点的值都等于1，就认定它们是同一个参数；也不能因为一个参数在多个列中出现，就分别放开成互不相关的自由度。

应从现有合同读取：

```text
完整fit列，包括零权重列
→ 每列使用的实际关系、角色和时间参数
→ 同一参数的真实出现引用
→ 变化后需要失效的拟合／预测／实验
```

现有`research_program_fit_contract`已经提供了完整声明列及读出重构基础，应直接扩展其消费，而不是重新从输出式反推全部模型族。

## 4.4 用反例检验划分，而不是直接指定答案

对允许变化的结构、绑定和关系，复用现有求解器计算：

\[
\widehat L(s,\mu,\eta)
=
\min_\beta
L_D\!\left(y,F_s(\phi_{\mu,\eta}(x);\beta)\right).
\]

然后比较：

> 固定关系是否足够？  
> 只释放关系是否足够？  
> 需要局部结构变化吗？  
> 是否必须改变角色或测量解释？

本次195行的联合成功可以提出这些问题，但**不能直接把0.9746124写进新方法**。

## 4.5 怎样判断“共享参数”被反驳？

这是需要特别谨慎的地方。

两个来源分别找到一个拟合区间，而且它们不重叠，**不一定证明不存在其他共同可行参数**。搜索找到的只是部分可行解时，二者可能还有未找到的共同解释。

因此，应区分：

- 当前共享实例失败；
- 所检验的有限共享参数族被排除；
- 参数共享假设在新的配对预测中失去支持；
- 仍然没有识别。

现有半径研究包含有限覆盖和局部细化，返回的区间也与具体拟合结构和已测几何相关，不能自动当成统计置信区间或目标装置的物理边界。

**最终输出应当是“目标识别程序”，不是“源参数包”。**

# 五、问题B：失败后怎样选择参数、结构、表示或新观测研究？

## 5.1 不用一个固定原因分类表，改用有限竞争诊断

对“工作更好、后继更差”，至少保留以下竞争解释：

| 解释 | 必须产生的可检验后果 | 最小研究 |
|---|---|---|
| 参数实例不合适 | 同一结构内重新识别能解释反例 | 目标资料上的剖面拟合 |
| 参数尚未识别 | 当前多个相容实例对某项未来实验不同 | 区间／候选预测驱动的区分实验 |
| 结构组合不当 | 改一个组合位置会改变相关预测 | 保留其他部分的局部结构干预 |
| 表示遗漏 | 当前表示合并了任务相关区别，或替代表示有不同后果 | 表示检查、合法历史或测量研究 |
| 角色／测量解释不当 | 相同物理干预在不同绑定下有不同读出 | 现有校准／角色区分 |
| 适用范围过宽 | 调用前可观察条件能解释并预测失效范围 | 有范围的配对验证 |
| 计算未完成 | 原研究还有明确、可报价的剩余步骤 | 完整续算，不新造世界假设 |

这些解释可以同时成立。不能强迫一次研究选出唯一原因。

## 5.2 每个诊断都必须回答“不同答案会改变哪里”

例如：

> **问题：当前关系数值能否沿用来源？**

两个答案分别意味着：

- 可以沿用：保留关系，仅识别目标读出；
- 不能沿用：释放这一关系组，重新计算依赖列并拟合；
- 当前不可辨：若影响父任务，设计区分实验；否则保留未决。

如果一个问题无论回答什么都不改变任何调用、预测或实验，它暂时不是当前任务的有效子研究。

## 5.3 如何选择下一项研究？

我建议使用三层规则：

**第一层：合法且完整可支付。**实验、绑定、权限、预算和交付条件必须真实成立。

**第二层：对父用途有区别。**不同答案要能改变预测、行动或任务完成判断。

**第三层：利用已有可比方法证据。**有同起点配对结果时用实际结果；没有时，承认是有界探索，不伪造“预计成功概率”。

候选分歧可以帮助找实验，但不能把有限候选比例称为可信后验。复制一个候选十次，也不能使它的重要性增加十倍。

## 5.4 “未完成”与“无效”的更新不同

- 搜索未完成：不反驳世界模型族，但可以说明方法在当前资源内没有交付。
- 程序异常：是执行失败，不是世界规律的反例。
- 完整研究无收益：是该有限方法和条件下的负结果。
- 行政暂停：科学比较受到干扰，但已付费用仍保留。

最新代码已经有多种失败和续研机制。下一步应让这些语义进入实际选择，而不是再加一层统一的“失败，请反思”。

# 六、问题C：怎样生成新研究程序，而不是只在旧动作间切换？

这里是本轮方案最重要的新增算法部分。

## 6.1 复用当前执行器，不再造DSL

仍然使用：

```python
select_actions(public_spec, observations, memory)
```

以及已有原生研究图和普通执行入口。

但生成器不只输出一个动作名，而是可以改变：

- 哪个参数组保持或释放；
- 哪份证据被哪个步骤使用；
- 哪个局部组合需要替换；
- 哪项合法实验用于区分两个答案；
- 收到什么结果后转向哪一段研究。

这才是研究程序内容。

## 6.2 依赖从真实产物提取

当前Common已经有精确步骤引用和整段回报，不能再按旧版“最近六步、动作名相同”诊断它完全缺失。

下一生成器应直接使用这些引用：

```text
真实失败
→ 实际父程序和拟合合同
→ 哪些参数／列／角色影响该读出
→ 哪次研究产生了可用子答案
→ 哪次比较和后续实验实际消费了它
```

但**数据依赖不是因果贡献**。一个步骤被读过，不代表它带来了全部收益；要评价删掉或替换它的价值，仍需实际干预。

## 6.3 首轮允许六种有限改写

| 改写 | 实际变化 |
|---|---|
| 释放参数组 | 从固定来源值改为目标重新识别 |
| 替换局部组合 | 改一个窗口／事件／聚合位置，保留其他计算 |
| 重绑角色 | 在公开合同支持下测试新的角色或测量映射 |
| 插入区分实验 | 对两个相容答案执行已有合法实验及分析 |
| 复用并续作 | 消费已有答案，执行当前题义所需的后续分析 |
| 改变后继分支 | 根据实际返回决定下一段研究，而不是固定重复 |

每种改写都来自真实反例和程序依赖。它们是**可试变换**，不是“正确答案模板”。

## 6.4 建议的首轮搜索界限

在新版本中，可以建议：

- 父前沿最多4个；
- 一轮最多12个不同候选；
- 初始每次改一个语义组或局部子图；
- 有限条件候选最多8个；
- 首先保留v8最多两个科学选择段。

这些是可报价的工程界限，不是理论最优，也不是自动增加授权。

# 八、问题E：确认覆盖、停止和方法价值怎样定义？

## 8.1 三种目标必须分开

### 任务分布上的平均风险

\[
R_D(f)=\mathbb E_{e\sim D_\tau}\ell(f(e),y_e).
\]

这是普通随机评价最接近的对象。

### 边界附近的风险

\[
R_{\mathcal B}(f)
=
\mathbb E[\ell(f(e),y_e)\mid e\in\mathcal B].
\]

边界面板要由公开条件和冻结候选的未决部分生成，不能看到真值后挑最有利区域。

### 某范围的最坏情况保证

\[
R_\infty(f;\Omega)
=
\sup_{e\in\Omega}\ell(f(e),y_e).
\]

有限随机通过不能自动得到这一项。需要有限域完整覆盖，或有效分析界与明确模型前提。

**当前原门槛不改。**下一代协议可以增加边界诊断，但应单列其目标，不能追溯否定或重新定义旧实验。

## 8.2 为什么48行可能漏掉错误？

一个纯数学例子：假设错误区域概率为1%，且48次试验独立，那么完全没抽到错误区域的概率是：

\[
0.99^{48}\approx61.73\%.
\]

这不是对项目48行的统计结论，因为轨迹行通常并不独立；它只是说明“随机批次都正确”与“边界已经正确”之间没有必然关系。

第76节中，新旧两稿在随机48行上都近零，但旧稿仍有已知开发反例。该随机子检验通过，不能清除那些反例。hegel_machine_next_construction…

## 8.3 停止应看任务后果，不只看区间宽度

对当前相容参数集合，可以考虑某实验上的预测不确定性：

\[
A_\tau(e)
=
\sup_{\theta,\theta'\in\Theta_D}
|f_\theta(e)-f_{\theta'}(e)|.
\]

但有限代表只能给代表分歧，不是整个集合的严格上界。

这能说明：

- 参数区间很窄，阈值处仍可能有大预测差；
- 参数区间很宽，当前任务可能完全不受影响；
- 不能要求所有理论唯一确定后才完成任务；
- 也不能因一次随机通过就忽略已知的重要区别。

现有完整响应区间研究和实验方法已具备可复用基础，不需要为此重造边界求解器。hegel_machine_next_construction…

## 8.4 方法价值继续保留向量

建议比较：

\[
(\text{完成},\text{原质量},\text{覆盖},
C_{\rm obs},C_{\rm measurement},C_{\rm compute},
C_{\rm time},\text{可靠交付}).
\]

同质量、同覆盖下，某方案资源都不更多且至少一项更少，可以记过程收益。

更准但更贵，或少观测但多计算，应报告权衡；没有用户指定资源偏好时，不制造一个任意加权总分。

工作更好但后效更差，保存两项并修订方法支持。当前这次@4回流修复正是应该保留的正确行为。hegel_machine_v4_v8_execution_v…

# 十、还需要注意的两项主线问题

## 1. “语言扩展”不等于必须创造数学上不可由旧Python表达的东西

当普通Python已经可用时，新抽象往往改变的是：

> **在有限预算内，系统能否实际构造、拟合和检验某种解释。**

一个新定义即使可以展开成旧代码，仍可能有价值；但新名字本身没有价值。

因此，不必先证明旧语言绝对无解，才允许提出新概念。需要的是实际未解区别、新表达的可检验后果，以及后继中是否改善研究。

## 2. 兼容旧知识，不能变成永远维护旧错误

新解释应保留：

- 可信原始事实；
- 旧理论有效范围内的成功；
- 仍然有用的计算。

它不需要无条件保留已经被反驳的过宽主张。

否则，“新理论必须兼容所有旧理论”会使修订本身不可能。理论谱应当能够限定、分叉、撤回和恢复，而不是成为一个只增不减、越来越难反驳的解释仓库。

## 二、A再明确一步：跨版本究竟继承什么？

上轮已经给了继承表：原始资料可以保留，改变参数化、结构、角色或条件之后，相应的新主张必须重验；同origin追加后效不能增加样本数。01_主线审计与A至E算法补充方案

现在把它落实为一句可以直接指导实现的规则：

> **共享原始事实；按真实依赖复用计算；不自动共享新方法的有效性结论。**

例如，将关系半径从“固定来源值”改成“用目标资料重新识别”：

**原始观测保留。**原物理命令、响应和轨迹不会因为方法换版而失效。但由旧校准推导的物理量不等于原始读数；校准变了，推导量可能需要重算。

**相关计算失效。**使用旧半径生成的特征列，以及依赖这些列的拟合、预测、评分，需要重新计算。无关且依赖完整的局部结果可以继续使用，不必全库重算。

**新方法支持不继承。**旧方法的确认仍然是旧方法的历史。新方法不能因为沿用了大部分代码，就继承旧方法的整体预测支持或研究效用。

可以写成：

\[
\text{本次变更}\cap\text{结论实际依赖}=\varnothing
\]

且命题、范围、评价不变时，才保留相应局部支持。依赖不完整时，应保留历史记录，但将当前支持标为未决。

这里还要补一条：**相同预测也不等于相同成本。**优化实现或缓存策略之后，即使科学输出不变，新的运行成本仍需要测量。

这不是让Codex新增证书系统，而是让现有依赖失效机制明确作用于哪些结果。

## 三、B需要补实的部分：研究收益怎样计算？

上轮这里主要给了“历史收益范围、来源数、资源报价、未识别范围”的向量表达，没有把具体计算完全展开。01_主线审计与A至E算法补充方案

### 1. 比较的是两项实际研究，不是一个成功故事

在某个公开研究状态下，比较候选研究\(a\)和参照研究\(b\)。只有真正满足**同起点、共同已有资料、可比工具与预算、同评价口径**的实际配对，才进入直接收益估计。

不同方法版本、不同阶段或不同预算下的结果，仍可用于提出候选，但不能直接拼成“这个状态下应该选\(a\)”的标签。

### 2. 先算每个物理来源的差异，再跨来源汇总

对具有共同冻结评价的配对\(j\)，计算：

\[
\Delta R_j=R_j(b)-R_j(a),
\qquad
\Delta C_{j,k}=C_{j,k}(a)-C_{j,k}(b).
\]

这里，正的\(\Delta R\)表示\(a\)预测风险更低；正的\(\Delta C\)表示它多消耗了第\(k\)种资源。

同一个物理来源中的多次研究先汇总，再在来源之间按预先声明的权重汇总。**不能让一个装置的100次续修，自动压过另一个装置的一次独立研究。**

这些数值首先是**匹配历史配对的经验结果**，不是自动校准的未来收益预测。

### 3. 没有交付时，不能给误差填一个方便的数字

某一臂没有交付预测器，风险差应为缺失，不能填0，也不能随意填无穷大。

同时必须保留：

> 全部尝试中的交付率、共同完成配对上的风险差，以及全部真实费用。

否则，只报告“成功完成那几次的平均误差”，就可能把一个经常无法完成研究的方法评价得很好。

### 4. 当前只有一个真实配对，应当返回什么？

应返回：

> 这一来源上的局部差异、实际成本、适用条件与未决范围。

不应返回：

> 一般成功概率、稳定跨任务期望收益，或已经成立的通用条件。

补传文件明确指出，当前@4只有一个真实方法配对，不同K版本与不同方法体不能混为同一策略样本。hegel_machine_v4_v8_execution_v…

**收益未知，不等于禁止研究。**没有可靠收益估计时，可以选择一次合法、完整可支付、确实能够改变父用途的有界探索；只是不把这个工程选择伪装成“已经证明它期望收益最高”。

这补上了B里“预计研究收益”的落地方式，同时避免凭空造一个总分。

## 四、C需要补实的部分：究竟怎样生成新程序？

上轮给出的`apply_one_edit`、`existing_legal_edits_from_contracts`等函数，表达了总体流程，但这些函数名本身还不是完整生成算法。上轮确实已经给了可编辑内容和依赖要求，问题在于关键变换还需要进一步展开。01_主线审计与A至E算法补充方案

### 1. 先选一个真实可实施的变换

这次最合适的窄实例是：

> **把“固定来源关系，再拟合目标系数”，改成“在公开合法范围内重新识别目标关系，并联合拟合目标系数”。**

旧片段大致是：

```text
读取来源关系参数
→ 按该关系生成目标特征列
→ 用目标资料拟合读出系数
→ 与旧池比较
```

候选新片段是：

```text
读取当前公开合法关系域
→ 对现有研究器选取的关系候选，重新计算受影响的目标列
→ 分别用目标资料拟合读出系数
→ 比较并返回候选、搜索覆盖与剩余分歧
→ 按原合同决定区分实验、确认或停止
```

**新程序保存的是“如何重新识别”，不是这次识别出的目标半径。**

### 2. 这个编辑怎样从经历产生？

不是开发者直接写一句“下次先改半径”，而是：

```text
对齐实际旧稿与修订稿的节点、参数绑定和角色
→ 找出真实改变的语义组
→ 回溯这些组影响的特征列、拟合与实验
→ 将目标拟合数值替换为“由目标资料识别”的操作
→ 保留所需依赖，并交给现有消费者
```

节点对应必须依据类型和真实绑定，不能仅凭变量名字或数值相等。

对于当前病例，还要保留一个重要限制：**联合修订同时改变了关系与拟合内容。**因此，它可以提供联合变换的生成材料，却不能直接证明“只释放半径就足够”。附件也明确说没有做因素拆分。hegel_machine_v4_v8_execution_v…

施工中尤其不能犯这个错误：

> 实际调用一个同时搜索关系和结构的入口，却把结果标签写成“仅重新识别关系参数”。

现有入口能够真实限制哪部分变化，就做哪部分对照；无法限制时，报告联合变体，单因素格保持未实现或未测。

### 3. “失败后追加哪段研究”的条件怎样来？

可以从经历中提出以下**候选分支**：

| 当时实际可见的状态 | 可以提出的下一段研究 |
|---|---|
| 系数重拟合已经完整结束，仍有未解释反例 | 关系组重新识别，或保留实际有依据的联合变体 |
| 开发资料已解释，但相容关系对合法未来轨迹仍有任务相关分歧 | 区分实验及其分析 |
| 原合同允许确认，且没有尚未履行的确认前置义务 | 冻结后执行原确认 |
| 冻结确认失败 | 保存失败、返回方法题，下一版本再修订 |

**这里的分支只是可试程序，不是已经学成的通用规律。**是否采用，应由同内容方法在不同公开状态下的真实配对与后效决定。证据不足时，继续保留`insufficient_paired_preferences`，不能强行生成一个条件。

这样，系统学到的对象才不只是“偏好structure动作”，而是：

> 哪个组允许变化、读取哪些证据、必须重算什么，以及什么返回会改变下一项研究。

### 4. 原伪代码有一处需要真正修正

原生成伪代码在达到候选上限时，只`break`最内层编辑循环；扩到多个父候选或多代时，后面的父候选仍可能追加结果。01_主线审计与A至E算法补充方案

我做了一个独立循环控制：**4个父候选、每个至少12项编辑、上限12，原片段会返回15个。**修正后严格返回12个。这只是对伪代码控制流的检查，不是项目科学实验。

另外，**只限制成功候选数，也限制不了大量无效或重复提案的耗费。**所以补充文件加入双重限制：

> 成功候选最多12个；首轮建议总编辑尝试最多48次，失败和重复也计入；提取、匹配、编译检查另受计算与时间预算约束。

这里的48是建议的工程上限，不是科学最优值，也不增加原实验授权。完整修正版伪代码和控制脚本已放入更新包。
