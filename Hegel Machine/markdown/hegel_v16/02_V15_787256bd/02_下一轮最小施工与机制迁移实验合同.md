# Hegel下一轮：选择性复用、机制地图与未见问题效用合同

依据：787256bd V15审计。日期：2026-11-18。本文是后续设计建议，不是已经完成的实现或实验结果。V15样本今后作为开发诊断集，修后不再宣称它们是新的前瞻测试。

## 1. 单一主目标

在预先明确的机制相关任务分布上，系统从真实研究经历形成、验证并修订范围化假设；强普通方法可以从相同经历重建同一知识，也可以放弃迁移直接研究目标；Hegel仍能提高未见问题在给定资源下的有效研究进度，或降低相同质量要求下的总成本。

这里的“新”指新于系统当前知识状态。无需先发明全新语言原语、跨任意学科、训练基础模型或自改整个研究器。

### 验收必须同时回答

- 哪些原始经历促成了哪一个新假设及其版本？
- 哪条可执行预测和什么范围被新证据支持、反驳或保留为未知？
- 为何选择重绑定、缩域、分支、融合、撤销或延期？
- 在哪个未见问题中，该对象或映射实际改变了下一行动？
- 对照可以重建同样知识时，改变了成功、成本、确认风险中的哪一项？

“更早进入提示词”“图边更短”“新假设数更多”“有采用日志”是中间指标，不是完整验收。

## 2. 施工边界与顺序

只交付三个包：

| 交付 | 内容 | 完成标准 |
|---|---|---|
| D1：修准证据与干预 | 最小代码修复、计费、12个A目标诊断 | 已知反例消失，事实链可复核，干净移除不强迫重建 |
| D2：选择性研究起点 | 一个可替换selector及有界动作选择；接现有研究器 | 至少能解释何时复用省事、何时跳过；不强求在旧样本跑出正收益 |
| D3：冻结的新机制族实验 | 强普通完整策略对照、必要的flat/graph归因、完整账 | 按预先阈值判断正/负/混合，不能结果出来后换主指标 |

不另建第二套知识库、通用证明引擎、多代理组织、全自动自改进平台或新物理大域。旧代码按功能借用，不能整套搬回导致双重状态。

## 3. D1：把现有机制修到能解释结果

### 3.1 修复清单与验收

| 优先级/落点 | 最小修改 | 有意义的验收 |
|---|---|---|
| P0，branch_reconciliation重建入库 | 记录完成后再计算统一版本；语义字段与计量元数据边界明确 | 事件、prior重算、inventory版本相同；用事件版本能精确删除该当前对象 |
| P0，_archived_probe_lookup_fn | 去掉任意首批回退；ID仅作索引；检查sequence/reset/protocol/schema/channel等真正依赖 | 同ID异sequence、同sequence异reset、无匹配均不返回exact；精确匹配保留原历史身份且只消费一次 |
| P0，memory移除支持 | 过滤revoked/无效证据；必要依赖与替代支持分开 | 有效独立第二根保留；失效第二根不保留；仅有parents字符串不标独立支持；检查实际recall和调用 |
| P0，_world_commitments入口 | 重建成为可选有界动作，不能自动拿走整个主预算 | 删除对象后可以直接研究目标；保留确认额度；失败重建在无新证据时不会每题从头重做 |

| P1，版本接口 | 当前先强制单cid单当前版本，或真正实现二元键；二选一并写清 | 重复cid的接口拒绝或能精确区分；不再宣称当前cid剪枝是多版本精确干预 |
| P1，hash/确认 | feature_bounds进依赖hash；无fresh holdout不标独立确认 | 改bounds失效、改无关wall time不失效；训练尾部不能得到fresh-confirmed |

已有60对路由一致性保留；补充真实guard内容、对象/模板版本及给定pilot的预测判定。不要求双方全部成本相同；调度顺序是否作为干预变量必须明确。

这些修复不是新的科研成果。用既有控制和本包探针回归即可；只对实际受影响的科学链决定是否重跑，避免每次都重新跑整个历史实验库。

### 3.2 依赖支持的最小语义

不要直接把parents改名为support_roots。两者语义不同：

- 程序执行依赖：运行还需要哪些定义/版本，通常为合取。
- 证明/经验支持：哪些证据组合足以支持该范围下的声明。
- 来源：候选曾参考哪些历史对象，不一定仍是必要支持。

若需要表达替代支持，可用小型结构：

~~~json
{
  "required_definition_versions": ["definition_A@v1"],
  "alternative_support_sets": [
    ["evidence_1", "evidence_2"],
    ["independent_confirmation_7"]
  ]
}
~~~

各support set内是全部需要，多个set之间是任一有效即可。一个set只有两个名字并不算有效：须核证据状态、适用范围和确实支持该声明。自己的新独立确认可以成为替代支持，但不能因为表达式被展开就默认获得独立实证。

### 3.3 对12个A目标做一次有限的失败定位

不再泛泛统计“调用过某模块”。每题仅导出：

1. focal源对象与版本、源实例参数、模板自由参数；
2. 首轮scope verdict、具体证据引用、是实例失败还是模板失败；
3. 正确机制进入候选的排名、首次合法实例化时刻和成本；
4. 最终选择是否来自focal，或者哪条旧假设经普通修订重建同一机制；
5. 重复审计/绑定/确认各实际leaf费用；
6. 去除某项重复工作后必须重新验证的具体责任，不能靠估算直接报提速。

优先看两个“采用但更慢”的A2，以及五个首轮排除focal的A目标。如果真实瓶颈是binding或重复实验，先修它；如果候选一直排不到前面，才优先图selector。

### 3.4 假确认的定向修复

在1053000:T6_B2和1054000:T5_B2上补保存决定性行：候选的条件值、真实可观测输入、预测、残差和所属确认批。外部评价标签只供离线审计，不允许喂回同轮研究器。

针对当前候选尚有分歧的条件做新实验：

- 在候选阈值区间两侧取点，包含边界附近。
- 固定gap改变位置，区分“只依赖gap”与额外位置二次项。
- 对有历史项的模型，在相同当前输入下改变前史。
- 验证行须在候选/版本冻结后才向求解器揭示，且未参与其生成、选择或调参；可以预先生成并密封。若用数据选过候选，就不能把同批数据再称独立确认。
- 预算不足则报告适用范围未知或未完成，不把近零训练误差升级为confirmed_exact。

“随机48行都对”只能证明有限评估通过，不是连续域普遍定理。可在模型内证明的性质交给checker；环境经验有效性继续单独报告。

## 4. D2：先决定值得复用，再付出复用成本

### 4.1 一个共享的动作选择器

让Hegel和强普通都有相同的基础动作集合：

- direct_research：直接用现有普通方法研究当前问题；
- bind_candidate：对候选旧机制做小范围角色/参数重绑定；
- discriminating_probe：做区分候选或确定范围的实验；
- reconstruct_local：按需重建当前可能相关的局部知识；
- defer_or_skip：暂不使用该条迁移路径。

选择器输入只允许当前可见的经历、候选、模型分歧和预算，不允许读取任务生成器真值、A/B/C标签或目标最终MSE。

建议策略是先用便宜的pilot和候选绑定判定是否值得继续，再按边际收益分配剩余额度。具体阈值在开发集确定并冻结，不能用测试集调。

~~~python
candidates = selector.query(observed_problem, experience_archive)
for h in candidates[:retrieval_cap]:
    verdict = validate_binding_and_scope(h, pilot, local_budget)
    if verdict == "supported_and_useful":
        propose_executable_candidate(h)
    elif verdict == "unknown_but_discriminable":
        propose_targeted_probe(h)
    elif verdict == "instance_failed":
        keep_template_unknown_and_try_refit_if_budgeted()
    else:
        record_reason_and_skip()

action = choose_from(direct_research,
                     best_candidate_path,
                     bounded_local_reconstruction)
execute(action, reserve_independent_confirmation=True)
~~~

这只是接口逻辑，不是要求为每个问题都把上述动作全做一次。选择器本身、检索和评分也收费。

### 4.2 重建的边界

- 给重建独立子预算，不能透支确认额度和最低直接研究额度。
- 用现存局部模板/一阶修订先做便宜尝试；高阶搜索只有出现可检验的需求才开启。
- 允许“当前问题直接重学比恢复旧知识更便宜”。
- 缓存重建成功对象和失败原因。失败键含源对象版本、原始证据版本、目标需求、搜索配置和已用额度。
- 无新证据、同额度、同配置时不从头重做；增加预算可从真实checkpoint继续，不能把cache failure永久当数学不可能。
- 重建成本归其实际受益任务或明确摊销队列；不能藏入别的题。

V15中5簇×6次近全预算重建应不再可能。修后实际通过多少必须实测，不预填为cold的32/36。

### 4.3 什么才算jumpstart

一个有效jumpstart至少应体现一项：

- 更早到达经独立验证的有效机制候选；
- 用更少实验识别关键方向、阈值、历史变量或适用范围；
- 在不漏掉正确解的情况下排除更多无效机制；
- 更早识别不适用并切回普通路线，减少负迁移；
- 多个后继目标共享一次有效组织成本，平均总成本下降。

如果只是“用了旧对象”，但新增审核、绑定和搜索比普通重学更贵，就不能算成功。

## 5. 小型机制地图：复用早期代码的正确接口

### 5.1 与现有主循环连接

当前可用的窄入口：

- unified_research.py::_recall：对现有records加可替换selector。
- memory.py::KnowledgeLibrary.propose：利用已有source_concept_ids接收候选来源集合。
- 保留现有role binding、scope检验、Program执行和独立确认。
- 研究问题依赖ResearchGraph与检索图语义不同，不直接混为一个图。

旧模块可参考：

- assumption_os/graph_memory.py：SimpleAssumptionGraph.retrieve的传播检索与可追溯存储骨架；
- assumption_os/retrieval_policy.py：检索策略接口与不同查询视角的组合；
- 早期structural morphism的角色/不变量表示；
- reconstruction_v2的official HippoRAG retrieve-only适配与运行见证。

采用前必须移除固定strategy-ID奖励、预置十题答案结构、合成gold相关标签参与排序，以及全样本选策略后再评估的路径。不是重建整个旧管线。

### 5.2 只需四类语义对象

在当前对象上增加引用即可，不先建立独立大平台：

| 对象 | 内容 | 作用 |
|---|---|---|
| Experience | 研究问题、实际实验/条件、观察、失败、来源版本 | 类似HippoRAG的完整passage，防止只记结论丢条件 |
| HypothesisVersion | 程序/预测、角色、参数、scope、支持和反例 | 当前可复用机制 |
| AlignmentHypothesis | 源/目标角色映射、候选不变量、条件、预测、状态 | 跨表述或跨领域映射本身也可被证伪 |
| DecisionEvent | 触发经历、旧新版本、动作、理由、成本、真实消费者 | 回答为什么修订/合并以及产生什么研究变化 |

边类型必须区分：

- resembles / candidate_alignment：检索线索；
- supported_under / refuted_under：带条件的经验或形式结果；
- derived_from / requires：来源与必要依赖；
- revised_to / merged_into / superseded_by：版本变化。

向量相似和PPR路径不能直接变成equivalent或validated_support。检索图与真值状态可以共存，但其权重和状态不能互相偷换。

~~~json
{

  "source_object_version": "hypothesis_12@v3",
  "target_problem_id": "unseen_042",
  "role_map": {

    "response": "measured_compensating_action"
  },
  "preserved_relations": ["conditional_opposition"],
  "required_conditions": ["specified_observable", "specified_time_window"],
  "status": "candidate",
  "evidence_ids": [],
  "predicted_discriminating_experiment": "experiment_spec_id",
  "refutation_witnesses": [],
~~~

这是建议schema，不是给系统提前写入“楞次=勒夏特列”的正确答案。候选来源可来自检索或LLM，但验证条件与状态转换由真实证据约束。

### 5.4 HippoRAG 2的具体移植取舍

建议移植：经历节点、关系三元组、query-to-triple召回、必要的相关性过滤、概念与上下文联合传播。

暂不优先：大规模图数据库、全库每次重抽取、无证据的高阶抽象节点、为了使用PPR而把五个候选扩成巨大图。

如果库很小，flat候选扫描可能更快。要用flat与graph同内容对照证明图值得，并把索引/过滤LLM费用算上。

## 6. 分支增长后如何保持一致性

### 6.1 先判断是否在说同一件事

比较两个假设前先对齐：

- 变量角色和单位/方向；
- 输入输出对象与时间窗口；
- 量词、扰动类型、可观测量；
- 参数是否可重绑定；
- scope是否有可执行重叠。

名称相似、来源同域、embedding相近均不足以认定冲突。定义不同或范围不交可能无需任何修订。

### 6.2 决策表

| 证据形态 | 行动 | 保留内容 |
|---|---|---|
| 当前实例失败，但存在便宜的可验证参数/角色重绑定 | refit/rebind | 原模板与源支持；记录绑定版本 |
| 各自在不同可判定范围成立，重叠处暂无矛盾 | split/conditionalize | 两分支及显式guard；未知边界继续未知 |
| 相同角色和scope重叠区预测不同，尚无区分证据 | discriminating experiment | 两者暂存；记录可区分输入 |
| 新实验反驳一个分支的局部范围 | shrink/revise | 旧有效范围、反例与修订原因；不全局撤销 |
| 支持根失效且无独立替代支持 | withdraw/quarantine | 历史与原因保留；停止作为合法执行前提 |
| 一个更简单规则覆盖两分支且通过旧支持、反例与新验证 | merge | 合并来源及范围；归档旧版本，能回溯 |
| 两者等价且一个仅是冗余表达 | deduplicate | canonical代表、原证据和身份别名 |
| 预算不足或scope无法识别 | pending/unknown | 不把未知当反驳，不把未验证当已支持 |

合并不是所有分支最终必须的结果。若新实验说明原反例解释错了，允许显式修正旧拒绝；若只是无损压缩，则不能丢掉仍有效的支持和拒绝见证。这是借鉴AWM时必须保留的区别。

### 6.3 限制分支检查成本

先用目标/机制/角色索引找可能重叠的分支，再对该小集做可执行检查。新版本只使相关依赖失效；缓存键包含真正影响判定的版本、证据、协议与scope。未知范围保留到实际可能消费时再检验。

branch数量、合并率都不是目标；总代价与有效研究进度才是。若维护费超过收益，可以不物化不常用的分支。

## 7. D3：机制相关任务集

### 7.1 第一轮用现有实验器，不新增大域

沿现有AnonymousObjectLab和有限程序语法构造任务族：关系方向、条件阈值、是否依赖历史、潜变量阶数、对象数、角色映射与可测通道。

每簇来源可有：

1. 普通研究获得基础无历史/对称机制；
2. 新经历暴露方向或条件差异，形成有范围的分支；
3. 受控前史实验暴露记忆机制，产生新候选；
4. 新源验证支持修订，或保留未知；
5. 冻结来源知识，再进入未见目标。

上述是生成任务的设计；不得把来源序号或族标签作为给agent的答案提示。只有实验接口和观察可见。

### 7.2 用两个正交维度避免“同学科=同机制”

| 表面/机制 | 机制兼容 | 机制不兼容 |
|---|---|---|
| 表面相似 | 常规参数/尺度迁移 | 最容易误迁移的hard negative |
| 表面不同 | 用户期望的结构捷径 | 应快速放弃的低相关目标 |

同一机制可改变变量名、角色排列、对象数、观测表示、控制增益；不兼容情形可保持词汇/外观却改变方向、记忆阶数、条件或有效范围。机器判断时看不到这个评测分层标签。

另外单列scope边界未知的目标：它们需要小实验决定，而不是强行贴正/负标签。

不能只挑已经知道Hegel能赢的题。兼容/不兼容比例与部署预期相关；在开发集估计并冻结。若暂不知真实比例，就报告分层结果与若干预定混合比例的敏感性，别用任意单一总分掩盖差异。

### 7.3 分割与冻结

- 按完整来源链/生成器参数族分簇，不随机拆同一条轨迹的行。
- 开发阶段只使用现V15和单独开发簇；selector、阈值、预算上限在此确定。
- 最终目标更换未用种子、参数组合、命名/接线及对象数；第一轮可以是同机制新实例，无需同时要求全新机制、全新学科。
- 如要主张跨表述迁移，hold out的是表述/观测实现；如要主张新机制组合，明确哪个组合是未见的。不要混用结论。
- 冻结test manifest、代码hash、源库hash、指标和预算；独立评测器保存标签，不让研究器或selector使用。
- 目标新知识是否跨题写回预先规定。主诊断可继续冻结来源库只保留合法缓存；若做持续学习，另作为双方都可更新的prequential实验。

### 7.4 样本量与成本控制

先用6–8个开发簇做机制定位，不把它们写成确证结果。冻结后可规划24个新来源簇、每簇6个目标作为首轮确认设计，再依据开发集的簇内相关性与差值方差做功效/区间精度核算。24不是统计保证，更不是越大越好；若真实差异小于维护代价，停止扩大计算。

每个目标资源上限保持预先设定并对齐。所有来源失败进入分母，不能只留下产生新对象的成功簇。只在部分源成功时也必须报告总体策略结果及预先声明的条件性结果。

## 8. 强对照：让普通方法真的有机会重建同一知识

### 8.1 主比较：完整策略O与H

| 权利 | O：强普通 | H：Hegel |
|---|---|---|
| 同一基础求解器/模型/工具/观察权限 | 有 | 有 |
| 访问同一原始经历类别 | 有 | 有 |
| 从经历归纳规则、重绑定、主动实验、缓存 | 允许 | 允许 |
| 直接研究当前目标、跳过昂贵迁移 | 允许 | 允许 |
| 编写范围表、失败缓存、局部知识摘要 | 允许 | 允许 |
| 同预算形成自己的来源知识 | 独立形成 | 独立形成 |
| 预先维护版本化假设与结构映射 | 可按普通策略付费重建等价内容 | 由被测组织策略维护 |
| 读目标真值/评测MSE选路 | 不允许 | 不允许 |

O不能仅是禁用若干核心求解能力的弱版本。尤其S3的范围筛选和失败缓存不能被专门禁止，否则测到的可能只是“有没有最基本的错误排除”。

O的实现与超参数在开发集选定后冻结，不能在测试集逐题取多个baseline里最低成本拼出oracle，也不能让H选择最有利普通版本。可以另报告预注册的多个普通方法。

### 8.2 图的归因比较：相同知识内容的flat与graph

如果主实验引入HippoRAG式检索，增加一个有限的同历史对照：

- F：同一组假设、范围、经历和版本，使用flat BM25/dense/结构字段检索，普通重排和绑定权限完整。
- G：内容相同，使用关系图/结构映射传播。
- 求解器、scope验证、top-k资源上限、确认机制相同。
- 共有知识形成成本记共同成本；图特有索引和维护另计，flat实际摘要/索引成本也计。

F/G区别用于回答地图的检索组织是否有用；不能据此声称图系统独立形成了更多知识。主E2仍用O/H各自实际来源轨迹，避免重新拼接知识库。

### 8.3 对象干预

按来源期信息或开发集规则预先选定对象，所有预定未见目标均进入成对干预分母；实际进入候选的目标另作机制分析，不能按测试期是否采用事后筛题。干预为：

- 有对象；
- 移除该对象当前版本及独占派生支持，保留原始经历；
- 两边使用同一可选择、可跳过的策略，重建权相同。

不要求移除组一定失败。若普通重建后同样成功且成本接近，结论就是可重建性强、该物化对象边际价值小。若收益来自支持路径/排除错误而不是最终采用，也要保存被改变的实际动作。

## 9. 指标：把jumpstart变成可检验对象

### 9.1 主要指标

建议预注册两个层次：

1. 质量：最大预算下严格成功率及假确认率；未确认但准确单列。
2. 在质量要求满足时，完整来源+维护+目标计算成本，以及观测/测量成本分别报告。

成功率的非劣界、可接受假确认差、最小有意义成本收益须按用途事前设定。若目前没有足够样本保证这些界限，就报告探索性区间，不能先看到点估计再宣布通过。

### 9.2 研究起点指标

- 第一个实际可执行、经独立评价有效的候选出现时的累计成本。
- 给定预算b时，已找到有效候选/已合法确认的任务比例S(b)。
- 达到同一正确机制所需实验数量、首次区分实验的信息贡献。
- 迁移候选被正确拒绝的成本，以及不必要迁移的额外支出。
- 同内容flat/graph的候选recall和排序只能作机制指标，必须关联后续实际动作。

用冻结的预算checkpoint离线评测候选，评估结果不反馈给该次求解。失败按预算右删失或预定cap处理，不只计算成功题的平均成本。

### 9.3 全成本摊销

令每簇未来任务数为m，分别计算：

C_total(m) = C_source + C_organization + Σ C_target(i)

各项必须互斥。若使用完整来源ledger，其中已包含的组织维护费不再单独相加；上式C_source指剔除已单列组织费后的来源研究成本。

所有检索、LLM提取/过滤、scope检查、重建、失败尝试、确认和维护都算入对应真实扣费。观测、测量、compute、模型token与wall time不随意混成一个“成本”；若要综合效用，权重预先给定，并保留分项。

给定同一已经取得的历史，采集成本是共同项；自主完整策略则使用各自真实历史成本。不能像V15 E1那样把同一份来源探针赠给一方、再宣称其实际少采了探针。

预设m=1、3、6及一个较长期前缀，检查优势是否增加、消失或反向。不能假设首次省下的索引成本会每题重复增长。

### 9.4 统计单位

以来源簇为配对单位，报告每簇结果、区间和角色分层。相同源下6个目标相关，不是6个独立源。重复使用同一K轨迹的多个表不是多次独立实验。

给一个完整成功案例只是解释机制；所有簇的总体结果才决定效用。负例同样写完整，不只挑最好看的故事。

## 10. 楞次—勒夏特列案例的安排

不把它作为第一项成果验收题。它适合说明需求与验证映射结构，但熟悉教科书的强普通模型可能直接给出类比；不能预设它不会。

若后续做跨领域演示：

1. 给系统原始过程描述与可交互环境，隐藏预写的“负反馈”共同标签。
2. 要求提出变量/角色/时间映射和可检验预测。
3. 包含相似文字但不满足范围的反例。
4. 对照用同一LLM、同一文档、同一实验权限，也允许主动提出该映射。
5. 评分看新情形预测与实验效率，不看是否说出“都是负反馈”。

一个简单的数学hard negative：即使响应方向与当前偏差相反，也不保证稳定。离散系统x(t+1)=(1-k)x(t)，当0<k<2时偏差衰减，而k>2时可振荡发散。因此“有反向响应”不能未经范围检验直接合并成“会恢复平衡”。这只是映射检验的教学例，不把它当作两条物理化学定律的统一推导。

真实化学例中，改变压力、温度、组成不是同一个控制变量；在理想条件下恒容加入惰性气体也不必导致反应平衡移动。电磁感应中反抗的是磁通变化。角色与边界若没分清，捷径会成为误迁移入口。

## 11. 每次对象变化只增加一个可读案例页

建议导出格式：

~~~text
原问题与先前可见经历
→ 原假设、范围与版本
→ 新经历暴露的具体残差
→ 两个仍可解释数据的候选
→ 区分实验与冻结版本
→ 观察证据和决定
→ 新假设/分支/融合及其有效范围
→ 未见目标上的角色映射
→ 实际替代或取消的研究动作
→ 普通重建对照
→ 成功、成本、假确认与剩余未知
~~~

每个箭头引用真实事件/证据ID。允许中途止于unknown。若无法指出被取消或减少的工作，即使最终采用了新对象，也只报告功能链通，不报告效率收益。

## 12. 接受负结果后的决策

- **H与O同样正确、H更贵**：压缩维护和候选路径；确认小库flat扫描是否足够；不扩大宣传。
- **图提高召回但未减少研究成本**：检查binding、重复实验、验证和候选执行瓶颈；图先保持可选。
- **收益只在来源S3**：可以先形成“顺序冲突条件下的研究完成率”这一窄结果；单独给强普通局部筛选能力再验。
- **收益只在某类兼容目标**：声明条件性有效范围；报告其他类的损失并学习选择性使用。
- **移除后可便宜重建**：承认对象持久化边际收益有限；看长期频率能否摊销，不阻止对照重建。
- **最终出现稳定目标净收益**：再扩到跨表述机制迁移，之后才扩更复杂领域和方法自改进。

本轮不需要强制得出“递归有效”。需要让真实收益或真实无效都能被同一协议清楚识别。这样才会缩短下一次迭代，而不是让每个版本继续增加模块却仍说不清哪个未见问题得到了帮助。
