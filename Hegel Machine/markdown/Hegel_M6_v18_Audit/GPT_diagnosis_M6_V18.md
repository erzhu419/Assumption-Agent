### 2. 图上连通，不足以证明跨域机制可运输

这是 M6 新计划中最需要校准的一点。

给定因果图的 d-separation 是有意义的图性质，但它不能单独证明：

- 两个领域共享相同结构方程；
- 相同角色名确实表示相同测量对象；
- 参数可以直接复用；
- 聚合尺度、选择机制或读出协议变化后，原关系仍成立。

例如两个领域都可以是 `X → Y`，但分别满足 `Y=aX+noise` 和 `Y=bX+noise`。共享结构可能有价值，参数仍需要目标域估计。

因此可以继续大胆检索和提出跨域候选，同时让证据决定使用权限：

> 结构相似 → 候选启发；  
> 角色、单位、时钟和读出绑定成立 → 可实例化程序；  
> 目标验证通过 → 该域的有效预测结构；  
> 因果识别假设或干预证据成立 → 更强的因果主张。

不需要所有开放世界推断都先获得形式证明。但当前代码中的一个 `connected` 或 `causal=true`，也不能替代这些不同层次。

## 二、最重要的发现：已有正确能力正在被执行和写回逻辑损耗

### 1. `fit()` 与 `predict()` 接口失配，把正确公式判成了错误理论

共享运行器调用 `fit(train_rows)`，然后调用模块级 `predict(row)`，但没有稳定处理 `fit()` 返回模型或参数的协议。实际作者程序有返回闭包、返回参数、修改全局状态等不同写法。

这已经造成真实失败。

| 保存的原程序 | 原执行结果 | 只修接口后的结果 |
|---|---|---|
| M6 Luna C05 | train / confirm / heldout：`0.229492 / 0.196291 / 0.220350` | 三段 RMSE 均降至记录精度下的 `0` |
| v18 Luna F06 | confirm RMSE：`3.348349` | 约 `2.20×10⁻⁸` |

这些控制没有改变科学方程、训练数据或拟合出的参数。

更严重的是错误反馈的后果：模型看到高误差后，把原本正确的结构当作科学反例，改写成更复杂的错误机制，最后弃答。这样软件接口错误会进一步污染理论修订过程。

另一个 M6 C03 程序也受相同接口影响，但接通之后 confirm RMSE 仍为 `0.055989 > 0.05`，所以不能声称所有相关失败都已救回。这个区分很重要：**先排除实现错误，再判断剩余的科学误差。** [共享执行器](https://github.com/erzhu419/Assumption-Agent/blob/b1d0c3e99f1e6b12cbc62ca8311f1a25d66f2dbf/Hegel%20Machine/src/hegel_machine/cognition/m5_live_gpt_and_provenance.py#L1087)

这里有几项特别值得展开。

### AMR：现在不能把它归因为算法复杂度墙

Hegel wrapper 给 verifier **480 秒、6 GB**；官方冻结版本给的是 **3600 秒、12 GB**，同为 4 CPU。

而官方 `references()` 会先计算独立参考体系，`test_reference_integrity` 依赖它，尚未评价候选程序。多个日志停在这个阶段。

应先在匹配的官方资源下重放相同候选，再分析候选的精度、守恒和速度。现在不能补算成功，也不能把参考体系没跑完当作候选科学错误。[官方 AMR 配置](https://github.com/harbor-framework/terminal-bench-science/blob/f81afac4f11048e77a15dfc8fb1dbfb897fea0ce/tasks/mathematical-sciences/applied-mathematics/amr-poisson-optimize/task.toml)

### Nanoindentation：日志里已经有很强的定位线索

sample06 的日志打印了大致：

- ramp-end hardness：0.33686。
- hold-end hardness：0.23536。
- verifier 目标：0.236。

后者明显更接近，但模型仍把部分接触几何与早期端点绑定，后续又主要精修别的样本。

这支持优先检查加载末端、峰值保持末端、卸载读出的协议，以及蠕变和面积计算的耦合。它还不是经过原始数据重放证明的唯一根因，所以报告保留了这一限定。

### Navigation：不能把失分都解释成小幅数值波动

最新失败是 canyon 的 outlier precision 约 0.279，对要求 0.88，差距很大。

一个轨迹估计器可以通过鲁棒性容忍异常点，但不一定能正确指出哪些点异常。应把状态估计、偏差校准与异常判别分别验证，检查误报机制和不确定性校准。

### Guided-wave、virtual baseline：更多同源模拟样本可能没有解决核心问题

它们都出现“自建案例很好，外部验证失败”。

共同模型错设是重点候选解释，但仍需排除优化、读出与接口偏差。下一步应增加独立不变量、不同合理生成机制和真实公开观测的残差检查，而不是只在当前模拟器上继续加随机种子。

### Clinical 与 symbolic：通过是真的，门控归因不成立

M6.2 的运行时 early-stop stress gate **没有在这两题触发**；实际触发的是 Koopman 和 spin-glass。

因此可以说新的轨迹做了更充分或方向更好的搜索，不能直接说 runtime early-stop gate 导致了这两题恢复通过。需要区分 prompt 效果、运行时拦截与模型自身行为。

## 六、全版本面板中需要修正的几种表述

### “曾经解过”的并集，不能当作单版本能力

`14/20` 或 TBScience 的 `10/15` 多版本并集，可以保留为研发覆盖率。

但官方 Terminal-Bench-Science 0.1 是 **70 题，每模型每题 3 次独立 trial**。选定 15 题、经过多版调试取逐题成功并集，与固定 agent 的完整官方结果不是同一指标。不能因为 66.7% 与某个 68% 数字接近，就判断已经对齐。[terminal-bench-science.ai](https://www.terminal-bench-science.ai/announcement?utm_source=chatgpt.com)

### CTRF 分母变化需要显式标出来

AMR 多次是 `0/0`，没有进入测试分母；M6.1 的 certified sparse 也出现 `0/0`，导致总分母从 110 降到 105。

此外，CTRF 会合并参数化测试名称：traffic 的 7 类对应 163 个 pytest case。因此 `102/110` 不能解释为“能力只差一个很小的检查”。

### “全部闭合”应该改为逐项状态

有实际修复的部分，应保留肯定：

- 时间原点处理。
- 同一模型的确认后宽域回退。
- PSD 与 lineage 多样性治理。
- 部分旧灰区、冷恢复与持久化摘要路径。

仍未闭合的部分，也有明确反例：

- 真实历史消费。
- traced/genuine 一致性。
- 联合绑定与数值权限消费。
- 作者发现到新知识内容的依赖。
- live 层公平对照。

附件给出了 F01–F11 的逐项表，没有把所有旧工作一概否定。

## 七、相关论文中，哪些最值得吸收

这次核对了 15 篇原始工作，报告逐篇登记版本和阅读范围。最贴近当前缺口的不是“最近又有一篇 RSI 高分论文”，而是下面几种实验和实现方法。

### 1. AIDE²：把“更强 agent”与“更强改进器”分别测

AIDE² 除了测试改进后的 agent，还把它放到外层改进器位置做 ignition test。作者仍认为结果不确定，没有据此证明改进器自身更强。

对 Hegel 最直接的启示是：需要单独测未来改进生产率，不能用当前题涨分代替。[arxiv.org](https://arxiv.org/html/2609.26457v1?utm_source=chatgpt.com)

### 2. Hyperagents：固定起点，只替换改进方法

它的 meta-only 迁移实验从相同初始 task-agent 出发，单独替换 meta-agent，再测 `imp@k`。

可以借鉴成：

> old/new knowledge × old/new improver 的 2×2 对照。

这样能区分“知道了更多领域答案”与“更会提出、验证、选择新假设”。[arxiv.org](https://arxiv.org/pdf/2603.19461v2?utm_source=chatgpt.com)

### 3. LILO、DreamCoder、Stitch：复杂共享结构需要可调用接口

这些工作与“部分共性逐层利用”非常接近。尤其 LILO 表明，学习到库与让 LLM 正确使用库，是两个问题。

建议保留完整 AST，再提供经过核验的类型、参数角色、适用条件、调用例子和反例；分别测冻结库本身的价值，以及当前 agent 的消费能力。这里不需要削减表达力。[arxiv.org](https://arxiv.org/pdf/2310.19791v4?utm_source=chatgpt.com)

### 4. ALMA：记忆内容与记忆算法分开版本化

ALMA 搜索的是可执行的 schema、update、retrieve 设计。对本项目，应分别记录：

- 知识内容版本。
- 检索/写回策略版本。
- 研究方法或改进器版本。

先测冻结库迁移，再打开在线更新，才能识别哪一层带来收益。[arxiv.org](https://arxiv.org/html/2602.07755v1?utm_source=chatgpt.com)

### 5. Skill∞：检索命中不等于方法生效

值得借鉴的是记录方法是否激活、是否造成实质修改、原故障是否改善。

对应到 Hegel，应追踪：

**召回 → 读取 → 绑定 → 实际执行或修改 → 故障变化。**

当前有些节点虽然出现在提示里，却没有被执行；也有正确 AST 已经到达目标，模型仍直接弃答。只记录“召回了某哲学方法”不能验收收益。[arxiv.org](https://arxiv.org/html/2610.35434v1?utm_source=chatgpt.com)

### 6. ACE、GEPA：保存复杂经验和互补候选，但要防止坏反馈长期化

ACE 的局部增量更新适合避免整份记忆反复摘要造成信息丢失；GEPA 的候选档案适合保存对不同任务有效的互补方案。

对项目而言，探索分支可以暂时变差，最终交付 incumbent 可以保守升级。二者应同时存在。错误接口产生的“反例”则不能未经分类就进入长期 Nogood。[arxiv.org](https://arxiv.org/html/2510.04618v1?utm_source=chatgpt.com)

## 八、我建议下一轮按这个顺序做

### 第一阶段：先修已经证实的损失

优先处理：

1. `fit/predict` 状态协议。
2. 写回 owner 与实际采用实例的绑定。
3. 同源多候选保留，移除 first-success 垄断。
4. CLI 特性预检、调用恢复、调用尝试与科学轮数分账。
5. 单文件快照。
6. AMR 等任务的官方 verifier 配置。
7. 验证回执与候选 hash 绑定。

这阶段已有明确触发样例，适合先用保存代码验收。无需马上购买一轮更大的模型实验。

### 第二阶段：让复杂知识真正被后继消费

优先复用仓库已有资产：

| 需求 | 已有入口 |
|---|---|
| 实例绑定、在线写回 | `m4_4_instance_role_closure_and_online_writeback.py`、`wormhole_forest.py` |
| 部分共享、候选族、证据裁决 | `branch_reconciliation.py` |
| 已付费代码与分数保留 | `paid_score_history.py`、`research_episodes.py` |
| 任务相关探针与停止 | `probing.py`、HEC 路径 |
| 长期方法学习 | `research_methods`、`method_feedback` 等历史路线 |
| 可恢复运行 | 共享 checkpoint/runtime 接口 |

这里确实有适配工作：旧 typed Program 与新任意 Python 作者输出不能直接等同。无法可靠转换时，先保存可执行实例和未解决的语义边界，不能靠题号补出“学得公式”。

### 第三阶段：只做能区分原因的对照

先冻结新的任务家族，再分别问：

- 同内容、同价格、同工具，树组织是否优于 Flat？
- 冻结学得库是否优于无记忆和人工 seed 库？
- 在线写回是否继续带来收益，还是放大负迁移？
- 复杂时间状态是否真的改变后继预测？
- 实际执行学得程序，是否优于只把它写进提示？
- 新研究方法是否提高同一起点下的后继改进效率？

这些对照不必一次全部跑完。先选能回答当前最大不确定性的最小组，比继续扩大同模板 repetitions 更有价值。

### 第四阶段：再检验递归改进生产率

固定底座、起始知识和预算，让旧、新改进方法分别产生后继；使用同一验证规则选择，最后在未参与选择的任务上评估。随后让后继接管下一轮，观察多代生产率与旧能力保留。

**下一次最有价值的提交，应当能展示：已有正确程序不再被误判，知识归属不再依赖完成顺序，复杂共享结构实际改变后继动作，以及这些改变在冻结新任务上带来可复核的收益。** 这些证据会比再增加一层概念名称、一个更大的题数，或一个多版本成功并集，更直接地推进你最初的哲学树构想。
