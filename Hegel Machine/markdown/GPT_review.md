## 一、这篇论文最值得保住的核心，现在已经清楚了

我认为你最好的贡献，不是“用黑格尔哲学做 Agent”，也不是“定义了一种假设距离”，而是这个区别：

\[
\boxed{
\text{接受一个预测}
\neq
\text{保留它的计算}
\neq
\text{在新解释中继续使用它}.
}
\]

论文中的例子很好：

\[
C=A+0.7B,
\qquad
D=C+0.7(B'-B).
\]

当环境改变后，**“C 能预测当前响应”可能已经被反例否定，但 C 作为一个可执行计算，仍可能帮助构造 D；旧条件返回时，C 又可能重新适用。**论文还把这个思想推广到研究程序：一个新方法失败，不意味着此前有效的方法及其证据应被删除。manuscript manuscript

这比“保留历史”“不要遗忘”更具体：

> **被撤销的是特定条件下的预测资格，不必连同计算资源一起抹除。**

它也比最初“新理论必须兼容所有旧理论”的说法成熟：你现在允许撤销错误承诺，只保留旧理论在有证据的范围内的有效内容。

### 最有价值的三组正面证据

| 证据 | 为什么重要 |
|---|---|
| **§5.4：反例之后保留旧响应**，180/180 对 159/180 | 不只是保存成功经验，而是测试已经观察到失败的计算是否仍然有用。 |
| **§5.7：保持程序库相同，仅删除方法书**，两组均 30/30 成功，但保留方法减少观测和计算 | 比“有记忆对无记忆”更能隔离“怎样研究”的价值。 |
| **§5.13/F.6：LLM 修订研究方法，冻结迁移从 10/18 到 18/18** | 修改对象已经是处理后续问题的方法，不只是当次预测答案。 |

这三组都有实质内容，尤其第二、第三组，最接近你原始构想中的“知识不仅改变答案，也改变以后怎样获得答案”。manuscript manuscript manuscript

## 六、数学部分：我认为现在“正确而克制”，但不应当被当作深理论主贡献

### 6.1 两个初等结论基本成立

Appendix A 的两条性质：

1. 更多实验可以细分观测等价类；
2. 表示把不同响应合并时，重新拟合存在误差下界；

都与正文论述匹配。你把它们称为 **elementary consequences**，这个定位准确。manuscript

它们帮助解释框架，但没有给出：

- 假设发现的完备性；
- 搜索效率的普遍优势；
- 长期继承的统计可靠性；
- 表示扩展比普通修复更好的条件。

所以这版不应继续追求“已经有数学深度 10/10”的宣传。

### 6.2 有一个值得加一句解释的数学细节：确定性预测下 TV 会退化

正文定义：

\[
d_E(h,g)=\sum_{e\in E}w_e\operatorname{TV}(P_h^e,P_g^e).
\]

如果预测是确定性的：

\[
P_h^e=\delta_{f_h(e)},
\]

那么：

\[
\operatorname{TV}(\delta_a,\delta_b)=
\begin{cases}
0,&a=b,\\
1,&a\ne b.
\end{cases}
\]

这意味着它区分“是否不同”，却不反映“数值相差多少”。

所以，**这个公式适合支持可区分性与等价类的概念，不应让人以为实现中的 MSE、候选跨度和这一 TV 几何是同一个算法对象。**正文已经说明实现使用 finite disagreement 和 task losses，建议再把这个细节讲透。manuscript

### 6.3 真正值得形式化的，是两类依赖，而不是再增加一个空间名词

我建议方法部分明确区分：

\[
E_{\mathrm{call}}
\quad\text{与}\quad
E_{\mathrm{support}}.
\]

- **调用依赖**：程序 D 调用了程序 C。
- **支持依赖**：关于 D 的经验结论，依赖某个关于 C 的命题成立。

这是核心。

“C 不能预测当前世界”不意味着 C 的代码不再可执行，也不意味着所有调用 C 的程序都无效。反过来，如果被调用代码或仪器绑定改变，旧确认证据也不能自动沿调用边继承。

用一张状态转换表说明：

> 什么被撤销、什么被保留、哪些父结论待重验、哪些证据只属于旧源码版本。

**这会比添加更多初等定理更有助于建立论文的技术身份。**

### 6.4 Fresh confirmation 仍然不是长期统计保证

你的论文已经承认有限 fresh confirmation 会出现错误确认，这是正确的。manuscript

但“每次都拿新数据，直到某次通过”，不自动消除反复选择造成的错误接受风险。

如果第 \(t\) 次验收确实具有条件性错误接受上界 \(\alpha_t\)，才能进一步讨论：

\[
P(\text{序列中至少一次错误接受})
\leq \sum_t\alpha_t.
\]

目前固定 MSE 门槛没有自动提供这些 \(\alpha_t\)。

因此本稿可以继续使用“新数据确认”“经验支持”，不必为了补这点重新建设一个庞大的统计验证系统。但若以后要主打 rigorous sequential validation，就必须与 POPPER 等已有明确错误控制的工作比较。POPPER 已正式发表于 ICML 2025。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v267/huang25n.html?utm_source=chatgpt.com)

## 七、最值得新增的一项实验：研究方法移植，而不是继续堆开发案例

如果只能选一个补充实验，我会选择：

> **在相同任务知识、相同实验权限和相同预算下，学到并修订的研究方法，是否让后继在未参与 authoring 的问题上更可靠或更省资源？**

这最直接连接你的原始 RSI 构想。

### 实验最重要的三个条件

| 条件 | 目的 |
|---|---|
| 完整 Hegel | 使用显式支持依赖、历史程序和可修订研究方法 |
| 强通用 executable archive | 拥有相同代码和证据，允许普通重验、回滚、修复 |
| 研究方法冻结组 | 相同预测知识与工具，但不允许改写所学研究程序 |

普通 Code/task-local 可以作为第四组，但不能替代第二组。

### 任务变化应超越“原方程换系数”

不必立刻跳到机器人和真实生物实验。可以继续用受控实验室，但加入：

- 只变响应；
- 只变仪器；
- 两者同时变；
- 未宣布的变化时点；
- 返回旧状态；
- 无法完全区分、必须保留不确定性的情况。

重点是：**Agent 不被告知应该修订哪一个层次，也不能每次靠开发者新增一个针对该问题的分支。**

统计单位应是独立的来源—后继研究序列，方法学习失败的来源也保留在分母。样本量应由效应目标和方差决定，不需要再次凭空规定一大串 case 配额。

这个实验比“再成功完成一个 known-state 修复”更能改变论文的竞争力。

### 9.2 计费计算的定义

当前 joint-growth 结果是：

- charged computation 下降 22.42%；
- process CPU 上升 17.92%。

这已经写得诚实，但需要在方法附录中具体说明 learned calls、库检索、筛选、拟合和宿主开销如何收费，避免读者以为“计费计算下降”就是“更快”。manuscript

还应给出方法学习的成本摊销分析，而不只展示迁移阶段：

\[
N_{\text{break-even}}
\approx
\frac{\text{学习方法的成本}}{\text{每次迁移的平均节省}},
\]

前提是这些成本可比且节省确实为正。不同资源不能换算时，就分别报告，不要强行汇总。
