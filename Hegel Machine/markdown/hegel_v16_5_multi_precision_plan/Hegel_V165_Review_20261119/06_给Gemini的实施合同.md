# 给 Gemini 的下一轮实施合同

日期：2026-11-19。目的：把 V16.5 修成可运行、可解释、可公平评价的跨域假设研究实验。保留现有项目和主模块，不另建平行状态机，不扩写下一轮宏大总架构。

## 1. 不变的主目标

从普通研究经历中提出一个未预填的、有条件的假设或研究程序；让真实反例改变其条件、表示或分支；在新的目标上使用；在强普通方法可重建同一知识的条件下说明它的净价值。

“两个案例引出候选”可以开始实验；“证明所有领域同一机制”不是开工条件。一般性来自统一的提议—映射—检验—修订—选择接口，而非要求所有任务共享能量函数。

## 2. 必须保留的现有设计

- 强普通、紧凑经验库与 H 使用同模型、工具、源机会、程序归纳、主动观测、缓存与直接解题权限。
- 同历史机制比较与独立端到端比较分开。
- 两阶段预解与迁移选择器；完整成本与失败回退入账。
- `FidelityCompression` 与 `EmpiricalRevision` 分开。
- 真实否证见证进入方法复用；外评器只读不泄漏。
- 现有 `question_semantics`、`growth_methods`、`research_methods`、`method_revision` 等接口增量接入。

## 3. 开工前的最小结构修订

### 3.1 通用对象与家族插件

通用核心只要求：任务目标、可执行操作、可观测结果、上下文/协议、候选承诺、证据与费用。松弛家族可以有 u/z/p/F；饱和家族有输入/资源/输出映射；边界家族有有序索引和判定 oracle。不能让所有家族都先跑被动性或 Schur 探针。

允许共享算法和数学原语，不要求源码完全没有领域公式。必须隔离隐藏家族 ID、机制答案、正确端口和评价器真值。

### 3.2 四个不同对象

```text
TaskView: 当前输出目标、质量/损失、范围和预算
ObservationMap: 原始通道→所用读出，含单位/符号/噪声变化
ScaleMap: 状态或时间的聚合/消元，含保留任务与误差
ClaimContract: 前提→结论或行动保证，含适用协议和证据
```

没有 ScaleMap 的普通任务可以不填，不强制制造微观/介观/宏观标签。

这些对象的语义变化必须参与 meaning hash、version、cache key、方法参数绑定和 replay 身份。保留旧版本以便审计，旧答案不得静默沿用到新协议。

### 3.3 局部蕴含代替全局 L 标签

每条 `implies` 或 `refines` 边保存：前提对应、保持的查询/行动、范围、证据状态。没有依据的边只能是检索关联，不能触发逻辑传播或硬剪枝。

初期无需构造所有节点的 join/meet，不把它命名为已证明的全局数学格。版本/依赖 DAG 与相似图、冲突关系、工作流循环分开。

### 3.4 抽象使用权限

```text
retrieve_candidate
bounded_trial
local_solver_guidance
validated_pruning
```

每次使用保存本次目标绑定和授权证据。`proposed_discarded_variables` 只是候选；必须指明在什么任务/范围/误差下可忽略。禁止由 LLM 自填 `rg_irrelevant_slots` 后直接无条件通行。

### 3.5 决策区域

region 绑定 `action_ref + output_contract + scope + tolerated_loss`。同 L 层不是 region。空候选进入模型失配；噪声与无效协议不当作确定性反证；停止额外辨识后仍做独立确认。

## 4. 分支、冲突与修订规则

至少保留五个诊断候选类型：执行错误、观测错配、协议/范围错配、抽象丢失关键状态、模型命题错误。

先检查便宜的工具完整性合理；不得强制总能靠透镜/尺度修复旧假设。每次修订必须输出一个在新数据上可检查的差异预测。

触发修订时依次记录：

1. 旧版本及其本次承诺。
2. 成功执行的探针和实际观测；工具失败另列。
3. 被冲突命中的具体前提/结论及备选解释。
4. 修改动作：补充读出、细化状态、缩范围、分支、弱化承诺、拒绝模型或保真合并。
5. 保留与撤销的消费者、缓存及下游后果。
6. 未用于修订的确认结果与全部费用。

不要把“单模失效”固定翻译成“保住 L2”。保留什么由独立证据决定。也不要把粗模型的伪反例都翻译成降精度：有时要增加状态或缩小聚合范围。

保真合并至少检查既有合法接受与拒绝，不仅检查拒绝集超集。经验纠错允许撤回错误拒绝，但新版本不能无记录覆盖旧版本。

## 5. 首批两个实验簇

### 5.1 簇 A：有序边界与诊断程序

源经历：两种独立表示/环境的有序判定任务，有真实观测与费用，不预填“必须学会二分”。共享原语可含折半算法；若使用该设置，结论是学会适用条件与组合，而非发明算法。

候选：若有限有序二值判定在两端不同，则可以用保持端点差异的折半程序找某个相邻翻转。

目标必须包含：

| 目标类型 | 合法行为 |
|---|---|
| 单调唯一边界 | 可返回唯一阈值 |
| 非单调多次翻转，任务要求任意翻转 | 可保留一般折半程序 |
| 非单调，但要求最早翻转 | 不得把任意翻转冒充最早；换策略或增加前提检查 |
| 端点相同但中间异常 | 端点证据不足，不能保证无异常 |
| 随机判定或中间点无法执行 | 复测、调整区间或未知，成本入账 |

检查任务目标是否被悄悄放宽。查询复杂度与实际构建/实验成本分别记录。

本簇优先验生命周期与条件修订，未必能击败已会二分的强普通方法；不把它的简单正确运行包装为性能突破。饱和/资源簇承担首轮主要效用探索，最终是否有效仍由结果决定。

### 5.2 簇 B：饱和、限制因素与组合探针

源经历：两个独立实现或数据来源的资源—输出曲线，可采用理想 Amdahl 与 Michaelis–Menten 作为透明起点，随后增加异质数据/实现。

候选：局部有理函数族 `y=u/(αu+β)`，附参数意义、输入域、单位和观测误差。参数模板可由共同程序语法表达，不能直接由 evaluator 送到 H。

目标必须包含：同族新参数、硬 min 瓶颈、并列瓶颈、传感器限幅、无界凹增长、拥塞非单调。源/目标分割不能只靠随机种子；目标结构变体在源阶段不可见。

拟合点与确认点分开；倒数坐标可用于提案，但在原观测尺度计算误差。对并列瓶颈必须允许组合干预，检查系统是否从单变量零收益反例中学会增加此类问题。

## 6. 一项多视图/多尺度增量实验

同一排队或服务环境给出三个不同任务：平均吞吐、突发负载下尾部指标、版本故障定位。

先验证系统会根据目标选邻居和研究程序。再在有明确定义的平均/聚合操作中验证“被忽略细节对当前目标可忽略，对另一个目标不可忽略”。例如丢弃包到达时间或序列可能适合某些均值估计，却破坏尾延迟预测。

将真正粗粒化与纯任务视图切换分开报告。无需将每一种切换都称为 RG。

## 7. 基线和消融合同

| 比较 | 信息与能力 | 结论范围 |
|---|---|---|
| 强普通 vs H，独立历史 | 同源任务机会、模型工具与总预算；各自自由行动、记忆、重建 | 完整策略价值 |
| 同历史快照，普通 vs H | 同原始轨迹和目标状态；可自行抽取同知识 | 给定经历的组织与消费价值 |
| 条件化技能库 vs H | 允许范围、尺度、反例、技能改写与恢复；成本一致 | 显式可执行治理是否有额外价值 |
| 同内容 Flat vs Graph | 同知识对象和全部元数据、门控及消费者 | 图索引本身的价值 |

对象移除要处理派生摘要/缓存，但不得删掉普通组原始经历或强制重新学习。源经历干预要区分只是删来源标签，还是独立重跑形成阶段。

若对照在本地只是 HExA 思路的改造，称 HExA-inspired，不报告为论文官方复现。

## 8. 门控与探索

部署门在有覆盖条件下比较同状态剩余路径的经验成本；共同已付成本留总账，最终确认也计费。质量不能为了低成本而放宽。

无覆盖的新簇进入预设预算的探索臂，允许失败；探索损失计入端到端总成本，不称为已获统计保证的优化决策。成功与失败都进入后续开发校准，正式测试上的学习与更新规则提前冻结。

固定 PPR 不等于无选择偏差；需要冻结全策略、保持源簇隔离，并报告未覆盖与回退情况。小知识库允许 Flat 起步；出现召回瓶颈再做 Graph，不阻塞主实验。

## 9. 结果目录与必交证据

```text

formation_events.jsonl
hypothesis_versions.jsonl

baseline_permissions.json

```

每个声称获益的目标必须可追溯：源经历 → 新候选 → 竞争解释 → 反例 → 修订版本 → 目标绑定 → 实际消费动作 → 独立确认 → 基线轨迹 → 完整成本差。

不能只交节点数量、scope pass 数、测试绿灯、召回率或一段解释性叙述。

## 10. 验收分层

- **生命周期验收**：一条未预填新关系/条件/程序的自主形成与真实修订链完成。
- **实例价值验收**：在明确未见目标上，强普通可重建同知识，H 仍在同质量更省或同预算更准；个案成本及反事实消费证据可查。
- **分布价值验收**：独立来源簇上维持净收益，误迁移和失败全入分母，给出不确定性与负例。
- **规模扩展验收**：图检索、多尺度分流或分支合并在规模增长后有独立贡献。

前三种不能被“更多理论名词”或“单一手工规则跑通”替代，第四种不应成为前两种迟迟不做的前置工程。

## 11. 负结果的去向

| 观察到的结果 | 应采取的动作 |
|---|---|
| 普通方法很快重建，H 付税反而更慢 | 缩短形成/检索/验证；保留结果，不通过禁用基线修复 |
| 父命题仍成立但无区分力 | 降为提示或不消费；记录“正确但无用” |
| 子模型失败、父命题独立成立且仍有用 | 保留该父命题，并明确新的可执行行动 |
| 仅同生成器换名获益 | 报表征鲁棒性；下一步换独立机制/实现，不宣称一般科学发现 |
| 只有 Graph 召回率变高，任务成本没改善 | 不认定主目标达成，检查消费者和检索税 |
| 修订后只在原反例上成功 | 保留为修订拟合结果，另找真正未见目标 |

本合同不预先保证 Hegel 赢。它要求下一轮的成功或失败都能直接解释是否接近主目标，并给出明确的后续动作。
