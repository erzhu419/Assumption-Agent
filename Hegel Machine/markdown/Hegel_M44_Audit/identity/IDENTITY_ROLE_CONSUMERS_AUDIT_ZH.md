# V17.6 / M4.4 实例身份、角色映射与动作消费者专项审计

固定提交：`b965f022b214f47a1341559f20041da6a224d66d`。比较基线：`3461535364fcdb4e9ae9c87ccba502b7e6b56fe8`。

本专项负责上一轮实例锚定、规范/匿名角色、OR 动作、fresh 盒交集、严格 loader 与 R3 的接线。主审负责完整 42 项测试、完整官方 study 与其他专项。本专项没有重建森林、没有修改源码或提交证据，也没有调用模型 API；有限执行从提交内快照及已确认产物恢复。遵循 AGENTS 的历史复用要求，先查 reuse hub 和目录，关键词没有返回新 M4 路线后直接复用提交内 M4.3 审计与现有 loader、dispatcher、fitter 和 register_node。

## 一、结论

**上一轮两项核心 P1 的原始实现缺口确实修复了。** 节点现在向严格 loader 提供它期待的确认实例，而非只验证目录内部自洽；M4.3 召回拟合所用的角色排列也被限制到过盒映射，并把选中的排列传到确认点与最终查询。不能把这些仍然描述成“只有字段，没有接线”。

本专项另确认两处较窄的 **P2 消费者边界**：

1. R3 的显式 `role_map` 接口没有执行同名规范轴恒等锁。调用方显式提供与规范轴名字矛盾的交换映射时，可以绕过原本应触发的细尺度升级；这不是原主表的正常调用方式。
2. OR 分支动作已接入 R3，却仍未接入 M4.3 的重新拟合召回链。后者先加载顶层动作，再授权某个 OR 分支。因此，未选中分支的产物不可用时，会阻止另一个完整、适用的分支被召回。普通、无尺度证书的真实两实例控制证实了这个后果。

在本专项执行的正常锚定与角色控制中，没有复现新的主表 P1 假确认。匿名短时变体虽然先花费了粗通道 pilot，但受限角色拟合失败后正确升级到细节点，最终误差为零。该结果反而支持“旧 gate/fit 脱节已经修复”，同时界定了角色尚未识别时的通道选择成本。

## 三、P2-A：R3 显式 role_map 尚未共用规范轴锁

### 原因

`ForestScopeDispatcher._point_in_box`（`m4_2...:498–518`）直接依照调用方的 `role_map` 改写点，再检查盒子；`dispatch_predict` 在 `557–563` 使用这个检查，在 `647–657` 又用同一映射执行预测。这里没有调用新加的规范轴身份验证，也没有拒绝“输入特征已经是规范角色名，却把它们相互交换”的映射。

两处使用的是**同一个显式映射**，所以这不是旧版“盒检查交换、模型拟合不交换”的原始 P1 再现。剩余问题是不同公共入口对相同规范名字执行了不同的身份约束。

### 有限实际结果

恢复未修改的提交内 `post_stage2` 森林，原始物理点为 `u_drive=2.7, T_horizon=0.47`；真实细模型值 `3.22880775`。

| R3 调用 | 选中节点 | 预测 | 绝对误差 | 状态 |
|---|---|---:|---:|---|
| 规范名字，不提供 role_map | `ode_micro_2mode_node` | 3.22880775 | 0 | `dispatched_ok` |
| 匿名 x0/x1，提供正确 x0→u、x1→T 映射 | `ode_micro_2mode_node` | 3.22880775 | 0 | `dispatched_ok` |
| 规范名字，却显式传 u→T、T→u | `ode_meso_schur_pi_thermal` | 0.96967258 | 2.25913517 | `dispatched_ok` |

第三行回执明确是 `within_tolerance=False`，不是审计隐藏了数值失败；该字段依靠控制传入的外部真值生成，并没有在输出前拒绝矛盾映射。

### 范围与建议

这是**显式映射的 API 验证边界**。当前主表不提供这种矛盾映射，不能据此重算其失败率。若设计把该参数视为可信调用方的显式坐标重命名，就必须明确它可以覆盖规范名字；否则建议让 R3、召回拟合与购测统一调用已有角色规范化规则：已命名的规范轴固定，匿名轴才映射，要求完整双射，并在任何盒检查前拒绝冲突。保留上表两个正对照，避免为了修这条边界损坏合法匿名坐标。

## 四、P2-B：OR 授权分支与重新拟合的动作来源仍未统一

### 原因

`m4_3...:1276–1296` 先校验 `program_steps`，读取顶层 `claim_contract.conclusion_or_action`，调用 `_load_node_verified_operator_spec`。后者在 `m4_1...:1419–1441` 也只读取顶层动作。之后 `m4_3...:1303–1319` 才授权 OR 分支，保存候选时没有消费 `gate.selected_action`。Tier 3 再授权（`1484–1507`）也没有检查它是否正是此前加载/拟合的动作视图。

相同模式还在旧 M4.2（`2725–2747`）及 M4.1（`1556–1568`）召回消费者中存在。R3 则已改为先选分支后加载，形成清楚的消费者差异。

### 普通 OR 的可达控制

为了避免把尺度证书约束混进问题，最终控制使用普通 Monod 节点，不含 Pi、coarse edge 或区域闭合证书：

- A 为当前 Stage 0 的真实增益 6 实例。
- B 为本提交 `markdown/Hegel_M4_3_Audit/instance/same_ast_distinct_gain_calibration/` 已归档的真实增益约 12 实例。它已经通过真实校准与独立确认；本轮只用当前严格 loader 验证，没有重新校准。
- A/B AST 相同，确认实例摘要不同；通过正式 `PhilosophicalForest.register_node` 注册两个互斥适用分支，语义摘要复算无差异。
- 目标落在 B 分支。禁用 fallback 是为了隔离“可用分支能否召回”，没有改变拟合器、授权器或产物内容。

| 控制 | R3 | M4.3 重新拟合召回 |
|---|---|---|
| A/B 均完整 | 加载 B；预测 5.33333333，正确 | gate 选 B，loader 实际加载 A；因同 AST 可再拟合，仍成功且 heldout RMSE 0 |
| 仅未选中的 A 的定位符不可用，B 完整 | 仍加载 B；预测 5.33333333，正确 | 在调用 gate 前因顶层 A 加载失败跳过节点，返回 `scoped_unknown` |

完整动作摘要、loader trace、gate trace 和回执在 `generic_or_actions.json`，复现入口 `probe_generic_or_actions.py`。

这里观察到的是**条件分支独立性与可用性问题**，不是“同 AST 的 A 重新拟合一定产生错误数值”。正对照明确显示它可以重新拟合成功。当前标准 post-stage2 的两个 Pi 分支共享同一实例，故原主表没有这次控制中的 A/B 差别。

### 不采用的探索控制

早先 `role_consumer_boundaries.json` 中保留了将 Stage 0 与 Stage 2 两个 Pi 实例放到不同 OR 分支的探索记录。两个产物各自合法，但**这个组合森林不满足当前 coarse-edge 重认证要求所有分支与同一证书实例相同的不变量**（`wormhole_forest.py:1284–1307`）。因此不能把该探索中 21→88 的测量费变化当成当前生产生命周期的有效反例。JSON 已增加 `scope_limit`，最终判断仅使用上面的普通 OR 控制。

### 建议

复用已有 `authorize_abstraction_use` 的 `selected_action`，先形成这次请求的有效动作视图，再以同一视图校验实例、路径、roles、operator_spec 和执行步骤。无须撤销当前 Pi 证书实例守卫，也无须允许异构法则合并。一个普通两实例 OR 的“B 可用、A 不可用”控制已足以验证修复，不需要重开完整科学基准。

## 五、匿名/部分规范轴：本轮观察到成本边界，未观察到假确认

复用上一轮短时 Pi 的同一 6 个点，只把 `T_horizon` 改名为 `x1`，或把两个轴改成 `x0/x1`。原始 fine/coarse oracle、容差和森林均保留。

这两个变体都会先以“存在某个能入盒的排列”购买 6 个粗 pilot，之后拟合被严格限制到该排列，训练 RMSE `0.09061448036` 超过 `0.055`，遂升级细节点，最终 heldout RMSE 为 0，没有错误确认。总测量费 88，其中 18 来自随后被放弃的粗 pilot。

这证明新的 `allowed_role_orders` 约束确实有效。也说明当前通道预检仍先挑一个可入盒映射（`m4_3...:1167–1197`），角色识别发生在购测之后。对于半匿名输入，已有规范名的轴也未被部分锁定：helper 只在两边完整名字集合相等时进入恒等锁（`m4_2...:2542–2548`）。如果后续 M5 要广泛接入匿名或半匿名传感器，应明确“粗通道授权所需的坐标来源”以及是否先用细数据判定角色；本轮不能把这两个成功升级的例子写成错误预测。
