## 二、你的目标不应当被降格成“高级案例库”，但也不适合存成一棵单根树

你说的“哲学树”可以保留为名称或展示方式。**底层更适合是带类型、作用域、版本和证据的理论图。**

原因很具体：一个新理论可能同时继承多个旧规律；一个理论可以在不同尺度下与不同理论对应；同一反例可能挑战多个前提。强迫每个节点只有一个父节点，会丢失你最关心的这些关系。

建议明确区分：

| 层次 | 例子 | 怎样检验 |
|---|---|---|
| **经验记录** | 某次实验、代码输出、文献中的一个陈述 | 来源与实际取得条件 |
| **具体假设实例** | 某装置的一组响应参数 | 当前证据和事前预测 |
| **模型族或结构规律** | 分段响应、对称性、有限记忆 | 跨实例约束与新条件预测 |
| **理论之间的关系** | 同族、特殊情形、部分对应、对偶 | 明确的映射和保持条件 |
| **研究方法** | 怎样识别边界、怎样区分历史效应 | 后继研究效果与成本 |
| **元先验** | 哪种结构值得优先搜索 | 使用该偏好是否改善后继学习 |

这些对象可以互相连接，但不能互相冒充。

例如，“优先试简单模型”是一项研究偏好；“这个环境确实是线性的”是一项世界假设。**前者有用，不证明后者为真。**

## 三、目前“假设形式不明确”的问题，究竟在哪里？

> **不同载体之间，缺少统一的“它究竟对什么作出什么承诺”的语义。**

目前：

- 问题 ID 表示持续研究工作；
- 模型路径表示执行入口；

\[
H=(k,\Sigma,\phi,\mathcal M,\Omega,\Gamma,\mathcal V).

| 部分 | 意义 |
|---|---|
| \(k\) | 假设类型：世界预测、结构规律、方法或元先验 |
| \(\Sigma\) | 输入输出、变量角色、单位、历史与干预的类型 |

### 3. 假设不能只是一段预测代码

例如：

\[

\]

是一条不变性假设。它不一定独立给出完整的 \(y\)，但约束了一整类可能预测器。

同样：

\[

## 四、一个最容易造成混乱的地方：问题、假设、模型族是三种不同身份

建议尽快把这三种身份分开。

### 1. 问题不是假设

问题是：

> 这段响应是否依赖到达当前输入的历史？

假设可以是：

> 当前值足够。

另一个竞争假设是：

> 需要某个历史状态。

子研究则可能是：

> 当前仪器读数是否仍然具有同样的含义？

**竞争假设不是原假设的子前提，代码任务也不是科学子假设。**

### 2. 同一模型族，不代表同一预测器

\[
f(x)=2x+1,\qquad g(x)=3x-2
\]

可以属于同一个仿射族，但不是同一个冻结预测器。

因此，新装置只需改系数时，应生成旧理论的新实例，而不是新增一条“新哲学”。

### 3. 同一研究会话，不代表同一理论

当前 `open_assigned_question` 通过 ID 找到旧记录并保留原 assignment，这能维持工作连续性，却不会判断问题是否在科学意义上改变了。

建议问题至少固定：

\[
q=
(\text{所求量或命题},
\text{物理干预},
\text{上下文},
\text{答案类型},
\text{父用途}).
\]

同一个理论可以被多个问题使用；一个问题也可以比较多个理论。

**不要让理论节点随着每一次 `scientific_revision_N` 被复制，也不要让沿用一个 `task` ID 掩盖所研究命题已经变了。**

## 五、你最初想要的数学“相似性”，可以定义，但不能只有一个

你提出这个方向是合理的。需要修正的不是“别做相似性”，而是：

> **必须先说明相似的是代码、预测、结构，还是对新问题的适用性。**

这四件事不能合并成一个数字。

### 1. 精确计算身份

对受限表达式，可以进行变量重命名、经过验证的化简、类型与单位归一化。

例如：

\[
x+x \quad\text{与}\quad 2x
\]

在相应算术语义下可视为同一计算。

这适合去重和缓存。但相同代码在新环境中是否适用，仍是另一问题。

任意 Python 则应保留为可执行黑箱；没有暴露的结构，不能仅凭程序可运行就自动获得语义等价判定。也不能对浮点程序任意套用实数代数恒等式。

### 2. 当前观测下的行为相似

固定物理实验族 \(Q\)，固定各输出的尺度 \(s_e>0\)，可以定义：

\[
S_Q(h)=\big(f_h(e)\big)_{e\in Q},
\]

\[
d_Q(h,g)
=
\max_{e\in Q}
\frac{|f_h(e)-f_g(e)|}{s_e}.
\]

它回答：

> 在这些实验所能看见的方面，两个候选相差多少？

这是你泛函分析思路最直接的可执行形式。满足相应条件时，它是伪度量；对同签名对象取商以后，才消除零距离的非唯一性。原稿已经给出了这一构造及其限制。supplementary

但看这个例子：

\[
h_1(x)=x,\qquad h_2(x)=x^2.
\]

在 \(Q=\{0,1\}\) 上：

\[
d_Q(h_1,h_2)=0.
\]

增加 \(x=1/2\)，二者立即分开。

所以：

\[
\boxed{
\text{当前观测相同}
\neq
\text{科学机制相同}
\neq
\text{可以永久合并}.
}
\]

同样，“距离小于阈值”一般不具有传递性。不能因为 A 接近 B、B 接近 C，就将三者永久归为一个理论。

### 3. 经过变换后的结构对应

跨单位、角色或对象类型，需要显式映射：

\[
p_g(T_{\rm in}(e))
\quad\text{与}\quad
T_{\rm out}(p_h(e)).
\]

它检验的是：

> 用这个输入／输出映射，旧结构是否仍然保持？

例如，两个装置都满足同一种缩放后的响应关系。其具体单位不同，但结构可对应。

**映射本身也是假设。**必须限制它的复杂度并在新条件上测试，否则任意逐案例映射可以人为把任何两个东西“对齐”。

所以，最小映射误差可以作为搜索准则，却不必称为严格距离。对局部映射，继续使用原始 v0.2 的“部分带类型结构对应”，比未经证明就叫同构或函子更合适。广义对位关系(1)

### 4. 对新问题是否适用

这需要：

\[
\text{类型与测量含义}
+
\text{作用域}
+
\text{支持前提}
+
\text{当前证据}
+
\text{前瞻预测}.
\]

它不是任何一个相似度能单独代替的。

**因此，相似性应该负责“召回和提出映射”，而适用性负责“决定能否复用”。**

这与结构映射研究中区分对象属性相似和关系结构对应的思想一致，不需要重新退回文本相似度。[Wiley Online Library](https://onlinelibrary.wiley.com/doi/abs/10.1207/s15516709cog0702_3)

## 六、对称、对偶、互异等关系，应该怎样进入“哲学谱”？

不能把它们全部解释成“接近程度”。

| 关系 | 应当有的可执行含义 |
|---|---|
| **同族** | 共享同一结构，允许声明的参数变化 |
| **对称／等变** | 指定变换下满足 \(f(Tx)=\rho(T)f(x)\) |
| **特殊情形** | 某参数、作用域或投影下恢复旧理论 |
| **部分对应** | 有限角色与关系经映射保持 |
| **对偶** | 明确的双向对象／运算变换，以及往返和定律保持条件 |
| **不相容** | 同一范围和解释语义下，主张不能同时成立 |
| **守恒** | 指定边界和单位下，多对象变化满足平衡约束 |
| **支持依赖** | 某条推断路径需要某个前提 |
| **计算调用** | 某个程序实际使用另一个对象 |

例如：

- \(f\) 与 \(-f\) 不自动构成对偶；
- 两个理论在不同范围成立，不构成矛盾；
- 两个不同程序得到同一预测，不代表它们依赖同一机制；
- 一个代码调用成立，不代表其经验前提成立。

**这些关系边本身也应有证据、范围和状态。**不是一旦贴上 `dual_of` 标签，它就成了已知事实。

这正是原始“广义对位关系”比普通相似案例库更有价值的地方。广义对位关系(1) 广义对位关系(1)

## 七、什么时候复用，什么时候开子研究，什么时候新建假设？

这里确实需要比“由 Luna 判断”更明确的算法。

但也不能制定一个表面确定、实际上把所有科学不确定性藏起来的分类器。

### 1. 先规定可执行的决策结果，而不是只判“同／不同”

| 当前情况 | 合理动作 |
|---|---|
| 旧对象与当前输入绑定一致，证据仍支持 | 复用并按新任务要求检验 |
| 结构相同，仅参数可能变化 | 重拟合旧族的新实例 |
| 结构可对应，但单位、角色或仪器含义未知 | 研究绑定，再检验迁移 |
| 旧模型只在部分范围适用 | 限定范围或学习条件分支 |
| 多个解释都兼容现有数据，但未来预测不同 | 做区分实验 |
| 当前表示存在任务相关冲突 | 研究表示、观测或随机性解释 |
| 当前有界方法持续失配，新结构产生不同可测后果 | 允许结构修订 |
| 搜索或证据不足 | 返回未决，不声称旧语言已被否定 |

这比“相似度低就开新节点”准确得多。

### 2. 子研究应由“未解决的父用途”触发

建议一个可调度子问题必须回答：

> **父研究的哪个结论或行动，取决于这个子问题的答案？**

假设父计算是 \(F(z)\)，子问题可能给出 \(z_1,z_2\)。如果它们都仍与证据兼容，且：

\[
d_{Q_\tau}\big(F(z_1),F(z_2)\big)>\epsilon_\tau,
\]

或者导致不同的实际行动，那么研究这个子问题可能有价值。

反之，如果已经能够证明所有允许子答案都不改变当前任务结论，就不必为“解释完整”无限向下钻。

**未找到不同后果，不等于证明没有不同后果。**有限搜索没有完成时，仍应保持未决。

### 3. 每个子研究应有明确的返回类型

可以返回：

- 一个参数区域；
- 一个角色绑定；
- 一条局部约束；
- 一个可调用子模型；
- 一个新的表示；
- 一个区分实验；
- 一份表明仍不可识别的结果。

“可能有更长历史”只是一条解释。  
“当前表示把这些记录合并，至少承担这个误差下界；新表示区分了它们，并改变这些未测预测”才是能够进入父计算的研究结果。

### 4. 不是失败就必须开子题

当前 live Common 已经在成功执行但未通过新确认时自动安排研究；多次“拟合好、确认差”还会升级方法调查。这些不是没有规则。

下一步应该将这些**粗触发器**细化为父用途驱动的研究路由，而不是再增加“失败了，思考一下参数、表示或机制”的长提示。

也不应重回过去那种要求：

> 必须证明所有旧模型都不行，才能尝试新模型。

那会再次把研究拖进无限排除。**值得尝试新解释，与已经证明旧语言不充分，是不同的主张。**

## 八、最上游的缺口：现在需要两个循环，而不是把一个循环无限拉长

### 循环一：解决当前问题

\[
\text{当前理论库}
\rightarrow
\text{召回与实例化}
\rightarrow
\text{检验适用性}
\rightarrow
\text{复用／子研究／修订}
\rightarrow
\text{当前结果}.

### 1. 从共享程序和共享约束中归纳

假设多个来源分别得到：

\[

\]

系统要尝试识别：

- 哪个结构 \(\alpha\) 是共同的；
- 哪些参数因对象变化；
- 哪些输入角色可以对应；
- 哪些前提决定它失效。

**“共用一段代码”只能提出“可能有共同结构”，不能证明它们共同描述了世界。**

### 2. 同时利用负结果

失败不只用于降低一个分数，还要用来区别：

- 这个实例参数错了；
- 这个结构在某范围失效；
- 这个映射不保持关键量；
- 这个实验没有辨别力；
- 这个研究方法虽然正确但不值得其成本。

如果只压缩成功程序，系统很容易抽象出一条缺少边界的“总规律”。

### 3. 新原则必须改变后继研究

例如，它可以从多次真实失败中提出：

> 当当前表示在可重复条件下合并了不同响应，而原始公开记录仍有区别时，先研究被删除的区别，再扩大同表示上的拟合器。

它应被编译为：

```text
什么状态下检索到它
优先检查什么
哪些候选或实验因此被生成
什么证据使它不适用
怎样比较使用与不使用它
```

而不是只把这句话放入 `philosophy.md`。

**原则进入候选生成、实验选择或复用判断，才真正成为元先验。**

### 4. 元先验也应有反例和作用域

上面的原则不意味着：

> 所有重复输入的不同输出都来自表示缺失。

在真实随机过程中，差异可能是噪声。系统应当保留竞争解释，而不是无限创造状态。

因此，“哲学谱”不应是一个越来越大的绝对真理集合，而是：

> **一组可检验、可修订、在不同条件下承担不同承诺的结构。**

假设集合与上下文支持维护可以借鉴 ATMS；但 ATMS 只是支持管理机制，不是自动发现器。[doi.org](https://doi.org/10.1016/0004-3702%2886%2990080-9)

## 十一、当前 source006 应怎样避免继续困在“多写几个模型”？

最新报告中的一个关键边界是：

> 两条不同历史经过某个共同后缀后得到相同输出，只说明所测协议下输出相同，不能证明隐状态完全相同。

这里就可以分成两个清楚的假设：

\[
H_1:\quad
\text{这两条历史在已测后缀下输出相同};
\]

\[
H_2:\quad
\text{这两条历史对一类未来干预都不可区分}.
\]

\(H_2\) 比 \(H_1\) 强。

接下来不是直接问 Luna“有没有隐状态”，而是：

> 哪个合法未来输入序列，会让仍然兼容 \(H_1\) 的解释在 \(H_2\) 上产生不同预测？

这会把：

- 观测相似；
- 状态可合并；
- 当前任务无需区分；
- 全机制相同；

四个不同命题拆开。

同理，039 与041目前是两个可执行拟合程序，但其分数差不能直接判定“顺序不变”与“持续隐状态”的真假。最新指南已经明确承认，竞争机制还没有严格编译成那两个模型。

**所以我不建议再让一次拟合器胜负承担整个机制判断。先让机制主张有自己可执行的后果，再决定要不要生成完整预测器。**

> 这个规律是否只在某个范围成立？  
> 两个已经学出的模型，是否只是同一结构的不同参数实例？

一个问题可以由不同方法回答。比如“阈值在哪个区间”，可以通过二分、批量拟合或复用旧证据回答。**换算法不等于换问题。**

同样，“有没有历史效应”这个问题，可以比较无历史、有限历史、测量延迟等多个假设。**竞争假设也不等于支持性子假设。**

这项区分会直接改变项目设计：

\[
\text{当前任务}
\rightarrow
\text{尚未解决的问题}
\rightarrow
\text{竞争假设}
\rightarrow
\text{取得答案的方法}.
\]

不能再把这四层都交给一个不断改写的 `question` 字符串。

# 二、你提出的数学理解：哪些保留，哪些需要修改

## 2.1 “一个函数就是一个假设”：可以作为起点，但少了科学含义

写出：

\[
y=f(x)
\]

给出了一个映射。但是，要成为可检验的科学假设，还需要明确：

**变量是什么、怎样测量、在哪个范围、允许什么干预、误差怎样解释、依赖哪些前提。**

同一段 `y=2*x`，当 `x` 分别表示时间、电压或校准后的读数时，不是同一个科学假设。

你论文原有的：

\[
h=(\phi,p,s,\Gamma)
\]

已经比“假设就是函数”更完整：表示、程序、作用域和支持前提。没有必要把这个基础推倒。manuscript

而且，有些重要假设不提供完整响应函数，而是**约束一个函数族**：

\[
f(-x)=f(x)
\]

要求偶对称，但没有确定究竟是哪一个偶函数。

\[
\sum_i q_i^{\mathrm{after}}
-
\sum_i q_i^{\mathrm{before}}
=q_{\mathrm{external}}
\]

约束守恒关系，但没有给出每个量的完整动力学。

因此，较一般的表示是：

\[
\boxed{
\mathcal M_H=\{m:m\text{ 在指定范围和解释下满足假设 }H\}.
}
\]

这只是定义假设允许哪些模型，不要求实际枚举整个集合。

**你希望积累的“哲学谱”，很大一部分应该是这些约束模型族的结构规律，而不仅是已经拟合好的函数。**

## 2.2 初始条件、边界条件不是附属注释

你对微分方程的提醒很重要。

例如：

\[
\dot x=F_\theta(x,u,t),\qquad y=G_\eta(x,t)
\]

通常还不足以给出唯一预测。初值、边界、输入轨迹、测量模型和噪声描述，都可能是问题的一部分。

对黑格尔机来说，它们应该被标记为：

- 已给定的条件；
- 当前估计的不确定量；
- 需要研究的支持前提。

**错误初值下的失败，不能自动否定动力学结构；动力学结构正确，也不能让未知初值变成免费已知量。**

这正是子研究应该承担的工作，而不是任何失败都整体换一个预测器。

## 2.3 “函数放大某些特征、压小另一些”：是有用的局部图景，不是一般定义

对于线性变换 \(z=Wx\)，确实可以沿不同方向放大或抑制；非可逆表示也可能合并原本不同的输入。

但逻辑谓词、排序、状态更新、条件概率核，不都是同一种滤波器。

另外，**确定性地组合旧特征，可能让已有信息更容易被学习器使用，但不等于取得了新的外部信息。**相反，如果表示丢掉了必要区别，后面的拟合器无法仅凭被压缩后的输入恢复它。

你之前“没有历史”和“历史值为零”被零填充合并，就是这个问题的实际例子。原始数据存在区别，作者的表示主动删除了它。Hegel_Machine_20261013_Online_S…

## 2.4 泛函不是“寻找最优函数”的同义词

可以这样区分：

\[
p:X\to Y
\]

是预测函数；

\[
J:\mathcal F\to\mathbb R
\]

可以是泛函，比如对一个候选函数计算误差或范数；

\[
\mathcal T:\mathcal F\to\mathcal F
\]

是把函数更新为另一个函数的算子。

在函数空间里优化 \(J(f)\) 是一个应用，但不是泛函分析的全部定义。

你的原论文中，“观测把候选函数投影成可见签名”的组织方式是成立的；不要再把它改写成“所有假设都是某种泛函，因此所有问题可以统一做函数优化”。论文自己也明确：一般实验、条件方差和研究标准未必是线性泛函。manuscript

# 三、正则化与先验：关系很直接，但通常不是因为“对偶”

## 3.1 最直接的对应来自取负对数

给定先验与似然：

\[
p(\theta\mid D)\propto p(D\mid\theta)p(\theta),
\]

最大后验估计为：

\[
\hat\theta_{\mathrm{MAP}}
=
\arg\min_\theta
\left[
-\log p(D\mid\theta)
-\log p(\theta)
\right].
\]

如果：

\[
p(\theta)=Z^{-1}\exp[-\lambda R(\theta)],
\qquad 0<Z<\infty,
\]

那么它对应负对数似然加正则项 \(\lambda R(\theta)\)。

**这里的对应首先是概率密度与优化目标的对应，不是因为先验和正则天然互为拉格朗日对偶。**概率推断和优化之间还有更广泛的变分联系，但应当分别说明。[机器学习研究杂志](https://jmlr.org/papers/v24/22-0291.html)

## 3.2 更复杂的先验，通常对应更复杂、可能非凸的正则项

| 先验 | 对应的负对数项 |
|---|---|
| 独立零均值 Gaussian | \(\frac{1}{2\sigma^2}\|\theta\|_2^2\) |
| 独立 Laplace | \(\frac1b\|\theta\|_1\) |
| 相关 Gaussian | \(\frac12(\theta-\mu)^\top\Sigma^{-1}(\theta-\mu)\) |
| Gaussian 混合 | \(-\log\sum_k\pi_k\mathcal N(\theta;\mu_k,\Sigma_k)\) |
| 分层先验 | \(-\log\int p(\theta\mid\eta)p(\eta)\,d\eta\) |
| 带基分布的结构偏好 | \(-\log p_0(\theta)+\lambda V_H(\theta)+\log Z_H\) |

上表是对相应概率密度直接取负对数得到的数学对应。只有真正与正在优化的变量无关的常数，才可以忽略。

几个容易影响你项目的细节：

**混合不等于惩罚相加。**混合先验允许多个模式；把几个惩罚相加，更接近把密度相乘，含义不同。

**分层边缘化不等于挑一个最佳超参数。**积分与联合最优化一般得到不同目标。

**不同候选的归一化常数可能不能丢。**特别是比较协方差、约束区域或不同模型结构时。

**不是每个正则都定义正规先验。**例如只惩罚导数而不约束常数方向，在无限范围上可能无法归一化。

因此，我建议项目保存的不是一句“使用这个先验”，而是：

```text
它偏好什么对象
它如何进入生成、拟合或选择
是否有正规概率解释
是否只是经验惩罚
适用条件和数据来源是什么
```

## 3.3 函数空间中要更谨慎

核岭回归与 Gaussian process 的后验均值之间，有明确联系；但不能因此把 GP 想成“在其 RKHS 里具有一个普通密度的随机函数”。无限维空间的测度、样本路径与 RKHS 有重要区别。[arXiv](https://arxiv.org/abs/2506.17366)

对当前工程，最合理的做法是：

> **先在明确的有限参数、Program 结构或已有 GP 后端中使用先验—正则联系，不先建立通用无限维先验编译器。**

## 3.4 这部分值得融入，但不要把所有知识都转成正则项

我建议分流：

- 已证明的形式约束：进入结构化参数化或受限搜索；
- 有范围的经验规律：作为可撤销软偏好，并保留违反它的竞争候选；
- 实测结果：进入证据／似然，不能再当成独立先验重复计算；
- 研究经验：改变候选生成和实验选择；
- 元先验：通过后继研究效果评价，而不只看当前拟合。

如果一条规则是从本次标签中学出来的，再把它作为“独立先验”乘回同一批标签，会重复利用证据。**“资料都学一遍”不等于“同一事实可以换个身份算两遍”。**

# 四、RL 的收缩性与你想要的相似性有关，但不是同一件事

## 4.1 不是所有 RL 都在证明收缩

折扣动态规划中的 Bellman 算子确实有重要的收缩性质；但策略梯度等方法可以直接研究策略目标的梯度和优化，不要求整个学习过程是一个压缩映射。[NIPS 会议论文](https://papers.nips.cc/paper_files/paper/1999/hash/464d828b85b0bed98e80ade0a5c43b0f-Abstract.html)

而且，欧氏空间本身就是 Banach 空间的一个例子，不是进入 Banach 空间之后才开始能比较“规律”。

## 4.2 收缩究竟在说什么？

对于固定环境、固定行动语义、\(\gamma<1\) 的折扣 Bellman 算子：

\[
(TV)(s)=
\max_a\left[
r(s,a)+\gamma\mathbb E[V(S')\mid s,a]
\right],
\]

有：

\[
\|TV-TW\|_\infty
\le
\gamma\|V-W\|_\infty.
\]

这里比较的是：

> **两个值函数经过同一个算子更新后，差异是否缩小。**

它没有直接比较：

- 两个不同环境的机制；
- 两个不同策略；
- 两条不同起点和终点的实际轨迹。

一个反例就能看清：

\[
T_1(v)=\tfrac12v,
\qquad
T_2(v)=\tfrac12v+100.
\]

两者的收缩率相同，但不动点分别是 \(0\) 和 \(200\)。所以，**相同收缩性不意味着相同规律或相同目标。**

“收缩”和“紧致”也不是同一个概念。完整的数学区分和反例写在第一份文件中。

## 4.3 更接近你直觉的是“预测状态”和“行为度量”

预测状态表示考虑：

> 给定当前历史，在不同未来行动序列下，会观察到什么？

这比只比较当前坐标，更接近你想比较的“轨迹规律”。相关研究用多步、行动条件化的未来预测来表示状态。[NIPS 会议论文](https://papers.nips.cc/paper_files/paper/2001/hash/1e4d36177d71bbb3558e43af9577d70e-Abstract.html)

MDP 中的 bisimulation 度量则可以同时比较奖励和转移规律。一个折扣形式是：

\[
(\mathcal Fd)(s,t)
=
\max_a
\left[
|r(s,a)-r(t,a)|
+
\gamma W_d(P(\cdot\mid s,a),P(\cdot\mid t,a))
\right].
\]

这里的逻辑是：

\[
\boxed{
\text{先定义有行为意义的差异}
\rightarrow
\text{再用收缩分析保证固定点的性质}.
}
\]

不是反过来用“有收缩性”定义一切相似。[arXiv](https://arxiv.org/abs/1207.4114)

**融入建议：**当前先用已有的有限实验预测签名；等明确了行动、状态、转移与任务意义，再考虑 bisimulation。不要为了数学统一，给开放式理论生长强加全局收缩——新观测有时恰恰应该让过去合并的解释重新分开。

### 特别值得注意的两项2026年近邻

**《Induction and Inquiry via Probabilistic Reasoning over Language and Code》**把假设表示成语言与 Python 的结合，通过顺序概率推断维护多个解释，再进行主动提问。它是2026年9月的预印本。[arXiv](https://arxiv.org/html/2609.01815v1)

# 六、下一版的核心对象：问题应当是一项“查询”，而不只是一个标题

## 6.1 给问题一个答案语义

对于答案唯一的情况：

\[
q:\mathcal M\to\mathcal A_q.
\]

含义是：

> 如果某个可能模型 \(m\) 成立，这个问题的答案是什么？

例如：

\[
q(m)=\text{模型 }m\text{ 的阈值};
\]

\[
q(m)=m(e_{+x})-m(e_{-x});
\]

\[
q(m)=\text{两条历史在指定未来行动族下的预测差异}.
\]

在候选模型上执行它，可以得到**预测答案**；真实答案仍要用实际证据获得。**不是让运行时直接读取隐藏世界。**

对于“找到一个足够好的解释”这样的开放问题，不一定有唯一答案，应该使用：

\[
\operatorname{AcceptableAnswer}_q(m,a),
\]

规定什么算一个合格答案，而不是强行指定唯一标准程序。

## 6.2 在代码里至少固定这些内容

```text
正在问哪个量或哪条关系
涉及哪些对象、角色和范围
答案是什么类型
哪些数据或推导能够回答它
答案将改变哪个父输入、实验或理论学习目标
```

随后再选择获得答案的方法。

原来的 `question_id` 继续用于会话定位。当前代码根据 ID 续用问题并保存原 assignment，这可以保留，但它不能承担科学语义判同。

## 6.3 初始问题语言不必很大

施工稿中给了九类查询，第一轮只要求完整实现其中几个：

| 查询 | 实际含义 |
|---|---|
| `Readout` | 某实验下某个读出的值或分布 |
| `Difference` | 两个共同语义读出的差 |
| `RelationResidual` | 指定关系在这些条件上的违反量 |
| `ParameterRegion` | 与证据兼容的参数区域 |
| `CheckApplication` | 旧理论在当前绑定下是否适用 |
| `FindDistinguishingExperiment` | 哪项合法实验能区分待解决答案 |
| `FindSharedStructure` | 多个已学对象是否存在可重构的共同结构 |

**第一轮不允许这些构造子只是字符串。**必须分别能在候选模型上计算预测、在实际证据上计算结果，并处理未知和错误绑定。

对于真正新颖、尚未形式化的想法，仍可以先保存为 `IDEA`。形式化不是禁止创造性的入口门槛；它是从构想到可检验主张的转换过程。

# 七、怎样提出宏观问题，而不退回“继续提高分数”？

我建议使用两个研究队列。

## 7.1 当前任务队列

处理：

> 当前答案依赖哪个尚未解决的区别？

来源包括失败确认、表示冲突、参数未识别、仪器变更、候选分歧和作用域不确定。

## 7.2 理论学习队列

处理：

> 多次研究能否被更一般的结构组织？  
> 两个方法为什么分别在不同条件有效？  
> 哪些区别可以在当前尺度下忽略？  
> 一条已有关系能否迁移到不同接口？

这个队列不能因为“没有立即降低当前MSE”就永远得不到执行机会。

但也不能无限占用资源。应由用户的研究使命明确授权一个理论学习阶段或预算，而不是 Agent 偷偷更改任务。

### 问题可以来自三个生成器

**确定性生成器**从真实依赖、过期结果、表示碰撞和参数区域中产生问题。

**结构生成器**从共享程序片段、角色对应和关系冲突中产生问题。

**LLM提出者**创造新的解释、映射、读出与问题。

三者共用后面的编译、检验和用途评价，不能只有第三条路径。

这样，“宏观问题”不再只是要求 Luna 多想一点，而是有了明确来源：

\[
\text{两个已学结构}
\rightarrow
\text{一个待验证对应}
\rightarrow
\text{共同后果}
\rightarrow
\text{新问题上的应用检验}.
\]

# 八、什么时候复用，什么时候开子研究，什么时候新建假设？

这是下一轮最应该实现的决策表。

| 当前状态 | 应采取的动作 |
|---|---|
| 旧实例、绑定和适用范围仍受支持 | 复用当前实例 |
| 同一结构，仅参数需要重新识别 | 旧族的新实例，不新增理论 |
| 结构可对应，但角色、单位或仪器未知 | 重绑定研究 |
| 多个解释都兼容数据，却给出不同任务答案 | 区分实验 |
| 当前表示存在可靠的任务相关冲突 | 表示／观测／随机性竞争研究 |
| 一个明确有限族与证据不相容 | 允许提出结构修订 |
| 当前任务已经能完成，理论仍有歧义 | 完成任务，保留理论问题 |
| 匹配或搜索尚未完成 | 未决，不声称旧语言无解 |

这里需要三项保护。

### 1. 不要将“没有找到”写成“不存在”

有限映射搜索失败、求解超时、候选池过小，都不能证明整个模型族或旧语言不够。

### 2. 不要将“当前相同”写成“永久同一”

对固定实验族：

\[
S_Q(h)=\big(f_h(e)\big)_{e\in Q},
\]

可以比较或共享当前预测缓存，但理论来源、机制和作用域仍独立保留。

例如 \(x\) 与 \(x^2\) 在 \(\{0,1\}\) 上相同，增加 \(1/2\) 就不同。也不能通过“距离小于阈值”的链式合并得到真正等价类。

### 3. 相似性与适用性分别返回

建议匹配器返回：

```text
精确计算相同
同模型族
需要重绑定
只在当前实验上行为相近
当前范围可用
仍有多个相容映射
未知
```

不要只输出一个“相似度0.87”。

结构映射理论可以帮助构造对应；但新环境是否满足映射和前提，仍需实证。[数字对象标识符](https://doi.org/10.1207/s15516709cog0702_3)

# 九、子研究的触发标准：它的答案到底会改变父问题什么？

我建议把这个要求变成可执行合同：

> **子研究必须有父用途，但不必有即时分数收益。**

假设父输出是 \(F(z)\)，子问题可能返回 \(z_1,z_2\)。如果两者仍与证据兼容，并且：

\[
d_{Q_\tau}(F(z_1),F(z_2))>\epsilon_\tau,
\]

或者导致不同的行动，就有理由研究这个区别。

例如，子研究可以返回：

- 参数区域；
- 坐标或仪器绑定；
- 可调用子模型；
- 作用域；
- 新表示；
- 区分实验；
- 条件性未决结果。

随后必须执行：

```text
核对答案类型与当前上下文
→ 安装实际绑定
→ 使相关旧拟合失效
→ 调用现有refit或重建待执行实验
→ 评价父结果
```

当前已有的 `bind_research`、组件、revision和refit应该直接复用。不要再造一个“子答案消息”工具，然后期待作者自己想起后续动作。当前指南已经明确这些连接存在；缺的是将它们稳定纳入研究决策。

### 但不是所有子问题都必须解决

如果能够在声明范围内证明，所有允许子答案都不改变当前任务结论，就可以保持该不确定性。

这正是你要的“尺度和问题相关的近似”：**不是所有微观区别都值得研究，但不能未经检验就把它们删掉。**

围绕所求答案而非全部模型细节选择信息，可以借鉴 BAX；它需要相应概率模型，当前有限候选没有可信后验时，应使用明确标注的有限池启发式。[Proceedings of Machine Learning Research](https://proceedings.mlr.press/v139/neiswanger21a.html)

# 十、怎样让“失败”真的约束后续研究，而不只是再换一个候选？

这部分有很强的已有先例。学习失败约束的 ILP 系统，不是只丢掉当前失败程序，而是从失败中获得对下一批程序的约束。[Springer](https://link.springer.com/article/10.1007/s10994-020-05934-z)

对你的系统，应当严格限定约束范围：

| 失败 | 可以约束什么 | 不能推断什么 |
|---|---|---|
| 类型或公开接口不合法 | 同一类型系统中的非法程序 | 其他合法模型都不行 |
| 没使用已测参数域 | 该“候选已经测试”的声称不成立 | 该结构被反驳 |
| 可靠确定性表示碰撞 | 所有只依赖该表示的确定性预测器 | 更丰富表示或随机模型都不行 |
| 单个实例前瞻失败 | 该实例在该处失去支持 | 同族所有参数都被否定 |
| 有限精确约束不可满足 | 证明覆盖的前提与结构组合 | 任意更广语言都不能解释 |

**这条约束必须进入候选生成或调度，不是只附加到下一轮提示末尾。**

而且，新候选如果明确改变了被反驳的前提，应允许重新测试；不能把旧反例错误地变成永久禁止研究该方向。

# 十一、如何把“哲学谱”从一个图，变成真正的学习过程？

建议把跨任务整合明确写成第二个算法：

\[
\boxed{
\text{材料}
\rightarrow
\text{研究事件}
\rightarrow
\text{共享结构提案}
\rightarrow
\text{来源重构与反例检查}
\rightarrow
\text{新问题上的检验}
\rightarrow
\text{进入未来生成和研究}.
}
\]

## 11.1 材料先区分证据身份

原始实验、作者解释、外部论文主张、假想例子、错误统计和失败结论不能混在一起。

尤其你当前已经反复出现“错误解释进入笔记，笔记再影响后续判断”的现象。如果不先区分这些身份，再向上总结为哲学原则，会放大错误。

“所有资料都学”应当意味着**所有新材料经过处理并可追溯**，不是所有材料都被接受为事实，也不是每次全部重读。

## 11.2 从实际程序与约束归纳，而不只总结文本

两个程序：

\[
p_1(x),\quad p_2(u)
\]

可能被抽象成：

\[
F_\alpha(v;\theta).
\]

可以先用带类型反统一寻找公共骨架，再记录不同参数和变量映射。Stitch、LILO提供了程序库学习的可用方法。[arXiv](https://arxiv.org/html/2310.19791)

但这只说明计算可共享。

要成为世界规律，还需检验：

- 两个来源的角色是否真的对应；
- 新结构能否解释已有反例；
- 是否预测了未参与归纳的条件；
- 适用选择器是否只是任务 ID 查表；
- 使用它是否改善下一次研究。

## 11.3 新原则要改变未来行为

比如从零填充及其他独立失败中，系统提出：

> 只有当被忽略的区别不会改变任务后果时，才可以把两个输入状态合并。

如果它只写进 Markdown，还不够。

它应被编译成：

```text
何种研究状态下召回
检查哪些实际表示
生成什么竞争解释
建议什么区分实验
什么证据使它不适用
后继如何评价使用与不使用它
```

这才是一个可用的元先验。

同时要保留边界：随机输出差异不必全部通过增加隐状态解释；有些任务也不需要这些区别。

**新的原则能够被撤销或限定，不是哲学谱的缺陷，而是其核心能力。**

# 十二、勒夏特列与楞次：如何变成一个真正可执行的“元问题”？

我建议分成三问，而不是直接回答“相似”。

### 第一问：保持的究竟是哪一种关系？

是响应方向？偏离量缩小？能量约束？还是动力学稳定？

这几种关系不同，不能因为都可用“反抗变化”描述就合并。

### 第二问：哪些映射与前提使比较有意义？

明确系统、扰动、响应、受控量、单位和时间尺度。

例如只能确认一个局部的响应方向对应，就不能自动提升成“二者都是全局收缩系统”。

你的原始 v0.2 已经明确纠正了这一点：这两个定律不无条件共同保证净扰动幅度缩小，适合作为远域类比诊断，而不是第一阶段唯一验收答案。广义对位关系(1)

### 第三问：这个对应对眼前新问题产生了什么预测？

比如，它建议在新系统中检查某个响应方向、恢复过程或约束是否保持，并指出哪项实验能否定这种迁移。

如果没有新的可检验后果，它仍然可以是启发性类比，但不能自动进入“当前可用理论”。

**这不会把宏观问题降格成局部调参。恰恰相反，它让宏观问题获得了实际内容。**

# 十三、现在交给 Codex，应该怎样施工？

我建议按三个主要提交推进，而不是同时建设一个“大哲学操作系统”。

| 顺序 | 必须实现的行为 | 主要接入位置 |
|---|---|---|
| **PR1：问题语义与父用途** | 同问题可换算法；所求改变不能覆盖旧问题；子答案真实改变父输入或实验 | `online_inquiry_llm.py`、`common_archive_inquiry.py`、现有绑定与revision |
| **PR2：判同、复用与研究路由** | 区分同族、映射、行为相近、当前适用；依据实际未解区别生成问题 | `structural_inquiry.py`、`world_relation_research.py`、表示诊断与历史索引 |
| **PR3：一个主题的理论归纳** | 从真实多次研究形成共享对象，保留反例，冻结后迁移并实际使用 | 现有方法库与Program上增加薄的整合层 |

当前内层没有 live provider，所以这三项中**可以计算的部分必须在零新增LLM实践中直接运行**；需要新候选或新解释时，显式返回外层作者工作。不能把不会触发的 live 子会话算成内层能力。

完整规格给出了问题表达式、匹配规则、父返回伪代码、无后验时的有限池选择器、带类型反统一，以及28项行为测试。

### 第一轮最重要的验收不是“所有字段都有了”

而是跑出：

\[
\text{旧证据被正确识别}
\rightarrow
\text{形成具体问题}
\rightarrow
\text{复用或取得子答案}
\rightarrow
\text{父计算实际改变}.
\]

先用历史记录重放这个链，不新增付费研究。

### 随后怎样证明值得额外复杂度？

至少比较：

1. 相同历史、工具、回滚与修复能力的强通用可执行档案；
2. 加入明确问题与理论匹配，但不学习新理论；
3. 再加入跨任务理论归纳。

三者共享模型、权限、预算和外部评价。不要让完整组独占正确候选，也不要通过限制普通 Code 的实验权限制造优势。

主要评价仍是：**新条件预测、错误迁移、任务完成、覆盖和完整研究成本。**问题数量、理论节点数量和叙述深度不作主成果。
