## 2. 最影响科学结论的问题：所谓强普通基线过度压缩可用历史

`OpenWorkspaceStrongOrdinary` 已实际消费 `raw_archive`，这一点比旧版前进。其限制在于 `open_workspace_wormhole.py:868–905`：

- 仅以 active arity 分组；
- 每个 arity 只保存一个 schema；
- schema 至少被两个不同 source surface_domain 支持才允许作为先验；
- `shared/` Python 文件被复制到目标工作区，但目标求解循环并不导入或执行这些文件。

因此两个不同的 2D 机制（松弛、Liebig 瓶颈）被迫共享一个赢家；3D memory 只来自一个近失例，于是缓存里始终是 `None`。相同历史内已经学会的 capped/memory 机制未被充分消费。`OpenWorkspaceHExASkills` 也把近失例写入 `mistake_bank` 后不在 `solve_target()` 使用（同文件 919–967）。这些是当前基线调用路径的问题，不能解释为图结构必需。

历史上更完整的能力已经存在：`src/hegel_machine/cognition/code_session.py:24–57,128–158` 的 `CodeResearchSession` 保存作者代码、lessons、付费 frontier，驱动真正 `CodeAgent` 行动。M2 复用的是 `code_agent.evaluate_python_model`，未把当前对照接到该 session。后续应接现有接口或如实把当前对照称作固定 schema 缓存基线。

### 最小干预结果

诊断控制 `Ordinary_all_validated_priors` 不增加任何目标 oracle 信息、不增求解器、继续使用相同源记录、实验点、候选合成器、确认器与外评器。只把“每个 arity 一个且需两域支持的 schema”改成“全部已验证同 arity 历史 schema，包括一域近失例”；目标再次付费确认后才能使用。每个额外先验候选另保守加收 `10 compute`，最终只重拟合已胜出的 schema。

四簇各 10 题，普通控制 **40/40 通过**。正差表示 Hegel 更贵：

| Hegel − 普通控制 | eval01 | eval02 | eval03 | eval04 | 均值/十题簇 |
|---|---:|---:|---:|---:|---:|
| 测量费 | +15 | +15 | +30 | +15 | **+18.75** |
| 目标复合成本 | +7.775 | +7.775 | +22.9 | +7.775 | **+11.55625** |
| 源期＋目标复合成本 | +21.375 | +21.375 | +36.5 | +21.375 | **+25.15625** |

原对照下 Hegel 目标优势 `-41.025` 与端到端优势 `-27.425`，在这个小修正下改变方向。**这不是新冻结实验，不证明普通方法普遍更优；它足以说明当前结果不能证明对强普通同历史方法的净优势。**

建议先修改历史消费与适用条件选择，再冻结公平对照；不要删除已经有效的 Hegel 知识、近失例分裂和付费确认机制。

## 3. NoHorizontal 消融主要测的是跨域历史使用资格

`wormhole_forest.py:800–808` 在关闭横边时仍允许 local node 匹配，但 `_filter_cross_domain()` (`open_workspace_wormhole.py:1412–1417`) 随后删除非目标领域的所有 local node。目标均为新命名领域，因而该臂失去大量本可尝试的历史模型。

诊断控制 `NoWh_allow_local_content` 仍关闭全部横边，保留同一森林节点、模型内容、Stage1 gate、目标确认，仅让已有 local node 作为跨领域候选进入原检索结果：

| 比较 | 原 NoHorizontal | 保留同内容 local 候选 |
|---|---:|---:|
| Hegel−对照目标成本，均值/簇 | -100.61875 | **-1.96875** |
| Hegel−对照测量费，均值/簇 | -96.25 | **-1.25** |
| 对照通过率 | 40/40 | 40/40 |

约 98% 的原成本优势消失。剩余差额仍可研究，但不能把 `-100.62` 解释成图拓扑、路径导航或横边表示的独立增益。

此控制也不是最终公平性合同：从边上移除的适用排除条件应在正式消融时保存在等内容记录中；这里的作用是辨别“关图”与“禁历史使用”两个不同操作。

## 4. Flat 对比的真实差额与两跳归因

原报告总差额 Hegel−Flat 为 `-1.74375/簇`，但按目标分解：

| 来源 | 均值贡献 |
|---|---:|
| 真正命名为两跳的 C4 | **-0.475** |
| A3 双模蠕变 | **-1.44375** |
| 其余目标合计 | **+0.175** |
| 总计 | **-1.74375** |

C4 两臂测量费都为 `35`；差额是 Hegel `53.5 compute`，Flat `63 compute`。Hegel 避免一次 restricted schema 合成 `10 compute`，同时检索多收 `0.5 compute`，净差 `-9.5 * 0.05 = -0.475`。A3 的差额只集中在 eval03（`-5.85`；其余三簇各 `+0.025`），与该簇楞次源失败后两种候选选择路径有关。

所以 **`-1.7437` 不是两跳组合独立产生的全部收益**。Flat 初始化时复制 gate 但原 `solve_target()` 不调用 (`1681`, `1704–1783`)；本审计把同一个 Stage1 gate 接回后，四簇数值完全不变。该设计差异应修，但不能错误归咎为本次差额来源。

两跳证据本身还有更深的限制：第二 relay 节点直接注册为 `SUPPORTED_IN_SCOPE`，边误差 `0.015`、`0.018` 均写死 (`1142`, `1156–1193`)，C4 公共 task attrs 带 `two_hop_bridge_only=True` (`open_workspace_labs.py:724–740`)，研究器据此选择累计误差门 (`1536–1555`)。这里验证的是预置组合检查规则确实执行，尚未验证从历史数据学得两个映射、估计误差后自主发现路径的好处。

## 5. 成本结论需要明确生命周期与权重

### 给定 gate 的原结果是正确的限定口径

原稿均值 `-27.425/簇` 的确包含各臂源期与目标期，并明确称“给定门控”。另行记录的 DEV 源期＋两分支校准为 `1884.35`。若只向 Hegel 计入这笔一次性开发成本，并平均摊给这四簇，差额为：

`-27.425 + 1884.35 / 4 = +443.6625/簇`。

这是另一种成本口径；不能称原稿隐瞒造假，也不能让原“给定 gate”结论自动变成全生命周期净收益。固定当前各批独立重建源知识、每批十题且平均收益不变的假设下，需要约 `68.709` 批，即 `69` 批方可摊销该开发费。若部署复用同一个源知识库而不重复付源期，则须另立对应摊销模型。

双源与单源同样如此：双源额外源成本 `390−250.825=139.175`，目标平均节省 `64.19375`，故这十题批次端到端为 **`+74.98125`**。不能只用目标差额证明双源形成已经经济划算。

### 代理 compute 不是实测运行时间

`run_workspace_python_synthesizer()` 的 `compute_charge` 固定为 restricted `10`、open `24`，并把每次合成的 `python_execution_seconds` **硬记 `0.02` 秒** (`495–496`)。验证函数使用真实 `external_python_wall_seconds` (`535–538`)。因此总 `python_execution_seconds` 混合了实际验证时间与合成的固定占位值，不能被称作完整实测计算时间。代理计价本身可保留，但应命名清楚，并独立保存真实耗时与计价敏感性。

### 对普通控制的权重敏感性

令 `C=M+λK`，K 为当前代理 compute 单位。对 `Ordinary_all_validated_priors`：

- 目标期：`ΔM=+18.75`，`ΔK=−143.875`，故 `ΔC(λ)=18.75−143.875λ`，交点 **`λ=0.1303214596`**。当前 `λ=0.05` 时 Hegel 更贵 `11.55625`。
- 源期＋目标：`ΔM=+28.75`，`ΔK=−71.875`，故 `ΔC(λ)=28.75−71.875λ`，交点 **`λ=0.4`**。当前 `λ=0.05` 时 Hegel 更贵 `25.15625`。

因此恰当结论是：此小型候选库里，普通控制多花代理计算、少花测量；在原权重下更省。较大候选库的检索/定位优势仍有研究空间，须用公平同内容消费验证。

## 6. 其余可定位问题

### 6.1 DEV fork 没有独立复制随机状态

`open_workspace_wormhole.py:1442–1443` 对 lab 执行 `deepcopy`，而噪声 RNG 在 `noisy_oracle` 函数闭包里 (`open_workspace_labs.py:290–295`)。函数不被 deepcopy，故两个分支的 `_oracle` 是同一对象，共享 RNG。最小检查中，相同 post-pilot 状态、相同下一查询得到 `-7.6594249001` 和 `-7.6598985959`。

这不证明原结果改变方向，也不意味着偷读答案；它说明“严格同随机状态分叉”合同未满足，分支执行顺序影响后续噪声实现。应显式保存/恢复环境 RNG 状态，或使用按查询与replicate key固定的噪声，并核验两分支独立推进。

### 6.2 capped signature 校准键与使用键不一致

`run_paired_post_pilot_rollout()` 在高角诊断前记录 pilot `sigs[-1]` (`1438–1439`)；目标路径高角诊断后追加 `sig:m2_2d_capped_ceiling` 再调用 gate (`1484–1529`)。原四簇 B2 实际全部以 `exploration_arm_no_prior_guarantee` 准入，未命中该专门 signature 的 DEV 校准。保留探索合理，但应按实际最终决策状态校准、明确标记未覆盖状态，不能将全部收益归于已校准门控。

### 6.3 统计外推范围

四簇使用相同十种题目结构，主要变化是参数和观测噪声；许多评估点固定为 5–6 点。统计单位正确应是 `N=4` 簇，不是 240 个独立机制。若仅根据4/4负差做符号检验，单侧概率为 `1/16=0.0625`，双侧为 `0.125`。报告没有正式显著性检验可以保留描述性结论，但“40/40”只说明这些样本上外评器通过，不能外推开放任务空间的零假确认。

## 7. 最小修复次序

1. 保留有效原回执、现有多域知识与确认器，先修普通同历史候选消费，以及 HExA mistake_bank 的实际调用；正式对照重用既有 CodeResearchSession/知识接口，或准确降级基线命名。
2. 正式消融保持同内容、同适用条件、同校准 gate、同确认预算；图开关只影响检索和组合方式。报告分别给“历史可用性”与“图表示”增益。
3. 两跳场景要让每条映射来自真实源期记录，误差来自相应数据/合同，去掉提示路径数的目标专用字段；分离 C4 自身结果，不把 A3 计入两跳收益。
4. 把实际耗时与代理计价分开；提供给定 gate 与明确摊销期的成本，并保留 λ 敏感性。
5. 修确定性 tie-break、RNG fork、最终 signature 校准键；只重跑这些连接对应的受控合同，再冻结一次新的完整M2对照。无需推倒现有能力，也无需把M0所有历史审计事项都作为本次前置阻断。
