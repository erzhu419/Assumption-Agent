## 1. 更新后的结论

**原始 JSON 的 `recall=0.0` 可以独立重计，确实是三对预期策略关系全部未被最终规则接受。** 但它不是“所有关系都检测不出来”：27 个策略形成的 351 对中，最终有 94 对被脚本计入同构类关系。其余是否误判没有完整人工标注，不能把不属于三对预期的结果全部当作假阳性。

## 5. “拓扑、谱、不变量门控”实际分别是什么

### 5.1 谱距离属于 Markov 核，不是策略图的拓扑谱

`metric_suite.py` 第 33–38 行对非方阵 kernel 做 SVD，取排序奇异值向量的 L2 距离。函数 docstring 称 Hausdorff，实际返回的是 `norm(sa-sb)`；不是 SEG 邻接谱，也不是带物理意义的不变量残差。

它只在紧 Fisher 条件下影响是否称为 `iso`；`weak_iso` 和 `subsume` 不要求 spectral 通过。三个预期配对均通过 spectral，所以这次漏检不能归为谱阈值过严。Frobenius 仅被记录，未参与分类。

### 5.2 SEG 有步骤顺序，但仍不是可执行因果/提问契约

`seg.py` 第 43–71 行按 `operational_steps` 建节点、按文本步骤顺序加边；`on_difficulty` 只提取首个 S 编号，作为指向共享外部节点 `-1` 的递归边类型。节点类别来自 `classify_step_text` 关键词规则。原描述截断存储，但 GED 只比较动作类别和边类型。

与之相对，kernel 的动作分布经 `LLMActionClassifier` 或其缓存构成。这意味着“v2 用了 LLM classifier”不等于 SEG 节点也已由同一 LLM 表征；两条通道的解析方法不同。

GED 第 91–110 行设置节点替换 0/1、边替换 0/0.3、3 秒 timeout，并除以两图最大步骤节点数。它不是自然限制在 [0,1] 的分数：保存值范围为 0.5 到 2.429。异常或返回 None 会被统一写成 1.0；JSON 没有 solver 状态，无法区分这类失败与正常得到的距离 1.0，也没有每项编辑操作的 witness。

因此可以说此表示没有显式保存实验的候选结果分区、单位、干预前提、因果符号等语义。不能仅凭 SEG 大于 0.8 认定两个策略没有可迁移的局部结构，更不能称其比较了化学或电磁方程 AST。

### 5.3 Blackwell 并非最终接受的硬门控

脚本只对 Fisher 最小的 30 对运行 Blackwell，JSON 恰好这 30 对为 `neither`，其余 321 对 `not_checked`。最终被接受的 94 对里，9 对为 neither、85 对根本没检查。

这与脚本第 80 行注释“kernel iso AND SEG<0.6 AND Blackwell equivalent”不一致。实际第 88–96 行是有顺序的条件改标签：只有 iso 被 SEG>0.8 降级，weak_iso 没有这一过滤；Blackwell `both_dominate` 可以升级某些标签，但 neither 并不统一拒绝。84 对 weak_iso 中，**80 对 SEG>0.8 仍被接受**。

这还造成分类不单调：S06–S09 在强 kernel 档被 SEG 排除；若仅在逻辑演示中将其 Fisher 改为 0.6，其他值不变，它会落入 weak_iso 并通过最终标签列表。这里 0.6 是说明代码分支的假设输入，不是重测值、推荐阈值或新结果。应先明确最终判定的科学目标，不能用后验调阈值让三对刚好通过来证明方法有效。

`blackwell.py` 实际检查能否用行随机矩阵 M 使 `K_b≈M K_a`，即把目标状态的动作分布放进源状态行分布的凸包；回执只保留最终关系字符串。输入状态行混合与对输出/动作通道后处理不是同一操作，不能仅凭函数名将结果升级成一般信息偏序或程序语义等价证书。其求解失败、异常和残差超容差都可汇入 `neither`；报告没有双向残差与 solver status，无法进一步归因。

### 5.4 没有独立的定律不变量 gate

这份报告的字段是矩阵距离、KL、SEG、Blackwell 和分类标签，没有法则对应、单位/符号残差、hard-negative transformation 或行为等价试验。可讨论表示为何可能遗漏这些信息，但不能说“实验已证明不变量检查失败”。这类量在这次管线中并未被直接测量。

## 6. 对“静态频率矩阵导致失败”的准确评价

该判断含有一个有源码支持的担忧，也包含一个未被隔离验证的因果结论。

有依据的部分：`kernel_builder.py` 第 140–160 行先将所有步骤汇总为同一个 `step_dist`，再根据状态适用度与 uniform 混合。对每个策略，所有状态行都是这两个固定向量的线性组合，故其矩阵秩至多为 2；它没有直接表示问题结果分支和完整动作时序。这是实现的代数性质，不需要把任意语义频率法一概判死刑。

尚未证明的部分：最终系统另有 SEG；唯一的预期 kernel 命中恰恰在 SEG 阶段丢失。报告没有使用相同解析输入、独立关系标签和冻结阈值的表示消融，也没有下游功能比较。因此不能证明只修复动态因果信息就一定恢复三对，或所有静态频率距离都无用。

三对 expected 来源于 `_config.py` 第 65–68 行，注释全部标为 **partial**。它们是设计者希望发现的部分关联，不是附带严格对象映射、状态/动作语义和双向功能证明的 gold 同构。控制变量与增量构建可以有局部共同操作，并不因此必须拥有同一个完整策略核或同形步骤图。先定义期望检测的是局部类比、策略精化、信息等价还是程序同构，才能判断这些 miss 是表示、阈值、标注还是评价契约不一致。

## 7. 缓存重建边界：不能声称原始核完全重现

本轮取到了固定 HEAD 的 27 个策略 JSON、分类缓存和必要源码。静态检查发现分类器需要 270 个调用键，缓存覆盖 269 个，S01–S26 完整，S27 缺一个键。缓存共有 269 个条目。

缺失项属于 S27“激励结构分析”的首个步骤：识别关键参与者；其 fallback 文本是“如果参与者识别不全，递归调用 S03（利益相关者分析）”。精确键保存在 `recomputed_formalization.json` 的 `static_cache_coverage.strategies`。

一次 cache-only 重建在此停止，**模型调用为 0、分类 fallback 为 0**。原分类器在调用出错时可以走关键词 fallback 且不保存新 cache，但当前资料不能确定当时究竟是 fallback、缓存遗失还是输入版本变化。本次没有选择其中一种来补值，也未继续计算完整核的 351 对距离。

所以本轮可以确认：27 个 ID 与 351 个配对完整；报告指标与判定规则在保存精度下内部一致。不能确认：原始 27 个核、全部全精度指标、GED/LP 运行以及提供 JSON 的原始 Git 来源完全一致。报告由用户补传，37 份源码属于固定提交，这两种来源在清单中分开记录。

## 9. 对下一轮施工的最小影响

不建议为复活这个历史分数扩建 Phase 3。只保留四项会影响当前设计的教训：

1. 先定义被检验的关系层级，并为预期正例保存角色/操作对应依据；不把一般有关联当成全程序同构。
2. 组合规则应与文字合同一致，weak/strong 标签的后续处理不能产生更不相似反而通过的无解释现象。修改后用独立对象验证，不能把三对旧例调通视为泛化成果。
3. 对抽取/分类、结构距离、求解未知和真实反证分别留状态；没有结果的计算不应伪装为理论不相容。保存完整精度、输入/cache/fallback 身份和 solver 状态即可，不另起审计平台。
4. 回到当前诊断程序切片，以实际新目标的可执行区分和研究成本作终点。图相近、kernel 相近或成功召回，都是候选证据，不能替代真实消费与强普通对照。
