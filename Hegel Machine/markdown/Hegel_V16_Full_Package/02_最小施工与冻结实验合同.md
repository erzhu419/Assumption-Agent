# Hegel V16 最小施工与冻结实验合同

日期：2026-11-19（Asia/Shanghai）  
适用冻结点：`787256bd415515905359626f6a5498174ad5db3c`及在其上实施的下一轮修改。  
本文件是建议合同，未声称这些修改已经实施或通过。它将主报告的判断转成工程对象、评价权限和停止条件。

## 1. 唯一主问题与三层完成标准

**主问题：从普通研究经历形成的可执行诊断知识，在强普通方法能够读取原始经历、重建同一知识并选择直接解题时，能否改善未见但机制相关的问题？**

分开记录三层结果：

| 层级 | 要证明的事 | 不能拿来替代它的证据 |
|---|---|---|
| A：机制链 | 经历导致新问题/模型，真实冲突与范围检验改变版本，后续研究实际消费 | 对象数量、字段齐全、手写演示树、检索命中 |
| B：实例收益 | 预登记的未见实例在同质量要求下，减少实际研究工作或得到此前没得到的正确结果 | 事后挑出的两个赢家、少枚举若干便宜候选、只省tokens但丢质量 |
| C：分布净收益 | 冻结任务分布与策略、按源簇计算不确定性，完整成本和质量满足预设要求 | 训练收益代替目标收益、把同轨迹重复表当独立样本 |

A通过而B/C未通过，应如实称“形成和消费机制已完成，效用待证”。无需每题获胜；负迁移和失败必须留在预先定义的分母。

“强普通”指预先确定、认真开发的算法集合，不是所有可能算法的数学下界。允许完全复制Hegel就不会存在不可重建性。研究应争取可复现的组织和选择优势。

## 2. 开工顺序：P0和一个切片并行

### 2.1 P0：会改变结论的现有边界

优先沿用现有修复对象、测试和账本；不再建设一个独立“总审计平台”。

| 问题 | 最小修改 | 验收证据 |
|---|---|---|
| 版本身份 | 程序、范围、前提、依赖与影响选择的成本/预算模型在使用前冻结；实际费用单独追加回执 | 修改语义产生后继版本；回执永久引用执行时版本，不因事后计费重写身份 |
| 协议身份 | exact archive与控制回放严格绑定请求输入、重置/前史、范围、观测协议和预算约定 | 不同输入或重置条件不可复用同一“精确”回执；相同协议可追溯 |
| 支持有效性 | 依赖显式区分AND必要前提、OR独立支持和仅供搜索的关联 | 撤回必要前提失效下游；撤回一个独立支持不误删仍成立的另一条支持 |
| 移除干预 | 清除目标版本及只由它派生的副本、别名、索引载体；保留原始经历与真正独立推导 | 干预前后知识可达性差异可审计；不偷删普通组可用原始证据 |
| 重建权限 | 重建可选、有界，普通方法能跳过、直接求解或从原始历史重建 | 不出现先强制花尽预算、再拿失败证明对象必要的实验 |
| 失败缓存 | 键含对象版本、绑定、协议、前提范围和证据版本；区分运行失败与经验反证 | 新版本/新范围不会继承不相关的永久否决；确实相同失败不重复付费 |
| 成本与新证据 | 互斥计费；独立新行与训练尾部/回放数据明确区分 | 原始动作合计等于总账；所谓fresh validation有真实新证据身份 |
| 运行回执 | 区分提出、检索、绑定、执行、采用、确认 | 能定位实际改变父研究的消费者，不能仅靠对象存在性验收 |

这些是行为要求，不是建议额外增加八个研究阶段。工程验证应针对现存反例和关键边界，避免大量只镜像实现的测试。正式效用运行在P0闭合后进行；切片研发可同步开展。

### 2.2 并行切片：从现有历史依赖实验室开始

选已有有/无历史依赖机制，先不同时新建化学、电磁、流体和图数据库。让普通研究自然经历：

1. 当前值模型解释初始数据；
2. 在记录了控制条件与协议的后续试验中，终点控制相同而前史不同，输出出现超出噪声解释的差异；
3. 系统保留竞争解释：隐藏状态、未控制变量、重置失败、噪声或测量过程差异；
4. 系统提出可以区分其中若干解释的合法实验；
5. 结果改变模型范围或分支，产生参数化诊断程序；
6. 冻结该程序，再进入未见目标；
7. 在目标重新绑定并获得新证据，实际取消、替换或提前结束后续工作。

不要预写正确的整棵问题树、正确目标方程或必选的历史对照。可以给所有组同样的研究原语、候选语言和工具API；形成过程必须留下它为何选择该实验的证据。允许基础模型提出候选，不把LLM先验假装清零。

第一条最小链包含一个兼容目标和一个容易误用的负例。负例可以暴露绑定错误、不可重置条件、前提不足或真正的反例。前者验证真实使用，后者验证有界调查、修订与回退。两例只做机制资格检查，不作为分布获胜结论。

## 3. 复用现有对象，补上缺失语义

复用 `QuestionSpec`、`question_semantics`、`question_continuation`、`ResearchMethodBook`、`growth_methods`、`WorkflowEpisode`和现有scope/确认/证据接口。现有工作流DAG并不自动表达结果分区，补适配层而非建立平行状态机。

### 3.1 六类对象的职责

| 对象 | 最小职责 | 关键边界 |
|---|---|---|
| Experience | 动作、协议、前史、观测、失败类型、真实成本和证据来源 | 原始观测与推断字段分离 |
| ModelHypothesis | 类型化预测、范围、参数、版本、支持与反证 | “未否证”不等于已确认 |
| DiagnosticQuestion | 干预方案、观测解释、候选结果分区、决策用途 | 好问句必须能编译为合法操作 |
| ResearchProgram | 问题/动作策略图、条件分支、有界循环、停止与回退 | 策略可有循环；事件与证据按时间/版本展开，执行成功不等于模型正确 |
| TransferProposal | 局部角色映射、待检前提、目标预测、反例和预算 | 候选映射不直接获得使用资格 |
| RevisionDecision | 修订/分支/融合/撤回/保留的理由与受影响消费者 | 保留历史身份，不抹掉错误记录 |

类名可复用现有命名，不要求新增六套框架。每一字段必须被一个真实消费者读取，否则暂缓加入。

### 3.2 问题契约

每个诊断问题至少记录：

```yaml
question_version: <immutable identity after all semantic fields are fixed>
candidate_versions: [<models or model families>]
preconditions: <executable or explicitly unknown conditions>
intervention: <legal actions, reset/history, control and observation protocol>
outcome_model: <predictions or likelihoods under each candidate>
decision_partition: <which outcomes change which next actions>
noise_and_tolerance: <units and calibrated limits>
estimated_cost: <calibrated estimate, distinct from actual ledger>
budget_cap: <including failure and fallback policy>
stop_rule: <decision-equivalent, evidence insufficient, or budget exhausted>
parent_use: <consumer action or research obligation changed>
evidence_refs: [<versioned source observations>]
```

少量数据不能可靠拟合概率时，可以先用保守区间或定性可执行预测。不能用伪精确概率掩盖未知。候选全同意也不保证真相：候选空间可能共同漏掉机制。保留来自候选集合外的检查或残差监测，停止理由明确写“候选内一致”或“预算不足”。

对于有噪声的连续检验，另记录检验在看哪些数据之前确定、数据重复使用范围、主/子假设关系、统计有效条件及停止规则。POPPER提供了这一局部合同的参照，但顺序e值要求条件有效性；反复用同一数据挑检验不会因转换分数自动合法。确定性反例不必转换成p值；没有统计前提时保持未确认，不借一个显著性标签声称安全。详见[顺序否证补充](learning/04_顺序否证补充.md)。

### 3.3 从经历形成程序：最小算法

1. 从真实父研究的动作与证据依赖中抽取有用片段，保留成功否证、条件失败及其后续变化。
2. 对至少一个支持经历与一个冲突/边界经历做对比，提出哪些角色可参数化、哪些操作前提不可删除。
3. 用现有类型系统把参数化片段编译成候选程序，明确可能结果及后继动作。
4. 在开发源经历中回放，核对来源、适用范围、动作合法性和模型误剪；不能把回放当独立新验证。
5. 生成最小的新验证义务并执行，符合条件后才准入库。
6. 给程序保留简短可读名称和适用说明，同时保存机器契约；说明文字不能替代执行验证。
7. 冻结入库版本与源成本，进入新目标。

可借LILO/Stitch的抽象与重写思路，但第一版只处理既有研究原语的片段。压缩长度是候选筛选量，不能直接充当未来收益。不要要求模型在这一轮发明一套全新DSL。

## 4. “相似”变成可检验的局部关系

用三个阶段区分职责：召回、绑定、使用选择。文本或图相似度只参与召回。

### 4.1 最小绑定条件

候选映射要保持本次诊断所需的：

- 对象/变量的操作角色、维度或明确单位变换；
- 行动的可实现性、干预与观察的区别；
- 顺序、持续时间、重置和历史条件；
- 预测的符号、单调/对称关系或可计算残差；
- 噪声界、容差和目标误判的后果。

不需要全图同构，也不因表面不相似就拒绝。对于源程序q及局部映射m，实际检验的是：目标操作m(q)的观测是否符合映射后的预测，并在规定误差内保留本次决策所需的候选区分。它不是所有未来环境上的万能函子证明。

### 4.2 真正的信息增益与工作节省

记录候选语义类或后继决策区域，避免等价AST重复计数。每个探针至少报告：

1. 删去或降权了哪些候选；
2. 是否误删评测器可知的真机制；
3. 改变了哪项后继研究；
4. 实际取消、替换或减少的动作与费用；
5. 探针、绑定与确认自身花费。

三次二元实验最多产生八种回答路径；均匀且均衡时剩余约1/8候选，不能普遍保证排除90%。连续读数可能区分更多候选，但必须考虑噪声和成本。若候选数量大幅减少而后继工作不变，不能声称研究效率改善。

## 5. 修订、分支、融合与撤回的决定表

先确定冲突是关于同一观测量、同一协议、相同前提交集中的不相容预测。文字相反、符号不同或使用场景不同都不自动构成经验冲突。

| 情况 | 系统动作 | 必须保存的理由 |
|---|---|---|
| 新场景超出旧范围 | 建立范围外调查或候选扩展，不先否定旧模型 | 哪条前提未满足/尚未知 |
| 两支适用域不相交 | 保留条件分支，不强迫融合 | 范围分离的证据与未知重叠 |
| 范围重叠、预测相容 | 提出合并或共享父程序，执行关键回归与边界检查 | 合并减少何种重复，哪些条件和拒绝保持 |
| 范围重叠、预测不相容 | 选择允许的区分实验；预算不足则并存且标冲突 | 可区分结果、实际证据、调查成本 |
| 一支在指定范围被反驳 | 撤回该范围的使用资格，传播必要依赖失效 | 被击中的前提、仍有效的其他范围与独立支持 |
| 两支均失败 | 重新提出模型/测量/协议问题，不硬选赢家 | 共同残差、候选空间不足的可能性 |
| 只有词句或标识重复 | 做身份/内容去重，不把去重称发现公共规律 | 等价核验与消费者迁移 |
| 旧拒绝被新证据推翻 | 版本化撤回旧拒绝，重验受影响对象 | 哪条旧证据/前提不再成立 |

区分两种合同：**保真重组**承诺保留已有有效内容、范围、拒绝与消费者；**经验修订**允许纠错，但必须撤回不成立内容并记录原因。AWM式拒绝保持可用于前者，不能成为后者永不纠错的限制。

父对象不能靠孩子多数票成立。必要依赖AND与独立支持OR分别传播；失败定位不充分时，只撤回已知受影响的使用资格，其他部分标未知，安排有界调查。历史版本保留为审计记录，不进入默认有效检索。

## 6. 使用选择：先解决带成本的研究决策

第一版选择集合控制在：直接研究、已有程序的有界绑定、少数诊断程序、从raw history有界重建、停止/回退。源库小的时候用现有检索即可。

### 6.1 可见状态

目标描述、已付观测、合法操作、候选版本、之前失败的绑定、剩余预算、可用原始经历。生成器真值、测试族标签、未来结果不进入状态。pilot若可省略，普通组和Hegel都应能省略。

### 6.2 估计与保守边界

先在开发源簇收集同决策前快照上的配对轨迹，使用简单分组成本表或小型可解释预测器。只对有覆盖的情境做经验选择。若有选择性记录而缺少备选动作结果，标为缺失，不能直接填入“此动作本会失败”。

若Q越大越好，`LCB(Q_option) − Q_direct点估计`不是优势下界。有适用联合覆盖保证时，可以用`LCB(Q_option) − UCB(Q_direct)`，或直接估计配对差的下界。选择后推断、多个候选比较和分布外状态还需单独控制；确定性实现不能自动消除这些问题。

第一轮不应给经验分数贴“安全LCB”标签。不同时学习PPR边权和准入Q，不直接引入完整离线RL。离线RL在有足够决策数据、替代动作覆盖和可评估长期价值时再讨论。

### 6.3 回退与摊销

回退保留已付检索、诊断和绑定费用。设置最大额外调查预算，并为合法直接研究及独立确认留出开发期校准的预算余量。“零税”只可能指未付任何额外工作时的直接路径。

源建库费在完整生命周期中算一次；目标单题表单列目标费用。报告不同目标个数下的累计成本和质量，不用人为假定无限复用把任何前期费用摊成零。普通方法自己的总结、建库与缓存维护也遵循相同口径。

## 7. 数据集：先同族，再跨表征，再物理展示

### 7.1 按机制与表面特征构造二维切片

|  | 表面相似 | 表面不同 |
|---|---|---|
| 机制/诊断兼容 | 基础复用正例 | 核心跨表征正例 |
| 机制/诊断不兼容 | 易误用的强负例 | 远域负例/直接求解情境 |

还要有前提暂时未知、需要少量调查才能决定的边界例。不能只有明显正负两类，否则系统可以靠拒绝所有不熟悉输入逃避范围检验。

任务生成器保存真值和干预语义用于评测，agent仅得到公开问题及API。类型、单位和操作合法性不能为匿名化而全部删去。变更变量名、参数或初值只证明相应层级的泛化，不能自动声称跨机制迁移。

### 7.2 源簇与数据冻结

一个源学习历史及其派生目标构成一个簇。同簇目标共享形成成本与知识，不能按完全独立样本计算区间。开发、校准、正式测试按源簇分离；记录生成器、种子、初始历史和任务哈希。

可先用6–8个开发簇检查可执行性和方差，这是建议的工程探查规模，绝非足够发表的功效保证。正式样本量依据最小实际改善、簇间方差和希望得到的区间精度预设；没有理由把24或36当万能阈值。

冻结测试保留完整预设的易中难、兼容与不兼容比例。不能试完后删掉普通方法占优的简单题，也不能把失败题改称不在目标分布中。预先报告的条件子组可以分析，但同时展示整体和失败分母。

### 7.3 两个以后才扩展的轨道

1. **跨表征**：角色排列、尺度与单位变换、不同观测通道、局部可控性变化。只一次增加可定位的主要变化，观察绑定和诊断为何仍成立或失效。
2. **物理展示**：勒夏特列—楞次或热/扩散关系。共享研究问法可以成立，完整定律是否可转移需要额外条件。化学平衡方向不直接决定反应速率；电动势与闭路电流必须区分。展示不承担当下最小主实验的全部验收。

## 8. 强普通与归因设计：必须同时区分系统与知识对象

### 8.1 主比较：完整学习系统

| 组 | 权限 | 主要目的 |
|---|---|---|
| H：当前Hegel加最小诊断适配 | 原始经历、版本化模型/问题、范围与冲突治理、可选重建/直解 | 测试所提系统 |
| O：强普通研究器 | 相同基础模型/原语、原始历史、检索总结、主动实验、构造同种程序、缓存、可选直解 | 排除“只是不给对方知识/搜索能力”的解释 |
| O-bank候选 | 用相同允许历史构造HExA式紧凑策略＋错误bank，允许修改合并与重新蒸馏 | 检验较轻量的经验组织是否已足够 |

O与O-bank可在开发期比较，按预设规则选择一个主强基线并冻结；其余作次要基线。不要到测试结束后挑最弱者比较。若原系统已有功能相当的bank，不另移植完整HExA环境。

完整学习系统可以各自生成自己的源轨迹，因为研究策略本来就会改变观察。对照的是同任务分布、研究权限和预算，不强行让各组重复完全同一动作。无需免费给O现成的Hegel成品对象；同时不能禁止O在其预算内重建它。

### 8.2 局部归因：固定历史和决策快照

另选少量预登记、未按收益挑选的快照，共享**完全相同原始经历、已付pilot、目标状态和剩余预算**：

- 允许调用新对象；
- 干净移除该对象，允许普通方法选择重建、检索、缓存或直接研究；
- 必要时同知识内容的平面bank，对照组织结构。

这样回答对象在给定历史上的边际作用。这个干预应清理独占派生载体，但保留独立取得的等价知识和原始证据；不要通过删除所有相似信息夸大必要性。完整系统收益与同历史对象效应分别报告，不能混成一个数字。

固定内容比较需要两组获得相同可用事实、例证、元数据和前提。图组若独享人工机制标签，测到的是额外知识而非图结构。索引构建和维护费用计入；只有候选规模/召回成为实测瓶颈时，才加入HippoRAG式图实验。

### 8.3 形成因果与来源检查

在小型机制案例中，移除或匹配替换关键源经历，保持其余预算和提示规则；观察新问题是否仍形成、内容怎样变化、目标操作怎样变化。这有助于判断知识是否确实由指定经历触发。

手写理想诊断程序可作为工程诊断对照，用来判断“若已经获得该对象，当前管线能否用好”。它不是自动学习成果，也不是所有可能抽象的理论性能上界。LLM可从先验独立提出同样内容时，结果本身应被保存，不能删掉以维护故事。

## 9. 指标、成本和统计

### 9.1 质量优先

预先选一个主端点：固定预算的严格成功率，或满足预设质量条件下的完整成本。单列错误确认、未解决、工具失败和有效拒绝；便宜失败不能在均值中抵消质量下降。

质量容忍界与最小实际改善应根据任务用途在看测试结果前确定。若最终质量不达要求，成本再低也不能称同质量加速。可以报告质量—预算曲线，避免一个人为预算点决定全部结论。

### 9.2 成本保持向量，不偷换单位

分别记录计算工作量、模拟/观测、测量数量、LLM输入输出token、墙钟时间和必要外部费用。当前本地有限语法任务没有LLM调用，就不能把计算计数当模型token节省。某个单位为主指标时解释原因，其余报告约束或次要指标。

完整账本分解为：

\[
C_{all}=C_{source}+C_{formation}+C_{index/maintenance}
+\sum_t(C_{retrieve}+C_{bind}+C_{probe}+C_{solve}+C_{verify}+C_{fallback})_t.
\]

实际实现中确保每个事件只属一项；一个源动作既产出答案又产出可复用经历，不应重复计费。共享投入可单列，但不能在不同组中采用不同扣除规则。

### 9.3 有用机制指标

- 形成：来源依赖是否成立、新增的是何种可执行区分，是否只换名；
- 适用：绑定正确率、范围误用、合理拒绝与未知调查；
- 消费：执行后的哪个动作或停止义务改变；
- 效率：从目标开始到首次**经验证且改变研究的操作**所需成本；
- 治理：分支修订/融合的可验证理由、旧有效内容是否保留、错误是否传播；
- 净益：配对实际成本差及质量差，完整序列的摊销前缀。

“为什么有用”的说明必须和执行回执对上。没有实际对照轨迹时，“原本会花多少”只能标预测，不能作为已观测反事实。

### 9.4 不确定性

按源簇聚合主要差异，采用适合配对簇设计的区间/置换或其他预登记方法；小簇数时明确区间不稳定。任务内重复种子用于估计随机性，不会把一个源历史变成多个独立源。多子组与多方案选择的探索性结果单列，避免事后选择造成虚假稳定。

目标评测期间是冻结bank还是允许持续更新，要提前选择。两者回答不同问题；持续更新实验必须遵守时间顺序，不能在已经消费目标反馈后仍把同一目标叫未见。

## 10. 只要求必要的回执，不继续堆“证明字段”

每条代表性案例应能按下列九步讲清：

1. 哪段真实经历；
2. 哪个残差或失败；
3. 哪个新模型/范围；
4. 哪个新诊断问题；
5. 哪次实际检验；
6. 为什么修订、分支或融合；
7. 在哪个未见目标怎样绑定；
8. 后继工作实际改变了什么；
9. 强普通允许重建后，结果与完整费用如何。

最小交付目录建议为：

```text
frozen_protocol.md
source_and_task_manifest.json
source_episodes.jsonl
knowledge_versions.jsonl
revision_decisions.jsonl
target_action_receipts.jsonl
cost_ledger.jsonl
paired_results.json
results_and_failure_analysis.md
recompute_results.py
```

这些文件可以是现有日志的索引或视图，不要求再复制一份庞大的事件系统。每个统计量由原始账本重算；正文声明、代码路径和回执保持同一冻结版本。

## 11. 停止条件与下一步选择

| 实验结果 | 下一步 | 暂不做 |
|---|---|---|
| 手写程序有用，自主形成失败 | 修轨迹对比、抽象参数化和结果分区 | 增加图数据库或更多物理领域 |
| 程序形成正确，召回不到 | 定位候选规模与排序；再做同内容Flat/Graph | 先假定PPR必然解决 |
| 召回正确，不能绑定 | 修角色/操作/协议/范围，保留未知 | 用相似度放宽到直接通过 |
| 使用正确，仍更慢 | 修选择、重复求解、重复确认和回退费用 | 仅提高题目难度迫使基线输 |
| O-bank追平 | 报告知识有用、复杂组织尚无增益；保留简方案 | 把普通组重建能力删掉 |
| 范围变化中H更稳健 | 增加预登记边界簇，定位治理的净价值 | 声称所有任务都更优 |
| 误删真机制/错误确认 | 修问题预测与开放候选检查，再用新测试 | 只展示正确赢家 |
| 正效果但簇太少 | 收集新的独立源簇 | 宣称细粒度Q已校准 |

本轮应暂缓：完整CQM-Hippo重写、通用范畴证明器、离线RL大模型、同时控制Q与PPR、任意学科统一树，以及没有真实消费需求的新schema。后续新增组件必须对应已经测出的瓶颈，并在公平对照里支付自身费用。
