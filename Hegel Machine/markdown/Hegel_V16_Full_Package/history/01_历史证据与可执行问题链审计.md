# V16 综合方案的历史证据与可执行问题链审计

固定对象：`erzhu419/Assumption-Agent`，`787256bd415515905359626f6a5498174ad5db3c`，复核日期2026-11-19（Asia/Shanghai，对应UTC 2026-11-18）。

本文件是总审计的历史证据子报告。它核对 Gemini 上传的 `hegel_v16_wormhole_synthesis_and_master_plan.md` 引用的旧结果，以及“结论 → 可执行问题 → 研究步骤复用”是否真的在历史中丢失。这里的旧 Phase 2 v16（2026-04-23）与这次 Hegel V16 方案不是同一个版本。

## 一、核心判定

Gemini 对“远距离机制迁移需要问题化、需要可反驳预测、不能仅靠最终公式的表面相似”这个方向有价值。但用于支持新架构的历史叙事，有四处必须修正。

1. **旧 v2 的 42% 是 100 题两两评审胜率；旧 v16 的 +72pp 是 86 胜对 14 负的胜负差。** 两者都不是客观正确率。前者不能单独证明短结论压缩无效，后者不能单独证明可执行问题树带来 72 个百分点提升。
2. **旧 v16 确有后续 50 题留出判决，44:6 与 41:9。** 不能把这段历史统称为没有正证据、没有留出。但当前缓存与当时报告已经不一致，执行输入和运行命令没有完整冻结；它不足以证明严格的未见迁移和同预算增益。
3. **“Phase three 的 recall=0 因为化学多项式 AST 与 RL 微分方程 AST 不同”不符合被引用的代码。** 实际评价对象是三对方法论策略的 Markov 核与步骤图。被引用原始 JSON 在本次全部 16 个 branch tip 的文件清单中未找到；0 这个数尚不能独立复算。即便历史值确为 0，也不能支持所述物理公式原因。
4. **当前系统并非跨任务只保存终端 Program。** 它已经有版本化可执行问题契约、问题续接、父程序使用，以及默认启用的研究工作流 DAG 学习和回放路径。真正需要修复的是这些结构之间的身份、语义和效果归因，以及证明它们在目标实验中的真实作用。重新造一棵平行的树会增加重叠状态。

以上判定不否定 Gemini 提出的跨域迁移研究目标；它要求把新目标建立在已存在的接口上，并避免用不同任务、指标和预算的结果互相替代。

### 2.1 Phase 2 v2：42/100 胜，不是“正确率跌至 42%”

原始判决文件 `phase two/analysis/cache/judgments/phase2_v2_triggers_vs_baseline.json` 的 100 个条目中，`winner=phase2_v2_triggers` 为 42，`winner=baseline` 为 58。复核程序没有调用模型，只重新计数已有判决。

#### 后续留出与当前缓存的身份边界

本次进一步复算得到：

建议的继承方式是保留旧结果为开发证据，新实验按目标题 ID、问题家族和机制来源切分案例库，冻结检索与选择输入，记录每道题实际进入上下文的案例 ID。不要抹去正结果，也不要扩大它的证明范围。

### 2.3 Phase three：0 的原件缺失，失败原因更不能改写

Gemini 引用 `phase three/analysis/formalization_v2_report.json`。本子任务对当前 cognitive、main 的固定文件读取均未获得该文件；根代理完成的全部 16 个分支头文件目录中亦没有它。历史提交中的已删除版本由根代理继续检索，本报告不声称覆盖所有历史 blob。

能确定的实现事实如下：

- `phase three/_config.py` 第 64–69 行的预期配对是 S01–S15、S16–S03、S06–S09，分别涉及控制变量/增量构建、求同/类比、特殊到一般/降维。

因此，**不能据这段历史宣称“已验证结构法无法跨越公式形状差异”，也不能据此放弃所有结构约束。** 更实际的弱点是动作分类是否足够、角色与因果信息是否丢失、阈值是否可靠，以及这些相似性与任务功能是否一致。

### 2.4 SCAR：99% 级覆盖崩塌真实存在，但不能概括成“形式化整体无效”

旧后验报告明确区分了 391 个原始 item、29 个预先判为 ambiguous 的 item，以及正式主分析 362 个 item 的 base/system-swap 共 724 个 variant。

| 正式版本 | 产生选择的 variant | 覆盖率 | 平均 pair-F1 |
|---|---:|---:|---:|
| semantic-only | 724/724 | 1.000000 | 0.677030 |
| flat-structural | 723/724 | 0.998619 | 0.487495 |
| 加 typed-incidence、无 composition | 8/724 | 0.011050 | 0.006183 |
| full + length-2 composition | 5/724 | 0.006906 | 0.004144 |

“98.9%”精确指 typed-incidence 这一步删除 `715/723 = 98.8935%` 个此前可选结果。完整 arm 的总弃权是 `719/724 = 99.3094%`。两者分母不同。

原报告第 150–180 行将主问题定位到：从不完备 narrative extraction 得来的关系图，被门控当成闭世界；未观测边未与已违背边区分，又缺少合适回退。composition 是次要的 8→5。这个机制解释有原始报告与分阶段结果支持。

但还必须保留三项负证据：

1. 即使去掉硬门控，flat-structural 的 F1 仍明显低于 semantic-only；放宽门控并不能自动获得收益。
2. 通过 full 门控的 5 个 variant 中仅 2 个达到 strict exact，说明结构一致性也不充分保证语义正确。
3. 该正式路径 `formal_law_binding_count=0`。它不是“13 条定律、T01–T22 已经失败”的实验。

同一数据上的后续修复恢复了 362/362 item 的覆盖，但 361 个结果不变，只有 1 个负向 override、0 个正向 override；`U1−S0=−1/724`，冻结 lower bound `−3/724`，仍然 FAIL。该修复是已经消费的数据上的开发/交叉拟合证据，不是新的 sealed holdout。另一方面，结构候选池在语义池外新增了 38/724 个正确 mapping；这说明候选补充有空间，但当时的选择器没有兑现它。

因此最值得继承的教训是：**将未知、反证和适用域缺失分开；允许结构通道提出候选；只有获得目标场景证据后才晋升使用；最终看选择后的效用，不看候选图有多复杂。**

## 三、“结论 → 可执行问题 → 提问树”实际已有多少

### 3.1 旧提示层的 self-question：确实存在，但不等于可执行 QuestionSpec

早期 scenario+self-question 将一句 wisdom 展开成使用场景和反思提示；v16 又加了带答案的案例和草稿审计。这可以帮助模型选择研究角度，也可以作为作者提案的输入。它本身没有定义可审计的答案类型、可用观测、资源扣账、版本绑定和 parent use，因此不能直接视作当前目标意义下的可执行问题。

### 3.2 当前可执行问题契约：代码已实现，自动提出能力仍有边界

`question_semantics.py`：

- 第 59–99 行：修改问题意义会递增 `meaning_version`、保留历史，并处理旧答案字段。
- 第 101–135 行：`compile_question` 核查答案类型、resolution、use sites 和 query。若只有自然语言想法而没有 executable query，返回 `author_work_request`，不会把文本直接当成已执行研究。
- 还有独立的 claim instance 版本化逻辑。

`question_agenda.py` 第 182–416 行：从实测反例、失败确认的前提、旧绑定、表示差异 witness 等来源生成问题，不需要为生成队列本身购买新观测。它也不会把“两套共享前提的程序同时失败”自动扩大成所有组成部分均被否定。

`question_continuation.py` 第 505–652 行：编译问题，检查支持对象及意义版本，按类型求值，对计算预算扣账，检验答案类型，继而调用 parent use。第 198–384 行包含父组件应用、父 query 准备与父程序修订义务。问题如果没有 use site，可以有答案但不能伪称已经改变父研究。

这些文件说明“问题作为带类型和版本的操作对象”并未丢失。其限制也同样明确：前提与 query 的操作化有时仍需作者工作；有问题结构不代表所有自然语言结论均能自主编译。上述契约也不能仅凭存在就认定全部进入了 V15 的主实验路径。

### 3.3 更直接的反例：当前主研究器已经保存并回放研究 DAG

以下是固定 HEAD 中可以逐项定位的实际链条。

| 环节 | 实现与行号 | 能支持的判断 |
|---|---|---|
| 保存程序性经验 | `memory.py` 179、194、1442、1475 | `research_workflows` 在 KnowledgeLibrary 初始化、序列化和恢复中存在 |

`growth_methods.py` 第 154–204 行还根据诊断特征形成经验适用域；`learn` 与 `revise` 在第 339–365 行区分新方法与修改方法。它不是只把已拟合公式复制到另一任务。

不过，这个 DAG 还不是完整的“候选假设 → 诊断问题 → 结果分区 → 分支选择”策略。`_compile` 第 81–87 行会跳过 `success=False` 及其失败依赖，第 113–125 行只保留最终 confirmation 的证据祖先；适用域来自诊断数值的正负例分隔。它对 `model_confirmed=False` 的 confirmation 另作处理：第 103–104 行转换为 `vary_controls`，因此不能笼统断言所有否证经历都被删除。正确边界是：未来适配 QuestionSpec 时，必须区分“动作没有成功执行”与“动作成功取得了否证某候选的结果”，保留后者的反例 witness、结果分区及条件分支；否则一个成功作业的步骤 DAG 仍不足以表示为何排除了某个研究方向。

选择器也不是无条件套用工作流：`ResearchMethodBook.propose` 第 224–235 行先过滤 `_matches`，再按 contrastive scope、已测知识收益和版本排序。当前排序状态证明代码存在选择逻辑，不证明 V15 对照实验实际选用过它，更不能据此声称已经学会一般的最优提问策略。

这条链支持一个确定结论：**“系统根本没有保存研究过程、只留下终端 Program”与源码不符。** 但它还不能支持另外三个更强结论：这些 DAG 是任意科学领域的通用问题树；它们已经与理论/概念层的全部 scope 和冲突关系统一；它们对 V15 E1/E2 贡献了已测得的收益。

本次按根代理提示检索了现存 `hegel_787256bd_v15_review` 中的 `learn_research_policy`、`replay_research_workflow`、`research_workflow_id`，未找到该实验的肯定消费证据。所提示的 `analysis_source` 目录当前不存在。V15 E1/E2 是有限 grammar、0 LLM 调用的 kernel benchmark；不能把通用工作流接口存在与该实测中的实际使用混为一谈。

## 四、旧 Hippo / morphism 应继承什么，哪些不能继承为真值

### 4.1 Hippo 历史的三种证据，不可混写

上轮同一固定 HEAD 的 `analysis_v15/hipporag_history.md` 已保留原始来源与详审，本次没有重新调用模型：

- 10 题结构 demo 的 10/10 对 3/10，是局部演示；结构通道拥有额外类型字段，比较方为仓库内 PPR 近似，不能等同官方 HippoRAG2 失败。
- 3000 题 MetaQA 的报告值 BM25 0.3077、固定配置 0.3627、学习配置 0.3630 是有用的开发记录，但 selector 接受规则使用全量行、分折回退保留全局选择等问题限制了严格留出的解释。
- 12 个 MuSiQue item、29 个变体的官方运行对照确有 raw 7/29、启发式 P 14/29、官方 Hippo 14/29 的记录；raw 是语料前五条，不是强 BM25，样本和运行配置也不能外推论文级优势。

这些历史支持检索与结构候选有局部可取之处。它们不直接证明假设的提出、冲突修订或科学效用。当前 `_recall` / `KnowledgeLibrary.retrieve` 主线也没有自动接回旧 PPR。最小重接应是增加候选来源，而不是恢复整套旧调度和评估系统。

### 4.2 可复用的旧接口

### 4.3 不能直接当成范畴证明的旧 `pass`

`check_structural_functor` 第 844–965 行确实检查对象、态射、端点、组合和不变量，但它是有限启发式检查：对象和态射可凭词命中视为 mapped；第 926 行甚至允许相关态射都映射成功就记组合律 preserved；最后用对象 0.67、态射 0.55、不变量 0.5、组合 0.5 等阈值作 pass。

这样的输出有助于解释检索理由，却不是数学函子证明，更不是目标系统的机制成立证明。旧 `finite_kernel_metrics` 的 `blackwell_dominance_proxy` 也只能按其名称理解为代理指标。

因此继承时应保留“候选对应 + 不确定项 + 可测试预测”，不应把字符串匹配、词表角色或阈值 pass 自动升级为 verified、equivalent、subsumes 或可执行 scope。负证据同样必须带版本和适用范围；某个子程序在局部条件下失败，不等于所有祖先问题或全部派生实现永久失败。

## 五、从历史出发的最小接续建议

以下是本子审计建议，不是现有能力陈述。

### 5.1 为现有对象建立一条可审计关联，而非先造平行树

给每个可复用知识对象保留四组引用：形成它的经验与版本；待回答的 QuestionSpec 与 use site；能执行的研究 DAG 及其绑定；导致晋升或修订的目标场景确认 receipt。新 motif 先作为可选的上层索引，引用现有 question / workflow / concept，不另存一份未同步的状态机。

最小候选接口可以是：

```text
TransferProposal
  source_object_ref + source_version
  question_ref + meaning_version
  workflow_ref + workflow_version
  role_mapping + units/sign/time-scale checks
  predicted_target_observation
  discriminating_probe + expected_refutation
  scope_status: supported | unknown | contradicted
  cost_estimate + remaining_budget
  evidence_refs + unresolved_obligations
```

检索负责产生此对象；当前研究器负责取得新证据、实际改变父程序和记录 consumption。仅检索到 motif、生成了一段问句、出现字符串 ID 都不能计为复用。

### 5.2 把“有问题”与“问题有用”分成可核对的事件

一条闭环至少记录：哪个失败或异常触发该问题；什么答案会改变研究行动；执行后实际得到什么答案；它改变了哪个 probe、拟合路径、scope 或父程序；后继任务中哪个被采用的候选继承了该变化；同预算普通研究本可做什么。

无需强制每次都生成新问题或新分支。如果答案没有改变任何行动，正确记录为答复完成、无 parent use；如果最强普通方法更便宜地完成同样工作，记录为无增益。这比单纯统计提问数、树深、图连边或复用率更贴合项目主目标。

### 5.3 用一个预算相同的机制迁移实验来判断该接法

至少比较普通研究、普通研究加相同来源材料、仅检索候选、候选加现有 question/workflow 绑定四个方法。每组允许执行相同类型的诊断探针和重新拟合；报告形成知识成本、检索/验证成本、目标失败成本及最后确认成本。

任务应包含适用机制、角色/符号错配、边界不满足与相同语义但不同机制的反例。保留普通方法独立重建机制的权限。评价应落到未见任务的实际研究成功率、成本与错误接受率；旧开放式 LLM 偏好结果只能提供设计线索，不能替代这个检验。

### 5.4 把未知留为未知

SCAR 的经验要求三值判断：某项结构证据未抽取到，不应直接视为已反驳；但未知也不能自动放行执行。未知应触发一个有限成本的判别工作，或在收益不足时回退普通方法。证据支持迁移后，仍需当前对象版本与目标范围的确认。
