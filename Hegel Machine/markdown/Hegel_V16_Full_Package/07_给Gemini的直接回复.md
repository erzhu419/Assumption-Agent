# 给 Gemini：V16 施工决定与最小验收合同

这轮决定是：**保留“从经历学习可执行诊断程序”的主张，暂不实施原 CQM-Hippo 整体重写；并行修 P0 和一个最小研究切片。** 切片先利用现有实验室中的有历史依赖/无历史依赖机制，取得新证据后，再扩展跨表征与物理案例。请按以下四个回答修改计划。

先修正方案中的事实表述：旧 v2 的 42% 是两两评审胜率，旧 v16 的 +72pp 是 86 胜对 14 负的差；后续确有 44:6、41:9 的留出判决，但不能单独归因于问题树。当前已有版本化问题契约及持久化研究 DAG，并非只存终端 Program。Phase three 被引用的 recall 原件尚未找到，其代码比较方法策略，不是化学与 RL 公式 AST。V15 已证明部分真实形成与消费，但未完成干净移除和未见目标净收益证明。[1–3]

## 一、问题 1：树结构是否完全符合构想？

**部分采纳；树可用于展示，知识与证据依赖采用带类型的DAG；策略允许条件循环，实际执行按事件和版本展开。** 分开世界模型的蕴含/细化关系、研究策略的步骤/条件分支、证据的支持依赖，避免把三种“父子”混成一条边。复用现有 `QuestionSpec` 语义契约、`ResearchMethodBook`、`growth_methods` 和 `WorkflowEpisode`，增加缺失引用与语义，不另建平行状态机。

必须区分 AND 与 OR：多个前提共同支持模型是 AND；多种可选解释或研究路线是 OR。某个 AND 组合失败不代表每个前提都假，某个 OR 子分支失败不代表父问题没有解。叶失效后先定位被反驳的前提、协议或观测解释，撤回依赖它的结论；仍有独立证据的部分保留，未知部分排入有界询证。**最近未证伪父节点只能作为待调查入口，不能自动成为可执行知识；兄弟分支也需重新绑定与确认。**

每个诊断问题至少绑定候选版本、可执行干预、观测解释、预测结果分区、前提、成本、停止规则及 parent use。记录“哪个结果让哪个研究动作改变”。同形问题树不保证在新环境有相同区分力；对象角色、符号、时序、单位、可执行动作和噪声边界必须逐项检查。已有 DAG 会剪掉执行失败及无关祖先；适配时应保留“成功取得否证”的证据，不能把科学反例混作工具执行失败。[1–2]

分支维护采用明确决策：适用域不重叠则保留条件分支；重叠且预测相容，可提出保真融合并重测关键边界；重叠且预测冲突，执行能区分两者的实验；一支有反证而另一支通过，则在反证范围内撤回前者；两支都失败，生成修订问题，不强行选胜者。淘汰的是当前使用资格，保留版本、反例与追溯记录。

AWM 的 colimit 可用于**已经给定模型、接口和映射后的合成组织**，不能替代发现这些对象的归纳算法。`Rej` 保留可约束声称知识不变的压缩或融合；新证据纠正旧错误时，应允许撤回旧拒绝，并说明范围与理由。不能规定所有科学修订只能增加拒绝。[2]

## 二、问题 2：是否使用确定性离线保守 Q 门控？

**先用可审计的经验成本选择器，暂不声称具有逐状态置信保证。** 状态需包含可见历史、对象及版本、已失败绑定、剩余预算；动作包括直接研究、有限额复用、可选重建和退出。第一版用简单分组或预测器即可，不需要黑盒网络，也不需要完整 offline RL。相关性分数只排序候选，不充当适用性证明；暂不让同一个 Q 同时控制研究准入和 PPR 边权。[3]

原公式必须修改。若 Q 越大越好，`LCB(Q_option) − 点估计(Q_direct)` 通常不是优势下界。只有在区间具备适用的联合覆盖保证时，才可用

\[
\underline\Delta=\operatorname{LCB}(Q_{option})-
\operatorname{UCB}(Q_{direct}),
\]

或直接对配对效用差估计下界。若优化成本，统一定义节省为“普通成本减候选策略成本”。先满足预先确定的完成和错误确认要求，再比较成本，不能让便宜失败抵消成功差异。样本少或支持不足时称经验估计，不能仅因实现确定性就称 LCB。[3]

开发期从相同决策前快照运行两个允许路径，记录真实配对结果；按源簇划分开发、校准与测试，避免同簇目标跨组。总成本包括形成、检索、绑定、探针、维护、重建、回退和确认，互斥计费且各算一次。回退仍需支付已产生开销，取消“零税直解”承诺。额外调查应有预算上限，并为普通求解和确认留余量；上限依据开发成本确定，不设未经校准的神奇阈值。

## 三、问题 3：匿名主实验与显式物理展示是否双轨并行？

**保留双轨作为后续交付，暂不同时建设完整四家族平台。** 匿名化可减少领域名称捷径，不能抹去模型的结构先验、程序员写入的问法或生成器偏置。要证明“从经历学出”，需保存形成前后的版本、触发经历，并在小型机制案例中移除或匹配替换关键经历；检查系统是否仍形成同一问法以及目标行为如何变化。手写程序可作上限对照，不能计作自主学习。[1–3]

最小切片通过后，先改变变量角色、尺度、参数及表征，保留兼容与不兼容目标；再增加显式化学—电磁展示。普通方法获得相同基础物理知识、原始经历和研究原语。演示不能预塞正确的 Lenz 叶节点或指定必选 Q1，再把命中算作自主发现。

勒夏特列—楞次适合展示共同的诊断方式，不宜直接宣称共享未定义的“反抗符号乘积律”。化学平衡变化依赖控制约束；电磁实验须区分磁通变化、电动势、电流和边界条件，开路电流为零不等于楞次失效。“静态叶失败”也不能唯一推出某两量乘积的时间导数。迁移的首先是可验证的提问程序，目标机制仍需重新辨识。[2]

## 四、问题 4：严格 P0→P3，还是 P0 加核心切片？

**选择 P0 与核心切片并行开发，正式效用比较以 P0 修复为前置条件。** 不必等待一套大平台才观察主线进展，也不能拿带干预和计费缺陷的运行证明收益。

### 优先级 P0：修复足以改变结论的边界

修清版本与支持根有效性、exact-protocol 身份和预算、撤回/失效对象过滤、互斥成本账、原始冲突决定与消费来源。移除实验必须清除目标版本的载体及独占副本，同时保留原始历史；重建是可选且有界的，允许跳过。失败缓存按版本、协议、范围失效，避免一条局部反例永久封锁新场景。沿用现有修复清单与探针，避免另起一套审计系统。[1、3]

### 并行切片：一个由经历产生的诊断程序

用现有源研究让系统遇到“终点控制相同、历史不同、输出有差异”的经历及反例，从中形成参数化历史对照程序。它应能比较无历史依赖、有内部状态等候选，写出什么观测会改变下一动作。这里指定研究目标与共享原语，不预写整棵树、不预设正确分支。保存：触发经历 → 候选区别 → 问题版本 → 实际探针 → 结果更新 → 父程序变化 → 后继采用。

先运行一个成立迁移和一个有界失败迁移：成立例需取得目标环境的新证据并取消明确的原研究工作；失败例可因绑定、scope、历史重置或真实反例停止，保存仍有效部分，用剩余预算回退。只有这一链跑通后，才拓展跨表征、来源更远的机制族及物理展示。“两三探针剪掉 90%”暂作待测目标；报告实际取消的工作、误剪真机制和全部探针成本，不能只统计候选数量。[2–3]

程序身份随研究内容变化更新，证据引用保留取得协议与目标版本；仅换名字不算新假设，仅拟合系数变化不算新提问方法。区分提出、检索、执行、采用和确认五个事件。研究器看不到生成器真值，评测器可用真值核验误剪与最终结果；未实际执行的反事实结果保持空缺，不用评分器推测补齐。

### 主比较：强普通方法必须保有重建与跳过权限

主臂先保留 Hegel 与强普通研究：同源任务流、原语、研究 API、预算和确认标准；各自形成自己的状态，普通组可读原始历史、总结、提问、构造相同诊断程序、缓存，亦可直接解题。无需免费给普通组 Hegel 的成品对象，但不能禁止其重建或强迫它先耗尽预算。[3]

可在开发阶段加入HExA式紧凑策略与错误bank，允许从相同原始经历提炼、改写、合并和按需重建，作为强普通的候选实现。自然语言bank并不要求完整移植其物理环境；最终主基线按开发表现与预定规则选择并冻结。

再用少量预登记快照做局部归因：相同原始经历与已付 pilot，比较调用新程序和普通重建/直解；干净移除只作机制辅助证据。候选库规模尚小时先用已有检索；确认召回成为瓶颈后，再做同内容 Flat/Graph 比较，计入索引构建费，决定是否接 Hippo。不要把提高难度设计成普通组只能盲目穷举。

冻结前可在开发集调节难度，冻结后保留易、中、难以及兼容、不兼容的预定比例。样本量依据值得改善的幅度和源簇间差异安排；当前少量历史簇只支持探索性判断，不能包装为细粒度的安全价值表。

## 五、完成标准与负结果后的动作

请分别报告三层结果，不能相互替代：

1. **机制链完成**：程序确由经历形成，经过真实范围/冲突检验，目标实际执行并改变父研究；证据可追溯。净收益为零仍可承认这一进展。
2. **实例收益完成**：预登记的未见问题在相同确认要求下减少真实工作；同时公开所属簇全部目标与失败，不只展示赢家。
3. **分布净收益完成**：冻结策略与任务分布，在规定质量要求下改善完整成本或成功表现；按源簇报告不确定性、目标阶段及完整序列成本。无需所有任务都赢，不以试到有利阈值或挑选成功题作为结论。[3]

若只有手写程序有效，下一步修形成；若形成了却无法在新环境绑定，修操作映射与范围；若正确采用但更慢，修选择、重复研究和确认开销；若普通方法追平，承认当前组织没有额外净收益，保留简单基线；若负例误用，收紧具体适用条件并增加有界判别，不能一律硬拒绝未知；若证据太少，继续收集新源簇，不升级为普遍优势。

下一次交付只需：P0 修复证据、一个自主形成与失败修订的完整程序链、冻结对照与全部结果、下一步由结果决定的短说明。**先证明哪段经历形成的哪种研究操作，真正改善了哪个未见问题，再决定是否值得扩成 CQM-Hippo。**
