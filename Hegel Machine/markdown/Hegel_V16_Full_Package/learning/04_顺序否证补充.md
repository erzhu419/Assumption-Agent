# POPPER：顺序否证需要统计合同，也需要正确的主张边界

日期：**2026-11-19（Asia/Shanghai）**。定向补读Huang等的[Automated Hypothesis Validation with Agentic Sequential Falsifications，2502.09858v1](https://arxiv.org/html/2502.09858v1)（2025-02-14），重点为§2–3、附录A与C；另读[官方README固定版本59611864](https://github.com/snap-stanford/POPPER/blob/59611864e09dd15d7528e240ad87c7ddbb4a701c/README.md)（提交时间2025-05-14）。没有clone、安装、跑实验或审计实现全代码；不引用摘要中的速度优势作为本次结论。

## 可借鉴的是“下一次检验的合同”，不是自动真值或迁移收益

POPPER接收主假设H，设计其零假设H₀的可检验子零假设，执行后把p值转成e值并顺序累积。论文要求：H₀蕴含各子零假设；agent训练独立于检验数据；每步满足条件有效性；停止只依赖已知信息。其构造为：

\[
e_i=\kappa p_i^{\kappa-1},\quad 0<\kappa<1;\qquad
\mathbb E[e_i\mid\mathcal F_{i-1}]\leq1;\qquad
E_i=\prod_{s\leq i}e_s.
\]

达到\(E_i\geq1/\alpha\)才拒绝H₀；未达到不等于证明H为假。具体实例使用静态数据，设计端仅看元数据和此前结果，执行端才分析原数据；逻辑相关性由LLM近似检查。论文附录C明确，单个假设的Type-I错误控制不等于发现结果全真，也不自动控制整库错误发现比例。[论文§2.3–3、C]

官方API也要求先`register_data`，再`configure`和`validate(hypothesis=...)`；示例开放显著性水平、最大检验数、重试和时限，自定义数据为csv/pkl。因此这是有可用数据与执行器的验证流程，不能仅凭自然语言主张生成一个有保证的分数。[固定README，Core API Usage / Run on your own hypothesis and database]

**对Hegel的直接建议只有一个局部增量：给已有QuestionSpec及检验回执补清统计合同。** 至少记录主/子零假设及蕴含理由、在看到哪些数据前确定了检验、数据访问与重复使用范围、结果统计量和检验有效条件、累计证据、停止原因。已有确定性反例仍可按语义否证，不必硬转为p值。只有真正具有相应随机试验或有效统计模型时，才启用顺序聚合；不新建一套独立平台。

这里尤其要避免把“允许相关实验”理解成“任何相关p值都能相乘”。条件有效性比各步边际p值有效更强；反复查看同一批数据再挑检验，或把自适应训练残差当确认误差，不会因转成e值就自动修好。设计端只看元数据是隔离措施，不能替代对数据依赖与执行端选择过程的核对。LLM相关性评分也不能替代H₀到子零假设的真实逻辑关系；检验无关命题获得小p值，不能算支持父命题。

**它不能替代Hegel的核心效用实验。** 主假设作为输入，下一轮提出的是检验方案与子假设，这不同于证明一个新主假设确实由普通研究经历产生。所读协议衡量验证错误与检验能力，没有给出本项目所需的“源经历形成方法—在未见目标消费—普通方法保留同历史并能重建—全成本净节省”的对照。即使统计结论可靠，提出、执行与汇总检验也可能更昂贵；Hegel仍要记录它究竟取消了哪些后继工作。

因此可把POPPER作为**防止连续试验与提前停止制造假确认**的参考，不把它写成已解决分支融合、方法迁移或净收益。预算耗尽应保持未确认/未决；库内多假设检验还需另外选择合适的错误控制目标。这里提出的是现有合同的边界说明，不增加本轮工程里程碑。
