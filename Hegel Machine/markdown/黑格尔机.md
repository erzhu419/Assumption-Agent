# 三、你关于“确认本质上是距离”的想法，需要一个修正

距离是很重要的一部分，但**确认不总是距离**。

确认一个假设可能通过：

### 距离

[
d(h,D)\text{ 小}.
]

### 约束残差

[
|F(D)|\approx0.
]

例如守恒。

### 顺序违反率

[
P\big(f(x)>f(y)\mid x\preceq y\big).
]

例如单调。

### 预测似然

[
p(D\mid h).
]

### Bayes factor

[
\log BF_{12}
============

## \log p(D\mid h_1)

\log p(D\mid h_2).
]

### 干预后果

[
P(Y\mid do(X=x),h).
]

### 压缩增益

[
L(D)-L(D\mid h)-L(h).
]

因此更准确的统一说法是：

[
\boxed{
\textbf{每个 meta-prior 定义一种“不一致度”或 violation functional。}
}
]

记为：

[
V_a(D;\theta)\ge0.
]

例如：

[
V_{\mathrm{sym}}
================

|R(x,y)-R(y,x)|,
]

[
V_{\mathrm{mono}}
=================

\max(0,f(x)-f(y)),
]

[
V_{\mathrm{cons}}
=================

\left|
\sum_i q_i^{in}
---------------

\sum_j q_j^{out}
\right|.
]

距离只是某些 (V_a) 的特例。

[

&w_o C_{\mathrm{object}}(F)
+w_m C_{\mathrm{morphism}}(F)\

[

> 在“扰动—诱发响应—减少偏差”的控制结构尺度上相近；
> 在微观动力学和守恒量尺度上不同。

这才是你想要的多尺度类比。

```text
  可食性主要由植物谱系决定，而不是颜色决定。

子假设1：
  种子形态可以作为谱系代理。

子假设2：
  相同谱系的毒性机制相近。

子假设3：

子假设4：
  某些谱系内部仍存在毒性变异，需要额外变量。
```

Agent 应当为每个子假设生成：

* 支持证据；
* 反例；
* 干预或查询；
* 依赖关系；
* 当前 posterior；
* 是否阻塞父假设。

父假设的置信度不应是简单平均，而应由 proof/causal dependency graph 聚合。

# 九、LLM/Codex 现在看似“会越来越接近 oracle”，但还没有你要的长期能力

Codex 的公开 agent loop 是：

[
\text{model inference}
\rightarrow
\text{tool call}
\rightarrow
\text{tool result 追加到上下文}
\rightarrow
\text{再次 inference}.
]

([OpenAI][4])

它还经过真实软件任务上的强化学习训练，能够反复运行测试、检查日志并修改代码。([OpenAI][5])

因此它表现出：

[
\text{generate}
\rightarrow
\text{test}
\rightarrow
\text{eliminate}
\rightarrow
\text{refine}.
]

但通常没有在一次项目过程中永久修改模型权重，也不会自动把新发现编译成以后所有任务都可调用的新认知语言。

当前改善主要来自：

* 预训练形成的巨大隐式 prior；
* 上下文中累积的证据；
* 工具与测试提供的外部 selection signal；
* 你的 repo 将失败记录下来；
* 下一轮 prompt 含有前轮结果。

这还是：

[
\boxed{
\textbf{contextual hypothesis updating}}
]

而不是：

[
\boxed{
\textbf{persistent meta-prior invention}}.
]

而且最新受控研究发现，LLM 在“评价候选假设”时通常比“从头生成正确假设”更好，并会出现 generation–evaluation gap；它们还可能在已观察数据附近看似持有正确规则，却对未覆盖区域外推很差。([arXiv][6])

这与当前 Assumption Agent 的结果高度一致：

[
\text{现有 evaluator / gate 可以做得很严谨，}
]

但：

[
\text{自由 proposer 很难产生真正新的、可执行的机制。}
]

# 十、我建议的新核心架构

不要再把主循环定义为：

```text
residual
→ propose hypothesis
→ execute
→ validate
```

应改为两层循环。

## 内层：在当前语言内学习

```text
current framework
→ object-level hypothesis
→ test
→ parameter/scope update
```

## 外层：修改假设语言

```text
persistent structured residual
→ ontology inadequacy test
→ invent new predicate/relation/metric
→ define semantics and scope
→ conservative-generalization test
→ active discriminating experiments
→ library consolidation
```

完整表示：

[
\boxed{
\begin{aligned}
D_t,T_t
&\rightarrow
\text{prediction and compression}\
&\rightarrow
R_t\
&\rightarrow
\begin{cases}
\text{repair inside }T_t, & I_t\le\tau\
\text{invent language extension }\Delta T, & I_t>\tau
\end{cases}\
&\rightarrow
T'*t=T_t\oplus\Delta T\
&\rightarrow
\text{conservative validation}\
&\rightarrow
T*{t+1}.
\end{aligned}
}
]

其中 (T_t) 是当前所有知识/假设的综合，而不只是一个 prompt。

# 黑格尔机：保守元先验发明与假设语言演化系统

## Hegel Machine — Minimum-Ambiguity Construction Specification v0.1

## 0. 核心目标

黑格尔机不是在固定假设库中选择最相似的假设。

黑格尔机必须区分并实现两种学习：

```text
内层学习：
在当前假设语言中选择、实例化、修正和验证假设。

外层学习：
当当前假设语言持续无法解释数据时，
发明新的对象类型、谓词、关系、关系定律、尺度或距离，
并将其保守地并入现有理论体系。
```

形式上：

[
\mathcal H_t
\rightarrow
\mathcal H_{t+1}
================

\mathcal H_t\oplus\Delta\mathcal H_t.
]

其中：

* (\mathcal H_t)：当前可以表达的假设语言；
* (\Delta\mathcal H_t)：候选新概念、关系或元先验；
* (\oplus)：经过保守泛化验证后的理论扩展；
* 未通过验证的候选不得进入正式语言。

系统最终应能回答：

```text
现有22条关系是否足够？
当前 residual 是参数误差、作用域错误，还是语言表达能力不足？
需要创造什么新关系才能压缩和预测这些 residual？
新关系如何兼容旧理论？
新关系在什么条件和尺度下成立？
什么结果可以证伪它？
```

# 1. 禁止退化原则

以下原则是硬约束，不是建议。

## 1.1 语义通道只能召回，不能确认

Embedding、关键词、LLM 自然语言判断只能用于：

```text
候选对象召回
候选旧案例召回
候选关系家族召回
候选角色绑定生成
```

不得用于：

```text
关系成立判定
新元先验晋升
结构对应确认
新理论写入正式知识库
```

系统必须保存：

```text
semantic_retrieval_score
structural_validation_score
predictive_validation_score
```

三个独立字段。

任何 accepted 假设必须满足：

```text
structural_validation_score independent of semantic score
predictive_validation passed
hard negatives passed
```

不得计算一个混合总分后用阈值接受。

---

## 1.2 自然语言标签不是新元先验

以下输出不构成新关系：

```text
“这是一种平衡关系”
“二者都抵抗变化”
“这些案例具有对偶性”
“它们表现出渐进趋势”
“这是新的复杂关系”
```

新元先验必须包含：

```text
新符号或新关系 ID
arity
role schema
输入对象类型
可执行成立条件
violation functional
作用域
尺度
正例
硬负例
新预测
反事实检验
与旧关系的 reduction map
```

缺少任一关键字段时，只能标记为：

```text
verbal_candidate
```

不得标记为：

```text
invented_meta_prior
```

```text

Formalizer
Falsifier

Promotion Authority
```

至少满足：

```text
Generator 不得看到 held-out outcome；
Falsifier 必须生成 generator 未提供的 hard negative；
Evaluator 不得使用 generator 的理由作为证据；
Promotion Authority 只读取结构化测试结果。
```

可以使用同一个基础模型，但必须：

```text
不同请求
不同上下文
角色隔离
输入隔离
输出哈希
无隐藏 scratchpad 共享
```

# 2. 四层认知对象

系统必须明确区分四层。

## L0：Observation

原始观测、执行轨迹、数据点、事件、文本证据、实验结果。

```text
Observation
  id
  source
  timestamp/order
  object bindings
  quantities
  interventions
  outcomes
  provenance
  uncertainty
```

## L1：Object-Level Hypothesis

在已有关系语言中的实例化假设。

例如：

```text
evidence A 与 evidence B 互补
该 treatment 只应在 family X 启用
变量 q 在区间 I 单调增加
```

定义一类对象之间允许或倾向存在的规律。

例如：

```text
complementarity
monotonicity
conservation
negative feedback
sparse exception
```

## L3：Framework / Hypothesis Language

规定：

```text
哪些对象存在
哪些关系可以表达
什么尺度有意义
使用哪些 violation functionals
什么算证据
什么算反例
如何把假设编译成 action/evaluator
```

黑格尔机的核心目标是允许 L2 和 L3 受控生长。

# 5. 确认性假设与生成性假设的硬分类

## 5.1 Confirmatory Hypothesis

若候选只完成以下任一行为，则为确认性假设：

```text
将数据绑定到已有 relation；
调整已有 relation 的参数；
收窄或扩大已有 scope；
选择已有 recipe；
选择已有 metric；
选择已有 scale；
组合已有关系而未创造新中间概念。
```

表示：

[
h\in\operatorname{Expr}(\mathcal H_t).
]

## 5.2 Generative Meta-Hypothesis

只有满足以下条件之一，才可能是生成性元假设：

```text
创造新的 predicate；
创造新的 relation；
创造新的 latent role；
创造新的 scale；
创造新的 violation functional；
创造新的关系组合算子；
创造能压缩多个旧关系的新框架。
```

并且：

[
h\notin\operatorname{Expr}(\mathcal H_t)
]

必须由受限表达能力测试支持，不能只由模型口头声明。

## 5.3 Expression Test

系统必须尝试使用现有语言表达候选。

若存在一个现有表达式 (e)，满足：

[
\operatorname{Prediction}(e)
============================

\operatorname{Prediction}(h)
]

且：

[
L(e)\le L(h)+\epsilon,
]

则候选不是新元先验，只是：

```text
existing-language reformulation
```

# 6. 本体不足检测器

在发明新元先验前，必须先证明当前语言不够。

定义 `OntologyInadequacyReport`：

```text
persistent_residual

existing_prior_best_predictive_score
existing_prior_best_compression
parameter_refit_failure
scope_refinement_failure

estimated_inadequacy_score
decision
```

## 6.1 必须依次排除

系统必须按顺序尝试：

```text
A. 当前假设参数重新拟合
B. 当前假设 scope 修正
C. 当前假设的 mixture
D. 当前假设的低阶组合
E. 新中间变量但不增加新关系
F. 新 predicate / relation / framework
```

只有 A—E 都无法达到冻结阈值，才允许 F。

## 6.2 不足判定条件

进入元先验发明至少满足：

[
I_t=
w_1R_{\mathrm{persistent}}
+w_2R_{\mathrm{structured}}
+w_3R_{\mathrm{compressible}}
+w_4R_{\mathrm{predictable}}
-w_5R_{\mathrm{noise}}

> \tau_I.
> ]

其中：

* persistent：多次或跨样本存在；
* structured：residual 之间不是随机独立；
* compressible：存在比逐例记忆更短的候选规律；
* predictable：对未见数据产生可检验预测；
* noise：可由已知噪声模型解释的比例。

单个异常点不得触发元先验发明。

# 9. 元先验发明过程

## Stage 1：残差结构化

将 residual 转换为：

```text
对象
变化
干预
响应
时序
符号
局部/全局范围
失败的旧预测
被保留的旧预测
```

禁止直接给 LLM 一个 residual 文本列表并要求“总结规律”。

## Stage 2：差异矩阵

构造：

```text
哪些数据被旧理论正确解释
哪些数据被错误解释
错误集中在哪些角色、路径或尺度
哪些旧关系在正例与反例间不具区分力
```

## Stage 3：最小新符号搜索

优先顺序：

```text
新二值 predicate
→ 新有序 predicate
→ 新二元 relation
→ 新三元 relation
→ 新 latent object
→ 新组合算子
→ 新框架
```

# 4. 统一使用 violation functional，而不是统一使用距离

每条 meta-prior 必须定义：

[
V_a(D;\theta)\ge0.
]

(V_a=0) 表示该关系定律完全满足。

例子：

## 对称性

|R(x,y)-R(y,x)|.
]

## 单调性

\max{0,f(x)-f(y)},
\quad x\preceq y.
]

## 守恒性

\sum_j q_j^{out}
\right|.
]

## 加性

|F(x\oplus y)-F(x)-F(y)|.
]

## 正交性

|\langle e_i,e_j\rangle|.
]

## 负反馈

\max{0,\Delta_D Q\cdot\Delta_R Q}
+
\max{0,|\Delta_D Q+\Delta_R Q|-|\Delta_D Q|}.
]

不允许将所有关系统一为 embedding distance。

## 6.5 尺度错误

关系是否在另一尺度上成立？

用新旧角色构造：

```text
predicate
arity
direction
sign/order
composition
scope
```

必须同时生成：

```text
positive instances
hard negatives
role-swap negatives
sign-flip negatives
out-of-scope cases
```

---

## Stage 4：Operational definition

每个新关系必须能被以下至少一种方式计算：

```text
deterministic constraint
small executable program
finite diagram check
statistical test
learned scorer with frozen features
solver/verifier call
```

纯自然语言描述不能晋升。

---

## Stage 5：Compression test

比较：

[
L(D,\mathcal H_{\mathrm{old}})
]

和：

[
L(D,\mathcal H_{\mathrm{old}}\cup{R_{\mathrm{new}}})
+
L(R_{\mathrm{new}}).
]

只有新关系带来净描述长度减少，才说明它不是局部重命名。

---

## Stage 6：Novel prediction

新 relation 必须预测至少一个生成时未使用的案例。

如果只能重新解释训练 residual，而不能产生新预测，应分类为：

```text
posthoc_cluster_label
```

不得分类为 meta-prior。

---

# 8. 防止退化为语义模式的硬禁止项

下列实现直接判定失败：

1. 使用 cosine/embedding score 作为 relation acceptance 的主要证据；
2. 仅根据关键词命中确定 object roles；
3. 将新 relation 定义成若干近义词集合；
4. 用 LLM 自报置信度替代 verifier；
5. 使用训练案例名称作为 relation 特征；
6. 无 hard-negative 测试；
7. 无 role-swap 和 sign-flip 测试；
8. 新 relation 没有 operational definition；
9. 新 relation 不产生新预测；
10. 新 relation 无法在旧 scope 下退化为旧 law；
11. 不能区分“语义近、结构远”和“语义远、结构近”；
12. 直接修改主 graph，而没有 shadow lifecycle。

Embedding 仅允许：

```text
candidate recall
object mapping proposal
paraphrase normalization
```

不允许：

```text
final structural decision
law verification
framework promotion
```

# 9. Generator、Falsifier、Evaluator 必须分离

## Generator

只能看到：

```text

```

生成 candidate relation。

## Falsifier

专门构造：

```text
role swaps
sign flips
counterexamples
boundary cases
alternative explanations
```

不得看到 Generator 的自报信心。

## Evaluator

使用冻结协议评价：

```text
old success preservation
residual explanation
new prediction
hard-negative rejection
compression
complexity
```

## Promotion authority

只读取 evaluator certificate。

不得由同一次模型调用同时提出、论证和批准自己的关系。

# 16. Claim 边界

第一阶段只允许声称：

> 系统可以在有限的关系语言中区分关系确认、关系修正和关系发明，并通过结构反例、操作性定义和保守扩展测试评估候选新 meta-prior。

不得声称：

```text
实现了人类级科学发现
完成了开放世界哲学演化
发明了任意数学概念
证明了人类与机器的本质差异
实现了通用范畴论推理
```

## 为什么必须具体到这个程度

你的问题不是 Codex 不理解“范畴论”或者“meta-prior”，而是任何工程系统都有一个自然退化方向：

[
\text{最容易实现的近似}
===============

\text{文本 embedding + 固定标签分类}.
]

这条路径：

* 容易编码；
* 容易获得漂亮的离线 top-k；
* 容易用相同来源生成 query 和 gold；
* 容易看起来“发现了结构”；
* 实际上没有发明任何新关系。

现有旧模块已经出现这种现象：先验库形式上有正例、负例和 verifier，但实际 retrieval 仍然是词法余弦；  structural layer 虽然名义上有 objects、morphisms、composition 和 invariants，初始 extraction 和匹配依然大量依赖关键词 markers。

所以施工规格必须冻结的不是类名或函数名，而是**科学意义上的不可退化条件**：

[
\boxed{
\text{新关系必须有新的外延、操作性定义、反例边界和新预测。}
}
]

缺少其中任何一个，它最多只是：

* 新名字；
* 新 cluster；
* 新 prompt；
* 旧关系的语义改写。

这份 v0.2 规格才真正对准你最初想做的“Agent 不仅提出假设，还能递归修改自己提出假设所使用的哲学语言”。

# GPT:

先校准当前位置：当前 `reconstruction_v2` 已有可审计的 `HypothesisProgram`、冻结 evaluator、paired validation 和 promotion；但通用 proposer 尚未稳定产生有效新机制，QuAC 的阳性结果来自人工事前冻结的关系型 evaluator，而非 Agent 自主发明关系语言。 旧 structural layer 的角色与不变量识别也仍大量依赖词语 markers，旧 conservative-generalization gate 的候选评价主要是 bounded fixture demonstration。

# Phase 2：Known-Law Structural Recognition

## 2.1 核心问题

> 当关系定律已经存在于 RelationLanguageSnapshot 中时，Agent 能否根据结构证据，而非语义相似，正确识别它是否成立？

这一阶段**不发明新 meta-prior**。

只允许输出：

```text
ConfirmatoryHypothesis
RefinementHypothesis
insufficient_evidence
```

---

## 2.2 首批定律

至少实现六类 operational verifier：

```text
symmetry / equivariance
monotonicity / order preservation
conservation / balance
complementarity / non-additivity
negative feedback
locality / Markov dependence
```

每一类必须有独立的：

```text
role schema
violation functional
scope conditions
required observations
hard negatives
role-swap tests
sign-flip tests
abstention conditions
```

不得共用一个通用 LLM judge 作为最终 verifier。

---

## 2.3 多尺度识别

必须实现 `ScaleContext` 选择。

系统需分别判断：

```text
semantic scale
object-role scale
dynamic-law scale
causal-mechanism scale
governing-equation scale
decision-relevant scale
```

输出必须类似：

```text
Le Chatelier ↔ Lenz

negative-feedback scale:
  relation preserved

microscopic mechanism scale:
  relation not preserved

governing-equation scale:
  partial correspondence

semantic vocabulary scale:
  low similarity
```

禁止输出无条件的单一“相似度”。

---

## 2.4 数据设计

每条 law 都必须包含四类数据：

```text
low-semantic-overlap structural positives
high-semantic-overlap structural negatives
role-swap negatives
sign/order/constraint violation negatives
```

例如 negative feedback 的负例不能只选无关句子，而必须包含：

```text
摩擦阻碍运动
牛顿第三定律力对
政治对立
一般 antonym
positive feedback
外部反向控制但非系统诱发响应
```

---

## 2.5 Exit gate

必须同时达到：

```text
known-law family classification passes
role binding accuracy passes
hard-negative rejection passes
role-swap sensitivity passes
sign-flip sensitivity passes
scale-selection accuracy passes
abstention calibration passes
structural model beats semantic-only baseline
```

并要求：

```text
embedding removed after candidate recall
仍能完成最终 law verification
```

---

## 2.6 允许的 claim

> The system recognizes and verifies a bounded set of structural relation laws beyond semantic similarity, with explicit scale, role, violation, and counterfactual decomposition.

中文：

> 系统能够在有限定律库内，超越语义相似性地识别和验证结构关系。

不得声称：

```text
发明新 meta-prior
开放世界理论演化
通用结构发现
```

# Phase 3：Ontology Inadequacy and Relation Invention

## 3.1 核心问题

> 当隐藏生成规律不在已有22条或其允许的低阶组合中时，Agent 能否先识别“语言不足”，再发明一个新的可执行关系？

这是项目第一次真正测试：

[
\mathcal H_t\rightarrow\mathcal H_{t+1}.
]

---

## 3.2 Benchmark 结构

一半任务：

```text
hidden law ∈ current ontology
```

另一半任务：

```text
hidden law ∉ current ontology
```

Agent 必须在以下四种决定中选择：

```text
existing_law_sufficient
refine_existing_law
invent_new_relation
insufficient_evidence
```

不能把所有任务都归为 invention。

---

## 3.3 新关系的最低内容

每个 `InventionHypothesis` 必须给出：

```text
new symbol or predicate
arity
role schema
scope
operational definition
violation functional
positive extension
negative extension
hard negatives
counterfactual predictions
falsification tests
description length
parent relations
```

如果只是：

```text
“这些案例属于一种新的模式”
```

但没有 operational definition，则分类为：

```text
posthoc_cluster_label
```

而不是 relation invention。

---

## 3.4 初始隐藏关系族

至少包括：

```text
parity-like relation
conservation with hidden sink
threshold-triggered regime change
mediated causal relation
higher-order complementarity
equivalence class / quotient relation
bottleneck law
hysteresis
delayed feedback
context-dependent order reversal
```

其中至少一部分不得在22条中直接命名。

---

## 3.5 Invention 验证

一个候选关系必须通过：

### 非等价测试

证明它不是：

```text
已有 law 的改名
已有 law 的参数调整
已有 law 的作用域收窄
两个已有 law 的允许低阶组合
```

### 压缩测试

[
L(D,\mathcal H_{\mathrm{old}}\cup R_{\mathrm{new}})
+
L(R_{\mathrm{new}})
<
L(D,\mathcal H_{\mathrm{old}}).
]

### 新预测测试

必须预测未参与生成的新案例。

### 反事实测试

修改关键 role、sign、order 或 hidden variable 后，预测必须按新关系改变。

---

## 3.6 Exit gate

```text
ontology inadequacy detection passes
false-invention rate bounded
missed-invention rate bounded
new predicate recovery passes
operational-definition correctness passes
novel prediction passes
hard-negative rejection passes
compression gain positive
semantic-label invention baseline loses
```

---

## 3.7 允许的 claim

> The system performs bounded predicate and meta-prior invention when its initial relation language is demonstrably inadequate.

中文：

> 系统能够在受控环境中检测现有关系语言不足，并发明新的可执行关系或元先验。

此时仍不能声称：

```text
开放世界演化
任意概念发明
人类级科学发现
```

# Phase 4：Conservative Framework Synthesis

## 4.1 核心问题

> Agent 能否不只是发明一条孤立关系，而是提出一个新框架，统一多个旧关系、解释 residual，并在旧作用域内退化回旧框架？

一个新框架必须满足：

[
F_{\mathrm{new}}
\xrightarrow[\mathrm{old\ scope}]{}
F_{\mathrm{old}}.
]

---

## 4.2 框架生成来源

候选框架必须来自真实证据，而非 fixture score：

```text
heldout old successes
persistent residuals
limiting cases
new prediction cases
cross-domain transfer cases
counterexamples
actual verifier outcomes
```

当前旧 gate 中的人工 candidate scores 只能作为机械单元测试，不能作为 Phase 4 性能证据。

---

## 4.3 Framework 可能做出的修改

```text
新增 latent role
新增 relation
重新定义 scale
统一多个 law
引入 exception mechanism
引入 regime variable
引入新的 composition law
将旧 law 变成 limiting cases
```

例如：

```text
旧框架：
  全局 monotonicity

新框架：
  regime-conditioned monotonicity
  + sparse change points
  + hysteresis boundary

旧 monotonicity 在单一 regime 内恢复。
```

---

## 4.4 多代 RelationLanguageSnapshot

每代必须生成不可变 snapshot：

```text
Snapshot_t
candidate extensions
rejected extensions
negative evidence
accepted conservative extensions
Snapshot_{t+1}
```

被拒绝的概念必须进入 negative memory，防止重复发明。

---

## 4.5 Exit gate

每个晋升框架必须通过：

```text
old-success preservation
parent-scope reduction
motivating-residual explanation
new prediction
hard-negative rejection
cross-domain transfer
compression gain
bounded regression
external replay
```

多代测试还要求：

```text
accepted descendants remain useful later
rejected descendants do not reappear under new names
language complexity does not explode
```

---

## 4.6 允许的 claim

> The system supports multi-generation conservative evolution of a bounded hypothesis language.

中文：

> 系统实现了受限领域内、多代、保守泛化式的假设语言演化。

这比“Agent 会提出假设”强很多，但仍不是开放世界。

---

# Phase 5：Open-World Theory-Language Evolution

## 5.1 核心问题

> 在没有完整隐藏关系清单、环境持续变化、未知类型不断出现的情况下，系统能否安全拒绝未知、发明新概念、保留旧知识并持续演化？

这里才开始进入真正的 open-world。

---

## 5.2 环境要求

数据必须以 stream 形式到达，并包含：

```text
new relation types
new object types
concept drift
regime changes
adversarial contamination
delayed outcomes
partial observability
temporarily untestable hypotheses
return of previously seen regimes
```

测试设计者不能事先把所有未来 law ID 暴露给 Agent。

---

## 5.3 必须新增的机制

```text
unknown rejection
ontology inadequacy monitoring
active evidence acquisition
long-term relation-language memory
concept consolidation
concept merge and split
deprecation
rollback
catastrophic-forgetting audit
confidence decay
reopening rejected hypotheses when new evidence arrives
```

---

## 5.4 安全规则

系统不得因为每个异常点都创建新 relation。

必须区分：

```text
noise
contamination
single exception
scope failure
parameter drift
regime change
new relation
new framework
```

新 framework 仍需 shadow lifecycle 和 conservative certificate。

---

## 5.5 Exit gate

要求长序列实验中：

```text
unknown detection remains calibrated
new concepts are discovered
old concepts are retained
obsolete concepts are deprecated
recurring regimes are recognized
false concept proliferation is bounded
language size grows sublinearly relative to data
new concepts improve future learning/sample efficiency
rollback succeeds after harmful promotion
```

还要求外部团队使用新的数据 stream 复现。

---

## 5.6 允许的 claim

推荐学术表述：

> Open-world meta-prior and theory-language evolution under nonstationary evidence streams.

中文：

> 在非平稳证据流中实现开放世界的元先验与理论语言演化。

可以在项目叙事中称为：

> 开放世界哲学演化的受控计算原型。

但不要直接声称：

> 完成了开放世界哲学演化。

“完成”暗示没有重要开放问题，这几乎不可证。

# Phase 6：Formal Mathematical Concept Invention

## 6.1 核心问题

> Agent 能否发明新的数学定义、谓词、结构或不变量，并证明这些概念在形式系统内一致、有用、可组合和可迁移？

这一阶段必须进入 Lean 等 proof assistant。

---

## 6.2 概念发明类型

```text
new predicate
new equivalence relation
new quotient object
new invariant
new algebraic operation
new decomposition
new functor
new natural transformation
new universal-property candidate
new lemma schema
```

每个概念必须有正式定义，而不是自然语言名称。

---

## 6.3 概念价值评价

数学概念不能只按“是否可定义”评价。

至少要测量：

```text
definition consistency
nontriviality
theorem compression
proof-length reduction
number of previously separate lemmas unified
new theorem generation
transfer to unseen problems
counterexample resistance
human interpretability
```

例如新概念若只把一个长表达式重新命名，但没有压缩证明、统一定理或产生新结果，则只是 abbreviation。

---

## 6.4 范畴论专线

构造正式 benchmark：

```text
objects and morphisms
functoriality
natural transformations
limits and colimits
adjunctions
monoidal structure
Markov categories
diagram commutativity
universal properties
category construction
cross-category transfer
```

必须使用 proof assistant 检查：

```text
definition well-typed
diagram commutes
laws hold
proof accepted by trusted kernel
```

测试集必须包含未见 category、未见 diagram 和未见组合，而不只是 Mathlib 定理复述。

---

## 6.5 Exit gate

```text
new formal concepts are generated
definitions compile
nontrivial theorems are proved
concepts reduce proof complexity
concepts transfer to heldout theorem families
category-theory benchmark passes across multiple families
human mathematicians judge concepts meaningful
independent formal verification passes
```

---

## 6.6 允许的 claim

可以声称：

> Autonomous invention of useful mathematical predicates and abstractions within specified formal domains.

或：

> General-purpose category-theoretic reasoning over a specified formalized fragment.

不能声称：

```text
发明任意数学概念
实现了无限制通用范畴论推理
```

原因不是保守措辞，而是“任意”量化了无限概念空间，无法通过有限实验验证。

---

# Phase 7：Autonomous Computational Scientific Discovery

## 7.1 核心问题

> 系统能否在可自动执行和验证的科学环境中，完成观察、理论形成、实验设计、结果分析、理论修正和新发现？

优先领域：

```text
algorithm discovery
simulation science
formal mathematics
program optimization
computational physics
computational biology
materials simulation
```

这些领域具有相对可靠的自动 evaluator。

---

## 7.2 完整闭环

```text
observation
→ anomaly/residual
→ hypothesis
→ sub-hypotheses
→ experiment design
→ resource allocation
→ experiment execution
→ analysis
→ falsification
→ theory revision
→ independent replication
```

只生成论文或代码，不等于完成科学发现。

---

## 7.3 Discovery 的最低标准

每个 discovery 必须同时满足：

```text
novel relative to available literature
not directly present in prompt or training corpus evidence
operationally instantiated
experimentally or formally validated
beats relevant prior method or explains new phenomenon
survives independent reproduction
produces further successful predictions
```

---

## 7.4 Exit gate

至少要求：

```text
multiple discoveries
multiple problem families
blind expert novelty review
independent reproduction
negative-result reporting
comparison with human and agent baselines
cost and sample-efficiency accounting
no hidden oracle use
```

---

## 7.5 允许的 claim

> Autonomous scientific or algorithmic discovery in bounded computational domains.

这一级已经是真正的科学发现，但仍是**有可靠自动 evaluator 的领域**。

---

# Phase 8：Empirical Scientific Discovery

## 8.1 核心问题

> 系统能否面对现实测量噪声、设备限制、未知混杂、伦理和不可完全自动验证的环境，完成真实科学闭环？

---

## 8.2 要求

至少选择一个真实经验科学领域：

```text
biology
chemistry
materials
physics experiment
clinical observational research
environmental science
```

系统必须参与：

```text
hypothesis generation
experimental protocol
controls
power/sample design
measurement
quality control
analysis
revision
replication
```

实验不能由人类在看到结果后替 Agent 修正核心假设。

人类可以负责安全、伦理和设备操作，但每次介入必须记录。

---

## 8.3 Exit gate

```text
preregistered protocol
independent laboratory replication
blind expert review
novel empirical result
successful prospective prediction
causal/confounding audit
negative experiments retained
full intervention ledger
comparison with matched human teams
```

---

## 8.4 允许的 claim

> End-to-end autonomous scientific discovery in a specified empirical domain, under documented human safety and operational oversight.

这是比“自动写科学论文”明显更强的主张。

---

# Phase 9：Human-Level and Cross-Domain Claim Audit

## 9.1 核心问题

> 系统在公平资源下，是否达到或超过人类研究者完成科学发现的能力？

“人类级”不能由单个案例、论文接收或专家印象决定。

---

## 9.2 人类对照设计

需要 matched human researchers：

```text
same research question
same initial information
same data access
same tool access
same compute/budget ceiling
same experiment budget
same time accounting
same evaluation protocol
```

至少比较：

```text
hypothesis novelty
hypothesis validity
experiment quality
falsification quality
discovery rate
replication rate
conceptual compression
cross-domain transfer
cost
time
harmful false discovery
```

---

## 9.3 跨领域要求

至少包含：

```text
formal mathematics
computational science
one empirical laboratory science
one observational/noisy science
one engineering/optimization domain
```

需要不同专家组和独立 replication。

---

## 9.4 Exit gate

“human-level”至少意味着：

```text
noninferior to matched human median
across predefined domains
on prospective unseen problems
under matched resource constraints
with comparable or lower false-discovery risk
and independent replication
```

更强的“superhuman”还要求显著优于高水平专家，而非普通参与者。

---

# 终局五个主张分别能否成立

## Claim A：实现了人类级科学发现

### 可以有条件声称，但必须限定协议

推荐措辞：

> Human-level scientific discovery performance on a preregistered, cross-domain protocol under matched resource constraints.

需要 Phase 9 全部通过。

不能写：

> 已经获得与人类完全相同的科学能力。

因为“人类级”永远取决于：

```text
哪些人类
哪些领域
什么资源
什么任务
什么评价标准
```

---

## Claim B：完成了开放世界哲学演化

### 可以形成强工程主张，但不建议使用“完成”

推荐措辞：

> An open-world system for continual meta-prior and theory-language evolution.

或：

> A computational realization of bounded dialectical framework evolution in open evidence streams.

需要 Phase 5，并最好经 Phase 7–8 验证新框架能指导真实发现。

“哲学演化”可作为理论解释；论文的技术主词应是：

```text
theory-language evolution
meta-prior evolution
framework evolution
ontology expansion
```

---

## Claim C：发明了任意数学概念

### 无法无条件声称

“任意”意味着：

[
\forall c\in\mathcal C,
\quad
\text{Agent can invent }c.
]

有限实验无法证明这种全称命题。

可声称：

> Autonomous invention of novel and useful mathematical concepts across multiple formal domains.

或者：

> Open-ended formal mathematical concept invention.

需要 Phase 6，并且新概念确实带来：

```text
proof compression
theorem unification
new provable consequences
cross-task transfer
```

---

## Claim D：证明了人类与机器的本质差异

### 这个项目原则上不能证明

项目可以检验以下功能性命题：

> 递归假设生成、元先验发明、保守理论整合和实践验证，是人类式开放学习的重要计算机制。

也可以比较：

```text
有无 meta-prior invention
有无 recursive sub-hypotheses
有无 framework evolution
```

对性能和泛化的影响。

但不能由一个 Agent 的成功或失败推出：

```text
人类的本质是什么
机器的本质是什么
二者存在不可跨越的本体论差异
```

那是哲学和认知科学命题，需要不同层面的论证。

最强可检验说法是：

> 本项目支持或反驳某个关于人类—机器认知差异的功能架构假说。

---

## Claim E：实现了通用范畴论推理

### 可以声称“general-purpose”，不能轻易声称“universal”

需要 Phase 6 的正式 benchmark，包括：

```text
unseen categories
unseen diagrams
functor construction
natural transformations
universal properties
proof generation
counterexample generation
cross-domain structural transfer
```

推荐措辞：

> General-purpose category-theoretic reasoning over broad formalized fragments, with machine-checked proofs.

除非对任意可形式化 category theory 问题有完备性证明，否则不能声称：

> universal category-theory solver.

---

# 最终 claim 层级

```text
C1  known structural-law recognition
C2  bounded meta-prior invention
C3  conservative multi-generation framework evolution
C4  open-world theory-language evolution
C5  formal mathematical concept invention
C6  autonomous discovery in computational science
C7  autonomous discovery in empirical science
C8  human-level performance on a matched cross-domain protocol
```

任何阶段只能使用达到的最高 claim，不得用未来架构愿景替代当前证据。

当前研究前沿已经出现能自动生成论文的 AI Scientist-v2、通过进化与自动 evaluator 发现算法的 AlphaEvolve，以及能生成假设、提出实验并根据实验结果更新假设的 Co-Scientist 和 Robin；因此，“完成闭环”本身已经不足以构成人类级主张，真正的门槛必须包括外部新颖性、真实验证、独立复现和公平人类对照。([arXiv][1])

下一步施工只应冻结并实施 **Phase 2**；Phase 3–9 目前应作为不可提前越级的 claim roadmap，而不是同时开发的功能清单。
