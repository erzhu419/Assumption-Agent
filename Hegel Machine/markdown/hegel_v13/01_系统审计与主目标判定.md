1. **真实新对象从普通入口形成：有限版本基本实现。** 新对象包括具体关系程序、经验性分支选择条件，以及同一关系骨架下的参数族。无需要求发明初始Python无法表达的新原语。

## 4. 新发现N1：购测失败会把旧资料标成新probe的结果

位置：`unified_research.py:8116–8138`，嵌套 `_exec_reconcile_probe`。

当前逻辑：

```python
p_rows = acquire(... probe=probe_obj)
if p_rows is not None:
    return p_rows, actual_transitions
if ep_obs_rec and ep_trans_rec:
    return ep_obs_rec, ep_trans_rec
```

而 `reconcile_competing_branches` 只检查非None，随后把结果写入 `paid_probes_executed`，ID使用刚才请求的probe。

### 本轮片段控制

令 `acquire`明确返回None：回调仍返回旧记录；调和器把 `new_probe_not_executed` 写入“已付执行”列表。没有任何成功的新购测。

这是证据身份错误，不是“不允许复用历史”。历史完全可以用于再分析，但必须标为旧数据，并核对它是否实现了该试验条件，不能把未执行的动作换个ID记成完成。

### 必须修改

回调返回有类型的取得结果：`executed_new / reuse_existing_exact / unavailable`。只有取得实际probe执行回执或证明确切同协议的历史执行，才能更新“这个probe已执行”。一般旧资料可用于独立的历史再分析动作，不能走新干预确认路径。

所有非None记录必须带原source、轨迹、reset、action序列、实际probe ID。执行不足保留未决；不能为了闭合生命周期补出一条逻辑上的“执行成功”。

**影响范围**：本轮证明可达代码路径缺陷，尚未重放所有episode判断保存结果有多少次触发。不要据此将全部正结果归零，也不要在修复前继续用`paid_probe_id`计数当作实际实验次数。

## 5. 新发现N2：双方失败时，真正需要递归的子问题被丢掉

`adjudicate_branches_on_paid_evidence`在新旧都错时返回一个 `ResearchQuestion`，要求研究遗漏状态、表示或机制。

但 `reconcile_competing_branches`只保存verdict和新旧claim，没有向上返回该问题，也没有在其自身返回中携带待处理问题。两个claim的status原样保留。当前普通入口的该调和路径位于episode收尾区；只有`exact_confirmed`成立才继续实质调和，未确认episode在这一入口中主要被归档。这不等于原研究器完全没有失败修订，而是这条新增分支路径没有把双方失败形成的问题接回去。

### 本轮片段控制

给两个常量预测器1和2，真实结果0：

- 裁决器确实产生 `research_question`；
- 上层调和结果没有该字段；
- 原新旧status均为`universal`；
- 没有新子研究入队。

### 含义

当前比较适合“已有新解释成功后，整理它与旧解释的关系”。它还没有充分闭合“两个解释都不够，需要继续研究”的路径。

### 必须修改

不增加新研究平台。将返回问题交给已有question/revision队列，并绑定：

- 当前测试的具体程序版本；
- 反例来源与范围；
- 父问题需要什么答案；
- 子答案要改变哪个参数、表示、绑定或后续实验；
- 当前是否有预算继续。

如果没有预算，保存待处理问题和反例；不能保留未限定的原适用资格。不要因一个范围失败全局删除旧计算。

如果新组装的branch predictor与原来已确认的交付程序不同，先核对版本再传播反例，不能误撤回另一个未被测试的对象。

## 6. 新发现N3：没有pilot不应被编码成“所有观测特征都为零”

`compute_observable_regime_features`在没有schema或没有transitions时返回全部0；没有有效近邻或负donor样本时，也返回0 rate。

`evaluate_scope_guard`调用白名单验证时不传实际pilot可用性，默认是True。

### 本轮片段控制

声明 `obs_unconditional_block_rate < 0.1`：

- 显式传`pilot_calibration_available=False`的验证器正确拒绝；
- 普通`evaluate_scope_guard`路径对空记录计算出的0接受该guard。

这说明底层测试通过不等于实际消费者执行了同样的前提。

### 必须修改

返回统计值同时附带样本数、可用性与协议身份。`0/0`是未知，不是0；`min(empty)`未知，不能伪造0。

guard至少返回 `accept / reject / unknown` 三态：unknown可以触发计费pilot或保留候选，不可静默按拒绝/接受处理。

不要新造全部统计框架；在现有公共manifest与特征接口补齐真实数据可用性即可。

另外，本轮从B回执发现25项非空guard的`requires_pilot_calibration=False`，尽管表达式使用的是pilot统计。它来自保留旧guard但本次没有新chosen_feature的分支，属于元数据计算不完整。应从最终AST读取所有依赖，而不是只看本次新加的原子。

## 7. 新发现N4：结构不同，不自动成为对方的世界反例

`autonomous_reconcile_library_episode`中“mutual observable scope refinement”会将不同 `_branch_regime_signature` 分支的pilot摘要，直接放进`out_of_regime_ces`，再调用缩域。

区别包括方向、机制和谓词骨架。这些是模型分类，**不是已经执行过的交叉预测结果**。

例如，复杂规则可能在某一子域与简单规则完全一致；两种模型类别不同，却不能据此说一方在另一方的整个来源世界上都错误。

### 这部分仍可能有实际价值

它可以学习一个经验性模型族检索/排序器：哪些观测摘要更常与哪类成功模型一起出现。这样的选择器能改善任务，且属于一种可学习对象。

### 必须区分两类含义

1. **应用范围的反驳/支持**：需要把待检验假设经合法绑定后，真的用于该数据，并记录误差与条件。
2. **候选路由的正负样本**：可以由不同成功结构产生，但它只是研究偏好，不是科学撤回依据。

无需删除当前有效启发式。把两条路径命名、状态和消费分开：路由器优先排序但不默认永久剪枝；有有效预测反例时才缩减科学适用资格。

### 新分支不等于旧guard的补集

当前裁决有把旧scope某一边界反转成新branch范围的做法。在开放假设集合里，`not old`并不意味着`new`，可能还有第三机制。复合guard的逻辑补集也不只是反转一个阈值。

这类表达可以是新范围提案，必须带有限支持和待检边界，不能直接覆盖整个补集作为已验证范围。

### 范围检验的独立单位

source一套自适应采样摘要与target另一套采样摘要并非自动可比。比例和最小值依赖采样策略。可选的有限修复：在共同公开协议下得到一个小型诊断摘要；或者为每个统计携带探测协议与可用性，只在兼容协议下用guard。不要扩大成通用因果理论项目。

## 8. 新发现N5：被报告剪枝的branch，其承诺可能又从普通池进入

`unified_research.py:617–719`：

- `pruned_scope_ids`收集的是`branch:concept_*`；
- 过滤`consistent_comms`使用的是`world_commitment:*`；
- 这两个命名空间不是同一个身份。

本轮执行原过滤块的最小控制：`branch:concept_A`被标为剪枝，但承诺`world_commitment:0000`仍留在候选池。

因此，当前效用有可能来自：

- 有效分支被提前排序；
- 一些家族被guard阻止抢占预算；
- 某些分支被其他premise audit过滤；

而不完全是档案声称的“所有不适用分支都被作用域隔离”。

### 修复边界

显式维护branch→commitment→source/version映射。世界族可能有多个来源支撑，不能因为一个branch范围不符就全局删掉仍有其他支持的族。

把日志拆成：`not_scheduled_by_router`、`scope_not_established`、`empirically_excluded_on_context`、`support_invalidated`。验证实际进入池、实际拟合与最终采用，而不是只记录一个pruned列表。

不必为此重建所有ID体系；复用现有来源与版本映射即可。

## 9. 新发现N6：R已有同API，但并不是完全优化的按需重建

本版相较v11是显著进步：R确实可以重建参数族并调用同一Pass-0，不再是把关键能力关掉的对照。

但 `reconstruct_parametric_families_from_ordinary_archive`：

1. 调用`OrdinaryPersistentCommitmentCache.get_or_consolidate`，不使用其返回承诺；
2. 为保留各来源常数，重新逐prior巩固；
3. 重新反统一；
4. 返回families，但调用者不缓存这些完整重建产物。

逐prior处理本身可能必要，因为聚合承诺丢掉部分源常数。问题不是“这个步骤必定多余”，而是**缓存层保存的不是本次真正需要的产物**。

原始回执显示，R的后续目标`cache_hit=True`时，family reconstruction仍消耗约4.9k–5.5k（有一条没有family的链约721）。此外，同一episode多次进入结构提案时仍可能再次重建。

这不足以证明全部77,623.5平均差额由缓存造成；不能从旧账简单减掉。它足以说明“强普通研究已充分实现”还需一次版本正确的lazy memoization验收。

### 应采用的基线

- 同原始经历、同角色与数值求解工具；
- 允许一次性生成family、scope候选或程序，并在本episode及未变化后继中缓存；
- 所有首次形成成本实记；
- 新来源、程序、作用域、证据或参数合同变更时局部失效；
- 不预先免费提供学习组的答案，但不禁止普通组调用相同算法自行得到它。

R对scope完全禁用是一个明确的“无预调和组织”消融，可以保留；若要称为一般强普通研究，还应允许其按需形成相同的范围/路由候选并计费。

### H*无效不该被修成有效

当前所有组已有单阈值重新识别器，H*可能是低成本可重新构造的抽象，所以删除不减效果完全合理。

接受这个负结果。可以将它保留在档案但不优先调度。不要通过故意削弱1D识别器、降低基线预算或构造只有新名字可调用的任务制造优势。

## 10. 确认、修订与泛化：还需要怎样收口

### 10.1 随机确认没有覆盖阈值边界

B的1005000目标在内部24行误差约2.23e-18，外部48行约1.70e-3。C也有保留下来的假确认。这是有价值的错误信号，不是“确认API还没接通”。

先做当前版本的开发诊断：保存全部相容阈值区间及会改变目标预测的边界；购测前冻结不同候选在边界上的预测，再取得合法区分证据。

随机分布评价与定向边界评价分开。定向数据买回来后可以成为下一版本训练，但不得继续叫该版本的独立终测。原容差不放宽，外部失败不被内部pass覆盖。

### 10.2 源确认与家族复验不同

H*形成时反复使用源模型过去的confirmation记录，主要证明“新参数化表达没有丢掉这些来源的已有成功”。这是合理且必要的保持性检查。

它不是每次形成家族后都新增了一份独立环境确认。对象字段和报告应使用 `source_preservation_verified` 一类准确名称；目标冻结后的评价才是来源外用途证据。

### 10.3 不需要现在要求无限语言或多代元策略改写

本任务可先在固定Program语言、固定M0上成立。常量槽统一、可执行scope/路由规则、分支复用均可算有效学习对象。没有LLM调用不是自主性缺陷；有LLM调用也不会自动提高证据等级。

v11.1的人工候选菜单12/12与v11学得M1的负结果，应继续分开。不要用手工补完的策略来覆盖旧meta-learning阴性结果。

## 11. 三个后续交付：必须有限、有停止条件

### A. 修证据与循环语义（不买新科学数据）

修购测回调、未知pilot、ID映射、双方失败问题返回、反例传播和家族cache。

使用旧回执和最小合成控制做回归；旧评估链已被审阅，不再作为全新前瞻效果证据。不要重写统一日志、证明内核或所有模型。

结束标准不是所有高级问题解决，而是这些具体路径能够正确返回actual/unknown/stale，并使真实父用途发生对应变化。

### B. 将有用对象明确为“候选路由规则”或“世界适用域假设”

当前代码的观察签名分类，可以先保留为候选路由器。

给当前有限家族加入两个诊断对照：

- **不同结构标签，但当前范围预测等价**：不能当作互相反例硬删；
- **相同结构/相同粗摘要，却有边界差异**：不能由于guard看起来相同就永久合并。

再跑一条双方都失败的短开发链，确认问题真的进入已有子研究队列，回答后改变父模型或下一实验；没有预算就保存未决。

这才测试“递归修订”失败分支，不只是成功任务末尾的整理。

### C. 在新源链上检验一个收紧的主张

冻结M0、共同工具与数值修复，至少保留：

1. 优化过的普通lazy archive；
2. 仅已学分支/路由组织，不优先H*；
3. 同组织＋H*。

需要时在机制开发中补足“有无scope×有无H*”第四格，区别交互与排序影响。不要在无效果时不断扩因子。

全部共享真实原始来源材料，包括调和时新增观测。普通组可自行重建等价对象并按需缓存。学习组完整来源费用、维护、额外购测和目标费用都分开计。

冻结目标使用新的物理源链，而非把当前8条再跑一次。样本量按准备声称的效应与源链方差确定；没有预算就报告当前探索结果，不凭空规定必须上百条。

主要终点：严格任务完成、未见风险、误确认、错误拒绝/错误迁移、覆盖、研究资源。逐源链配对。代码覆盖和节点数量不算主终点。

## 12. 应当怎样回答“究竟已经解决了吗？”

最准确的答复不是全否定，也不是全通过：

> **在明确有限的机制和Program语言内，系统已经能从普通研究中自动产生、组织并复用部分假设；当前独立目标结果给出了组织效用的初步正信号。但是，具体区分实验与scope证据处理、普通基线的重构复用和若干反例返回路径仍不完整。新H*没有测得独立任务收益，所以目前不能将23/24直接宣传为“新统一理论本身使系统更强”。**

修复后若强普通档案仍打平，应保留负结论。若scope/路由组织在同工具独立对照中继续有效，这已经是v4主线的一项真实成果，不必追加“必须发明任意理论、连续改善全部任务”才承认它。

本轮下一步不是扩能力，而是**让目前真正产生效果的那部分知识获得正确身份、可靠证据和公平归因**。
