# 下一轮最小施工与实验合同：不扩框架，闭合v12已有链条

基线：`6e963206fd2822476c894fd2d0f09db4be70223c`。

本合同针对本轮发现，不要求新增物理族、不要求全面Lean化、不要求在线大模型调用。所有科学实验需遵循原预算和实际授权；文件分析、回归和新科学评价分别记录。

## 1. 本轮目标与非目标

**目标**：普通入口产生一个有类型的假设/路由对象；对真实反例采用正确证据语义；必要的子问题能够实际返回；在允许普通档案同样重建知识的条件下，测出或诚实否定其后继增益。

**非目标**：让H*必须赢；让全部新模块一起赢；把未知变成肯定以达到100%；再增加DSL、通用证书、全新任务家族或复杂元策略。

允许结论为：当前参数族H*没有增量效果；分支组织仍有有限作用；优化后的普通基线打平；当前数据不足。不得为制造正例而降低基线能力。

## 2. PR-A：证据身份、未知值和失败返回

### A1. 取得证据结果

修改入口：`UnifiedResearchAgent.run`中的`_exec_reconcile_probe`、`reconcile_competing_branches`。

返回下列既有字典合同之一，不新增执行器：

```python
{
  "status": "executed_new" | "reused_exact_protocol" | "unavailable",
  "requested_probe_id": ..., "actual_probe_id": ...,
  "observation_refs": [...], "transition_refs": [...],
  "program_versions_frozen_before_result": [...],
  "rows": ..., "transitions": ...,
  "cost_ref": ...
}
```

- `executed_new`需要实际成功购测回执；
- `reused_exact_protocol`需要同动作、reset、历史准备、角色与读出意义的已有执行；保留原ID，不创造新测量；
- 普通旧资料再分析走独立`reanalyze_paid_evidence`动作，不伪装成请求probe；
- `unavailable`不更新该干预的支持或反驳，保存研究未决。

不能以“返回了两组非空数组”为执行成立条件。重复数据用于拟合可以合法，但不能成为新增独立确认次数。

### A2. scope统计值

入口：`compute_observable_regime_features`、`validate/evaluate_scope_guard`、所有消费者。

统计至少含：值、有效计数、协议/来源引用、可用时点。没有观测、没有有效负donor、没有有效近邻时，对应统计是unknown。

规则返回三态：`accept / reject / unknown`。不要把unknown等同False，以免仍然静默剪枝；也不要等同True。消费者可以购买一个已经合法且可支付的pilot，或将该候选保留在未验证集合。

最终guard的pilot依赖从其完整AST计算，不能只看本次新增原子。

### A3. 双方失败与新对象反驳

入口：`adjudicate_branches_on_paid_evidence`、`reconcile_competing_branches`、普通问题队列。

裁决结果返回`pending_questions`及其父用途，调用者必须安装到现有队列。反例至少绑定：实际被测程序版本、角色/参数绑定、声明范围、真实证据引用。

- 双方失败：限制两项具体声明在此范围的支持，保留旧计算，研究遗漏表示/机制等；
- 新方失败：不得覆盖旧有效声明；新实例反例不自动等于整个模型族失败；
- 旧方局部失败：保留旧来源有效范围，新增scope候选待检；
- 预算不足：原样保存待处理问题，不签发“已研究完成”。

当新branch predictor是由源数据重新拟合而来时，核对它与最终交付程序是不是同一版本；反驳传播只到实际依赖它的声明。

### A4. 分支身份与执行门控

入口：`_propose_schema_structures`现有分支消费。

建立明确的`branch_id -> commitment_id -> source/version`查询，不用字符串巧合对应。科学反驳/依赖撤回必须过滤对应实例；经验路由不命中只影响排序，不能在没有反例时撤回知识。

一个world family由多个source支持时，不能因一个branch不匹配而删掉其他独立有效支持。

## 3. PR-B：将scope归纳和普通基线的含义修正

### B1. 两种scope来源

- `empirical_applicability_scope`：负例来自对这个声明的实际测试失败；
- `routing_scope_candidate`：负例来自不同成功模型的标签、不同结构签名或检索分类。

v12的`out_of_regime_ces`默认属于第二类。可以保留其研究排序价值，不再直接变为世界反例。

需要第一类时，对待比较分支作合法绑定，在共同已付数据或明确新的区分实验上执行。检验是固定实例还是可重拟合族必须声明，不能用不同参数实例失败去否定整个族。

新范围不能仅由旧范围补集自动确认。未知第三机制始终允许存在。补集表达只作为提案，在旧支持、新支持和新条件上分别检查。

### B2. 范围未识别的处理

- 如果只有一个任务/一个摘要支持一个范围：记录这个局部依据，不称全物理范围验证。
- 不同采样策略下的比例/极值需要同协议诊断或协议标识；不能无条件比较。
- 逐点冲突与模型族签名是不同信息。
- 确认阶段必须保持原世界门槛。允许近似候选存在，但不能标为严格支持。

### B3. 普通档案缓存

入口：`reconstruct_parametric_families_from_ordinary_archive`与其调用者。

缓存实际需要的三类产物：

1. 各prior保留独立参数身份的提取结果；
2. 固定来源集合的参数族反统一结果；
3. 可选的经验scope/路由重建结果。

缓存键绑定相关源码/语义版本、类型/单位、来源证据版本、拟合容差和算法版本。目标绑定不进入源族结构缓存，目标拟合结果另行缓存。

首次计算实记费用；后续未变同输入可复用；变化时局部失效。不能把部分构建写成完整命中。已有普通持久缓存复用即可。

不允许普通组先付费构造一个后来不用的全集，再重复为所需逐源结果付费而无缓存。若逐源计算确有必要，明确记录且缓存该产物。

### B4. 同历史的实际定义

所有比较组可访问共同原始来源、源中的真实反例和调和时新增的数据。结构化组可以提前支付巩固成本并保留产物；普通组可以按需使用相同算法并支付相应成本。

`_freeze_branch_writes=True`用于冻结跨目标学习处理，不能成为禁止普通组在当前任务内临时形成并复用结果的理由。

## 4. PR-C：一条有限反例链与冻结后继

### C1. 开发单位（旧材料允许使用）

至少重放三个实际选择点：

1. 已有新旧预测分歧，成功取得新probe；
2. 同一请求因预算/接口未取得；
3. 两个候选在新数据上都失败。

同一普通入口下分别观察结果更新、未决保存和子问题返回。必须看到第三种情况下真的改变后续候选、表示或实验，而不只是留下“请研究机制”的字符串。

再加入两个小型保护对照：

- 不同结构标签但在已声明范围没有证实冲突，不得硬缩域；
- 相同粗观测摘要但阈值边界不同，不得永久合并。

这些是算法行为回归，不算新物理科学成果。

### C2. 冻结目标协议

修复后固定代码、M0、生成目录、预算和确认规则；当前B/C源链全部视为已曝光开发材料。

后继至少比较：

- 优化普通lazy archive；
- 学得的分支/路由组织，H*不优先；
- 同组织+H*。

需要纯作用域归因时，开发中补齐同一branch representation上的`scope开/关 × H*开/关`，仅改指定干预；不要将status、独立支持、顺序、算法权限一起改了却叫单因子。

外部target结果不进入该轮选择；新确认前冻结实际候选版本。源失败保留在分母；target未完成与预测误差分开。

统计以物理source chain为簇配对，报告每簇差异、总成功、错误确认、误删和资源。置信区间注明簇结构，不把24个同源target都当独立样本。

### C3. 阈值边界问题

在已有合法probe接口上使用残留可行参数区间生成区别实验。不要注入真实阈值，也不要只比较一个点估计。

区分实验是训练/研究数据，之后需要新的未消费确认；标准随机分布评价与定向边界诊断分开。不能因为少量随机通过就宣称整个范围正确。

## 5. 16项行为验收（复用现有测试体系）

| # | 控制 | 必须观察到的行为 |
|---:|---|---|
| 1 | acquire返回None | 不新增executed_probe，不对请求干预签支持 |
| 2 | 历史记录与请求动作不相符 | 只能历史再分析，保留原ID |
| 3 | 确切同协议历史probe | 允许复用，独立样本计数不增加 |
| 4 | 无pilot或统计分母0 | guard返回unknown，不以0代替 |
| 5 | guard含保留的旧原子 | pilot依赖从完整AST导出 |
| 6 | 双方候选被反驳 | 有具体待处理子问题，绑定父用途与真实反例 |
| 7 | 子问题预算不足 | 状态未决，知识不假装已修好 |
| 8 | 新实例被反驳 | 不覆盖旧有效实例，不自动否定整个族 |
| 9 | branch与commitment ID不同 | 具体实例过滤/排序与真实映射一致 |
|10 | 一个来源撤回、另一个独立支持仍有效 | 不全局删除共同计算或家族 |
|11 | 不同签名但无实测冲突 | 标路由候选而非科学反例 |
|12 | 旧guard之外还有第三机制 | 不把整个补集直接确认给新假设 |
|13 | 同raw source重复重建家族 | 第二次实际复用完整产物，成本和结果一致 |
|14 | 原始来源新增/改版 | 只使相关缓存失效，不复用陈旧结论 |
|15 | 删除H*后仍打平 | 原样记录，不改门槛、预算或削弱原识别器 |
|16 | 内部确认通过但外部失败 | 保留false confirmation，下一版本才允许使用该反例 |

这是行为验收，不是新增16个认证关卡。每项直接针对一个当前已见缺口，能由已有测试、receipt和短控制覆盖就不再扩展。

## 6. 停止条件

- PR-A/B修完后，不再以“新模块数量”为进度。
- 普通入口在新数据下没有合格新对象，允许未决；不手工填正确范围或正确结构。
- 优化基线打平，不继续削弱它；结果用于缩小主张。
- H*无增量而路由有增量，以路由为当前贡献，H*保留为可选表达；不强制所有模块获胜。
- 新基线计算耗费减少，不从旧结果机械扣账，必须另版运行。
- 未获授权的科学购测/模型调用不执行。没有新队列资源时，冻结现有正负结果与修复范围。

## 7. 本轮完成时应提交的简明结果

1. 哪个新对象在普通运行中产生，实际表达式与来源是什么；
2. 哪个真实反例限制了哪一条声明；
3. 子问题答案改变了哪一个父预测或实验；
4. 哪个冻结新目标受益或受害；
5. 强普通档案是否能重建它，耗费多少；
6. 全部源失败、误确认、未决与完整成本。

只有这六项共同构成主目标证据。hash、工具调用和专项测试负责可信运行，不代替科学效用。
