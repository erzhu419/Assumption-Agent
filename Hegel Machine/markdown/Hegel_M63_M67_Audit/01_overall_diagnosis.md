# Hegel M6.3 至 M6.7 整体诊断

固定审阅版本：`948e2d57a48b74369158ba2fbdee87bd32102403`。历史基线：M6.3 `0f6bd7d6f`、M6–M6.2 `b1d0c3e99`。日期：2026-11-22。

## 一 核心判断

**计划与实施都有问题，但这组实验没有否定哲学树、多尺度时间特征或跨域部分共性结构。最关键的失败是：把“成功能力的形成、保存、适配、验证、选择、再继承”这条长链，过早等同于“挂载几个 Python 模块并让模型多调用”。随后，又把调用统计、完整性审计和跨版本通过并集解释成机制有效的证据，导致下一轮根据不准确的归因继续加干预。**

建议下一阶段采用修订后的 B′：先接通完整能力保留、目标契约、候选验证和提交选择，再评估 A 的双轨预算收益。B′不等于退回文本经验，也不等于把四个补丁塞进最后两秒；它应让复杂的历史成功程序及其部分共性结构真正进入后继运行。双轨可以保留为后续研究，但目前不能承诺 16–17/20。

原生分数序列为 M6.3 12、M6.4 12、M6.5 10、M6.6 11、M6.7 10。并非每版单调变差；可以确认的是新增复杂度尚未带来稳定净收益，M6.7 相对 M6.4 丢掉两题、没有新增通过。每个版本每题只有一条新轨迹，即每版一次完整的20题评测，且多项因素同时变化；不能据此估计“±2–3 题自然波动”，也不能把所有失分归为新增机制必然有害。

证据总览：全部相关修改共有 16 个源码、脚本、测试和计划文件；三项专项追踪了其主调用链及相近历史能力。Frontier 遍历 309 个 episode occurrence、169 个不同 DAG，1,306 项 SHA 一致；Track A 为 96 条新 DAG、522 项 SHA。执行了 7 个现有纯本地测试及针对缺陷的离线控制；没有新增付费模型运行。详细覆盖和未重复的工作见 `coverage_notes.md`，逐题来源见 `results/twenty_task_appendix.md`。

## 三 计划层面的逻辑跳跃

### 1 跨版本并集不是一套系统已经拥有的能力

16/20 的跨版本并集可以证明研发过程中找到过这些题的解法；它混合了多轮模型采样、不同提示、工具版本、人工日志诊断和部分环境调整。它既不是一个固定策略的 pass@1，也不是普通同分布 pass@K 估计，更不是存在可公开选择器就能自动实现的分数。

已有两轨的上界非常具体：

| 已有候选组合 | 已存题级并集 |
|---|---:|
| M6.4 + M6.7 | **12/20**；若采用 M6.4 重评声明则 13/20 |
| Bare 重评口径 + M6.7 | 14/20 |
| M6.3 + M6.4 | 15/20 |
| M6.3 + M6.4 + M6.6 | 16/20 |

M6.7 通过的十题全部包含在 M6.4 的原生十二题中。即使选择器预知真实正确性，这两个现成候选池也达不到 16–17。新的改良分支当然可能产生新解，但这属于待验证增益。实际机械选择还要扣掉择错损失；候选互补、选择器质量、预算三者缺一不可。

### 2 从 Track A 到 Frontier 缺少适用条件与完整对象的桥

Track A 的函数接口、给定因果图、任务生成机制与源—目标变量语义较受控。Frontier 包含数组程序、文件输出、C++ 积分器、模型状态、数值条件、长时间读出和真实物理假设。一个成功的 `row -> y` 程序运输控制，不会自动证明任意求解流程都可平移。

现有 Frontier 初始化是 K12 固定方法节点，观察/尺度设置主要为 `present_snapshot` 与 identity；横向签名与边参数手工给定。相关 caller 没有实际调用 M5 的多尺度折叠、公共子树提取或完整语义/角色/单位/时间绑定。LLM 在一题内可以写出复杂动力学，这与控制器已经将历史动力学结构保存并跨域运输是两件事。

因此，应将 Plan20 的丰富对象明确接入 Frontier：状态历史、时间核、观察窗、单位、角色、边界条件、适用域、非平凡投影、共享部分与未知插槽。不能把这些义务降格成 `family_tag`、ODE 字符串或图边名字。

### 3 新理论概括旧理论应当是有条件的关系

项目“哲学的历史构成哲学自身”的原则，适合转化为：保留来源、对旧理论成功域给出解释、区分继承的结构与需要修正的前提。它不应变成“所有新旧模型在所有环境都必须相等”。粗粒化会改变读出与有效参数，消去变量可能留下记忆项；不同观测条件还可能使旧关联只在特定环境成立。

这里最需要加强的是条件化保留与真实投影，而非砍掉潜变量或多尺度。当前 Track A 投影回执没有传真实旧模型，正好错过了这条原则最有价值的可检验部分。所谓 d-connected 路由也只能支持检索或一个给定图内的依赖判断，不能单独证明不同环境间的因果不变性。

### 4 正反合需要候选间的内容关系

双轨搜索本身有合理工程价值，但“干净 ReAct 一轨 + 强工具一轨 + best-of-two”尚未体现项目独特的理论增长。若要对应正反合，应记录共享子结构、分歧假设、区分它们的实验，以及综合后哪些适用条件扩大、哪些旧成功域保留。综合可以是条件化模型族，也可以是含状态/记忆的复合机制；不必为可解释性压成简单公式。

计划的验收目标应改为这类可观察能力链，不再先承诺一个 16–17/20 数字。

## 四 实施层面的主要断点

### 1 当前库主要是六个预置模块，历史成功程序没有完整继承

六个固定模块真正被挂载，部分函数真正参与求解。这项工程已经做成。在线导出却只查看当前 Wave 1 的成功 `.py` 终稿，保留长度 60–2200 字符、无外部 helper 依赖的前四个顶层函数。`fit/solve/predict`、下划线函数、复杂闭包和 producer 依赖很容易被排除。

M6.4/5/6/7 当前 Wave 1 分别导出 5/7/8/4 个 API，完整 DAG 中的 activated function 名与这些 API 的交集均为空。记录支持六个预写模块被使用，尚未支持新学得 API 被后继消费。每次运行又重建森林，没有自动从旧 M6.3/4/6 导入历史成功求解闭包。

更严重的是终稿快照漏掉大状态、二进制和 `/tmp` producer。certificate/sparse 的保存快照为空；Koopman 只存报告。要防止“会过又不会”，首先要保存已会的具体对象。仅挂载通用 projection 或 locator 函数无法代替整个初始化、拟合、分支选择与输出过程。

### 2 以调用代替有效性，导致错误的自我评价

M6.7 的 1,382 次调用字段与 14/15 激活，不能解释为 14/15 题获得有益技能。遥测在返回前记数，失败也计一次；生产门控中包含随机数据 LOCO 和虚拟 conservation 候选的自测调用；完整 JSONL 未保存，部分总数只能从 summary 读取。

15/15 TB 都标记宿主门控 executed，只有 clinical、symbolic、baseline-free 三题有报告。其余十二题的空数组混合了不适用、失败、超时等状态。没有可靠的“绑定—执行—验证—采纳—收益”分层，下游计划自然会被活跃度而非能力变化牵引。

### 3 保存候选与选择候选的协议不足

当前候选 archive 没有接成持久化的提交 incumbent；通用验证门识别 shell 字串而非精确候选验证回执。本次控制显示，打印 `solver.py` 可以解除验证债，重复 submit 或最后轮次可以结束未经验证的候选；反过来，正常修改并验证合并在同命令中又可能触发重复检查。

应该允许探索走入暂时差的区域，但最终产物和已经确认的历史能力必须有独立版本。修改候选不能抹掉旧稿，公开验证不能跨 artifact hash 复用，提交应从已确认候选中完成事务。

### 4 Track A 的成功也不能直接充当全部理论保证

Track A 的 M6.3 Sol 20/20 与 522 项哈希均可复算；原写回串树、不同变量候选被覆盖、callable ABI、helper 和 selected observational 处理等具体修复通过控制，应保留。

但新反例仍然重要：

- Sol Flat 两条成功 C04 用常量 tuple 和 `row[k]`，被提取为 `used_keys=[]`，巩固时丢弃；两臂实际巩固 8 与 10 条，不是完全同内容。
- “Pareto”按变量集合判同项，同变量不同机制仍会被覆盖或丢弃。
- 两个不适用 C05 warm-start 在 C01 pilot 误差约 0.996/1.145，容差 0.05，却因“有程序执行”关闭 identifiability 提醒。
- 回溯投影使用 `mean(y)`、恒等 `z` 和 `obs_z=y`，没有传入真实旧模型；替换档案中的旧律描述也不改变一致性回执。
- 在真实 Sol 回执上禁用 d-sep，最终档案哈希与写回费用不变，仅阻断日志改变；当前用例没有隔离该机制的独立贡献。

这些问题都可以沿现有模块修，不需要推翻哲学方向。它们同时说明为何从小范围 Track A 结果外推 Frontier 稳态是过早的。

### Nano 的精确勘误

官方版本有 12 个样本、29 对必要属性。保存 CSV 的满足计数为 M6.3 25/29、M6.4 26/29、M6.5 28/29、M6.6 28/29、M6.7 28/29。M6.5 错 H07；M6.6 漏 pop-in07；M6.7 错 E06。M6.7 相对容差多出的量是 **0.260989 个百分点**，不是总体算法距离成功只剩 0.26%。

使用已曝光的原题继续修复完全合理，但应把它列为开发案例。若根据隐藏 E06 真值和容差反调固定阻尼，再在同题报告“零泄漏盲测突破”，评价口径就错了。下一次独立外推应冻结该经验，在新实例确认。

## 六 为何“更强干预”会产生负收益

证据支持如下机制链，但各具体环节的分数贡献仍需配对干预测量：

1. 成功求解过程没有完整留存，后继经常从头重解，因此跨版本优势会丢失。
2. 静态算子按家族/关键词进入上下文，部分绑定和适用性不成立，却被当作已验证先验。
3. 有些干预实际无效或只是启动自测，仍增加模型注意、token、运行与排错成本。
4. OOF、稳定性、动力学残差等代理信号没有覆盖全部目标风险，可能推高错误候选的地位。
5. 候选晋升、恢复与提交协议不完整，最后找到的版本未必是当前最好已验证版本。
6. 总结用调用/全绿审计掩盖这些断点，使下一版继续强化错误环节。

M6.7 相对保存的 Bare 总 token 多 17.32%、effective token 多 18.58%、episode wall 合计多 62.62%，分数仍较低。这里 Bare 复用旧轨迹，wall 是逐题求和，并非同期并行 elapsed；因此这些数字是成本信号，不是严格的速度因果估计。至少可以确认“同 28 轮”没有意味着同实际成本。

## 七 下一阶段的明确决策

**不直接采纳原 A，也不照原 B 做末端静默补丁。先完成 B′ 的可执行继承与选择闭环，再把 A 作为有对照的算力分配实验。**

近期验收应是：历史成功 producer 可重建；复杂依赖不再静默丢失；目标变量、时间与单位能合法绑定；所有门控有精确状态；候选修改不会破坏已确认稿；完整选择流程的公共验证能检验其自身的择错风险。完成后再用冻结新实例测真实收益，而不是提前设定 16–17 必达。

完整施工顺序、已有复用入口、数据契约、任务修复、实验矩阵与文档替换见 `02_plan_and_implementation_changes.md`。这条路线保留项目最有价值的结构性目标，并把预算优先花在已经被日志定位的损耗上。
