# M6.3 Track A 独立诊断：修复确有收益，但尚不能作为 Frontier 稳态继承的已完成底座

审计对象：固定提交 `948e2d57a48b74369158ba2fbdee87bd32102403` 中的 M6.3 实现及 96 条新运行证据；历史对照来自 `b1d0c3e99f1e6b12cbc62ca8311f1a25d66f2dbf` 的 M6.1。本文仅涵盖 Track A 与它对整体计划的支持范围，Frontier 算子、宿主门控与逐题结果另有专门报告。

## 1. 结论与已完成的核验

M6.3 修好了上一轮几个实际、可复现的损耗点：原来 C01/C05 的写回串树、Luna C02 先成功者独占、Luna C05 `fit()->callable` 被丢掉、顶层 helper 依赖漏提取、非行参数字典被误改、selected observational probe 被当作干预。这些修复应保留。五个对应的现有非 Docker 测试函数在本次审计中实际执行通过，并非只照抄报告。

但“修复上述具体反例”与“已具备完整的 Pareto 部分结构归纳、因果投影证书、跨域自我改进底座”相距甚远。最新实现仍有真实成功程序在巩固时被静默丢失；所谓 Pareto 档案将同一输入变量集合的不同机制合并成一项；投影回执没有调用旧模型；Bayes-ball 在实际允许迁移的候选上没有独立筛选作用。这些正是从 Track A 外推到 Frontier 时需要补齐的接口与证据，而不是要删除多尺度或部分共性结构。

## 2. 首要实施问题

### A01 — 已成功的复杂 Python 表达式仍被丢掉，且实际影响了“同内容”对照

**已发生，不是潜在风险。** Sol `EqualContent_LearnedFlat` 的两条 Wave-1 C04 均 `strict_pass=True`、`heldout_rmse=0`，但巩固事件中缺少它们。原因是两个程序均用 `_KEYS=('u_outdoor','u_indoor','p_weather','a_foot','impact_idx')` 配合 `row[k]` / `row[key]`。新提取器只识别字符串字面量下标；返回 `ok=True, used_keys=[]`；巩固器在 558–559 行直接跳过。

证据：

- `workspaces_and_dags/wave_1/gpt-6.2-sol__EqualContent_LearnedFlat_LiveGPT__W1R1__C04_MultiDepth_RootPullback/episode_receipt.json`，代码摘要 `2a29c3ee4719a780d1bdd75f07213175fd06eb983c36a75e0763bf8da38ec7c8`。
- 同路径 `W1R2__C04_MultiDepth_RootPullback`，代码摘要 `df8a7a724c1b2a272abbb6af1cf67a3f358b723f9fd67c7e7cd69b47d66d6c9a`。
- 对应巩固 JSON 中 Flat 只有 8 条事件，Hegel 有 10 条；Flat C04 无源代码保留、无 Wave-2 warm-start。

这没有解释 Sol Flat 丢失的全部三题：Flat 的两条 Wave-2 C04 最后仍自行重解成功。它说明“完全同内容”不成立，不能把 20 对 17 的全部差异直接解释为图组织的纯因果贡献。

**应改成什么：** 先无损保存每个被确认的完整模块及依赖；“暂时无法静态解释”不能等于“删除成功技能”。为常量 key tuple、局部闭包、关键字实参、数据流别名提供可验证的适配；对未支持语法保留 opaque executable，并标记 `binding_status=unresolved`，由小规模目标接口试执行验证后使用。子结构提取是完整程序保留之上的第二层，而非先决条件。

源码：[AST 提取与巩固](https://github.com/erzhu419/Assumption-Agent/blob/948e2d57a48b74369158ba2fbdee87bd32102403/Hegel%20Machine/src/hegel_machine/cognition/m6_3_sovereign_causal_wormhole_engine.py#L301)。

### A02 — “Pareto”目前是一组变量一个胜者，仍丢弃同变量的不同机制

`_append_pareto_candidate` 在 479–487 行仅按 `tuple(sorted(used_keys))` 区分候选。两段不同 AST 只要使用同样变量，除非新确认 RMSE 严格更小，就丢掉新稿；更小时则覆盖旧代码。没有行为域、时间尺度、源环境、复杂度、稳健性、运行成本等轴；没有保留被覆盖版本。

本次最小控制：`predict(row)=row['x']` 与 `predict(row)=row['x']**2`，相同变量及相同已声明确认分数时，第二个 `added=False`，档案只剩第一个。这个控制验证的是档案判重语义，不声称两公式在任何一般分布上都同样正确。

所以 M6.3 确实修复了“R1 用三变量、R2 用两变量”的历史 C02 反例；没有修复“同变量、多机制、不同适用条件”这一更普遍的 Frontier 情形。哈希排序消除了完成顺序差异，却可能把语法哈希决定的单一稿稳定地保留下来；确定性不等于正确选优。

还有 `archive[:3]` 文本摘要和 `cands[:2]` pilot 执行限制。完整 `pareto_confirmed_candidates` 仍随 note JSON 传给模型，因此前者不是三项存储上限；真正的自动试算仅取前两项。应保留完整候选集，通过目标契约和预算选择实际探测集合，而不是默认只试变量数最少的前两项。

**应改成什么：** 使用独立 `artifact_id/source_hash/parent_version` 保留所有真实版本；以“同一任务契约和同一评估集上”的损失、边界失效率、成本、复杂度定义 Pareto 支配。源参数与可重拟合结构分开，域外新条件不能靠单个源确认分数判胜。当前 `_append_pareto_candidate` 可直接修订，不需要再造一套与原档案平行的新库。

### A03 — 成功调用的低门槛被误认为可用知识，实际关闭了需要保留的诊断

`_evaluate_recalled_pilot_warmstarts` 只要 Python 执行 `ok=True` 就加入列表，不要求 RMSE 达标；随后 `has_transported_L2=bool(warmstarts)` 直接关闭 identifiability 检查。是否来自正确角色/机制、是否从别树运输、是否只是无关近邻、是否拟合极差，都未参与这一布尔值。

实际 Luna 两条 C01 Wave-2 日志中，唯一 warm-start 都来自 **C05 direct actuator**：

- Aprime 的 pilot RMSE **0.995529**；
- Fdouble 的 pilot RMSE **1.145122**；
- 任务容差 **0.05**；两个 episode 都没有 `D4_M6_3_STRICT_IDENTIFIABILITY_CHECK`，均失败。

模型本身在 Aprime 首轮文字中正确指出 direct-actuator 候选不符，因此不能断言错误 warm-start 独自导致最终失败。可以确认的是宿主控制流将“程序运行完成”误当成“存在已绑定可用 L2 知识”。这与 Frontier 把调用数当成技能激活成功，是同一类状态定义错误。

**应改成什么：** 将 `retrieved / bound / executed / validated / adopted / improved` 拆开记录；保留实际误差与角色匹配证据。可用技能也不应自动抑制目标环境的 identifiability 检查；只有已绑定且能解决同一不确定性的证据才能解除相应告警。对不可辨识目标，增加无意义重复 passive probe 不会带来新识别信息，应明示仍有多候选，保留诚实未决。

源码：同模块 777–820、913–916 行；证据：两条 `W2R*__C01...` 的 `decision_provenance_dag.json`，`D4C_SKILL_ACTIVATION_PILOT_WARMSTART`。

### A04 — 回溯投影回执没有检验哲学主张对应的量

在 596–608 行，调用 `verify_retroactive_projection_certificate` 时：

- `obs_z` 被赋为观察到的 **y**；
- 旧模型固定为 `lambda _: mean(y)`；
- 新模型固定为 `lambda x,z:z`；
- 没有传入旧关联程序，也没有传入本次作者的新因果预测函数；
- helper 的 `certified` 和实际 projection defect 没有存入回执；
- `passive_shadow_consistent` 仅由新程序在同 5 个 pilot 点上重新拟合后的训练 RMSE 决定。

所有现存回执都用 5 个 pilot、1 个 bin。此时 helper 比较的实际上是同组 y 的均值与自身均值。离线控制保持真实已确认的 Sol C01 代码与数据不变，仅把档案旧律文本分别改为 `y=+1000000` 与 `y=-1000000`，两次回执完全一致，仍 `passive_shadow_consistent=True`。

**应改成什么：** 保留可执行的旧关联模型及其原观测环境；在共享的旧环境数据上，用真实新模型及相应条件分布做投影，然后记录旧、新两者逐点或逐组的差异、样本支持、估计不确定性。当前统计 helper 可以继续用作有限样本诊断，但必须接正确对象，不得把有限数据上的拟合一致写成整个域上的上界证书。无法建立旧模型时应记 `unavailable`，仍可保留新候选进行后继验证。

这项修正恰好让“新理论解释旧理论为何在旧条件下有效”的思想真正进入计算，无需削弱其哲学内容。

### A05 — 当前 Bayes-ball 与完整 role-map 检查重合，尚无独立贡献证据

传输的两道条件是：

1. `active_dag_nodes={vmap[k] for k in curr_keys}+{Y_out}` 与 `wh_dom_dag_nodes={vmap[k] for k in role_map}` 不能 d-separated；
2. `curr_keys` 必须是 `role_map.keys()` 的子集。

在存在已映射活跃变量时，满足条件 2 已保证这两个集合重合。`is_d_separated_dag` 会因 source/target 交集在函数开头直接返回 False，无需考察因果边。已被日志写为 collider blocked 的路径，又会因不满足完整 role-map 条件而被第二道门挡住。

本次使用实际 Sol Hegel Wave-1 回执做无模型调用消融：仅把 d-separation 检查替换成恒 False，**完整节点档案相同、SHA-256 相同，写回费用都是 10.5 C**；只改变阻断日志计数 2→0。

这不否定 Bayes-ball 算法，也不否定哲学树有用；它否定的是当前回执足以归因“图上的 d-sepset 屏蔽带来了独立改善”。实际可证的是预先给定图和角色对应上的代码传播。

**应改成什么：** 重新定义每条运输义务：哪个机制可变、哪个接口/目标量须保持、环境选择变量是什么、该映射在哪些条件下允许。用不与完整角色覆盖逻辑重合的源—目标查询测试门控；另加同源同代码同工具的 `gate_on/off` 保持/移除消融。局部因果承诺必须被保留并可修订；d-connection 本身不是跨环境公式可运输性的充分条件。

### A06 — Owner 修复了历史串树，但“已验证归属”的条件仍过弱

报告和函数文档说验证 `used_keys <= vmap.keys()`；实际 393–395 行要求的是**至少一个变量重合**，且排序首先比较 signature overlap，再看完整覆盖。控制程序含 `m_2, foreign_required_1, foreign_required_2`，只给一个 C02 节点，即被判 `verified_existing_node`。

保留宽模型不是错误，强行丢掉额外变量也不是解决方式。应分别表达“核心机制属于此节点”和“完整模型还有额外依赖”：完整 AST 存派生/复合节点，核心子结构用其单独的依赖和适用条件挂回源节点。当前凭一个交集直接写回完整模型，无法提供这一精确区分。

本次保存的 C01/C05 控制确已过；本文不把这个潜在反例写成新运行中再次发生同一种串树。

### A07 — 新 AST 分析器支持范围仍窄，未支持语法应显式退回完整模块

除了真实发生的 `_KEYS` 漏提取，定向控制还得到：

| Python 写法 | 当前结果 | 风险 |
|---|---|---|
| `helper(q=row)` | 漏掉 helper 内 `q['x']` | 关键字参数未传递行来源 |
| `predict` 内部定义并调用 helper | 漏掉内部 helper 的 x | 只建立顶层命名函数调用映射 |
| `r=row; r={'x':7}; return r['x']+row['z']` | 把 `r['x']` 改成 `r['x_target']`，字典 key 仍 x | 别名重赋值没有清除来源污点 |
| `_KEYS=('x','z'); sum(row[k] for k in _KEYS)` | `used_keys=[]` | 常量传播缺失 |

这些不是要求支持任意 Python 的完备静态分析。工程上应建立“可靠支持的子集+未解析依赖的显式状态+模块/运行接口兜底”，在无法确认时不改写，完整保留复杂结构。

### A08 — ABI 的主要修复成立；“通用”和“100%全封闭”仍过度

已验证修复：保存的 Luna C05 原程序一字未改，`fit_returned_callable` 达到原预期的三段 RMSE 0；`predict(row,state)` 的必需第二参数也确实接入。

边界：若作者写的是 `predict(row,state=None)`，runner 仅按“必需的位置参数数目≥2”决定是否传 fitted state，会忽略返回状态。本次简单控制同样 `fit()->2`，必需 state 得 RMSE 0，可选 state 走默认值，RMSE 265.64544。应规定并检查明确 ABI，避免通过 Python 参数默认值猜科学语义；未声明接口的程序以显式 adapter 适配。

隔离方面，清空 PYTHONPATH 与审计钩子确实阻止了旧的直接 import、普通 open 反例。但允许导入 `ctypes`，且没有 OS 层文件系统隔离；调用 libc 读文件不经过 Python `open` 事件。本审计仅对自己创建的外部数字 marker 做比较：Python open 被挡，ctypes/libc 读取成功，按 marker 返回三段 RMSE 0。未读任何真实敏感文件，未修改仓库。

扫描 96 新 episode 保存的 **163 个 model_step Python 文件**，没有命中 `ctypes`、`hegel_machine` 或所检查的宿主路径关键词。因此这是保证边界反例，**不是原模型实际作弊的证据**。要宣称机器强制隔离，应使用已有容器路线建立只挂载允许输入的独立工作域；审计钩子可保留作额外约束，不能替代 OS 边界。

## 3. “同内容对照”仍混入多项因素，不能用来一次性证明哲学机制全成立

当前两臂各自进行 Wave 1，分别学习出不同代码和不同成功集合；之后分别巩固。Hegel 还独有：PPR 检索、identifiability 提醒、precondition BFS、最多 3 层额外组件召回、角色传输，以及新复合节点连接。Flat 的 Wave-1 source 从一开始就不是同一份，且 AST 漏提取进一步造成内容缺失。

这是一组有效的系统级结果：给定本次任务与协议，Hegel 比该 LearnedFlat 臂表现更好。它不是严格控制后的“相同内容仅换组织”的消融。尤其 Luna Hegel 本次比 Flat 多成功的四题恰为两波 C04 四题；其余失败/成功集合基本一致。C04 的额外组件来自 Hegel 独有的 BFS 提示，因此对照不能把这四题差异直接归为新学习代码在两跳虫洞上迁移的净效果。

**可复用当前实现的改法：** 从同一批已冻结 source receipts 构建同内容档案并复制；向所有臂提供同一组结构候选和可用工具，分别控制组织/排序、角色传输、前提展开与 d-sep 授权。也保留当前自主各自学习的全系统对照，但明确它回答的是整套系统价值。旧 M6.1 基线共享任务 seed，却没有新 ABI、重试策略及新提示，应作为历史结果而不是同期仅一个变量的对照。

## 5. 对整体计划应怎样调整

### 5.1 保留核心研究目标，收回过早的确定性承诺

Plan29 的“只需挂载已验证的 Pareto AST 库，即可把 15/20 稳态锁死”并不由 Track A 的结果推出。上述控制说明 Track A 本身还是一种受给定图、预设关系与有限接口支持的程序运输原型。M6.3 合成森林使用 `temporal_readout_mode='present_snapshot'`；这些回执没有单独检验多尺度历史动力学。多数有效角色映射仍为同名变量恒等映射，非平凡映射的工程单测与多领域原生任务迁移要分开陈述。

因此后续计划要把“保存原有复杂能力”与“证明能跨环境组合”明确接起来，不能将实现函数的名字当作已实现理论结论。这里需要的不是简化任务结构，而是让完整复杂对象拥有可执行身份、依赖、适用边界和真实前后效果。
