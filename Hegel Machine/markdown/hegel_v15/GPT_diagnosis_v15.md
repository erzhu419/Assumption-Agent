## 4.3 重放中仍会把局部实例失败扩大成模板失效

重放函数的一条路径是：

> 固定实例在新批次失败  
> → 尝试识别范围  
> → 没识别出来  
> → 整支设为 refuted  
> → dispatcher 连同同源模板一起排除。

关键在于：**只有缩域成功时，它才去检查模板能否合法重绑定。**

本次最小控制中：

- 真实缩域函数返回 `scope_unidentified`；
- 重放将旧分支设为 `refuted`；
- 模板检查调用次数为 **0**。

控制中提供的模板检查桩被设为返回重绑可行，但实际没有得到调用。这证明了一条确定的控制流问题；没有证明它解释了全部 D2 差异。[重放代码](https://github.com/erzhu419/Assumption-Agent/blob/c9b60dc525b5d87409619cc5c7b0f904d6761bf8/Hegel%20Machine/src/hegel_machine/cognition/branch_reconciliation.py#L3917) · scope_replay_probe_results.json[控制结果](sandbox:/workspace/scratch/9d1e58286220/hegel_c9b60dc5_review/evidence/scope_replay_probe_results.json)

这里需要作一个严格区分：

**一个真实反例当然可以否定固定实例的普适性声明。** 但这不等于已有局部支持全部消失，更不等于所有允许重绑定的模板都已被否定。

应保留的是局部支持和待检查模板，不是恢复已经被反例否定的普适性。

## 4.4 “4/4 消费”和“七句事实账本”仍有失真

### 消费判据太弱

# 六、下一轮我建议怎么做

## 第一阶段：只关闭剩余的关键实现与归因缺口

建议拆成四个有限交付：

| 交付 | 具体工作 | 完成标准 |
|---|---|---|
| **1. 真实对象移除** | 按实际 list／定义／绑定结构移除指定版本及独占派生，保留原始证据和重建能力 | 首次合法重建前不可召回；重建后可以重新使用，费用可追踪 |
| **2. 共享状态更新规则** | 修复 replay 的过度撤销；统一在线与重放的实例、模板、范围、反例处理 | 同历史得到相同语义，或明确承认比较的是不同组织算法 |
| **3. 真实消费与事实导出** | 删除字符串判据；修 action／状态字段；按失败状态生成文字 | 每句解释能定位到真实事件，失败不会生成成功故事 |
| **4. 有限回放与缓存修复** | 补指纹依赖，复核已曝光的关键实例 | 修复对应风险，不要求科学任务全部成功 |

优先使用现有案例：

- **1031000**：定位 R/K 首次出现状态分歧的批次。
- **1041000/T1**：检查对象真正移除后如何重建。
- **1042000/T1**：核实“字符串出现”与实际消费的差异。
- **1043000、1045000**：核实失败账本。
- **1037000/S2、T3**：查明准确模型为何仍未决。
- **D1 Replay E**：确认新修改没有破坏累计预算和恢复路径。

这些都已曝光，应作为开发回放。**不要为了让它们全部成功而降低确认标准，也不要重新称为未见泛化。**

## 第二阶段：让递归维护成为有条件的研究动作

D3 的主要问题已经显现：子问题策略平均多花三十多万计算，但没有多完成任务。

因此下一项值得研究的假设是：

> **当已有证据已经足以触发合法机制研究时，局部进入研究器，比先穷尽大量旧分支检查更有效。**

具体可以这样做：

1. 先拆出重复评分、重复拟合、区分探针、修复、新确认、维护各自费用。
2. 只比较受当前变化影响的分支和支持依赖。
3. 没有区分价值的检查允许早停。
4. 没有预计消费者的昂贵抽象按需构造。
5. 预算不足或预期收益不明确时保留 pending，允许普通研究继续。
6. 为独立确认保留预算。

这只是**待验证的调度策略**。普通基线也必须能使用相同证据与合法策略，否则即便更快，也不能把全部优势归因于持久假设组织。

更不能读取 `focal_memory` 等隐藏世界标签来决定何时调用 latent；可使用的是已付观察、历史残差、预算和已有对象。

## 第三阶段：把两个研究问题分开实验

### 实验 A：同历史下，持久组织有没有价值？

双方：

- 拥有同一完整原始历史；
- 使用相同科学状态更新语义；
- 具有相同合法 API、确认规则和目标预算；
- 一组提前物化，另一组按需重建并缓存。

R 可以使用缓存、去重、批处理等语义等价优化，不必机械支付 K 的每个历史中间步骤。

这个实验回答：**保存与维护学习产物，比现场重建是否更划算？**

### 实验 B：整个自主研究策略有没有价值？

普通方法使用自己实际形成的库继续研究；递归方法使用自己的库继续研究。

两者从相同初始条件、任务、API 和预算出发，允许探索轨迹不同，记录完整来源到后继的成本。

这个实验回答：**从形成假设开始，整个研究流程到底有没有变好？**

两者都必要，但不能拼接成绩。

## 第四阶段：按真实结果决定是否继续扩大

下一轮不应以“必须得到正结果”为验收条件。

合理的决策分支是：

- **普通方法仍打平或更好**：接受当前任务上的有限效用结论。
- **只省观测、多花计算**：根据实际观测成本判断是否值得，不默认称整体提升。
- **只有少数昂贵路径获益**：研究可观察的触发条件，不能用测试实例 ID 做路由。
- **只提升可追溯性**：将它作为可审计研究系统的成果。
- **正确移除后依然很快重建**：说明当前强研究器下，这类知识的持久存储边际价值有限。
- **准备进入更复杂机制或开放语言提案**：提出新的实际需求与独立评价，不用扩展研究范围来回避当前负结果。

# 七、你关心的分支修订、融合、消除，应继续遵守什么逻辑

这套逻辑不需要推倒重来，但必须在在线与重放两条路径里一致：

| 实际情况 | 应采取的动作 |
|---|---|
| 固定参数实例失败，重绑后能解释 | 生成新实例，保留模板；旧绑定的反例保留 |
| 两支适用范围不重叠 | 共存 |
| 范围重叠、预测不同 | 做真实区分实验 |
| 一支通过、一支失败 | 限制失败实例或有充分证据的模板范围 |
| 两支都失败 | 提出遗漏状态／机制子问题，或诚实延期 |
| 现有观察无法区分范围 | 保留未知关系，研究缺失的区分信息 |
| 多支存在共享结构 | 提出一般化候选，检查旧支持和旧反例是否保持 |
| 融合后丢掉旧反例 | 回退融合或缩小融合范围 |
| 某来源撤回，仍有独立来源支持 | 局部减少支持，不全删共享结构 |
| 只是路由不典型 | 后置尝试，不冒充科学反驳 |
| 预算不足 | pending，不宣称全库已经一致 |

其中最关键的原则是：

**撤销一个固定实例的普适性、保留它的局部证据、保留可重绑模板，是三件可以同时成立的事。**

当前 replay 的问题，正是没有在所有路径里保持这个区分。

# 八、结合 AWM 与 RSI，我对项目下一阶段的判断

AWM 对这个项目最直接的启示，是结构重组必须保留已经测试出来的支持与拒绝区别。合并不能丢失反例，无法识别范围也不能自动抹去仍有依据的局部知识。当前阶段可以先落实这一原则，无须因此追加 Lean 工程。[arxiv.org](https://arxiv.org/html/2610.40503v2?utm_source=chatgpt.com)

AIDE² 的研究协议强调固定预算、隐藏评价和外部未见任务，并保留对外层自改进比较的不确定性。这提醒我们：**自主产生修改、修改被采用、修改提高研究效率，需要分别证明。** Gemini 按人工审计修改项目，不自动构成系统自身方法层 RSI 的实证；假设层递归可以先作为较窄的成果验证。[arxiv.org](https://arxiv.org/html/2609.26457v1?utm_source=chatgpt.com)

我对这一版的最终定位是：

> **V14 已经拥有值得保留的真实自主修订机制，也开始提供可信的负结果。下一步应补齐对象干预与知识更新语义，再研究哪些经历、哪些任务分布和哪些资源条件下，递归假设维护确实值得做。**

下一版最有说服力的交付，应当能从机器事件直接生成这样一段事实：

> 系统在 E1、E2 后形成 H@v1；E3 否定了其某个具体绑定或范围；它据此形成 H@v2，并完成哪些新确认与历史分支检查；在未见任务 T 中，这个版本或其合法派生实际改变了哪个研究动作；允许强普通方法从相同经历重建后，双方完成率、假确认与全部资源差分别是多少。

如果对象没有形成、检查没有完成、没有实际采用，或者普通方法打平，就在相应位置如实写出。**这仍然是本项目下一轮最应该完成的目标。**
