## 1. 直接结论

**V14 取得了实质进展，但用户的主目标仍没有完成。** 现在已经能够承认：普通研究产生了具体的新修复假设，真实子问题可以改变父程序，部分未见目标确实采用了该修复来源的合法派生。上一轮关于生产证据接口、延期问题没有消费者、修复后没有再调和等批评，不能原封不动沿用。

目前尚不能承认的是：

1. 所有真实来源历史都能在普通按需重建与预先调和之间得到等价的范围、反例和调用资格。
2. D3 已经完成了真正的单对象移除，并证明修复对象的独立效用。
3. 每条链都能从原始事件准确回答“为什么修订、为什么分支共存、后来谁使用了它”。
4. 递归修复在强普通方法拥有相同合法能力和预算时，已经稳定提高未见问题的研究效果。

这四点并非要求扩大研究目标。它们分别对应上一轮合同已经要求的语义一致性、真实干预、事实账本和净效用。

**建议的项目定位：已有可执行的自主假设修订研究原型；部分连续生命周期已成立；完整解释与因果效用尚待补齐；当前递归策略的平均净收益没有成立。**

## 5. D3：同一修复对象的连续性确实前进，效用仍未证实

### 5.1 新假设是什么

6 条连续来源链中，1041000、1042000、1044000、1046000 产出了合格的含 accumulate 的修复对象；1043000、1045000 未产出合格对象，保留在分母是正确做法。

以 1041000 为例：

- 先有普通马尔可夫来源与已确认分支。
- 新 focal_memory 研究暴露原候选无法解释的历史依赖。
- 真实子问题记录了父程序 before/after，修订后程序含 accumulate。
- 保存为 concept_0004，分支语义版本 323e791fc0e2d6e540fbbc1a。
- 记录了新的 24 行确认；最终 episode 确认损失约 1.30e-16，外部 48 行约 1.23e-16。
- 后继 N=5 任务中出现了以此来源生成候选并最终采用其合法派生的结构化事件。

这是**既有语法与研究器内形成的新可执行机制假设**。不必要求系统自己发明 accumulate 原语，才允许承认它学到了新假设；同时也不能把这解释成系统自主发明了潜变量研究算法。[S7]

### 5.4 整个来源到后继的普通端到端基线尚未运行

## 6. P0：名义上“删除修复对象”的实验没有真正移除可执行对象

D3 建臂函数在第 953–978 行移除修复 meta_prior 和分支，但概念删除仅在 concepts 是 dict 时执行 pop。

固定提交 memory.py 第 180 行却明确把 concepts 定义为 list。abstracts、definitions、definition_bindings 也没有在该干预中清理。UnifiedResearchAgent._recall 会通过这些结构召回概念；meta_prior 存在与否并非必要门槛。[S4][S8][S1]

本次提取原始建臂函数、使用真实 list 形状的最小控制结果：

| 存储层 | concept_0004 是否残留 |
|---|---|
| meta_priors | 否 |
| active branches | 否 |
| concepts | **是** |
| abstracts | **是** |
| definitions | **是** |
| definition_bindings | **是** |

因此当前组并不是“完整移除修复版本及其独占可执行派生”。另外，该组还把 on-demand family/routing reconstruction 设为 False；保留目标内 latent 搜索 API，不等于允许从相同来源历史重新建出该知识。

准确结论应为：

**当前实现的干预没有观察到完成率增益；但它不足以判定完整修复对象的因果边际价值。**

不能因为删除失败就反过来声称对象一定有效。也不能禁止普通方法重新建出同样知识来制造正结果。

下一步只需实现按版本的最小移除：清理所有独占的可执行载体和缓存，保留原始经历、其他独立支持来源和合法重建能力；重新生成的等价对象允许使用，重建费用照实计入。现有 without 方法可供参考，但不能不加检查地删除所有后代，误伤多源独立支持。

## 7. P0：普通重建与在线调和仍采用不同知识语义

D2 的 R/K 来自同一来源库、拥有相同原始历史，目标冻结 branch writes。我按源概念统一了 branch: 与 archive_src: 的名称差异，再比较每个目标**首次消费**的 dispatch。24 对任务身份、episode UID、目标角色和完整 observable_regime_features 全相同。

但以下判定仍不同：

| 字段 | 存在差异的配对数 |
|---|---:|
| scope_claim_level | 24/24 |
| support_invalidated | 18/24 |
| empirically_excluded_on_context | 20/24 |
| empirically_excluded_bound_instance_only | 7/24 |
| not_scheduled_by_router | 10/24 |
| scope_not_established | 7/24 |

例如 1031000/T1，相同 48 条转移摘要下，R 将 concept_0001、concept_0005 列为支持失效，K 没有；R 将 concept_0002、concept_0004 作为 refittable_template，K 对应为 bound_instance；两者路由延期也不同。两臂本题最终均通过。

这不是单纯 ID 不同，也不是把目标开始与目标结束的状态错位比较。回执没有导出全部目标前预测程序，故不声称每个预测函数都不等价；但足以否定“范围、支持和调用资格已经完全相同”的概括。[S6；同包 scope_replay_receipt_comparison.json]

源码上，K 在线经 reconcile_competing_branches 逐步调和，R 先从现有 priors 重建分支，再走另一套 replay 判断。共享末尾 refinement 函数不能自动使前面的状态转移一致。

V14 有一个三分支的小型语义等价测试，检查预测点与 guard，应给予认可；但是生产 Replay D 的 passed 主要检查 cache hit、哈希变化和跳过 H* 构建，并没有验证实际 D2 来源末态。

**D2 当前可以称为两种完整组织策略的比较；不能称为同一语义状态、只改变提前或按需维护时机的单因素比较。**

## 8. P0：replay 仍把“无法识别范围”升级为整个分支失效

这是第 7 节之外可以独立复现的语义漏洞。

replay_evidence_batches_onto_branches 第 3917–3944 行：

1. 某个固定实例在新批次上失败。
2. 尝试通过可观测摘要分离支持与反例的范围。
3. **只有缩域成功，才检查模板是否合法重绑。**
4. 没有识别出范围时，直接把分支置为 refuted 或 contested_refuted_on_probe。
5. dispatcher 随后按同源对象排除其调用资格。

本次最小控制中，真实 shrink 函数返回 scope_unidentified；replay 却将旧分支置 refuted；模板检查调用次数为 **0**。控制中提供的模板检查桩被设为返回重绑可行，但实际未被调用。旧来源的独立支持并没有消失。[S2；同包 probe_scope_replay.py 与结果]

“现有观测特征不能区分两个范围”可以意味着缺少状态变量、历史信息或合适的区分实验。它不能直接推出“所有合法重绑定的模板均错误”。

如果旧声明确实声称该固定实例在所有情形都成立，一个真实反例当然可以撤销这项普适性。这里的实现问题在于：它同时取消了仍有局部支持的可复用来源及其可重绑模板的资格，而没有完成模板层的检查。修复不能恢复已经被反例否定的普适性，应保留的是有证据的局部支持与尚待检查的模板。

应保留旧来源支持，只记录当前版本/绑定/上下文的反例；范围未知则进入待检或延期状态。若要取消模板资格，需要检查其声明允许的重绑域。该修复应进入 K/R 共用的状态转移逻辑。

控制使用了显式依赖桩，没有证明此路径解释了全部真实 D2 差异或某一题的胜负。修复后应以实际来源批次定位影响，不做超出证据的归因。

## 9. P1：消费与解释账本仍不能直接视为事实证明

### 9.1 4/4 使用判据实际上是字符串出现

脚本第 1334–1338 行把修复 cid 是否出现在全部 actions 的 JSON 字符串中作为 invoked_repaired_object。ID 在候选目录或审计信息中出现，并不意味着该对象生成候选、被选中或改变实验。[S4]

按专门的结构化消费事件，T1 中存在“修复来源生成候选 → 最终采用”记录的链：

| 臂 | 明确的结构化来源采用 | 仅字符串标 True、缺少该来源采用事件 |
|---|---|---|
| K_eager_noH | 1041000、1044000、1046000 | 1042000 |
| R_lazy_noH | 1041000 | 1042000、1044000、1046000 |

缺埋点不能直接证明绝对没有使用；但现包不能据此证明所有四条都使用了该对象。最终候选 ID 与初始候选 ID 不同也不自动否定使用：合法参数重标定会产生新候选，V14 已有 provenance 传递，应保留这类合法派生的归属。

### 9.2 调和已被调用，但具体决定没有导出

脚本筛选的 action 名是 autonomous_reconcile_library_episode，真实 action 是 autonomous_branch_reconciliation；读取 status，而实际状态主要在 epistemic_status。

结果是：

- 六条链的 initial_conflict event 都是 status:null、decisions:[]。
- 四条成功链的 post event 虽然 executed:true，状态和决定仍为空。
- D3 JSON 没有完整保留相应原始调和事件，无法从现有包恢复具体分支判决。

应当表述为“生产已接再调和，但 D3 的解释证据没有完整导出”，不能误判为引擎仍然没有该调用。[S1][S2][S4]

### 9.3 两条失败链仍被写成成功故事

1043000、1045000 没有合格修复对象，外部 MSE 约 0.03976、0.03268，却仍生成：

“Repaired object None passed an independent fresh 24-row confirmation …”

这是七句账本由无条件模板生成的错误。保留原始失败是优点；给失败配成功文本则破坏用户最关心的解释能力。下一版应从结构化事件按状态生成文字，缺证据时明确写缺失，不补一段看似完整的故事。

## 10. 其他需要一次性修正的有限问题

### 10.1 缓存仍漏两个实际依赖字段

内容哈希纳入了观测、转移、协议等，但不包含 replay 实际使用的 radius_value 和 commitment。最小控制中只改这两个字段，哈希不变；改 observation.target 则会变化。

这可能在语义修订后复用旧缓存。冻结的 D2 中没有证据证明发生过此类编辑，不能用它否定全部成绩。补齐依赖字段及对应控制即可，不需要新缓存架构。[S3][S2]

### 10.2 episode 分母与报告表格

D2 有 112 条臂—episode 记录，D3 有 120 条，合计 **232**，不是 214。按任务实例去掉实验臂后的唯一 episode UID 为 **106**，两个交付没有 UID 重叠。214 恰好等于漏掉 D3 的 6 个锚点和 12 个普通来源，不能叫“源去重”。

232 次判定中，207 次内部确认并严格通过、25 次未决/未确认、0 次内部确认但外部失败。它们不是 232 个独立研究样本，统计单位仍是来源簇。0 假确认是本批有限评价的好结果，不是任意新世界的无错误保证。

上传 Markdown 的少量表格数值与 JSON 不一致：

| 指标 | Markdown | JSON 与逐题重算 |
|---|---:|---:|
| D2 锚点平均计算 | 82193.6 | 114263.125 |
| D2 锚点运行墙钟 | 4.31 秒 | 6.39594 秒 |
| cold 目标平均测量 | 3962.5 | 4032.5 |
| R 目标平均测量 | 4095.6 | 4122.5 |
| K 目标平均测量 | 3893.1 | 3932.5 |

主要成功率和目标计算均值正确。应修正手写表，不必将其扩写成原始回执全部失效。

### 10.3 “零错误迁移”不等于没有负迁移

wrong_transfer 的定义要求“采用知识且内部确认后外部失败”。因此没有假确认时该指标自然全为 0，不能覆盖错误召回、多耗计算或增加未决。

scope 汇总还读取了 scope_unknown_branch_ids / excluded_out_of_scope_branch_ids，而 dispatcher 实际输出 scope_not_established / empirically_excluded_on_context。当前汇总的零值不能证明没有未知范围或范围排除。修字段映射并保留原始 first-dispatch 即可。[S4][S2]

### 10.4 H* OFF 的范围要说准确

本轮各实验臂显式关闭 H* 前置，R 目标重建确实跳过家族构造。但 K 来源维护仍有反统一与融合检查，它们已经计入维护账；引擎个别 getter 的默认值也仍为 True。

不能说这是假省略成本。更合理的后续优化是：若没有预定消费者，就不强制支付来源期家族构造费；把“实验关闭前置”与“全系统默认不构造”分开描述。[S2][S4]

## 11. 对“提出—验证—修订—分支—融合—复用”的整体判断

| 生命周期环节 | 当前证据 |
|---|---|
| 从普通经历提出具名可执行假设 | 已有实例，D3 四条合格修复链 |
| 真实失败促使新表示/机制研究 | 有父 before/after 与子问题记录 |
| 独立新确认 | 已有真实批次与预算路径 |
| 新场景重绑、修订、局部适用 | 主路径已实现，replay 仍需防止过度撤销 |
| 与历史分支重新检查 | 调用已接通；D3 逐分支决定导出不足 |
| 自主决定共存、融合或撤回 | 引擎具备相关算子；本轮连续链尚不能充分展示每个决定及其证据 |
| 未见问题调用同一修复来源 | 部分链有结构化候选与采用事件 |
| 同历史强普通基线允许重建 | R 主比较已明显加强；纯语义等价和对象移除臂尚不完整 |
| 明确证明某个新对象提高未见研究效果 | 仍未成立 |
| 持续、自主的研究方法层 RSI | 本轮不构成证明，也不是这次最小验收的前提 |

不能因为没有最后两项就说前面全无进展；也不能因为前几项已执行，就宣告最后两项完成。

## 12. AWM 与 RSI 对此项目的具体启示

AWM 的结构重组要求保留已测试的支持和拒绝区别。对本项目最直接的启示是：合并或重建分支时，不能因结构压缩丢掉原反例；也不能因当前摘要分不清两个范围，就抹去一个仍有真实支持的可重绑模板。模型内部的检查正确与模型是否充分描述环境仍是两类问题。本项目此刻无需追加 Lean 工程，先把已经拥有的证据区别保留下来。[L1]

AIDE² 对研究方法层 RSI 使用固定预算、隐藏评价和外部未见任务；论文也明确保留外层 ignition 比较的不确定性。对本项目的启示是：自主生成改动、改动被采用、改动提高研究效率，需要逐层证明。Gemini 根据人工审计修改代码，不能自动成为系统自身方法层 RSI 的实证。假设层的递归修订则可以先作为独立、较窄的研究成果成立。[L2]

这两条原则支持当前收口方向：保留诚实负结果，补齐因果链，不通过弱化普通方法或扩展框架来掩盖现有无增益。

## 13. 下一阶段方向：有限修补后，研究“何时值得做”

### 第一阶段：把剩余证据与状态错误关掉

只做四个有明确输出的工作包：

1. **真实移除与事实导出**：按版本移除所有独占可执行载体；保留重建能力；用结构化采用事件替代字符串；修调和字段、失败叙述、分母和表格。
2. **同历史状态一致性**：让在线与 replay 共享同一状态转移规则，或明确放弃“纯时机单因素”表述；修 scope_unknown 到全局 refuted 的跳转。
3. **有限缓存依赖修复**：补 radius_value/commitment 等实际语义输入，不另造缓存层。
4. **用已曝光案例回放受影响链**：1031000 的 R/K 首次消费差异、1041000 的对象移除、1042000 的消费计数、1043000/1045000 的失败账本、1037000 的准确模型未决状态。修复前后保留同一实例，不重新称未见验证。

工程验收不要求这些科学任务全部成功；正确输出未知或失败完全可以通过工程验收。

### 第二阶段：不再默认对每次研究支付全套递归维护费

D3 的计算增加不是靠“更多调和”自然解决的。应基于已曝光轨迹，先把额外成本拆成对旧分支评价、重复拟合、区分实验、修复、确认和后续维护。找出真正重复或不被消费的工作。

推荐研究的具体策略是：已付证据足以触发某个合法机制研究时，不必先穷尽全部历史分支；没有可区分的竞争假设、没有预算、没有后继消费者时，保留 pending，允许普通研究继续。必要的科学状态一致性检查仍需执行，昂贵的优化性抽象可以按需进行。

策略必须是可比较的候选。普通基线也可使用相同信息与策略；否则得到的是新调度器的收益，不能全部归于持久假设组织。

### 第三阶段：分开回答组织价值与整个研究流程价值

- **同历史条件实验**：双方拿到相同完整原始历史，使用相同程序/范围更新语义；只改变提前存储或按需重建。该实验估计持久组织的价值。
- **自主全流程实验**：普通方法使用自己真实形成的库，递归方法使用自己的库，双方在相同任务、合法 API 和预算下运行来源到后继全过程。该实验估计整个研究策略的价值，允许两者探索轨迹不同。

不要把两个实验的片段拼接。后继任务数、顺序、旧域回访和机制变化频率须在看结果前固定；延长复用跨度只有在真实应用确实会有这么多后继任务时才有意义。

如果正确干预后仍打平，应接受“当前小库和既有强研究器下，持久修复对象的额外效用有限”。此时可以保留可审计研究系统的成果，暂停更强效用主张；若要进入更复杂机制或开放语言提案，应单独提出有实际需求的新研究命题。

## 14. 最终验收句

下一轮应当能够从机器事件直接生成：

“系统在经历 E1/E2 后形成 H@v1；证据 E3 只否定其绑定 b1，留下可重绑模板；新子研究形成 H@v2，经 E4 新确认后与历史分支完成哪些具体检查；在未见任务 T 中通过哪条候选来源改变了哪个动作；允许普通方法从同样历史重建后，完成率、误确认和全部资源差分别是多少。”

如果对象未生成、调和未完成、没有实际采用，或普通方法打平，这句话必须如实写出。**可信地回答这一句话，比再增加一个“全闭环”标签更接近用户原来的目标。**
