## 4. 交付三：统一范围状态与重放规则

### 4.1 先修 replay 的局部失败过度撤销

修改位置：branch_reconciliation.py 的 replay_evidence_batches_onto_branches，尤其当前第 3917–3944 行；以及 dispatcher 对状态的解释。

当前流程错误：

固定实例失败 → 无法识别缩域条件 → 整支 refuted → 同源模板一起被排除。

所需行为：

| 观察 | 实例资格 | 模板资格 | 后续动作 |
|---|---|---|---|
| 固定版本在某已执行批次错误 | 该绑定/上下文有反例 | 仍待合法重绑检查 | 保存版本、绑定与证据 |
| 重绑可解释新批次 | 旧绑定继续限域 | 模板保留 | 新实例/参数版本，重新确认 |
| 有支持和反例，但摘要分不开 | 当前范围未识别 | 不因此撤销 | unknown/deferred，必要时提出区分实验 |
| 有限搜索没找到解 | 已执行搜索的结果保留 | search_incomplete | 不推导全部模板不可能 |
| 声明域下完整检查已不可行 | 对应域的实例排除 | 对应模板域排除 | 保存完整性依据 |
| 预算不够 | 不产生新增科学判断 | 不产生新增科学判断 | 保存待处理成本与证据身份 |
| 所有竞争实例都失败 | 局部失败 | 依各自模板证据判断 | 表示/机制子问题，或诚实延期 |

“支持有效性”“某上下文可用性”“调度优先级”保持独立。未知范围可以降低使用资格，但不能伪装成全局科学反驳。

一个真实反例可以撤销固定实例的普适性声明；保留局部来源支持或可重绑模板不等于恢复该普适性。状态与 dispatcher 必须分别处理这两件事。

### 4.2 一套状态转移，两种执行时机

上一轮合同的同历史比较，要求相同知识更新语义。建议在现有 branch_reconciliation.py 内复用一个核心转移入口：

输入：先前知识状态、一个真实 EvidenceBatch、当时已经存在的候选及版本、合法重绑域、预算。  
输出：新的状态、未决项和真实 decision 事件。

在线 K 在每个来源经历后调用；R 在需要时按相同时间顺序重放。R 可使用缓存、去重、批处理等语义等价的加速，不必机械重复每个中间步骤或支付相同费用。R 不能先把未来才产生的全部来源都初始化为 universal，再用不同规则回放历史，而仍声称与 K 只有构建时间不同。

无需逐字要求内部 ID 一样。使用 source/version 对应关系比较：

- 合法绑定下的实际预测；
- instance 与 template 的资格；
- scope guard 的 accept/reject/unknown；
- 原始支持、反例、撤回对象的归属；
- 未决问题和独立支持边；
- 路由顺序及其依据。

若确实希望保留两套组织算法，允许这样做，但实验名与结论须明确“完整策略比较”，不再单因子归为 eager/lazy 的时机差。

## 6. 分支增多后的修订、融合与撤回规则

下表是既有逻辑的验收语义，不要求新对象层。

| 情况 | 决策 | 不能省略的证据 |
|---|---|---|
| 同一结构，参数换了即可解释 | 新参数实例或局部修订 | 旧绑定反例、新绑定的独立确认 |
| 两个分支范围明确不重叠 | 共存 | 可观测范围与各自支持 |
| 范围重叠，预测不同 | 做合法区分实验 | 事前冻结版本，实际 probe 与结果 |
| 一支通过，一支失败 | 限制失败实例/相应模板域 | 已执行的反例和完整性边界 |
| 两支都失败 | 形成遗漏机制/表示子问题 | 共用失败数据和所需返回对象 |
| 暂时找不到区分观察 | 保留未决关系 | 未找出区别不等于等价 |
| 可提取共享结构 | 形成一般化候选 | 旧支持覆盖、已测试拒绝保持、独立来源 |
| 融合使旧反例变为可接受 | 回退融合或缩小范围 | 丢失的是哪一项区别 |
| 旧来源撤回但仍有独立来源 | 局部减少支持 | 其余支持根仍然有效 |
| 新域之外仍有旧支持 | 旧支保留，当前资格待定 | 不把局部反例升级全局删除 |
| 只是路由不合典型 | 降优先级 | 仍允许有预算时尝试 |
| 维护预算耗尽 | pending，暂不声明全库一致 | 尚未比较的邻居/依赖 |

使用结构签名索引筛选相关邻居，可以减少比较数量；签名负责决定先比较谁，不直接充当正确性判决。每次修改只检查受影响的邻居、支持根与已测反例，不默认全库重新研究。

## 7. 完成以上修补后的研究方向

### 7.1 先做成本剖分，决定是否值得继续

V14 的观测—计算取舍是真实结果。下一轮不应把“更多递归层”作为自然目标，应逐链记录这些费用：

- 原始研究与探针；
- 对历史实例重复评分；
- 区分实验；
- 参数重绑与新机制研究；
- 新确认；
- 分支调和和索引/家族构造；
- 后继重建与消费。

优先优化真实重复工作和没有消费者的来源构造。H* 前置关闭时，如果未来消费者也不使用 H*，来源期反统一默认按需；是否保留压缩价值另列，不把它冒充任务求解收益。

建议的选择逻辑：

只有当预计避免的后续重建/搜索费用及错误减少，大于额外探针、修订、确认和维护费用时，才提前做昂贵组织。未知时先保留可恢复的 pending 或按需计算。概率、复用次数和资源权重只能来自训练/开发经历或预先给定的应用工作负载，不能读取未见任务隐藏机制。

这不是已经验证过的优胜算法，而是下一项可被否证的具体研究假设。

### 7.2 值得试的一个小策略改动

在已付观察已显示历史残差、普通 latent API 可以直接尝试时，不强制先穷尽所有旧马尔可夫分支；允许局部证据触发合法研究器。对不具区分价值的成对检查早停，把剩余额度留给新确认。

同时保留一个共享此调度规则的强普通方法。否则即便更快，也只能归因于新的调度策略，不能归因于持久假设组织本身。

这是条件式预算安排，不是硬编码“看到 focal_memory 标签就调用 latent”。合法输入是已付观察、残差、预算和已有对象，不是隐藏世界类型。

## 8. 两个研究问题分开实验

### 8.1 E1：同历史的持久组织是否有价值

| 项目 | R 按需组 | K 持久组 |
|---|---|---|
| 初始研究器、合法 API | 相同 | 相同 |
| 完整原始来源与反例 | 相同、可重放 | 相同、可重放 |
| 程序/范围状态转移 | 同一实现 | 同一实现 |
| 目标确认和预算 | 相同 | 相同 |
| 已有派生产物 | 首次需要时构造，之后缓存 | 来源期构造并保存 |
| 重建权限 | 全部保留 | 移除干预中也保留 |
| 计费 | 原始历史共同项单列，按需工作按实计入 | 来源维护按实计入 |

cold 可作为参考锚点，不替代强 R 主比较。真正删除修复版本的组主要用于对象归因，不需要每轮无限新增消融。

对三种现有后继任务继续保留：相容新参数/新布线、返回旧域、相近但不适用的反例域。任务顺序预先固定或平衡，因为 cache 冷暖会改变费用。

### 8.2 E2：从来源研究开始的整个策略是否更好

普通方法使用它在来源任务中**实际形成**的库继续后继研究；递归方法使用自己的实际库继续。两者具有相同初始信息、任务、API 和资源约束，允许自主探索轨迹不同。

必须保存一条完整来源—后继轨迹。不能把 E1 的共享来源条件与另一轮普通父修复成本拼接起来。

这一实验比较整个研究策略；信息路径不同是策略的结果，因此不再称“固定完全相同历史”的单因素试验。E1 和 E2 各回答一个必要问题，不相互替代。

### 8.3 前瞻集合与统计边界

先完成工程回放，再固定代码与实验清单。当前 103/104 系列全部退入开发材料。

下一次新样本数应由已曝光来源簇的配对波动、拟检测的最小有意义收益和可用预算预先确定。不因为看到两三个成功就停止，也不持续加样本直到显著。资源只够少量簇时，结果保持为案例/描述性试验。

可以预先比较后继长度 k=1、3、6 的前缀，但 k=6 只有在真实工作负载预计会出现六个相关任务时才有经济含义。不能延长到刚好回本，再回头宣称一般收益。

## 9. 效果指标与判定规则

### 9.1 质量与可交付性分开记

- 准确模型是否已经找到。
- 最终状态是否合法 completed。
- 独立确认是否完成。
- 外部严格通过、假确认、未决。
- 旧域保留与新增错误硬排除。
- 失败原因是研究、范围、预算、确认还是状态实现问题。

1037000/T3 已说明只看成功布尔值会丢掉重要诊断信息，但不能据外部结果倒填内部成功。

### 9.2 效用分资源报告

按来源簇输出：

- 全部来源形成和维护成本。
- 目标计算、观察、测量、墙钟。
- 冷缓存与暖缓存。
- 前缀成本差、均值、中位数和每簇胜负。
- 所有失败尝试，不能只选双成功子集。

若需要一个经济效用分数，先固定资源价格和质量约束。没有业务资源权重时，优先报告 Pareto 取舍，不能事后选择最漂亮的指标。

### 9.3 研究结论的四级门槛

| 结论 | 所需证据 |
|---|---|
| 机制已实现 | 真实生产路径和数据结构控制通过；未知、预算和版本语义一致 |
| 某对象被实际采用 | 可追溯版本/合法派生的生成、选择、确认事件 |
| 某对象帮助了具体未见任务 | 同历史、同能力对照和真实初始对象移除；结果能定位到具体行为变化 |
| 给定工作负载上持续有净价值 | 预先冻结新簇、质量约束、全成本和簇配对不确定性支持 |

一个指标 p>0.05 不等于等价或非劣。若要更强统计结论，预先定义质量容忍差及效率最小收益，报告对应置信区间；预算不足则明确不作总体推断。

## 10. 停止与分支决策

1. 修补后普通方法仍打平或更好：接受有限效用结论，不削弱普通方法。
2. 只有降低观测、增加计算且成功率更低：保留资源取舍，除非实际应用明确重视昂贵观测，否则不默认启用。
3. 只有少数昂贵路径获益：研究可观察的触发条件；不能用测试实例 ID 或隐藏类型做路由。
4. 只有可追溯性改善：将它作为审计/解释能力成果，暂不写研究效率提升。
5. 真实对象移除后仍快速重建：说明当前强研究器下可压缩/可重建知识的边际价值有限，不是要求禁用重建。
6. 当前有限语法空间已经足够容易：先结束该命题的验证。若进入新机制组合或开放语言研究，应有独立的实际需求、评价和预算，不能仅为获得正例。
7. 方法层 RSI 等到假设层的身份、证据、更新和效用合同稳定后再研究；每次策略更新仍须面对冻结的强普通基线和未见任务。
