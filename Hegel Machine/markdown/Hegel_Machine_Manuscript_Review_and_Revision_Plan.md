## 一、总评：已经有实质论文内容，但不建议把当前版本直接视为最终投稿稿

我的建议是**大修后投稿，而不是推倒重做，也不是继续扩张系统范围**。

这版稿件已经从早期“通用假设框架的愿景”转向了真正可研究的命题：

> **撤销一个程序作为当前预测器的资格，不等于删除该程序作为后续研究资源的价值。这个区分同样适用于预测程序和研究程序。**

稿件据此展示了 acquisition、failure、repair、return，以及研究方法的学习、修改、回忆和再次执行。这是值得保留的科学主线。[稿件 §1、§3.4、§4.9，pp.2、6、14]

当前最主要的问题不是缺少更多功能，而是：

1. 尚未充分隔离“显式假设状态和依赖管理”的价值与“普通程序库、回滚和热启动”的价值。
2. 最强正面结果主要来自受控数值研究器；最完整的共同模型 Agent 比较没有优势。
3. 方法修订、回忆和新任务使用尚未在一个统一冻结的、多环境研究序列中形成完整证据链。
4. 58 页包含大量不同版本、不同队列和开发修复，读者难以迅速识别一个核心算法及其最有力证据。

### 适合的当前定位

**有明确概念区分、机制干预和正负证据的累计研究框架论文。**

### 尚不适合的定位

- 已证明通用 Agent 优越性的算法论文；
- 已建立可靠长期递归自增强的 RSI 论文；
- 以泛函分析新定理为主要贡献的理论论文；
- 实现了最初全部黑格尔机愿景的完成报告。

这不是否定研究价值，而是把论文的结论与现有证据对齐。稿件的限制部分实际上已经做了大量正确的限定。[稿件 §7、Appendix F.10，pp.30、53–56]

## 二、真正值得放在最前面的贡献

### 2.1 接受、保留、再利用，是三种不同决策

论文最有辨识度的不是“Hegel”这个名称，而是：

\[
\operatorname{AcceptPrediction}(p,s)
\neq
\operatorname{RetainComputation}(p)
\neq
\operatorname{ReuseInRepair}(p).
\]

例如：

\[
C=A+0.7B,
\qquad
D=C+0.7(B'-B).
\]

当环境中的事件机制改变，关于“C 预测当前响应”的命题可能失败，但 C 的程序仍可参与构造 D，并在旧条件返回时重新成为有效预测器。[稿件 §1、§3.4、§5.4，pp.2、6、17–19]

这是比“不能删除旧知识”更准确的主张：**允许撤销真值承诺，同时保存有条件的计算价值。**

### 2.2 不同知识对象已有可分离的干预

§5.7 中的 procedure intervention 保持程序库相同，仅清除方法书，然后改变仪器名称、单位和顺序。两组均 30/30 成功，但保留方法减少观测和计费计算。这比单纯比较有记忆与无记忆，更接近识别“怎样研究”的独立价值。[稿件 §5.7，pp.21–22]

### 2.3 子问题返回值确实改变了尚未执行的父实验

图 6 和 §5.10 不只是给已完成拟合补一张依赖图。子问题的坐标答案使父问题修改下一次 probe，从无法区分两个候选，变为区分四个候选。稿件另有干预返回证据、使父推断改变并被新确认拒绝的机制测试。[稿件 §5.10、Figure 6，pp.25–26]

这比早期 post-hoc dependency graph 更符合题名中的 recursive research。

### 2.4 LLM 修改的是后续执行的研究程序

§5.13/Appendix F.6 中，作者看到父响应反例后修改研究方法，冻结新方法，在不继续调用模型的条件下进行迁移：10/18 变为 18/18，且原本成功的十个任务保持成功。[稿件 §5.13、Appendix F.6，pp.27、44–45]

这是当前最值得强化的元层证据。它不是“某次答案被改对”，而是一个处理未来失败的程序发生了变化。

### 2.5 负结果被准确保留

稿件没有把以下结果藏起来：

- conditional feedback 与 unmarked retention 完全相同；
- recursive 与 strong flat control 都能成功；
- 普通 Code/Text 的共同模型结果优于 Hegel 的完成数；
- 新知识可能只增加筛选成本；
- 计费计算下降但实际 CPU 上升；
- 模型有时不采用已提供的有效方法。

这有助于可信度。问题不在于这些结果应该被删除，而在于应当用它们收紧和组织贡献，而不是让它们成为散落在长附录中的补充说明。

## 四、最重要的审稿问题：与普通程序库、版本控制和修复系统相比，增量是什么？

### 4.1 现有 deletion 对照正确，但只能回答有限问题

删除 C 和其依赖知识，会同时改变可用宏、搜索起点和某些研究路径。保留组优于删除组，说明所保留资源整体有价值；不能单凭这一结果归因给特殊的作用域语义或假设管理机制。[稿件 §5.4，pp.17–19]

稿件自己的 unmarked-retention 对照已经给出关键答案：

\[
\text{Conditional retention}
=
\text{Unmarked retention}
\]

在所有实例和后继阶段中，终测误差与计费成本相同。由此应明确：

> **这组主要收益来自保留可执行知识，而不是新增的 conditional 标记。**

这是论文目前最重要的可归因边界。

### 4.2 最缺的对照：同样保留全部代码，但没有特殊假设语义

建议增加一个强而朴素的基线：

> **Executable archive + revalidation + local repair**。

该组与 Hegel 共享：

- 相同历史程序和测量数据；
- 相同版本来源、执行权限和实验菜单；
- 相同候选表达能力、搜索和资源上限；
- 相同 fresh confirmation 与最终评价。

差别是它不采用 Hegel 特有的 supporting-obligation 管理、特殊 applicability 记录和递归研究控制；它可以对旧程序重新评价、回滚、拟合残差并执行普通修复。

这才更接近回答：

\[
\text{Hegel-specific organization}
\quad\text{相对}\quad
\text{generic executable memory}
\]

究竟增加了什么。

若两者相当，论文仍可以保留“框架与机制”贡献，但不应把优势归因给尚未显示独立收益的结构。

### 4.3 保留 call 不等于证明不可替代的知识继承

\[
D=C+0.7(B'-B)
=A+0.7B'.
\]

这并不否定保留 C 的价值，但意味着“程序中仍有 C 的调用”是操作性指标，不是唯一合理的认知继承定义。

建议区分：

- **精确调用**：是否执行同一历史定义；
- **语义保留**：内联、编译优化后是否仍保留同一功能；
- **研究收益**：它是否减少找出正确替代程序的成本。

可以加一个小型诊断：对语义等价的 retained-call 与 inlined/cancelled 表示，比较预测、搜索和执行成本。不要把编译优化消掉一个 call 当成“忘记知识”。稿件现有 11/12 direct-call 与 72/72 accuracy 的区分已经朝正确方向走了。[稿件 Appendix C.3，pp.34–35]

### 4.4 需要明确两类依赖边

建议在方法部分区分：

\[
E_{\mathrm{call}}\quad\text{与}\quad E_{\mathrm{support}}.
\]

`E_call` 表示一个程序调用另一个计算；`E_support` 表示一个经验结论的正当性依赖另一个命题。

撤销“C 预测当前环境”并不意味着 C 的代码不可执行，也不自动使所有调用 C 的新程序无效。相反，如果子程序源码改变、且父程序原先的证据依赖其旧行为，父结论的支持不能自动继承。

建议正文给出一个小的状态转换表：预测承诺撤销、程序保留、依赖待重验、新程序确认分别影响哪些对象。**这是把核心概念变为清晰算法语义，而不是再造证书基础设施。**

## 五、实验上的几个关键缺口

### 5.1 Abstract 的 180/180 vs 159/180 应突出真正发生分歧的后继任务

§5.4 的 180 个任务包含两组共享的 90 个学习前缀任务。因此依据稿件数字可以推得：

\[
\text{后继任务：retention }90/90,
\quad\text{discard }69/90.
\]

同时，预设 primary original-return accuracy 实际是三组均 30/30；准确率差主要发生在第一次改变后，30/30 vs 10/30。[稿件 §5.4，pp.18–19]

建议：

- 正文保留完整序列总成本；
- 摘要明确“共享学习前缀之后的后继任务”；
- 明确原条件返回的主要收益是成本，而非准确率；
- 不把次要终点包装成预先指定的准确率主终点。

这不会削弱数据，反而使干预估计更清楚。

### 5.2 删除组有大量未花完预算的失败，必须先解释停止原因

§5.4 报告：20 个首次修订失败中，16 个内部未解决，4 个错误确认；失败时还保有观测、测量和计算额度，紧凑记录尚不能识别共同停止原因。[稿件 §5.4，p.18]

这会让审稿人追问：

> 是保留知识真的降低研究难度，还是 deletion 后某条路由、重访或停止规则提前终止？

建议先做低成本 trace audit，不急着再花模型调用：

- 最后一次候选生成后有哪些可用动作；
- 哪项单轮/总轮数/确认保留约束导致停止；
- 删除动作是否额外清空研究程序或目标绑定；
- 是否存在可在剩余预算内执行却未执行的动作。

这是解释现有主要效果的重要补充，不应事后修复后覆盖原结果。新修复必须作为新版本另行实验。

### 5.3 Dense fixed basis 不是足够强的主要竞争基线

稿件已经明确承认：该基线以 48 个训练观测拟合 185 个系数，连属于其线性子空间的 conserved-total 任务也失败；它缺少自适应模型选择。[稿件 §5.3，p.17]

建议保留它作为算法特定对照，而不要把 0/180 用作主要优势展示。更强的有限族基线可以提供同样的结构候选、正则化或模型选择，并使用相同的全轨迹划分与确认预算。

这里不要求引入最昂贵的神经模型。关键是排除“对照的拟合配置本身失败”。

### 5.4 Task-local 比较中，资源池也随记忆状态变化

§5.3 中 full 可以把未使用的序列预算用于 revisit，而 task-local 保持逐任务预算。稿件诚实说明这是跨任务知识与资源分配的联合效应。[稿件 §5.3，p.16]

不应改写成“纯记忆带来 76.25% 收益”。若要分离，可补一个小的 2×2 诊断：

\[
\text{persistent knowledge on/off}
\times
\text{shared resource pooling on/off}.
\]

§5.7 更干净的相同表达能力比较和方法删除干预，已经能承担一部分主线，不必把所有旧对照重新做一遍。

### 5.5 递归机制有效，不等于递归比 flat 更好

§5.10 三组都 120/120 成功；递归组用 852 个观测，flat 用 647，但计费计算分别为 388,496 和 735,048。[稿件 §5.10，p.25]

这支持一个资源权衡，不支持一概优越。另一 temporal matched-repertoire 比较也得到相同准确率，而且 flat 以更多 response fitting 换取更少观测和测量。[稿件 Appendix F.2，p.40]

有两条合法路线：

- **机制论文路线**：明确只证明子证据能改变父实验，不要求这一章出现优势。
- **递归算法路线**：系统改变支持依赖的规模、共享子问题程度或结构，使 recursive 与 flat 的成本—性能曲线可以比较。

不要为了制造胜出结果而故意剥夺 flat 的关键实验或候选。

### 5.6 完整 LLM Agent 比较仍是负结果

Code、Text、Hegel 分别为 29/30、29/30、26/30。所有提交的预测器都通过独立评价，主要差别在完成研究的可靠性。[稿件 §5.11、F.1，pp.26、39–40]

这不证明黑格尔机没有价值，也不证明其内部推断一定更差。但它意味着：

> **当前稿件不能以“更强自主 Agent”作为已建立的主结论。**

后续少量已知任务上的开发修复，不能替代该完整共同模型比较。应保留注册分母，另外分解服务故障、资源耗尽、未提交与预测错误；不得只排除对某一组不利的故障。

### 5.7 8/10 vs 2/10 是一个状态上的回忆干预，不是通用元学习

F.11 的统计单位必须写为：

\[
1\text{ 个既有程序回归状态，20 次作者尝试}.
\]

它不是 20 个独立研究问题。两组未来确认流不同，因此本研究是相同预算下的局部可用性干预，不是配对随机轨迹对照。[稿件 §5.15、F.11，pp.28–29、56–57]

此外：

- 七次 unchanged publication 对应同一个已评价程序；
- 旧 12/12 target 结果仅引用一次，这是正确做法；
- 三份修改后的程序只有六个 source practice cases 的通过结果；
- 本研究没有新 transfer target。

**最低成本补强**：冻结这些实际产出的不同最终程序，对新生成、未进入 author feedback 的 transfer tasks 统一执行。不重复计数相同源码，不需要再次调用 LLM author。

这仍不能带来跨域结论，但能补上“新程序通过 practice 后能否泛化”这一直接缺口。

### 5.8 更强的元方法证据需要多 donor 与真正结构变化

10/18→18/18 是有意义的方法迁移，但一个作者学出的一个程序，在固定原语与参数变化上成功，不等于一般研究改进机制已经稳定。[稿件 F.6，pp.44–45]

推荐最有价值的一项新实验：

> 多个独立来源环境产生研究程序；冻结后，将这些程序移植到未参与 authoring 的任务结构或干预组合；比较相同基础任务知识下的后继研究。

样本量应依初步方差和最小有意义效应设计，不再由任意 gate 数量决定。

## 六、数学部分的意见：正确且克制，但不是深理论贡献

### 6.1 Appendix A 两个结论基本成立

A.1 正权 TV 加权和给出伪度量，并在观测等价类上给出度量；新增实验细分等价类。A.2 两个被表示合并却响应不同的确定性样本，会产生不可由重新拟合消除的平方误差下界。[稿件 §3.3、Appendix A，pp.6、32]

稿件把它们称为 elementary consequences 是准确的。不要再把这两条包装为“数学深度 10/10”或一个完整的泛函分析发现理论。

### 6.2 TV 在确定性点预测下会退化为是否相等

若：

\[
P_h^e=\delta_{f_h(e)},
\qquad
P_g^e=\delta_{f_g(e)},
\]

则：

\[
\operatorname{TV}(\delta_a,\delta_b)
=
\begin{cases}
0,&a=b,\\
1,&a\ne b.
\end{cases}
\]

因此，该理论距离可以描述可区分性，却不反映数值误差大小。它与实现中的预测跨度、MSE 和 pinball loss 不是同一对象。

稿件已在 §3.3 说明实际使用 disagreement 与 task losses，这避免了严重错误；建议再加一句明确上述退化，避免读者以为系统在算法上学习了 TV 几何。

若未来研究距离选择，可以另行定义有任务含义的差异，但本稿不必再增加一个新 metric learning 项目。

### 6.3 比添加更多初等定理更重要：明确支持如何传播

最能帮助论文的方法形式化是：

\[
\operatorname{Support}(p; s, D, v),
\]

其中 v 是实际程序版本，s 是作用域，D 是确认证据。更改程序、绑定或作用域时，哪些支持保留，哪些需要重验，应明确列出。

可给一个具体组合命题作为理论工作方向：如果支持的仪器误差有界、响应误差有界且响应满足适当 Lipschitz 条件，如何控制父预测误差；若仪器或响应之一改变，该界为何需要重新验证。

这只是建议方向，**不是本次审阅已经为当前算法补出的通用定理**。

### 6.4 Fresh confirmation 不自动产生长期错误控制

独立新数据能降低直接重用训练样本造成的问题，但“不断修改、不断测到通过”仍需控制多次选择，尤其在小样本噪声下。

条件性说明：若第 t 次验收对错误接受有条件概率界 α_t，则用 union bound 可得：

\[
\Pr(\text{序列中至少一次错误接受})
\le \sum_t\alpha_t.
\]

当前的固定 MSE 门槛并不自动给出这些 α_t。论文已经报告 false confirmation，因此不宜使用 statistical guarantee 的语言。[稿件 §7、F.10，pp.30、55]

两种合理处理：

- 本稿保持“新数据确认/经验支持”，报告误接受和序列累积风险，不承诺统一统计保证；
- 后续单独研究有明确零假设、抽样条件和序列控制的验证机制。

POPPER 已将这类统计验证作为主要贡献，因此若强调“形式验证更强”，必须与其具体保证逐项比较，而不是只比较假设是否结构化。[E1]

## 七、成本、统计和可复现性

### 7.1 计费计算下降不能简写为更快或更便宜

§5.7：计费计算降低 22.42%，实际 CPU 上升 17.92%。§5.3：总体 CPU 下降，但配对区间包含零且有尾部代价。[稿件 pp.17、21–22]

应保持向量报告：

\[
C=(N_{obs},C_{meas},C_{charged},t_{CPU},t_{wall},N_{tokens}).
\]

不要未经说明合成一个“总效率”。尤其须说明：

- learned call 是否按展开后的计算收费；
- fitting、screening、dependency evaluation、library lookup 是否计费；
- Python/宿主开销哪些未进入 charged computation；
- authoring 的失败调用、缓存输入与 unknown usage如何记账。

这些是计费合同的论文附录说明，不要求另造可信证书。

### 7.2 需要收益摊销边界，而非只给迁移阶段节省

研究方法学出来的成本为 C_learn，每次迁移平均节省 ΔC，则在成本可比且 ΔC>0 的假设下：

\[
N_{break-even}\approx C_{learn}/\Delta C.
\]

对观测、计算、时间、模型调用分别报告；无法统一换算时不要强行给一个数字。若节省量为负或不确定，应明确没有建立摊销回报。

### 7.3 统计已做对的部分要保留

稿件在主要数值队列中按完整 apparatus sequence 做分层 paired bootstrap，而不是把同一序列所有任务当独立样本；也记录了失败和预算未完成。这些设计应保留。[稿件 §5.3、§5.4、Appendix D，pp.16–19、35–36]

### 7.4 仍需补清的统计边界

- 哪些是预注册 primary endpoint，哪些是次要和事后诊断；
- 不同 snapshot、cohort、author phase之间不做隐含的因果比较；
- 重复使用历史 target 结果只计一次；
- repeated authors 与 independent apparatuses使用不同分母；
- 多次短 confirmation按整条轨迹而不是逐行独立解释；
- 同一故障状态的 8/10 vs 2/10即便做显著性计算，也不能推出跨任务普适性；
- source failure导致 target不可开始时，保留 registered denominator，再补 stage-wise breakdown。

### 7.5 PDF 中的复现链接需要修复

本次检查了 PDF 内部链接注释：共有 156 个链接注释，其中 105 个指向相对文件路径，PDF 未内嵌这些文件。包括：

```text
../artifacts/...
../src/...
figures/...
```

这不是说原始文件不存在，而是**单独分发该 PDF 时，这些链接不能可靠地将外部读者带到材料**。

建议：

- 为每个 study指定不可变 commit、release或归档标识；
- 用有效的永久访问位置替代本地相对链接；
- 提供一张 Study ID → code snapshot → protocol → raw results → analysis command 的表；
- 区分“重新跑研究”和“从保存结果重新生成论文表格”；
- 模型实验补齐服务接口、实际返回的模型标识、调用日期、reasoning参数、提示词、工具schema、上下文规则和限额检查方式。

不要以“gpt-6-luna + medium”一句话代替完整模型实验环境；也不要猜测该别名背后的未公开模型身份。

## 十、最有价值的一项新实验

### 10.1 目标

> **在相同任务知识和相同实验权限下，学到并修订的研究方法，能否使后继在未参与 authoring 的研究问题上更可靠或更省资源？**

这对应原始构想，而不是继续展示“程序能被序列化和保存”。

### 10.2 建议设计

多个独立 donor 环境产生研究程序。程序冻结后，分别移植到未参与 authoring 的消费者环境。保留或删除方法时，基础预测知识、当前付费证据和工具权限保持一致。

最低三组：

| 组 | 定义 |
|---|---|
| 完整 Hegel | 显式支持依赖、可执行历史、程序修订与主动实验 |
| 强通用 executable archive | 保留相同程序与证据，允许普通重验、回滚和修复；无特殊研究依赖管理 |
| 研究方法冻结组 | 同样程序知识与资料，禁止学得方法的在线改写，允许相同基础操作完成任务 |

普通 Code/task-local 可以作为第四组，但不应代替第二组。

### 10.3 消费者环境

至少包含下列变化中的两三种，不需要立刻扩展到机器人、生物和交通三个领域：

- 只改变响应；
- 只改变测量机制；
- 同时改变二者；
- 未宣布的变化时点；
- 返回旧状态；
- 干扰变量或不可完全区分的条件。

真正增加的是**失败原因与修订需求的结构变化**，不是只给原方程抽新的系数。

### 10.4 主要终点

- 每个独立序列的联合确认/终测成功数；
- 错误确认与错误继承次数；
- 固定总预算下的风险或预测损失；
- 全部 acquisition、authoring、失败和维护成本；
- 修改过的方法在下一轮是否实际被调用，并改变实验/修复路径；
- 新旧程序回归情况。

### 10.5 必要限制

- 提议与实验选择可以自由，但最终评价固定且独立；
- 不为每一次失败手工添加一个题目专用分支；
- 不以“完成了足够多 gate”代替终点；
- 开发失败保留，正式比较只用一次冻结版本；
- 方法学习失败的 donor也保留在总体分母，而不只迁移成功 donor；
- 样本量由设计与方差决定，不在本审稿意见中凭空指定。

这项实验比继续增加一批小规模开发样例更能改变审稿结论。

## 十二、最终建议

**作为可公开讨论的框架技术报告，这版已经有完整价值。作为要在强算法/Agent 研究竞争中投稿的定稿，我建议大修，并优先补一项强对照的统一方法迁移实验。**

最值得保住的不是“我们实现了所有递归认知能力”，而是：

> **一个被经验否定的预测或研究程序，不应只有继续相信和彻底删除两种命运。将预测资格、计算保留和修复再利用分开，能够产生可执行、可检验的累计研究机制；其价值必须在后续研究中支付完整成本后衡量。**

目前已报告的结果足以说明这不是空想。下一步需要做的是证明这一组织方式相对同样保留代码、同样能修复的强基线，确实值得其额外复杂度。

**不要再增加一长串阶段认证来推迟这一检验。也不要为了让论文更像成功故事而删除当前负结果。**
