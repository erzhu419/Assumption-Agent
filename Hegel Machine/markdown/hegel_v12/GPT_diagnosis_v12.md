原始回执给出的核心表是：

### 结论一：新世界知识有正向信号，应当保留

B比A少用了观测和计算，并多通过一题。不能再说“新知识完全没有效果”。

\[
[0,\;0,\;0.5,\;0,\;0,\;0].
\]

报告自己的bootstrap区间也是 \([0,0.25]\)。因此，**“当前有限队列出现改善”成立，“通过率已经稳定显著提升”不成立。**

### 结论二：当前最好的配置是 \(K_1+M_0\)，不是“全部新功能开启”

引入 \(M_1\) 后：

\[
K_0:\ 8/12\rightarrow4/12,
\qquad
K_1:\ 9/12\rightarrow6/12.
\]

完整新组合D甚至低于旧组合A。**所以不能用B的最好成绩，替代整个自递归系统的结论。**

### 结论三：预测正确与完成确认，是当前两个不同瓶颈

八阶段实验中有一个特别有诊断价值的例子：

**链951000的右向目标：**

- 普通缓存组外部fresh48误差约为 \(4.32\times10^{-19}\)，但内部没有完成确认；
- 结构组内部已经 `confirmed=True`，外部误差却是约 **0.00442**，最终严格不通过。

这说明总通过率混合了两种不同问题：

> 一种是已经找到好预测器，但在预算内没有完成交付流程；  
> 另一种是内部确认通过，但新轨迹暴露了预测失配。

**两者都应按原合同计分，但诊断必须分开。**不能把普通组说成“完全不会解释”，也不能用内部pass替结构组证明泛化。

# 四、最重要的问题之一：源假设的“确认”仍有后见调整

remember_confirmed_selection(

也就是说，**先看到fresh48误差，再把门槛设到这个误差之上，然后写入“已确认”。**

# 六、系统到底自己形成了什么？哪些还是脚本在替它决定？

和

\quad\land\quad

再在目标装置上重新估计 \(\theta\) 和关系半径。

实验环境当然可以由研究者设计。**问题不是脚本知道真实世界，而是它根据真实世界替研究者选择了算法路径和科学操作。**

这类实验可以证明组件能力，但不应直接称为：

> 系统自己发现历史分支冲突，决定开子研究，并形成新的理论组织。

# 七、分支模块中，我复核出了三个具体正确性问题

本轮实际执行的是**固定源码中三个小函数的片段控制**，采用最小Program适配器；不是整个仓库模块的端到端测试。脚本和输出都在交付包中。

## 1. 很近的阈值，被当成严格等价

`_programs_algebraically_identical` 把相差不超过 \(10^{-9}\) 的常数视为相同，上层可以据此返回：

```text
proved_absent = True
```

考虑：

\[
p(x)=\mathbf 1[x>0],
\qquad
q(x)=\mathbf 1[x>5\times10^{-10}].
\]

在

\[
x=2.5\times10^{-10}
\]

时，两者分别输出1和0，但被检查的小函数返回“相同”。

**这不是最后几位数值精度不重要的问题。比较器会把微小参数差放大成离散分支差。**

应当明确分开：

- 精确规范等价；
- 声明范围内、带误差界的近似等价；
- 目前有限样本没有区分出来。

后二者不能直接签发第一种合并结论。

## 2. 第三个同类分支加入时，反统一会失败

现在：

```text
0.22 与 0.46 → theta_0
```

可以成功。

但随后把同样骨架、阈值0.34的第三个分支加进来，已有`arg(theta_0)`与新的`const(0.34)`不能匹配，返回`None`。

这直接卡住了你要求的：

> 分支多起来后，进一步发现更一般结构。

现有测试主要检查“两个相容分支能合并”，再加入一个不同方向分支应该拒绝；**没有覆盖三个相容分支的增量统一。**

修复要支持已有参数槽、替换环境和多分支一致绑定，而不是继续添加更多两分支演示。

## 3. 未声明独立支持的新根，被默认视为有依据

输入：

```python
{"claim_id": "new_root", "status": "candidate"}
```

在被检查的撤回传播函数中，会得到：

```text
support_validity = valid_grounded
```

因为无依赖根的`independent_empirical_support`默认是`True`。

**缺少支持信息应该是未决，不是独立支持。**

本轮的无根循环控制确实被正确拒绝，所以循环检查本身有用，应保留。但它不能弥补根节点的宽松默认。

此外，新家族ID目前只对边谓词骨架做hash，未包含方向、完整读出和作用域。同一谓词骨架的左向与右向世界族可能取得相同ID，给撤回、支持归属和统计带来碰撞风险。应把**共享谓词骨架身份**与**完整科学家族身份**分开。

# 八、K1的收益为什么还没有被干净归因？

这里需要避免过度否定：**现有组合工作流的收益可以保留，但它不是一个纯粹的知识表示消融。**

**K0组**主要拥有两个初始来源。

\[

=

+
\text{新知识对象}
+
\text{不同执行路径},

而不是仅仅“自主假设比原假设好”。

\[
B-E
\]

更接近“当前结构化工作流包”与普通档案实现的比较，也不能全部归因于假设本身。

# 九、M1为什么没有变好？现在要研究的是算法，不是接线

这次 \(M_1\) 的形成包含真实学习：

> 从开发实验中测得某些观测带来的不确定性下降，再拟合探针特征权重，经过开发选择集筛选，形成一个可执行的探针评分器。 

但当前奖励主要关注：

- 方向是否确定；
- 半径区间是否变窄；
- 阈值区间是否变窄。

它不直接评价这次实验是否完成了执行器标定、是否帮助纯控制预测、是否为最终确认留下足够资源。

因此，一种很合理的解释是：

> 它学会了更快缩小局部关系的不确定性，却没有学会完成整个研究任务。

例如，固定pair探针把驱动 \(u\) 设为0，可能有助于分离交换关系，却不利于识别其他必要部分。但**这目前只是有源码依据的候选原因，不是已经通过消融证实的唯一病因。**

还有一个需要准确记录的细节：实际晋升的不是全部原始回归权重，而是`disagreement_plus_scale`变体，部分权重被截断、设下限，尺度惩罚也由模板规定。固定的`ensemble_std_only`策略在开发选择上还与它打平。因此更准确的表述是：

> **数据拟合与人工候选族结合，经过有限选择形成了M1。**

不是所有研究规则都由系统从零发明。 

本轮应保留 \(M_0\) 作为默认，把 \(M_1\) 留在探索档案中。其失败目标已经曝光，可以进入下一轮开发；**不能在同一批任务上修好后重新称为独立后继成功。**

# 十、还有两项会影响“有效指标”的问题

## 1. 成本账本仍有默认常数代替实际返回

条件源的费用使用：

```python
og_s.get("compute_spent", 45000)
```

而当前helper实际返回的是：

```python
"compute_cost": budget.spent
```

因此这里会落到默认45,000。C脚本还用固定8,000补反统一费用，用每项350补开发probe计算；原始回执中的“induction_and_selection_compute=324”也不是完整候选选择实验的总成本。   

这不表示目标端所有数字都错误，但**来源形成和长期净收益不能靠这些账本直接闭合**。

## 2. 新遥测仍然把“生成候选”写得像“改变父解释”

Pass-0／Pass-1中的`parent_after`会直接填第一个新候选，`probe_after`可能是“parametric_slot_calibration”这样的说明字符串。

这可以记录“产生了候选”“进行了内部标定”，但不是最终采纳的父模型，也不是实际购测的探针。

你的核心指标必须重建的是：

\[
\text{形成对象}
\rightarrow
\text{实际消费}
\rightarrow
\text{改变实验或采用结果}
\rightarrow
\text{改变未见任务表现}.
\]

不能在“召回／生成”这一层就把后面几步自动填成真。

# 十一、究竟是Gemini施工没到位，还是计划仍有局限？

**两者都有，而且需要分开承担责任。**

### 明确的施工问题

包括后见调确认门槛、人工覆盖支持统计、近似阈值当严格等价、第三个相容分支无法反统一、未知根默认有支持、成本字段取错和不准确的消费遥测。

这些都有具体源码位置和反例，不需要再讨论哲学定位。

### 计划仍需补实的地方

前几版对“假设应该怎样表示”“证据怎样保留”“什么不能过度声称”规定得比较细。

但**怎样从混杂经历中自主选出值得比较的假设对、怎样产生有用的范围条件、怎样决定何时开哪个子研究**，仍然缺少足够有效的普通运行算法。

这不是多加一个`reconcile`函数就能自动解决的。当前实验脚本替代了其中一些决定，正说明计划中的这一步还没有充分落实。

我此前的方案也需要更明确地规定：

> 实验harness可以设计世界和任务序列，但不得替Agent选择科学研究路线、补支持事实或手装研究结论。

### 当前属于真实科学负结果的地方

\(M_1\) 的负迁移、小库索引与普通缓存打平，以及部分候选内部确认后外部失败。

这些不能全部归结成工程错误，更不能通过弱化基线或换种子消除。

## 交付C：固定M0，先把世界知识增益证明清楚

给普通档案、未巩固的同历史库、自动调和库相同工具、原始经历、目标标定能力和预算。允许普通研究重建同一族，允许结果打平。

独立评价需要新的源链，并变化机制参数、作用域覆盖和分支顺序，不能只把两个固定阈值场景换六套匿名接线。形成失败必须进入分母；严格完成、外部预测、误确认、旧范围退化与成本分别报告。

## 最终判断

**Gemini已经解决了一批旧的工程阻塞，也做出了真实的参数化知识消费和有限方法学习；但还没有用当前证据完整证明你要求的自主假设生命周期。**

当前最有希望的部分是：

> **来源中的可执行关系结构，经过参数化和目标重新识别，帮助部分新问题更快形成有效解释。**

当前最明显的不足是：

> **假设之间的研究议程、分支选择和融合决策，仍有相当部分由专项脚本承担；而真正学得的实验方法，本轮并没有泛化得更好。**

所以，我不会把它评成“又全部失败了”，也不会认可“主目标已实现”。

**下一版最重要的交付，是让一个真实新假设从普通研究循环中产生，经过真实的冲突与范围检验，并在允许强普通方法重建同一知识的条件下，仍然解释清楚它究竟改善了哪个未见问题。把这一条做干净，比再扩展十种机制更接近黑格尔机的核心。**
