## 1. 请先回答的核心问题

**Luna 已经测到了有用的时间结构、条件边界和反例，但这些证据没有可靠约束后续可执行假设。怎样复用已有黑格尔机实现，让局部发现真正改变参数、表示、父模型和下一实验？**

这轮不是完全没有发现。它自行做了脉冲、持续输入、边界扫点和整轨迹留出验证。然而：

1. 实测否定的线性规律仍被文字笔记记成成立；
2. 已经缩小的参数区间没有进入后续拟合网格；

4. 不同门控／窗口组合被轮换尝试，但局部成立部分没有被保存为父模型实际调用的组件；
5. 最后又退回通用回归器和超参数搜索，耗尽额度。

## 3. 证据如何在研究中失效

### 3.1 已测反例被错误概括成旧规律的支持

第25—34次决策附近，Luna 通过独立重置、延迟脉冲和持续输入，找到了三步左右的时间影响。这是实质进展。

但第34次的实际输出表明：`z=−1` 和 `z=+1` 脉冲都使输出减少约0.461237。第35次笔记却把 x、z 一起概括成“负脉冲反转响应”，随后反复继承这个说法。

第48次已付数据重算又给出直接反例：

| 控制条件 | 线性脉冲解释的稳态预测 | 实际稳态响应 |
|---|---:|---:|
| x=1,z=−1,c=0 | −2.258002 | −5.025426 |
| x=z=0.5,c=0 | −2.924798 | −2.578870 |

同时 x=1,z=1 与 x=1,z=−1 的实际响应相同。这个证据足以挑战“z线性且符号反转”的解释，却被后续笔记继续描述成混合输入具有加性。

因此仅让更多日志进入上下文不能解决问题。需要让一个可执行解释继续面对自己已引用的反例；文字概括不能替换数值约束。不是要求旧解释全盘撤回，而是保留已经成立的时间影响，重开仍有矛盾的响应形式。

### 3.2 参数已经被研究出来，却没有进入候选

第58次起，Luna 自己研究 c 对持续混合输入的作用，最终在第82—83次明确记录边界区间 `(-0.17625,-0.176)`，还检查了不同 x、z 组合。

第86、89、91、92次拟合却继续使用旧阈值网格，例如：

```python
[-0.18, -0.1775, -0.17625, -0.175, -0.17]
```

这个列表没有任何点在最新区间内部。第91次已经尝试“按当前c分支＋最近三个控制的二次表示”，但用错误参数和有缺陷的历史表示得到大误差后，转向其他结构。

这里不能下结论说“分支二次解释被反驳”。被测试的是特定阈值、特定重置表示下的实现；参数研究的返回值甚至没有真正用于它。

### 3.3 表示本身把可区分历史压成了同一个输入

后期多种拟合器共用的表示，把不足三步的历史用全零控制补齐，却没有保留有效历史长度。

已付记录416、417、418等在零输入下有：

| 重置后的有效步数 | 零填充后三步控制向量 | 输出 |
|---:|---|---:|
| 1 | 全零 | −0.27472346 |
| 2 | 全零 | −0.54944692 |
| 3 | 全零 | −0.82417037 |

对这个特征映射，三个不同物理状态无法区分。无论后面换成 Ridge、树还是神经网络，同一特征都只能给出一个预测。

在现有1664行上，共找到13组“相同零填充特征、不同标签”；按每组最佳常数预测计算，这个表示的经验MSE下界为 **0.00631439**，高于1e-6。这个下界来自真实数据，不是对所有模型族的泛泛猜测。

这是原始“泛函分析／观测决定可区分性”构想的一个具体有限实例：原始历史中存在差异，但 Agent 自己构造的映射把它消掉了。下一步应该改写表示，而不是继续优化这个映射之上的回归器。所需历史长度原本就在公开输入中，并不要求增加仪器或购买隐藏状态。

### 3.4 研究成了脚本序列，局部结果没有进入组合闭环

最终状态只有一个反复改写文字的 `task` 根问题：无子问题、无模型依赖、无条件组件、无观测组件。唯一的候选比较与revision记录均继承自trial095，本轮没有新增。

正式 `refit` 没调用，但 Luna 确实手写了整轨迹留出检验，因此不能再说“它根本不验证”。真正缺的是：验证后究竟保留哪部分解释、哪部分重开，以及局部条件如何实际进入父预测器。

第86、92次主要尝试“每个历史时刻先分支，再相加”；这与“用当前条件选择整个窗口的响应”不同。第91次靠近后一结构，但参数与重置表示同时有缺陷，导致没有隔离各自责任，最后退回 HGB 搜索。

另有5次完整重复购测，合计240行：第30、31次重复第29次；第63、64次重复第62次；第77次重复第75次。前一组与把只含前几步的预览误读为完整轨迹有关。完整记录没有丢失，真正问题是读取和利用它们的策略。

## 4. 事后数值分解：缺数据，还是没有正确使用数据？

这部分是宿主知情诊断，单独保存在研究工作区之外。使用已有付费数据，没有生成新标签，也没有修改 Luna 的模型或把答案传给作者。

首先精确复现第91次：最近三个控制、缺失历史零填充、二次基、按当前c分支分别Ridge、整轨迹留出。105条轨迹／1600行的均值和最坏误差与原日志一致。然后分别只更改参数或历史表示：

| 事后对照 | 阈值 | 按轨迹平均留出MSE |
|---|---:|---:|
| 复现Luna第91次最佳设置 | −0.175 | 0.154179995 |
| 只采用已测区间中点 | −0.176125 | 0.015126394 |
| 只增加有效历史计数，仍用旧阈值 | −0.175 | 0.138443817 |
| 同时采用已测区间中点＋有效历史计数 | −0.176125 | 1.214×10⁻¹⁶ |

增加的计数仅为 `min(3, len(row['history']) + 1)`，不使用目标或隐藏状态。各留出折的系数只由训练轨迹拟合。用前1600行拟合、预测已付的末64行，第四项MSE为3.199×10⁻¹⁶。

另外用已知实验室定义分解组合次序。令：

\[
v_t=\left(n_t,\sum_{j\in W_t}x_j,\sum_{j\in W_t}z_j^2\right),
\qquad n_t=\min(3,t+1).
\]

诊断模型 `y_t=β_{b(c_t)}ᵀv_t` 只有两支共6个拟合系数：105条付费轨迹上的留出MSE约4.05×10⁻²⁹。若将分支放到窗口内，让每个历史时刻按各自条件选择再相加，同批数据的相应留出MSE约0.4693。

这说明同时存在**参数区间未被使用、表示丢掉重置信息，以及门控与窗口组合次序未被清楚比较**。其中前两个问题已经足以解释第91次为何错过一个可用表示。没有必要先发明更多回归器。

[数值结果](../docs/evidence/conditional_online_failure_20261013/paid_data_diagnostic.json)及[分析脚本](../scripts/analyze_conditional_online_failure.py)已纳入仓库。可只用约285KB的付费轨迹节选复现，无需数十GB研究现场：

## 6. 下一轮建议：修研究对象与决策，不再只接更多接口

以下是待网页端评审的实施方向，本次没有改在线科学策略或启动新付费研究。

### A. 让局部发现成为可执行的研究结果

复用已有组件、父子返回与revision。把局部假设连到它实际解释的记录、参数约束和反例；父候选必须使用子研究返回的参数或表示文件。这里的例子是“边界区间已改变”应改变下一拟合的取值，而不只是更新文字笔记。

不要求每次强行制造子题。只有待解决因素会改变父模型或下一实验时才分解；产物应是实际输入变换、参数约束或可调用模型，而不是更多问题名称。

### B. 区分参数失败、表示不可分和组合结构失败

优先复用旧反例重开逻辑和留出工具，在当前已付证据上定位：

- 当前候选是否真的使用最新已测参数约束？若没有，先完成该候选的有效试验。
- 当前表示是否把已付的不等输出映为同一输入？若是，继续优化该表示上的确定性预测器不能消除矛盾，应研究缺失的可观测差异。
- 保留已支持的组件后，哪一个组合关系仍未定？为竞争组合预测设计实验，而不是同时更换阈值、窗口、响应函数和拟合器。

这里的“定位”必须进入下一实际动作，不能再变成只输出报告、不改变决策的检查器。噪声情形需要证据强度判断；当前任务是无噪声开发来源，不必先建设通用噪声框架。

### C. 让实验针对仍未解决的差异

复用0.135同背景实验原则与现成 `query.revision`：保持已成立部分，构造使竞争解释产生不同预测的短轨迹，再用实际读出决定保留或修订。局部解释不必先满足最终全局门槛才允许试验。

对同一确定性装置，已执行过的完全相同轨迹可以取回付费结果；重复性本身若是待研究问题，仍允许主动重测。重点是把已付动作与结果真正送入选择，不用禁止重复的硬规则代替科学判断。

### D. 成功之后再归纳，保持原实验链

先让冻结后的 Hegel＋Luna 在同一来源上取得真正独立确认，保留旧确认与失败成本；成功后才进入原九实践和56目标。旧10/10保持原协议，目标不带入来源拟合系数或付费观测。

若选择把0.135原生求解器直接作为Luna可调用方法，这可以验证旧能力的采用与重用；但应与“Luna从自由Python自主构造了该表示”区分。两种路线都可能有研究价值，不能换了路线仍沿用原自主发现主张。

## 8. Limitations

- 本轮只有一个按失败选出的开发来源，没有同预算Code对照，不能据此评价完整Agent的稳定优势或Luna的能力上限。
- 事后模型和特征修改由宿主知情提出；它们只解释失败来源，不是系统自我发现、独立确认或迁移成果。留出过程仍复用了同一研究收集的数据，且某些轨迹完全重复。
- 0.00631439下界只针对本例零填充映射在这批已付数据上的经验误差；不是所有表示或未来分布的下界。观察到阈值区间仍留下未测边界歧义，当前中点没有得到未来确认保证。
- 脚本重放证明输入表示和参数使用存在实质性问题，尚未证明增加某种组织机制就能让Luna自主修正它们。29次query中有1次无效；不能把所有调用都计作有效实验。
- 近99.3%的报告token为输入，约24.9%的输入命中缓存，长上下文重复携带了大量研究脚本和笔记。应减少错误总结与无关材料反复进入决策，但缓存优化不能替代科学算法修订。
