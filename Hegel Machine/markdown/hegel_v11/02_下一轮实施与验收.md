## 1. 交付A：先修结论可信性

### A1. 索引版本与原子更新

修改 `premise_commitment_index.py`，继续复用现有KnowledgeLibrary/Program。

- 优先使用不可变的 `(claim_id, semantic_version)`。semantic_version覆盖Program、参数共享关系、scope、支持前提、已使用证据引用及语义版本；表示和检查器版本也要绑定。
- `_cached_commitment_group_key`必须依赖同一语义版本。参数规范化可用于家族分组，但不能替代具体实例和证据的身份。
- 增量更新构建新快照；只有某组及其相关检查完成才发布该组。未完成组保留dirty/pending，不把完整prior集合指纹提交为已完成。
- 预算耗尽返回明确状态，可使用最后一个已验证快照作候选召回，但不能将过期内容当当前已确认事实。
- `not_retrieved / not_tested / inconsistent / refuted / budget_pending`分别记录。检索未命中和预算没访问不叫反驳。
- 报告实际扫描数、归一化AST数、求解器调用、时间；SearchBudget是约定计价单位，不能直接当CPU指令。

验收：同ID同条数修改真实有效Program/参数/证据后，相关组必然更新；无关组不必重做；预算中断再续跑与一次足额构建最终一致；未访问候选不得写反证状态；依赖撤回使相关子结论过期，独立支持仍有效的结论不被无差别删除。

## 2. 交付B：一个有实体内容的分支处理回路

### 2.1 不增加一套空壳对象

沿用已有Claim/Program/ResearchQuestion/支持依赖/理论队列。补的是实际算法和调用，不是新增多个没有生产者与消费者的类型。

把以下决策编译成实际流程：

```python
# 规格伪代码，不是已提交代码。
def reconcile(new_claim, old_claims, observations, budget):
    candidates = align_semantics_roles_units_and_time(new_claim, old_claims)
    for old in candidates:
        overlap = assess_scope_overlap(new_claim, old)
        if overlap.certified_disjoint:
            retain_conditional_alternatives(new_claim, old)
            continue
        if overlap.unknown:
            schedule_scope_question_if_decision_relevant(new_claim, old)
        disagreement = find_feasible_prediction_difference(new_claim, old, overlap)
        if disagreement.proved_absent:
            propose_semantics_preserving_consolidation(new_claim, old)
        elif disagreement.witness_available:
            paid = execute_discriminating_probe(disagreement.probe, budget)
            update_only_supported_or_refuted_claims(paid)
            propose_minimal_scope_or_structure_revisions(paid, new_claim, old)
        else:
            retain_unresolved_competition(new_claim, old)
    test_new_abstraction_on_sources_counterexamples_and_fresh_cases()
```

“proved_absent”必须有该语言范围内的实证/形式判据。有限点没找到差异只能叫未发现，不自动调用等价合并。scope未知时不允许通过“默认不相交”绕过冲突。

### 2.2 提出者的具体工作

先实现类型化反统一与现有Program局部编辑：抽取共享子式、将确有来源差异的常数参数化、尝试可执行条件、组合已有角色与操作。可调用已有LLM开放提出者生成候选AST；编译/语义/预算/确认仍由独立固定工具执行。

新候选应给出：相对于哪个父模型改变了什么、在什么可观测条件下适用、在哪个可行实验上会与旧模型不同。不能要求提出时就知道其真值，但也不能只交一段无法执行的解释。未能编译的构想可保留IDEA，不假装已验证，也不因未立即降低MSE而永久删除有授权理论使命的研究。

禁止将测试的隐藏机制名、任务编号、完整正确AST或目标阈值传给提出者。实验生成器可以知道真环境以评分，但不能以家族答案作路由条件。

### 2.3 一条能暴露关键缺口的研究链

使用现有环境能力，不加新PDE：

1. 从真实source经历形成H0并冻结。
2. 在同结构但参数/绑定变化的目标验证可复用性。
3. 给出使H0预测失败的新证据；Agent自己选择区分实验。
4. 形成有可执行条件的H1，保留H0仍有效的范围。
5. 引入另一个历史分支，安排真实重叠与预测分歧，迫使系统处理冲突而非仅按id并存。
6. 尝试H*共同结构：独立检验是合法参数族、仍需分支，还是不应融合。
7. 回到H0旧范围，验证旧能力未被覆盖。
8. 在全新源组检验H*或条件分支的预测/研究效果。

不同作用域的诊断拒绝集不能无条件并集后强迫新理论全部拒绝；应先把scope与仪器绑定纳入检查输入，再验证相应范围内的区别保持。

第5步不能只通过手工给两个条目加 `conflict=True` 完成；第6步不能只合并JSON或让整体MSE掩盖少数旧区域退化。至少要有一次“应合并”和一次“不应合并”的实例。

开发链用于调试；评价链的独立单位是物理源/机制组合，不是同一source派生的48行轨迹。独立评价源不得从失败后反复挑种子直到通过。

### 2.4 十项足够聚焦的行为验收

1. 同一问题换变量名/单位经合法映射后不产生假冲突。
2. 不同范围的真实规则保留为条件分支，条件来自可观测证据。
3. 重叠范围不同预测触发能区分二者的实际probe。
4. 新候选被反驳时不覆盖旧有效程序。
5. 旧全称假设被新反例否定后能缩域，不只新增例外文字。
6. 真等价的已支持对象可去重；有限点相似不自动认定等价。
7. 共同骨架形成后通过来源重构、旧真实反例与独立新点。
8. 错误融合在细分范围测试中被拒绝，原分支可恢复。
9. 撤回前提后真实依赖链更新；循环标签不自我认证。
10. 整条链改变了实际候选/实验/预测，且至少部分改动在新问题上有可核验作用；只有日志增多不算完成。

## 3. 交付C：证明使用假设后的收益，进一步区分方法学习

### 3.1 最小主命题

> 相同底层工具、共同原始研究经历、相同总资源上限下，运行时形成并维护的假设体系改善独立后继任务表现或在相同表现下节约完整成本。

这不要求自动训练权重，不要求系统没有任何人工先验，不要求每个新假设都更简单，也不要求全部物理场景全面领先。允许普通基线重建等价方法；平手就是可接受的科学结果，只是不能宣称额外增益。

### 3.2 将世界知识K与研究策略M拆开

完成主命题后，使用同一接口进行2×2实验：

| 条件 | 世界假设 | 研究策略 |
|---|---|---|
| A | 冻结旧K0 | 冻结旧M0 |
| B | 运行时学得/修订K1 | M0 |
| C | K0 | 从开发经历归纳M1 |
| D | K1 | M1 |

所有组的原始历史、可用工具、预算、候选生成权限相同。K/M是显式处理因子，基线可从相同历史自行重建，不伪造完全没有记忆的弱基线。另报告优化archive作为强普通研究锚点。

B-A观察新增世界假设的价值；D-B在同K下观察研究策略价值；D-C观察新策略下的知识价值。成本分别报告；若设效用函数，应预先固定并同时给出原指标。动作轨迹必须证明M1确实被调用，而不是效果全部来自K1。

### 3.3 选择一个可学习的研究规则，不写死改进答案

候选方向：当多个条件假设在现有数据上都一致时，如何选择区分实验，而不是继续拟合更多相同区域；当出现迟滞/记忆迹象时，如何比较匹配前缀与重置实验；当旧理论失效时，如何分配范围检查与结构搜索预算。

形成过程：真实失败/成功episode对照→提出可执行研究规则→在独立开发问题上匹配比较→保留有支持的规则或暂存候选→在新source上使用。所有手工写入的规则明确记录作者来源，不归功于运行时学习。

需要更强RSI声明时，再让接受的M1参与产生M2，并分别评估M1与M0作为“改进者”的下游增量。只做M1后任务更好，已经有价值，但还不等于证明M1更会产生下一代。

### 3.4 评价约束

- 开发、候选选择、最终评估分开；重复选择的问题不能仍称隐藏测试。
- 统计以独立源组/完整研究链为单位，报告配对差、置信区间、全部失败与未调用分母。多代筛选需处理选择偏差；不要把每个候选入档都强制成高门槛显著性测试。
- 探索档案与默认策略晋升分离，允许有前途但暂时打平的候选保留，避免只接受即时贪心收益。
- source形成、图维护、重构、LLM、环境观测、测量、确认及墙钟分别记账；不用任意加权总分掩盖权衡。
- 评价器、隐藏标签、合法性核验、预算账本固定在不可由候选改写的边界外。可以研究自己的推理过程，不能改评分器使自己“通过”。

## 4. 停止条件与下一决策

如果修复后结构化组仅省缓存费用，应作为工程成果报告，不换更弱基线求胜。若世界假设有用但方法学习无增益，先发布/保留前者，定位候选生成、适用性还是调用失败，不堆更多图节点。若新方法确实改善跨source研究，再扩大机制组合与规模，而不是先开下一批物理家族。

此轮最有价值的交付是一条可追溯的真实变化链：

**哪段经历形成了什么可执行假设 → 何时被新证据修订 → 为什么保留/融合/撤回哪些分支 → 在独立新问题上究竟改变了哪个实验或预测 → 与同历史强普通研究相比带来了什么。**
