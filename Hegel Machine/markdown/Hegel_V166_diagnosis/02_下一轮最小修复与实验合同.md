# Hegel V16.6 后续：最小修复与实验合同

本合同依据固定提交 `675f52612a9d0f1fb208da8bdb0552de3c571758` 的实际源码、完整离线重放及定点反例制定。它是下一轮建议，不声称以下功能已经存在或通过。

## 0. 下一轮只回答一个核心问题

**系统能否从可追溯经历中形成并修订一个有适用范围的研究程序，使它在未见目标上有实际效用，并且这种效用在普通方法真正可以重建、缓存和消费同知识时仍能被解释？**

先保留两个已有的任务方向：有理族的低成本拟合/验证程序、多资源的联合询证程序。边界定位作为严格正确性与范围治理回归，不要求它胜过已经会二分的普通方法。

通用原语、有限函数族语法和人工设计的基础算法都允许使用；所有对照同样允许。首阶段无需要求 LLM 从零发明数学定理，必须要求最终选用的主张、程序和适用条件确实由经历决定，而不是由 episode 名称、源数组位置和固定目标名决定。

## 2. R0：先修可能把错误当成功的路径

### 2.1 最早翻转必须具备对应证书

修改 `family_plugins.py::verify_or_find_earliest_flip` 及共享 direct solver：

1. 对全局单调序列，接受明确来源和版本的单调前提证据，再使用二分。
2. 对任意非单调序列，最早结论必须有覆盖整个前缀的观察或等价证书。不得把步长 8 未见反例当成无更早翻转。
3. 如果任务公开保证最小异常段宽度，允许按该保证优化覆盖；保证必须进入 ClaimContract，变更后使旧证书失效。
4. 预算不足就返回未知/未完成。可以附带“已找到一个翻转”，但不将其作为 earliest 完成。
5. SKIP 跨越应独立定义为“最近可测试点间的翻转”，不要静默改成物理相邻索引；噪声下重复投票的置信范围与确定性保证分开。

最低验收：本包两个短故障反例；同号端点仅短孤岛；无可用单调前提；不足以覆盖前缀的预算；一个合法单调快路径。检查具体返回保证与实际查询位置，不能只检查字符串中有 `earliest`。

### 2.2 支持准入由证据决定

修改 `form_and_revise_from_experience` 和节点注册流程：

- 未通过相应检验的候选允许以 `CANDIDATE/UNKNOWN` 留档，不能授予已支持主张的消费权限。
- `strict_pass` 是任务级回执；主张支持还需主张自己的判据、范围和 witness。即便某源任务完成，也不能自动证明更强的全局规律。
- 源的独立性至少检查 episode ID、生成实例/原始数据哈希、任务角色和来源过程；完全重复的同一经历不会凭计数升级为“双源跨域”。相关源可以有用，但必须标清相关结构。
- 不再按 `sources[0]`/`sources[1]` 自动写入“CPU/生化”角色。候选映射由任务公开变量、单位、响应形态和必要的识别步骤生成，并保存竞争解释。
- B1 的最终确认值必须参加是否晋升强消费程序的决定。允许保留“联合动作值得试”的弱规律，不得由一个联合增益自动得到全局 min 齐次模型。

最低验收：两个全零 A 源不产生受支持的 opposite-endpoint 主张；重复 B 源不产生虚构的生化来源；`min(2u1,2u2,10)` 对目标 16 的确认失败时，不将比例放大路径标为受支持。

### 2.3 授权要成为动作前置条件

`solve_target` 的 ordered、1D、2D、ScaleMap 分支采用同一约定：

- `retrieve_candidate`：只返回候选。
- `bounded_trial`：可执行明确限额的诊断探针，不可继承强结论。
- `local_solver_guidance`：在本目标证据范围内执行候选程序，但仍保留独立结果确认。
- `validated_pruning`：还需具体排除/蕴含证书，才可放弃其他解法。

拒绝 guidance 后若允许 bounded_trial，应显式执行 bounded_trial 程序并记录其预算，不能继续原 guidance 再把日志说成已经降档。

把 `heldout_confirmed=True` 这样的调用者自述替换为可解析 evidence receipt。最小字段是 `target_instance_id / hypothesis_id / hypothesis_version / protocol_hash / observations_hash / test_id / result`。第一版可以是内部对象，不必建立复杂签名设施；关键是校验存在、匹配、当前有效。

### 2.4 语义、版本、边与缓存同一次修订

保留稳定 question id，对变更后的 claim/task/protocol/readout 调用现有语义更新函数。一个 revision transaction 应完成：

1. 保存旧节点和旧 QuestionSpec。
2. 更新 operational meaning 与版本。
3. 清旧答案，通知直接和可追溯的下游消费者。
4. 将绑定旧版本的 implication/wormhole/消费证书标为失效或待复核。
5. 新证据验证成功后才生成新边版本。禁止只把旧边的版本数字改成最新。

删除的 AND/OR 逻辑应保留；对传递删除后的残留边和缓存再做一致性检查。只有记录级变更无需影响科学含义时，才保留原 meaning version。

展示字段剥离需要 schema 边界：`metadata.notes` 可忽略，谓词 literal 中的 `{"notes":"mode_A"}` 不能忽略。

### 2.5 回放与合并的最小修补

无当前判据的 condition/witness 返回 UNKNOWN/需要操作化；来源 `observed_outcome_status` 只作出处与候选提示，不直接决定新目标分支。

规范化 top-level 与 value 内的 outcome，再检查执行错误。工具异常不写科学否证，也不写已回答的科学语义答案。

FidelityCompression 在对齐范围和查询集上保存 `(ACC,REJ,UNKNOWN)` 及输出合同。遇到同范围 ACC/REJ 冲突，不作“保真”合并；可以继续保留两个条件分支，或用新证据走 EmpiricalRevision。未知升级为已知必须有新增证据来源。没有共享适用范围时，合并对象应保留各自的条件分派，不能用简单前提合取删除合法案例。

## 3. R1：把一条经验变成真实可执行研究对象

### 3.1 优先使用多资源程序

建议把这一条作为最小生命周期演示：

> 在当前资源条件与输出协议下，两个单轴增量都没有可检测收益时，不把两个资源永久排除；花一个受限预算尝试联合增量，并根据联合响应决定后续问题。

其候选表达应至少包含：

```json
{
  "question": "单轴无效是否由互补限制或不可见瓶颈造成？",
  "preconditions": ["观测预算可用", "两个轴可干预", "单轴增益在协议分辨率内为零"],
  "program": [
    {"op": "measure", "at": "base"},
    {"op": "measure", "at": "axis_1_increment"},
    {"op": "measure", "at": "axis_2_increment"},
    {"op": "condition", "test": "both_single_gains_below_resolution"},
    {"op": "measure", "at": "joint_increment", "when": "condition_true"},
    {"op": "branch", "test": "joint_gain_above_resolution",
      "true": "investigate_complementarity_and_new_limits",
      "false": "investigate_saturation_sensor_or_irrelevant_controls"}
  ],
  "does_not_entail": ["全局为min函数", "任意幅度下齐次", "当前比例配置全局最优"]
}
```

这是建议表达，不是要求固定 JSON 模板成为学习答案。真正归纳步骤从实际动作轨迹提取“当什么观测出现，哪个追加探针带来什么判别收益”。现有 `growth_methods` 编译器可以承担有限 DSL 抽取，先接一条完整链即可。

### 3.2 强主张分开验证

在弱程序基础上，新候选可能是 `y=min(c1u1,c2u2)`。它与有容量上限的 `min(c1u1,c2u2,M)`、平滑互补、观测裁剪等应在语法中竞争。

每次使用前先决定实际目标需要多强的模型：若只需提高一点输出，联合干预可能足够；若需最小成本达到 16，则要检验可达性、范围外推和配置代价。最终确认失败应使强模型退回未知/被反驳，而弱诊断程序可以继续保留。

### 3.3 同时接有理族程序

有理族候选由源拟合及未参与模型选择的留出检查形成，存储的是：变量角色映射、适用输入区间、观测噪声/误差容忍、短拟合程序、留出确认和失败回退。源提供的具体 alpha/beta 不直接当新目标参数。

消费者必须根据对象的程序/合同执行，而不是靠固定 node_id 选择硬编码 solver。允许对象引用共享已知 primitive，关键是程序选择、参数角色、条件和证据由所学对象提供。修改对象内容后，动作应发生可解释变化。

### 3.4 自动成立的最低证据

一条有效谱系应可追溯为：

`原始动作/观测 → 候选程序及竞争者 → 独立否证/范围检验 → 版本修订 → 未见目标匹配 → 实际消费动作 → 目标独立评价 → 成本差`。

四个便宜控制足以先排除脚本式伪闭环：

1. **来源重命名/顺序交换：** 科学对象的内容应按观察等价变化，不能换一个 ID 就改成生化解释。
2. **信息移除/打乱：** 知识支持度或范围应下降；不能只因仍有两条记录就保持 supported。
3. **程序内容干预：** 删除新学得的联合询证/范围排除，目标行为要相应变化；若只是解释字符串变化，记录为尚无新增效用。
4. **确认失败：** 强主张不入库/不授权；弱的诊断经验可保留并说明与失败证据的一致性。

不用要求每一个学得分支都必须赢。只有一条有完整因果链的改进，也比几十条无消费者的结构化记录更能回答主问题。

## 4. R2：真正赋能普通方法，再分离三个实验问题

### 4.1 最低能力验收

普通方法应可以从自己或共享的经历：拟合相同函数族、提取相同 primitive、生成联合探针、保存条件化技能、以自然语言或结构化字段表达协议/尺度约束、按需重建并缓存结果。其直接求解、重建、复用路径按开发集校准的选择规则运行，而不是为证明 H 优势强制多买探针。

能力测试应在正式实验前证明：

- archive 有合适历史与 archive 为空时，ordinary 的候选或动作能变化；
- 第二次相同重建需求命中缓存，不固定重复收整笔重建费；
- 删除/修改 skill/mistake 内容会改变对应消费路径；
- 同一工具预算和测量价格下，ordinary 也能做三点检查加一次确认；
- ordinary 可以使用 TaskView 的尾延迟声明拒绝不适用的均值模型。

普通在开发集选择不重建是合法的，但必须能审计其可选动作与成本判断。没有实现选择分支，不可称为“自主决定不重建”。

### 4.2 实验 A：同历史的知识表示与消费

给所有方法完全相同的源、近失例原始轨迹和工具回执。不要只复制四个成功源而遗漏修订依据。

| 臂 | 得到什么 | 必须能做什么 |
|---|---|---|
| Hegel | 原始历史 + 由自身形成的版本化结构 | 条件检验、程序复用、失败修订 |
| Strong ordinary rebuild | 同一原始历史、同一基础算法与语法 | 选择是否重建，缓存并消费同等知识 |
| Conditional skill / HExA-inspired | 同一原始历史或同内容条件程序 | 条件、错误恢复、尺度约束和跨轮改写可实际执行 |

这回答“结构化管理是否比普通可重建知识更有效”。各自形成成本单列，目标阶段和共同历史沉没成本的处理明确。

### 4.3 实验 B：同内容的图组件

固定已形成的节点、程序、角色映射、范围条件和证据快照。Flat 组可以在相同预算内直接检索任何适用对象并执行相同映射，不得要求先有一条横向边才准跨域。

Hegel 与 Flat 仅改变图路径检索/关系索引的组织方式。若去掉一条边同时移除映射知识，那是在做知识内容消融，需要另起结论，不叫图索引纯贡献。若候选库很小，Flat 持平甚至更省是正常结果。

本轮不必实现 HippoRAG PPR 才能推进核心知识效用；先把本地 Flat 对照做正确。

### 4.4 实验 C：独立源→目标策略

各臂从同样可获得的源任务流自主研究、学习、修订，再解决相同未见目标。学习步骤的原语能力对齐，策略差异允许存在。这样比较的是完整系统，而不能把某一分量的胜负单独归因到“表示形式”。

单源/双源作为学习投资消融，既报 target-only，也报给定目标前缀长度 n 的累计成本。当前数据已显示单源全账更省，应保留这个结果作为下一轮选择何时再收集源经验的依据。

## 5. R3：冻结、费用和评价

### 5.1 冻结什么

冻结求解器、候选语法、可用工具、基线能力、gate 校准规则、成本价格、质量阈值、源/目标分割及评测生成器版本。记录代码哈希和冻结时间。新的测试种子/数据由独立评测入口产生；如果评测后更改策略，重新声明为开发并换一批评测实例。

未见应分层记录：新参数实例、新公开表征/单位、新过程实现、新机制家族。第一轮可以只承诺前两层，不必一开始证明跨所有科学领域。

### 5.2 Stage-1 比较真正的剩余路径

从同一已购买的 pilot 状态复制两个可回放状态，两个路径共用相同观察、随机状态与缓存；分别测 transfer / direct 到满足同一质量目标的剩余成本。共同沉没成本不再重复进入 gate 比较，但保留在完整账本。

校准不按 `T_B1/T_C1/T_B5` 名称分类，按当时可观察特征与任务合同分类；当开发覆盖不足时允许小预算探索并记失败费用。当前 `mean ± std/√n` 若只是经验筛选分数，应这样命名；若声称置信上/下界，需说明有效样本、估计方法和覆盖条件。

### 5.3 同时报告三个成本视角

1. **原始向量：** 模型 calls/tokens（无调用时为 0）、环境测量 calls、工具调用、wall time、实验测量价格。
2. **预注册复合费用：** 明确 compute 是代理计价还是实测，不在看见结果后调权重。
3. **累计投入收益：** 离线开发/校准、源采集和形成、目标绑定与复用、失败回退、最终确认、按需重建及缓存维护。

建议使用：

\[
\Delta C(n)=\Delta C_{\mathrm{development}}+\Delta C_{\mathrm{source}}+\sum_{t=1}^{n}\Delta C_{\mathrm{target},t}.
\]

研发作为给定成本时，明确报告条件化版本并另列开发账，不把不同臂的研发成本任意不对称计入。目标前缀例如 1、2、4、8、14、28 在冻结前指定；不只选首次转负的前缀。

当前双源相对单源的已知例子是：`+73.075 − 39.650 = +33.425`（14 个目标/簇）。更多目标能否摊平需要新实验；简单线性外推只作规划假设，不算证据。

### 5.4 质量必须先于费用解释

最早位置、资源可达性/最优性、原读出尺度 RMSE 等质量合同各自固定。相同正确率但置信、范围或允许输出不同，不算同质量。保存拒绝、未知、工具失败与假确认，不能只展示完成的成功题。

选择统计单位时以独立来源生成/学习簇为主，目标嵌套在簇内。可以先跑一批便宜的参数和范围控制来排查程序错误；正式样本量依据开发波动与期望最小有用效应确定。当前 4 簇仅作早期诊断，不通过反复换种子直至显著来选结果。

## 6. 数据导出的最小增补

沿用现有证据目录布局，优先补缺字段：

| 记录 | 必需增补 |
|---|---|
| 原始经历 | source/near-miss/target 均保存实际动作、参数、观测、时间/预算、工具错误；唯一 run/arm/cluster/episode ID |
| 候选与竞争者 | 每个族/程序的拟合与独立检验结果，不写预填 rejected list |
| 主张版本 | 支持/反驳 witness 的可解析引用、scope、QuestionSpec 版本、语义摘要 |
| 边与映射 | 两端确切版本、可执行角色映射、误差来源、当前目标许可依据 |
| 实际消费 | 哪个节点/边/程序版本改变了哪个候选、探针或停止决策 |
| 提交 | 可序列化模型/程序、参数、预测值或 replay ref；不要只删掉 predict_fn 后留下 family 名 |
| 成本 | 真实调用与代理价格分离，开发/校准单列，可按前缀聚合 |

失败记录也要存在。当前 source 导出还需去掉单源臂与主臂的身份歧义，不能靠数组顺序再恢复成本归属。

## 7. R4：只替换一个真正过程环境

优先改 C 服务环境即可，不同时建设所有领域：以到达过程、服务时间、并发限制、队列和拥塞状态产生事件流；长窗吞吐与尾延迟从同一事件日志估计。这样才能测试一个尺度投影保留均值但破坏尾部的真实证据。

保持酶 ODE 源作为独立实现，新增一个变量重命名和单位换算包装，检验映射到底是否被执行。遇到更多上限或非线性不要求每题迁移成功，要求系统能识别适用、限制试错开销并带已有数据退出。
