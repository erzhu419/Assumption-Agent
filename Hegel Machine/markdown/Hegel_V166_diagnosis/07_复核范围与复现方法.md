## 2. 三种证据必须分开

| 证据 | 本次例子 | 可以证明什么 | 不可以声称什么 |
|---|---|---|---|
| 正式提交回执与源码 | 主表成本、25节点无question、eval01旧边 | 当前运行的数字/数据关联与实现事实 | 不自动证明因果、普适性或来源自主性 |
| 原函数的控制执行 | 短故障、重复源、失败确认、无边local消费 | 存在可执行反例或改变该因素能改变行为 | 不把控制结果混进原56题分母 |
| 隔离接口控制 | typed nested error、特定Fidelity verdict表 | 接口合同存在边界漏洞 | 不称正式目标已经触发或完整agent端到端复现 |

ordinary 历史消费控制属于非预注册诊断：它量化一个已确认缺口的影响，不是替代下一轮冻结实验，也不证明最强普通性能上限。

没有观察到 M1 目标求解器直接读取 `_oracle`、`_sim` 或隐藏机制参数。该版本的问题主要来自预设形成/消费控制流、未被消费的历史、消融权限差异以及证据准入。不要把这些问题笼统写成“已经证明偷偷读取答案”。

## 4. 命令：在该提交的正常 checkout 上复现

以下均在本压缩包根目录运行。将 `/path/to/Assumption-Agent/Hegel Machine` 替换为实际固定提交目录；将输出放到源码目录之外。脚本主要使用 Python 标准库，并在内部建立命名空间包，避免导入无关顶层 formal 模块。它们不要求 LLM API key。

### 4.1 原回执复算

```bash
python scripts/recompute_v166.py \
  --evidence '/path/to/Assumption-Agent/Hegel Machine/docs/evidence/v16_6_cross_domain_wormhole_20261119' \
  --repo-root '/path/to/Assumption-Agent/Hegel Machine' \
  --output '/tmp/hegel_audit_recomputed.json'
```

### 4.2 原研究重放、开发费用记录和 ordinary 窄控制

```bash
python scripts/replay_and_baseline_control.py \
  --repo-root '/path/to/Assumption-Agent/Hegel Machine' \
  --output-dir '/tmp/hegel_v166_replay'
```

该脚本检查 8 个模块哈希与 runner Git blob。仅把 runner 中用于元数据的 `git rev-parse HEAD` 返回值设为本次固定提交；求解、模拟器、拟合、门控、评价代码保持原样。回放输出目录保存由原脚本生成的报告，它们仍包含原作者的验收口径，应与本审计的判断区分。

### 4.3 形成、修订与消融控制

```bash
python scripts/probe_formation_and_ablations.py \
  --repo '/path/to/Assumption-Agent/Hegel Machine' \
  --output '/tmp/hegel_formation_controls.json'
```

此脚本使用默认 gate 做定向机制控制，不是重新声称开发校准后整套效用分数。特别是无边但允许 local 跨域的控制仅用于识别原消融的权限混杂。

### 4.4 M0 接口控制

```bash
python scripts/probe_m0_semantics.py \
  --repo '/path/to/Assumption-Agent/Hegel Machine' \
  --output '/tmp/hegel_m0_controls.json'
```

其中 `open_assigned_question` 与 `step_question` 用原函数 AST 隔离，工作流使用显式工具/数据夹具。详细边界见 `05_M0接口与治理审计.md` 与脚本开头。不要把该测试计为完整 InquiryLLMAgent 会话。

### 4.5 最早边界反例

```bash
python scripts/probe_boundary_contract.py \
  --repo '/path/to/Assumption-Agent/Hegel Machine' \
  --output '/tmp/hegel_boundary_controls.json'
```

两个反例严格保持公开任务要求，新增短早期异常区间。当前版本预期出现 false_confirmation=True；修复后应修改验收脚本为不允许错误强保证，不能通过删除该输入使测试转绿。
