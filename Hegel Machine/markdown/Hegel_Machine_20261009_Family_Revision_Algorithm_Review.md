**审阅日期：2026-10-09**  
**审阅分支：`codex/hegel-cognitive-mainline`**  
**固定源码快照：`29065c7d4fc2e584e9b49c056fd0f54cdc615a8b`**  
**任务依据：`Hegel_Machine_Web_GPT6_Design_Questions_20261009.md` 的四个问题。**

本文区分三类内容：已读取源码支持的事实、据此提出的机制诊断、尚需实现和检验的算法建议。本轮未重跑真实 Luna、529-action checkpoint 或完整世界实验；没有读取隐藏环境机制来反推该关卡答案。小型数值例子是本文构造的说明例，不是实际关卡的解法或实验结果。

## 0. 先定案：最有决定性的缺口是什么

**当前缺的不是更多假设提示、子 Agent 接口或一个更精致的相似度，而是把“一个拟合代表被否定”连接成“一个持续存在的解释族及其跨条件预测受到什么约束”的机制。**

当前循环很容易是：

```text
已有数据 → 找到一个仍兼容的系数/区间代表
        → 找到这个代表认为可以激活的新设置
        → 实测失败 → 再找一个兼容代表 → 重复
```

建议改成：

```text
持续的解释族 + 参数共享约定 + 已付约束
→ 对未测条件作出可检验的后果
→ 购买响应或支持性测量
→ 先核对实验—对象—证据绑定
→ 更新旧版本的预测记录和解释族的可行后果
→ 必要时修订参数、共同前提、表示或作用域
→ 新旧解释一起接受未来检验
```

这里“持续”不意味着强制保留一个错误模型，也不意味着先证明整个旧语言不完备才允许新模型。它意味着：**更换代表不能重置过去的反例、前瞻预测失败及参数共享义务。**

最窄的首轮目标是：保留现有有限 `Program`、物性绑定、联合响应约束求解、实际执行和父答案返回，只增加一个**解释族级研究状态与统一的条件化测试更新器**。先让这个闭环在小型世界里改善任务和新条件预测；本轮不做通用本体发明，不建设新的证书治理体系。

## 1. 源码审阅：哪些判断有直接依据

### 1.1 已有能力不是空壳

`world_llm_inquiry.py` 中已经明确要求：`bind` 返回实际观测行、`Program` 候选和前瞻探针；同一程序要预测声明的多行及探针；拟合不能冒充确认。提案阶段只计算和写稿，不直接执行世界实验，由父研究决定采用。继续加强这段提示本身，不是新的算法答案。[S1]

`world_relation_research.py` 已有实际拟合、旧候选冻结、验证、确认和实验选择。不能把当前问题描述成“还没有可执行假设”。[S2]

### 1.2 第一个关键连接点：参考实验被放在目标实验之后

`world_response_hypotheses.py::_select_response_experiment` 先构造目标对象的未试设置，随后执行：

```python
reference_search = not experiments
if reference_search:
    # 才构造 reference experiments
```

也就是说，**只要目标对象还能提出一个可试设置，参考对象的实验就不进入这一轮竞争**。[S3]

这不是说“参考实验一定更好”，而是目前的优先级使参考研究无法用证据价值赢过仍然不断出现的目标点。对于已经测出正例的参考对象，研究连通窗口、边界、可重复性或物性变换可能约束多个目标；当前策略在目标建议源源不断时会延后这种机会。

### 1.3 第二个关键连接点：联合拟合仍然产出少数目标条件化代表

`world_response_constraints.py`：

- 每个基函数族最多返回两个执行检查通过的代表；
- 负响应通过区间两侧的析取分支表达；
- `BRANCH_LIMIT = 128`；
- 当前目标设置作为 LP 变量，被要求处于拟合的激活带内；
- 再用靠近旧预测中心或最小归一化斜率 L1 的目标选代表；
- 源码明确说明，搜索失败不排除控制网格外的激活。[S4]

所以它产出的是：

> 在已声明基函数、已检查分支及目标可达条件下，找到的可执行兼容见证。

不是：

> 来自真实后验的独立样本，或者这个族全部可能性的均匀代表。

`world_response_hypotheses.py` 也明确把“可达目标支持”标为 test-design condition，而不是已经观察到的成功。[S3]

**目标可达约束可以帮助找待试设置，但不能同时成为解释族的基础事实。**新设计中应分离“解释历史的可行族”和“为了构造动作而临时附加目标成功条件的查询”。

### 1.4 第三个关键连接点：任意声明的互补预测能获得分歧

`world_experiment_choice.py` 检查 ID、描述、可执行动作和 Boolean forecast，然后把 forecast 列转成 `Candidate`，交给现有 `choose_probe`。它不负责证明这些 forecast 是从跨条件解释推导的。[S5]

这本来是合法的局部 `contrast` 接口；问题在于其 separation 不能被提升为一般的“解释进步”。“本段会命中”与“本段不会命中”可以产生最大二元分歧，却可能只定义了当前扫描的一次结果。

### 1.5 第四个关键连接点：新候选与确认语义

`world_relation_research.py` 的继续研究分支主要沿用 `previous.candidates`。`binding_changed` 检查旧拟合行和 basis 变化，不以新 `hypotheses` 列表作为自动替换依据。接口提示因此要求新族另开关系问题。[S1, S2]

同一文件实际使用：

```python
set(row["evidence"]).isdisjoint(fit_evidence)
```

筛选验证行，并用与 `confirmation_after` 全部记录的分离筛选确认行。它把“旧物性读数 + 新响应”整体看成不够新，这与附加问题描述一致。[S2]

另外，有限候选全不拟合时的 `representation_inadequate` 应只读成当前有限搜索的操作诊断，不能读成整个表示空间已被证明不充分。

### 1.6 诊断强度

这些代码结构与报告中的长时间停滞相容，构成值得优先检验的机制解释；**本轮静态审阅不能证明它们分别造成了多少次失败，也不能保证修改后该关卡一定成功。**

## 2. 问题一：最小假设对象，以及什么才算跨条件解释

### 2.1 分开“族”和“成员”

一个解释族记为：

\[
F=(\phi,p_\theta,\Theta,s,\Gamma,\mathcal T).
\]

| 部件 | 含义 |
|---|---|
| `phi` | 把实际物性、控制和历史变成输入的可执行表示 |
| `p_theta, Theta` | 程序结构及允许的参数集合 |
| `s` | 可在预测前判断，或明确尚未判定的适用条件 |
| `Gamma` | 测量含义、稳定性、确定性、共同响应带等支持前提 |
| `T` | 哪些参数跨对象共享，哪些可局部变化，以及变量如何跨对象绑定 |

一个**成员**是固定参数、固定程序版本和固定绑定的实例 `h`。测试否定某个成员，不必否定整个 `F`。

当前激活任务可以保留已有形式：

\[
h_{F,\theta,\ell,r}(o,u)
=\mathbf 1\{\ell\le u-p_\theta(\phi(o))\le r\}.
\]

该形式中的线性可拟合部分、共享带、确定性和对象状态稳定性，全部是工作假设，不是实际世界真理。

### 2.2 为什么一个程序“能跑多个对象”还不够

查表也能跑多个对象。因此不按文字深度、程序名称或节点数量评判解释，而记录：

1. 对象之间究竟共享了哪些参数和关系；
2. 哪些新对象/新条件允许预测，而不先用其响应重拟合；
3. 该预测是否在看见响应前固定；
4. 对象 ID、结果索引和新增条件分支是否只是记忆过去答案。

查表和局部拼接不必禁用：它们可以是有用的操作记忆。但新对象若没有对应条目或局部参数，必须输出未定，不能凭默认值获得跨条件解释资格。

局部子假设也不必强制独自预测很多对象。**它可以通过父解释产生跨条件后果。**例如只测一个参考对象的仪器校准，只要其结果经明确的共享绑定改变两个目标上的预测，就有研究价值。

对可获迁移证据的预测程序，输入应限于声明的实际物性、控制、历史与可观察条件；观测行号、答案表和当前待判响应不能作为预测特征。对象 ID 可以用于定位读数，但直接按 ID 查旧答案只获得已见对象的支持。不能用正则表达式判断“像不像查表”：短代码也能编码复杂表，物理问题也可能有合法类别分支。首轮的有限族、参数共享和描述复杂度是公开归纳偏好；真正的通用性仍需未见条件上的预测。

### 2.3 三类修订及不变项

| 修订 | 可以改变 | 必须保留或说明 |
|---|---|---|
| 参数修订 | 同一族内的 `theta, ell, r` | 旧反例仍约束当前适用范围；新成员另记前瞻预测 |
| 作用域修订 | 可观察条件、例外分支、当前可用性 | 原广义主张的反例不被删除；缩域是新主张，不能追认旧主张正确 |
| 表示/观测修订 | 新物性、物性变换、历史变量、测量解释 | 新输入的来源和支持条件；必须仍预测同一物理结果 |

由旧特征计算乘积、比例等，是表示修订，不是新物理观测。购买一个以前没有的读数才是观测扩展。两者都可能有用，但证据和费用不同。

### 2.4 旧解释作为特殊情形

优先提出包含旧模型的嵌套族，例如：

\[
p_{\rm new}(x,z)=p_{\rm old}(x)+\alpha g(z),
\qquad \alpha=0\Rightarrow p_{\rm new}=p_{\rm old}.
\]

或在可观察条件 `c` 内保留旧模型。嵌套关系可由代数或程序求值证明；**当前世界是否处于旧条件，仍需证据。**不能为了“保守继承”强行保留已被可靠反例否定的全称命题。

## 3. 泛函分析思路怎样成为可执行诊断

### 3.1 首先固定物理实验含义

实验 `e` 至少指明对象、设置、状态/时间条件、读取什么结果。候选表示改变时，仍比较同一个 `e`，不能偷偷更换评价对象。

对已有或计划实验族 `Q`：

\[
S_Q(h)=(\operatorname{Predict}(h,e))_{e\in Q}.
\]

若两个候选在 `Q` 上相同，它们只是**在这些实验下不可区分**。不能丢弃其他地方可能区分它们的结构，也不能宣称找到了全局真实等价类。

### 3.2 在线性数值子问题中直接计算不可见方向

对于 `p_theta(z)=b(z)^T theta`，已有数值观测的设计矩阵为 `X`。若：

\[
Xv=0,
\]

则沿 `v` 的参数变化在这组读数下不可见。新测点有：

\[
b(z_*)^Tv\ne0,
\]

才可能区分这个方向。

这给出可实现的小诊断：数值秩、零空间、目标预测是否沿未识别方向变化。秩阈值与测量精度需记录，病态近似零空间不能伪装成精确证明。

**当前激活是 Boolean 带内/带外观测，不能直接把控制读数当连续标签套用上述等式。**主路径应使用下一节的可行约束和响应签名；线性零空间只对适用的连续子模型或局部诊断有意义。

### 3.3 四种不同的诊断结果

| 观察 | 支持的判断 | 不支持的判断 |
|---|---|---|
| 同一族有兼容解，额外合法 probe 能区分它们 | 继续估计参数或检验该区分 | 当前族正确 |
| 当前 probe pool 中全部候选预测相同 | 这个 pool 没有已发现的区分 | 世界中不存在区分实验 |
| 同一真实已控条件和充分复核的表示对应不同响应 | 确定性充分表示/状态假设需要研究 | 一定是不可约随机噪声，或一定缺某指定变量 |
| 对某族的全部相关分支有可靠不相容证明 | 该明确限定族与证据不相容 | 一切旧表示、整个语言均被否定 |

改变观测的依据不必是“证明整个旧语言无能”。它可以是一个更窄的未识别需求：**当前多个解释都拟合，但对目标决策分歧；某个合法测量预计能区分它们，且父模型如何消费这个结果已写清。**

## 4. 问题二：进步单位改成“可迁移后果”，不是代表数量

### 4.1 持续约束集

对每个固定族版本，保存：

\[
V_t^F=\{\theta\in\Theta_F:\theta\text{ 与当前适用的已付证据相容}\}.
\]

在族、作用域和证据语义都固定时：

\[
V_{t+1}^F\subseteq V_t^F.
\]

参数代表可以换；`V` 的历史约束不能重置。修改族或 scope 创建新版本，重新筛查旧证据，不能把“删除旧约束”记为科学进步。

### 4.2 不需要完整枚举参数，也不要回到全 DSL closure

首版只在当前带模型及小型前瞻后果上做可行性查询。接口给四种结果：

```text
SAT_WITNESS       找到执行复核通过的兼容见证
UNSAT_VERIFIED    对该精确定义查询的相关分支有可靠排除依据
UNKNOWN          超时、只检查部分分支、数值不可靠、求解未完
INVALID_BINDING  不是数学反例，而是实验/对象/读数绑定无效
```

现有 `linprog` 的 infeasible 状态、128 分支 cap 或未找到代表，不能不加区分地全部映射为 `UNSAT_VERIFIED`。最初版本无法可靠核对不相容时就返回 `UNKNOWN`，仍能继续进行前瞻成员测试。

对每个小型析取查询，可靠排除需要覆盖全部相关分支，并核对数值界或不可行性依据。若使用有限精度 margin，结论只对声明了该 margin 的族有效。**不要求先建设通用证明器，更不要求在允许修订前证明整个语言不充分。**

### 4.3 使用一个很小的“未测后果面板”

给本轮父问题选定 4 个未测物理条件作为起始面板 `T`；规模可在开发阶段调整，例如不超过 6 个。面板包括当前目标之外的一个条件，或与当前测试不同的目标设置。它是待预测条件，不含隐藏答案。

定义：

\[
P_t(T)=\{(h(e_1),\ldots,h(e_m)):h\in\cup_FV_t^F\}.
\]

Boolean 情况最多 `2^m` 个签名；`m=4` 只有 16 个。它不是参数空间体积，也不需要给每个参数向量分配概率。

保存两个近似：

- `P_in`：已有执行见证的签名；
- `P_out`：尚未被可靠排除的签名，包含 `UNKNOWN`。

只有验证过的排除才能缩小 `P_out`。搜索找到更多见证可以扩大 `P_in`，这叫计算覆盖改善，不叫世界证据进步。

### 4.4 必须看联合签名，而不只看每一点的上下界

若一个族要求两个对象响应相同，允许 `{00,11}`；另一个族允许 `{00,01,10,11}`。它们的逐点取值集都是 `{0,1}`，但共同关系完全不同。

因此面板至少保留联合结果或明确的关系后果。不能只有每个目标的最小/最大值，然后声称已经检验了共享规律。

### 4.5 新证据真正排除了什么

对一次实验 `e` 的实际结果 `y`，记录：

\[
G_{\rm evidence}
=\left|\left\{z\in P^{\rm in}_t(T):
\operatorname{Feasible}(D_t\cup\{(e,y)\},T=z)
=\text{UNSAT\_VERIFIED}\right\}\right|.
\]

含义：此前至少有一个兼容模型实现的跨条件后果，在加入新证据后已无法实现。

注意四个限制：

1. 若同一个签名仍可由另一个兼容族实现，就没有在候选集合整体上被排除。
2. `T` 不含刚刚执行的 `e`，否则“知道刚测点结果”会被直接包装为迁移进步。
3. 面板改变时另记比较 epoch，不能缩小面板制造更大分数。
4. 这一计数只是小面板上的逻辑进展，不是总体准确率或总体信息增益。

如果族都不能可靠排除，`G_evidence` 可以一直是零。此时仍然保留真实新数据、固定成员的预测成功/失败、控制覆盖和任务进度；不能为了让指标好看把 `UNKNOWN` 写成排除。

### 4.6 一个窄的实验排序准则

对于可负担的合法候选实验，尝试估计：

\[
g(e)=\min_{y\in\{0,1\}}G_{\rm hypothetical}(e,y).
\]

`G_hypothetical` 使用同样的查询，但此时是假设某个结果发生的计算，不是已得证据。无法完成的分支不给保证增益。

这不是 Bayesian expected information gain，而是一个**对声明模型集合和小面板的保守后果区分准则**。不得把它命名成校准概率。

任务动作与研究动作采用清楚的优先级：

1. 若有受当前证据支持的直接任务动作，优先完成任务；它不必为了“更深解释”而被耽误。
2. 对当前选择有实质影响且 `g(e)>0` 的实验，优先更大跨条件后果区分；同级再考虑费用。
3. 已出现停滞而没有正 `g` 时，进入共同前提诊断，不继续用新代表的票数制造分歧。
4. 没有可用解释性实验时，允许标明为 operational exploration 的覆盖或搜索，或报告不可识别。

多个币种继续分别收费，不把 model tokens、世界动作和 CPU 强行汇成未经论证的一个效用数。

这条规则也有边界：两个任意生成的可执行程序仍可能被人为安排成跨整个面板互补。任何有限分歧准则都不能单独证明它们是有根据的科学解释。本方案排除的是“仅填两列互补文本 forecast 就获得解释分数”和“复制代表改变票数”；更一般的过拟合仍要靠候选输入权限、共享结构、复杂度以及真正前瞻失败来约束。若全部候选来自一个差的生成器，结果仍可能很差。

### 4.7 复制候选、不同维数和不完备

**复制候选。** 同一程序重复一百份不改变可行后果集合，因此不会增加区分价值。有限面板上行为相同只用于本轮计分，不能永久合并可能在别处不同的程序。

**不同维数。** 不比较“参数空间剩下百分之多少”。重参数化会改变这种体积，维数也使它不可直接比较。比较同一个物理面板上的后果、未来固定预测误差和所需资源。复杂度只作明确的搜索偏好或平局规则，不充当真理概率。

**不完备。** `UNKNOWN` 是正常结果。保留部分边界和见证，缓存可复用求解结果；不能用新一轮代表采样重置停滞历史。

**长期只有负响应。** 一个反例首先约束实际试过的设置。没有带宽下界、连通性或共享关系证据时，它不能可靠排除未试的连续邻域。始终可能有一个更窄或移位的激活区间。此时更好的记账不能创造可识别性。

## 5. 最小状态与研究选择/返回算法

### 5.1 只需要在现有对象上补六类状态

| 状态 | 最少内容 |
|---|---|
| `FamilyState` | 程序/basis、共享参数图、scope/支持前提、累计约束、求解状态、当前成员版本 |
| `EvidenceState` | 实际对象/状态/控制/读数、属性与响应各自引用、来源和取得顺序 |
| `ForecastState` | 在什么证据截止点固定了哪个版本，对哪些未测条件预测什么 |
| `ConsequenceState` | 固定小面板、可行见证、未排除集合、可靠排除及原因 |
| `ResearchState` | 当前待解的共享前提、子问题、返回槽、无进展轮数、待试动作 |
| `MethodState` | 当前研究策略版本及实际执行反馈；首轮先固定策略，不同时测试自改写 |

不用把每一类都实现成一个新子系统。多数可以是现有 question / binding / result 的附加字段和一个共享更新函数。

### 5.2 停滞触发不是“族被证伪”

给出一个首轮可实施的策略：连续 **两个完整“冻结预测—实测—更新”周期**满足下面条件，就暂停同一目标的代表轮换：

```text
任务无改善；
没有新的跨条件前瞻预测支持；
未测后果面板无可靠缩减；
主要变化只是重新拟合出另一个代表。
```

两轮是开发用调度超参数，不是统计显著性，也不是通用最佳值。更换代表、改名字或再调用一次求解器不清零该计数。可在开发集比较 1/2/4 等阈值，主实验之前固定。

### 5.3 停滞后先检验哪些共同前提

顺序由当前失败义务决定，不是永远固定八级排除梯：

- 实际装载对象、控制设置及状态是否与预测一致；
- 同一设置的激活结果是否可重复；
- 已有正例是否能支持一段连通区间及其边界；
- 共享带/共享偏移在参考对象之间是否还有约束能力；
- 哪个物性或校准解释使现有候选对目标仍不可识别。

现有源码已经能检测同一对象“两个正例夹一个负例”与单连通带不相容；应该把它作为支持前提的实际反例返回，而不只是一次候选构造失败。[S4]

**参考对象和目标对象的动作从第一轮就应在同一实验池中比较。**不用等 `target experiments` 为空，才允许研究参考对象。也不应反过来把参考对象永远置顶。

相同子问题在同一证据截止点、族版本、实验可用性和研究方法下返回 `unknown` 后，不自动原地重开。只有新证据、新候选、可用测量变化或明确增加的有效求解资源才能重访；这与把该前提永久判假不同。否则只是把“反复换代表”改成“反复调用子 Agent”。

### 5.4 伪代码

```python
def research_step(state):
    # 同一份实际世界记录，先检查绑定；执行错误不当科学反例。
    events = read_new_public_events()
    valid, invalid = validate_event_bindings(events, state.pending_tests)
    state.record_invalid(invalid)

    # 先评估此前固定的预测，再把响应加入重拟合。
    score_outstanding_forecasts(state.forecasts, valid)
    update_scoped_support(state, valid)
    append_family_constraints(state.families, valid)

    # 新草稿显式加入共同候选集合；不隐式替换旧结果。
    for draft in explicitly_adopted_drafts():
        child = compile_and_bind(draft, state.paid_evidence)
        check_on_all_applicable_paid_evidence(child)
        state.register_new_version(child, confirmed=False)

    solve_small_family_queries(state, bounded_compute=True)
    refresh_consequence_sets(state, keep_unknown=True)

    task_action = supported_direct_task_action(state)
    if task_action is not None:
        return freeze_test_plan(task_action, state)

    experiments = propose_task_and_reference_experiments_together(state)
    ranked = rank_by_nonlocal_consequence_gain(experiments, state)
    if ranked.has_positive_gain():
        return freeze_test_plan(ranked.best(), state)

    if not state.stagnating() and has_justified_parameter_query(state):
        return bounded_refit_or_identification(state)

    # 不要求所有旧解释已穷尽；允许检查它们共同依赖的前提。
    obligation = choose_blocking_premise_or_missing_observation(state)
    if obligation is not None:
        child_question = make_child(
            obligation,
            parent_versions=state.current_parent_versions,
            return_map=explicit_parent_update,
            consequence_panel=state.fixed_unmeasured_panel,
        )
        return run_or_resume_child(child_question, reserve_parent_step=True)

    if bounded_representation_proposal_is_available(state):
        return request_executable_revision(state)  # 可以返回 NO_PROPOSAL

    if useful_operational_exploration_is_available(state):
        return freeze_test_plan(coverage_action(state), state,
                                role="operational_exploration")

    return Unresolved(reason="not_identified_under_available_evidence_and_actions")


def consume_child_result(state, result):
    if result.kind in {"execution_error", "invalid_binding"}:
        return repair_execution_without_changing_scientific_support(state, result)
    if result.kind == "unknown":
        return keep_parent_conditional_and_choose_other_action(state, result)

    parents_before = snapshot_parent_forecasts(state)
    apply_only_declared_return_map(state, result)
    recompute_parent_candidates_and_forecasts(state)
```

`no positive gain` 不意味着“没有信息”。它表示这个保守小面板/当前搜索没有找到可证明的跨条件区分，下一步可以做信息获取或探索，只不能虚报其保证。

### 5.5 如何处理模型仍不给 bind

不要再把希望全部寄托在“请更深刻解释”的提示上。

调用现有提案出口时给出一个**实际反例包和待修订槽**：旧程序、哪些旧预测失败、共享约束、哪类未来后果尚未确定。给最小可执行草稿骨架，允许模型填入 `Program`、basis 变化或测量绑定；编译和 paid-data 比较由现有工具执行。

首版还可由现有有限合成器提出几个邻近修订，例如添加一个已测特征、一个交互项或一个历史项。这些都是**公开的搜索偏好**，必须给所有对照同样权限，不能借隐藏机制生成正确项。

若模型仍只提交扫描程序，就保留为 operational proposal；若没有候选，记录 `NO_EXECUTABLE_EXPLANATION_PROPOSED`。不能由评测器补写正确解释，再归功于模型。

## 6. 一个完整小例子：子研究改变父解释和未测预测

**这是说明例，不对应实际 DiscoveryWorld 隐藏机制。**为了看清推理，暂把已使用的激活带 `[1,2]` 作为明确的工作前提；实际实现应像现有 LP 一样联合保留带端点的不确定性。

旧父模型：

\[
H_0:\quad Y(o,u)=\mathbf1\{1\le u\le2\}.
\]

参考对象的已测特征 `z=0`，在 `u=1.5` 激活。另一个对象的 `z=1`，在 `u=1.5` 未激活。该反例否定旧模型的这次跨对象应用，但不能确定失败原因。

一个候选修订是：

\[
H_1:\quad Y(o,u)=\mathbf1\{1\le u-\alpha z(o)\le2\},
\qquad \alpha\in[0,2].
\]

还有局部对象差异、带形状变化、状态变化等竞争解释。不要仅凭一个反例认定 `z` 有因果作用。

子问题是：**这个共享特征偏移是否对当前对象成立，若成立能约束到哪里？**

| 子实验实际结果 | 对工作族的约束 |
|---|---|
| `z=1, u=2.4, Y=1` | `alpha ∈ [0.4,1.4]` |
| `z=1, u=2.6, Y=1` | 与上行合并得 `alpha ∈ [0.6,1.4]` |
| `z=1, u=1.9, Y=0` | 得 `alpha > 0.9` |
| `z=1, u=3.1, Y=0` | 得 `alpha < 1.1` |

所以子答案不是“这段扫描命中”，而是：

\[
\alpha\in(0.9,1.1)
\quad\text{在共享偏移/固定带/绑定稳定前提下。}
\]

父研究现在对**尚未测试**的第三个对象 `z=2`、设置 `u=3.5` 预测：

\[
u-\alpha z\in(1.3,1.7)\subset[1,2].
\]

因此该族全部剩余成员预测激活；旧模型预测未激活。父实验改变为检验这一跨对象预测。

这个例子展示四件事：

1. 局部子研究合法，但其结果能约束未测条件；
2. 同一共享参数解释所有当前对象，不是为第三个对象先拟合新参数；
3. `alpha=0` 时新族退化为旧族；在 `z=0` 上始终保留旧行为；
4. 第三个对象实测前，不能把这个前瞻推断写成现实中的新确认。

若第三个对象失败，要重新考虑共享偏移、作用域、测量含义或带模型。不能只为第三个对象加一个无约束 `alpha_3`，继续声称原共享解释已经确认。

## 7. 问题三：旧证据、新响应和滚动新解释

### 7.1 新证据不要求所有输入都重新测量

把一次待验证响应写为：

\[
Y_{t+1}\mid Z_{\le t}, U_{t+1}, C_{t+1}, \Gamma.
\]

只要模型、拟合参数和这次预测在 `Y_{t+1}` 揭示前固定，旧物性 `Z` 可以作为条件输入。需要成立的是属性身份、测量意义、有效状态和稳定性假设，而不是文件引用完全不重合。

因此，把现有 row 的引用拆成最小语义角色：

```text
conditioning_refs       已有物性、校准、固定上下文
outcome_refs            这次实际响应
acquisition_context     对象、状态、控制、读取类型
selection_cutoff        候选与预测何时固定
support_assumptions     属性稳定/校准/共享机制等
```

新响应不得已被用来选这一个候选或参数。否则仍可用于拟合和反例分析，但不再是该版本的前瞻确认。

### 7.2 这种确认究竟确认了什么

| 使用方式 | 合法结论 |
|---|---|
| 旧物性 + 新响应，预测先固定，稳定性仍有支持 | 新的条件化预测证据 |
| 旧物性 + 旧响应，被新理论重新拟合 | 回溯相容性，不是新确认 |
| 属性可能随状态变化、但未检查 | 依赖未解决，不能假设该物性仍适用 |
| 同一个错误校准被多个响应共用 | 这些检验有共同依赖，不是多份独立校准证据 |
| 新响应后更新了参数，再对该响应评分 | 新版本训练拟合，不是它的未来确认 |

新响应不等于整条观测向量独立。连续轨迹、同一装置、共同传感器误差产生相关性时，应按实际试验块报告，不能简单连乘概率或把每行当独立复核。

### 7.3 最小候选与证据状态

候选/成员不必只有一个扁平状态。保留三项就够：

```text
fit_status:        unchecked / compatible / incompatible / solver_unknown
prospective_status: untested / supported_on_tested_scope / contradicted
applicability:     applicable / suspended / outside_declared_scope / unknown
```

每项绑定程序版本和适用条件。历史 support 记录不可覆盖。旧模型在新条件下失效，不删除它的旧条件证据；旧条件返回时需要当前绑定/状态复核，不能仅凭环境名字相同自动恢复。

### 7.4 新解释加入的实际更新顺序

1. 新草稿由旧反例产生，显式登记 `parent_version`、修订种类和用过的证据截止点。
2. `adopt_candidate` 把它加入父研究的共同候选表；原候选及其支持记录保留。
3. 对所有适用的已付记录重新比较，不能只挑 motivating residual。
4. 解释当前旧数据成功，仅记录 compatible。
5. 在揭示新响应前，固定新旧候选对同一实际测试的预测。
6. 新结果先逐版本更新预测记录，之后才能为后续拟合使用。
7. 若所有族共同失配，生成支持前提/表示研究需求；若只有某个成员失败，在族内缩约束或换成员。

`research_update` 可以继续承担 paid-data 比较，但其输入需要明确的候选增量或共同 registry revision；不能继续依靠修改 `hypotheses` 列表产生隐式注入。

缓存至少绑定：程序版本、表示/读数绑定、scope/共享约定、证据截止点。复用缓存不能跨这些语义变化。

### 7.5 三个时刻必须分开

**反例发生：**此前固定的候选或族级必然后果与有效实测结果冲突。

**拟合成功：**加入该结果后找到一个新兼容参数或新程序。

**新确认发生：**修改后的固定版本在随后未揭示的响应上作出了正确预测，且当前依赖仍适用。

特别是：

\[
\forall t\;\exists\theta_t:\theta_t\text{ 拟合截至 }t\text{ 的数据}
\]

远弱于：

\[
\text{在看到 }Y_{t+1}\text{ 前固定的同一 }\theta
\text{ 正确预测 }Y_{t+1}.
\]

当前“失败后又能拟合一个代表”的现象，恰好落在这个差别上。

### 7.6 C5 实验与 C4 记录错配怎样消失

每个实验计划保存：

```text
experiment_id
question_id + parent_version(s)
subject_object_id + state binding
control settings / allowed adaptive procedure
expected observable and extraction rule
frozen forecasts
permitted conditioning_refs
fresh outcome slot
declared update targets / child return map
```

执行器返回实际动作与实际读数，中央更新器核对后才填入 outcome slot。

若计划测 C5，却实际解析出 C4 响应：`INVALID_BINDING`，不更新 C5 的科学支持。新记录仍保留供纠错。**C4 的证据可以通过共享模型影响 C5 预测，但必须沿明确的跨对象关系返回，不能冒充 C5 的响应。**

计划允许自适应扫描时，要保存真实执行轨迹和停止条件。未扫描完整的区间、安装失败或缺响应，不能解释为“整个区间无激活”。

## 9. 问题四：最窄而有解释力的实验

### 9.1 不把已消费难场景继续当正式独立验证

529-action checkpoint 用于开发诊断与差分测试，不能重新宣称 untouched。保留两臂都失败以及未产出 bind 的记录。

首个机制实验使用新的小型对象—控制—激活世界，仍是三参考、两目标及已有物性接口。环境由评测器持有，研究端只见公共动作与已付记录。采用少量可执行家族验证机制不是作弊，但必须明确：这不是一般自动发现证明。

至少包含三类情形：

- 现有族内参数就足够；
- 需要使用一个可测/已测共享特征来产生跨对象后果；
- 某个共享前提失效，或者现有观测下仍不可识别。

种子、变化类型和哪个家族适用都不提供给研究控制器。首轮可做每类若干实例的可迭代 pilot；这只是算法诊断，不凭这个小样本宣称跨领域统计优势。正式规模之后按 pilot 方差和目标效应规划。

### 9.2 主实验三臂：先隔离最关键的机制

所有臂共享同一来源数据、模型产生者、工具、候选程序集合及允许资源。第一轮不允许实时改写研究算法。

| 臂 | 状态与实验选择 | 回答什么 |
|---|---|---|
| A：当前代表法 | 当前有限代表/Boolean separation，其他执行修复同样具备 | 现有基线 |
| B：平铺族级研究 | 持续族约束、条件化新响应、小面板后果、参考/目标共同入池；无显式子研究调用 | 族级状态与选择方案是否有独立作用 |
| C：父子族级研究 | 与 B 同样候选、后果求解和数据权限；待解前提作为子问题，结果经固定 return map 改父研究 | 显式父子组织在共同语义上是否增值 |

A→B 是本次**族级记账与选择的联合算法效果**，不能只归因给某一个字段。B→C 才是父子组织对照。B 必须有能力直接分析同样的参考数据，不能故意拿掉关键能力。

候选内容在主机制比较中先固定或共享同一冻结 proposal bank。这样成功不能归因于只给 C 一个更好的答案。模型若负责选择动作，各臂用相同模型与工具；若第一轮用冻结数值控制器，应明确标记为非 LLM 自主发现证据。

### 9.3 怎样排除“只是花了更多探索”

报告相同预算上限之外，还报告共同花费检查点上的任务成功和未测预测。世界动作、真实响应获得次数、模型调用和计算分别列出。

增加一个零/低额外模型成本的机制重放：在同一份已执行动作—响应日志上，让 A/B/C 的更新器只做证据更新和后果计算。它可以检验“数据相同时表示更新是否不同”，但**不能冒充在线策略的因果效果**，因为不同在线策略本来会购买不同观测。

如收益只在 C 使用更多响应后出现，而在共同花费点没有收益，应报告更多探索的贡献；不能仅靠相同最大预算说已完全排除这一解释。

### 9.4 候选内容与方法改写分开做插拔，不与主实验混因果

**候选内容插拔：**选同一个研究控制器和同一公共停滞状态，比较“原候选库”与“加入冻结新 proposal bank”。使用同一 proposer 的同一批候选；所有生成费用保留。结果只说明这批候选内容的价值。主实验里 B/C 都获得这批内容，不能让 C 独占。

**方法改写插拔：**在开发 donor 上产生一个新研究方法后，将其冻结并移植到新实例；比较原方法与新方法，保持任务知识和候选库相同。若代码改写同时偷偷新增候选族或更大预算，就不是纯研究方法效应。

不声称三臂实验已经辨识四个因素的全部交互。先证明最窄闭环，再做上述两项局部扩展，比一开始铺开庞大 factorial 更合适。

### 9.5 主终点

优先报告：

1. 固定投入内是否完成目标任务；
2. 在看答案前冻结的跨对象/跨条件预测是否正确，及其覆盖率；
3. 错误确认、范围过度扩张与未解决案例。

后果集合缩减、代表更换次数、子问题深度、节点数只是机制指标。

二元响应大量为零时，不使用总体 accuracy 单独评价。至少同时报告正/负条件表现、预测覆盖、目标激活和错误排除；终测条件由研究端不可见的固定评价程序产生，不能由 Agent 挑只会失败的点。

统计单位是独立世界或独立来源—后继序列。反复调用同一个 checkpoint、重复检验同一对象不能膨胀样本数。获取不到足够终测正例应报告评价覆盖不足，而不是默认安全。

### 9.6 什么结果支持什么结论

| 观察到的结果 | 可支持的结论 |
|---|---|
| `bind` 被生成并成功执行 | 接口采用；尚无科学收益 |
| 扫描终于命中目标 | 局部任务/搜索成功，不自动是跨条件解释 |
| 新程序拟合历史成功 | 回溯相容性 |
| 子研究结果改变父程序或待测实验，并提前改变另一条件的预测 | 存在实际父子传播机制 |
| 随后未测条件预测被现实支持，且旧条件仍按声明恢复 | 有限的解释修订与迁移证据 |
| C 与 B 持平，但 B 优于 A | 族级算法有效，显式递归无额外效应 |
| 所有臂同样失败，或普遍 UNKNOWN | 当前信息/语言/动作仍不足；不能说接口设计已解决科学问题 |

给 child return 做替换/阻断可以成为机制单测，但伪造子证据后的运行不计为真实世界效能实验。有效性最终要靠实际获取的支持与独立后果。

## 10. 先做的差分测试

无需真实模型调用，即可先验证下面九项：

| 测试 | 预期 |
|---|---|
| 同一候选复制 1/10/100 次 | 后果集合与解释实验价值不变 |
| 改名或同体参数表示重编码 | 不增加科学支持 |
| 一个代表失败但同族仍有兼容见证 | 只撤销成员，不撤销族 |
| 128 分支限制截断或求解超时 | UNKNOWN，不是排除 |
| 只有刚测设置被排除 | 记局部覆盖，不记跨条件进展 |
| 旧物性 + 新响应，版本先冻结且状态稳定 | 可以进入条件化前瞻检验 |
| 新响应先用于重拟合再回放 | 只能记拟合 |
| C5 计划绑定到 C4 响应 | 无效绑定；不污染两者支持 |
| 目标仍有建议，但参考实验有明确非局部价值 | 参考实验可以被选择，不被 fallback 规则挡住 |

再做两个端到端 pilot：一个参数修订即够用，一个子研究应改变父条件预测。只有它们工作后再接真实 proposal，自主性失败继续如实计入。

## 11. 这套方案会失败在哪里

**可识别性不足。** 若所有允许观测下两个机制本来等价，没有状态表示或调度器可以凭空区分。输出未解决是正确结果，但任务仍可能失败。

**激活带可任意窄或位于不可达控制域。** 长期负响应无法排除未试的所有地方。不能擅自塞入“真实宽度至少多少”的 benchmark-specific prior。

**共享假设错。** 把不共享的对象硬绑成同一参数，可能迅速收缩可行集却产生错误预测。共同失配必须打开 scope/关系研究，而不是再加对象常数把一切吃掉。

**求解几乎全 UNKNOWN。** 小面板也需要约束工具。若非线性太强或分支过多，保守准则可能全零；应退回明确的固定候选前瞻测试、实验设计或操作探索，而不是声称精确族排除。

**候选生成没有有用结构。** 本方案不能保证 Luna 一定产生正确新特征。接口失败、空提案和错误提案是需计入的发现能力结果。

**隐藏状态或测量噪声。** 错误的确定性约束会把真实模型删掉。反复同设置测试只能暴露该工作模型问题，不能自行证明噪声不可约或某个潜变量唯一正确。

**有限面板偏差。** 对面板收缩不代表对整个世界预测更好；必须保留独立终测。适应性改变面板不能回填旧分数。

**模型之外的世界。** 全部已声明族一致预测失败也可能全错。支持式 task action 和求解界仅对当前模型集合条件化，不能写成现实安全保证。

## 12. 最终施工取舍

本轮最值得实施的是：

```text
持续解释族与共享参数约定
+ 小型未测后果查询
+ 条件化的新响应确认
+ 子结果的明确父更新
```

优先去掉两种不必要的绝对化：

- 不必先穷尽旧语言，才允许提出新解释；
- 不必重新测量所有已知物性，才能检验一个新响应预测。

同时不能放松两种真正重要的约束：

- 后见拟合不能伪装成前瞻预测；
- 没找到见证不能伪装成排除解释族。

**最小成功不是“又多一个 schema，也不是主线出现更深的子问题树”；而是一个局部子研究实际缩小或修订了父解释，使它对未测条件给出不同且正确的预测，并帮助完成任务。**
