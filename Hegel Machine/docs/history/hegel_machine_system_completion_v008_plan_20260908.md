# 黑格尔机整机目标与系统性完成路线

最新进展见[0.18.0 迁移反例与研究修订](../hegel_machine_transfer_repair_20260909.md)。[0.12.0 整合研究系统](../hegel_machine_integrated_research_20260908.md)保留整机各阶段接通的运行结果。

日期：2026-09-08。当前机制版本：0.18.0。本文依据 GPT6 建议及其详细审视报告组织整机目标。测量与连续状态见[0.11.0 功能报告](../hegel_machine_measurement_and_state_20260908.md)；0.8.0 的阶段结果保留在[历史运行报告](../cognitive_runtime_v6_results.md)。

[0.9.0](../hegel_machine_functional_implementation_20260908.md)已接通具体证据、竞争解释和计划的恢复、行动收益经验及条件知识；[0.10.0](../hegel_machine_callable_concepts_20260908.md)已接通可调用的组合概念。0.11.0 增加实际测量选择、连续状态程序和独立进程环境，并保留累计证据支持的解释。下文从 0.8.0 开始的施工顺序保留其设计依据，当前状态以最新逐项报告为准。

黑格尔机要成为一个能够持续研究和解决任务的系统：既有解释失效时，它能提出竞争解释，主动取得区分证据，构造并选择可执行的修订，把有效结构保留下来，在后续问题中复用，并根据新反例改变旧知识的适用范围。一次任务结束后，留下的不仅是答案，还应包括以后能够使用的概念、研究经验和仍未解决的问题。

这决定了本轮工作的尺度。联合状态搜索处理已明确暴露的认知缺口；持续研究会话把这些能力连接成可运行、可保存和可继续的整机。跨任务研究经验进一步改变它怎样分配搜索工作。之后的实现继续沿这条生命周期展开。

## 1. 本次请求对应的文档依据

用户提到的 `GPT_advice.md`，在当前目录没有同名文件。上下文中的方向调整来自 [GPT6_advice.md](../../markdown/GPT6_advice.md)，其末尾明确链接了 [Hegel_Machine_Vision_Progress_and_Research_Critique.md](../../markdown/Hegel_Machine_Vision_Progress_and_Research_Critique.md)。更早的 [GPT_advice&roadmap.md](../../markdown/GPT_advice&roadmap.md)补充通用先验、机制主张与可执行处理的组织方式。这三份文档共同约束本文的研究方向；它们包含的历史评估、示例与施工建议，按当前代码重新判断。

GPT6 的建议把主问题明确为“选择值得付出代价的认知变化”。详细审视报告进一步要求把表示修订、主动观测、复杂度控制和可撤销的长期知识连接起来。早期 roadmap 强调从机制假设产生预测，再通过检验转为可执行程序。这些要求在整机上汇成同一条链：

```text
外部任务与固定目标
  → 已有知识和当前观测
  → 竞争解释与未解决问题
  → 分配搜索、观测和行动资源
  → 执行子问题、构造表示、产生候选
  → 用新证据选择修订
  → 预测或决策
  → 提炼可执行知识与研究经验
  → 下一任务的迁移、反例和再研究
```

“整体完成”应首先指这条链能够由一个公开入口持续运行，内部的产物确实成为后续步骤的输入。研究能力的强弱则继续由任务质量、学习成本和长期变化回答。

## 2. 目前已经连通的部分

当前 `CognitiveAgent.run` 已经完成单任务内的真实闭环。它从 `LearningEnvironment.observe` 得到数据，依据残差构造竞争问题，通过共同的 `Program` 语言生成候选，为取得新参考轨迹前固定的候选比较预测，再决定采纳、继续探索或恢复前一解释。程序、抽象、主动实验与风险模型都参与这条执行路径。

递归研究已有一个有限但实际执行的起点。`diagnosis` 产生带子问题的 `ResearchQuestion`；`planning` 将表示、关系、组合和不确定性操作组织为有依赖的步骤。中间候选被保留下来，后续步骤能以它们为输入。需要继续发展的是按新证据改变子问题结构和研究次序，而非继续增加只供记录的树形字段。

知识也已经进入真实计算。`KnowledgeLibrary` 保存可执行程序、参数化抽象、变量角色、经验支持范围和迁移结果。新任务可以保留旧参数，也可以重新绑定角色并拟合；两条路径产生的候选都要接受当前观测的比较。反例能使直接复用的知识收缩范围或撤销。删除某个概念及其派生内容的干预也已有入口。

0.7.0 的 [运行报告](../cognitive_runtime_v5_results.md)显示，旧任务平均平方误差降至约 0.000716，新状态任务分类错误率降至约 3.05%，知识在两个分区都节省了观测和计算。结果同时指出组合状态条件与真实转换时刻的明显缺口。这说明持续推进有实际基础，也说明下一步应针对认知结构继续建设。

## 3. 0.7.0 在整机连接上的关键缺口

0.7.0 的 `run_sequence` 负责依次运行预设任务并汇总评测。它是有效的研究入口，但任务顺序来自环境构造器；一个任务内部尚未解决的问题，不会成为一个持续研究系统中的可恢复待办。该版本命令行的 `--memory` 能保存知识库，尚不能单独表达一场研究已经做了什么、剩余多少总资源以及应从哪里继续。

研究行动经验在该版本的任务边界会丢失。`PlanAllocation` 会根据新轨迹上的改善和实际计算量改变依赖计划的预算，但 0.7.0 在每次 `run` 开始时重新创建它。系统可以记住“什么关系曾经有用”，却没有持续记住“面对这种失配，什么研究步骤值得先做”。已有反馈机制适合作为跨任务研究经验的起点。

知识和研究过程之间还有一个需要持续打通的方向：抽象可以迁移，但一个未解决的表示问题通常仍要从诊断启发式重新开始；实验构造也主要面对本任务的候选。整机应该能够把“哪个组合坐标仍不确定”“哪个旧概念缺少当前条件下的证据”保留下来，并在下一次获得相关环境时实际补做实验。

这些缺口意味着新的任务会话需要掌握生命周期，而现有控制器继续负责一次有界研究。单任务的候选搜索、跨任务的知识组织和整场研究的资源使用，由此能够分别改进并互相提供实际输入。

## 4. 本轮实现的两条主线

### 联合状态坐标与多输入实验

0.7.0 剩余状态错误的 83.2% 集中在双输入组合条件。专门状态搜索直接在单个原始变量上拟合进入和退出阈值；主动转换实验又经常把另一个输入固定在中点。这使系统反复精细化一个局部轴向切面，却难以恢复共同决定状态的坐标。

本轮已将可执行的联合坐标引入状态候选，使“怎样组合变量”和“在何种历史状态下转换”共同接受数据检验。实验随候选中的坐标变化，同时改变相关输入，并比较相同当前控制在不同准备历史下的输出。新的坐标与状态关系继续使用已有语言表示，能够进入抽象提炼、角色迁移和反例处理。

初筛保留同等最佳拟合下使用不同观测变量的解释，使联合表示能够进入新轨迹比较。已有反例带来的预测改善若超过新增复杂度，且参考与新预测不退化，也可以支持更大的有效程序。改动分别解决候选产生、获得比较机会和按证据采用之间的连接问题。

这条改动的整机意义在于让一种表示改变带动一种观察改变，再产生可复用的关系。实际收益需要同时看总体状态分类、切换行误差与真实支出；减少普通状态行的错误不能替代转换行为的改善。

### 持续研究会话

本轮已通过 [ResearchSession](../../src/hegel_machine/cognition/session.py) 接通从任务开始到保存知识和继续研究的入口。会话持有任务进度、总资源、共享知识、研究行动经验与已经发生的结果；它将选中的任务交给 `CognitiveAgent`，再把实际产物反馈到下一次研究。

当前执行方式是：建立会话后取得一个任务，用现有控制器进行一轮有界学习，保存结果和余下任务，再加载会话继续运行。一次研究中知识的增加、复用、范围修订与撤销出现在同一份连续记录中。任务暂停或一次运行额度用完时，已完成访问的结果和共享知识仍然可继续使用。重访会重新购买初始观测并建立候选；保存的问题树尚未成为可恢复执行的研究分支。

跨任务行动经验使用实际新观测上的改善与所花资源更新，并按可观察的任务条件组织经验。会话先覆盖每个任务，再将仍有明显学习误差的任务列为待办，按相对于初始损失的超额误差选择下一次研究。每个任务最多访问的次数和整场研究的总观测、总计算预算由运行参数决定。最终没有达到学习侧误差目标的任务继续列在 `unresolved_tasks` 中；`completed` 表示允许的研究访问结束。

已取得比较结果的风险任务使用最近仍支持的改善安排重访。`evidence_gain` 达到最低改善和当前离散余量时，归一化该收益作为研究优先级；否则记录 `no_observed_revision_gain` 并保留未解决损失。尚未完成比较的任务保留继续研究机会，已经测得没有新收益的非零 pinball 损失则留待后续有新研究依据时处理。

`PlanAllocation.remember` 按观测响应的 binary、numeric、risk 及单输入/多输入组织经验；状态转换、联合坐标和依赖计划都更新新参考预测的收益与计算投入。收益相对当前损失归一化，后续任务据此改变状态与数值搜索之间的预算分配，以及各依赖计划的配额。

会话所依据的是任务公开接口、已经支付成本得到的观测以及控制器实际运行结果。研究用的最终评测仍在学习结束后完成；它用于评价会话产物。

命令行可以建立跨分区研究，先运行两个任务访问，在进程结束后继续：

```bash
PYTHONPATH=src python3 -m hegel_machine cognition session \
  --checkpoint artifacts/hegel_session.json \
  --partitions development confirmation forward continual stateful \
  --seed 809 --steps 2

PYTHONPATH=src python3 -m hegel_machine cognition session \
  --checkpoint artifacts/hegel_session.json
```

CLI 每完成一个任务访问就保存 checkpoint，任务来源与顺序也随其保存。恢复默认继承配置和资源；`--total-observation-budget`、`--total-compute-budget` 及 `--max-visits` 可以显式增大，使仍未解决的问题继续获得研究机会。`--steps` 限定本次新增完整访问数。

环境工厂在每次访问时重建同一任务，并以确定的任务索引和访问次数改变查询种子。保存与恢复发生在完整任务访问之间。Python 接口也接受只有 `spec` 与 `observe` 的外部环境对象，由调用方维持或重新连接其实际状态。

[会话测试](../../tests/test_cognition_session.py)使用实际学习路径覆盖获得知识、相关任务复用、同条件反例撤销、JSON 保存恢复、先覆盖后重访及共享资源约束。命令行已用独立进程验证保存和继续，先前结果及知识中的研究经验保留。完整任务序列、进一步的恢复行为及联合状态改进结果集中记录在 [0.8.0 报告](../cognitive_runtime_v6_results.md)。

## 5. 通用先验如何成为这台机器的一部分

早期 roadmap 的六个根类仍有价值，但它们应在候选、预测和实验中产生差异。

压缩与充分表示类已经落实为程序复杂度控制、稀疏变量组合、历史表示和可复用子表达式。接下来需要让抽象压缩实际减少后续工作，并允许新实验把原先无法区分的表示重新分开。低秩、最小充分状态等更强主张，需要相应的数据对象和执行过程。

分解与机制复用类已经落实为加性及交互项、依赖计划、可参数化模板和角色映射。联合状态坐标是这条路线的新组成部分。下一阶段应让子问题的输入与结果可以在多个任务中复用，并研究怎样发现一个现有分解本身有误。

几何与动态类已经包含历史深度竞争、起始分支、阈值关系和状态条件。新的状态坐标让多个观测维度可以组成动态条件。对连续潜在状态、长期稳定性和真正多尺度机制的学习，仍需要扩展表示和对应实验。

不变性与物理结构类目前只有部分可执行特例，例如角色重命名、单调方向和简单代数关系。任意对称群、守恒量与拓扑结构尚无完整的发现链。接入这类先验时，应以一个能实际操纵和测量的环境为对象，实现具体候选和能够区分它们的变换实验。

异常与不确定性类已经接通残差位置、尺度、尾部拟合和固定外部代价下的行动。后续重点是根据观测判断何时应增加结构，何时应接受残差不确定性，以及新的校准投入是否换来实际收益。

认识论原则已经体现在主动区分、前瞻比较、知识作用域和撤销中。持续研究会话进一步承接“现在应该研究什么”的问题，使它能够使用长期经验。新添先验只有在改变了候选或实验的实际行为后，才成为系统能力。

## 6. 从本轮整机到更完整的自主研究

本轮整机运行连接新状态表示与持续会话，覆盖获得概念、跨任务复用、遇到反例、修订知识和保存后继续运行。多种子研究衡量算法变化的收益，两者分别回答“能否完整运作”和“为什么值得这样运作”。此后的系统建设继续以这条完整生命周期为单位。

研究经验已经影响搜索预算，接下来需要把更具体的子问题和实验结果带入后续行动选择。系统应依据已测收益联合调整表示、实验、抽象和不确定性研究的次序，并把暂时没有改善的子问题带到有信息的新条件下重新研究。总预算下的其他任务构成真实机会成本；一个困难任务的额外研究应与后续任务的机会共同考虑。

接着扩展知识的条件结构和组合能力。一个概念的参数、适用范围、依赖关系和研究经验，应能在跨环境复用时分别改变。组合任务既是表达能力问题，也是“采用旧概念后是否还注意到了新的反例”的研究问题。

随后通过同一任务接口接入更丰富的可交互环境，例如具有连续隐状态的控制过程、多尺度动态或带工具操作的结构发现任务。输入对象改变时，相应增加可执行表示与观测操作。代码生成器可以参与提出候选，但所得程序仍应使用该环境真实提供的观测和行动来解决任务。

## Limitations

- 本文定义整机目标、当前执行路径和后续研究关系；具体效果与运行范围以 [0.8.0 报告](../cognitive_runtime_v6_results.md)为准。
- 当前主要证据来自公开的有限合成任务，尚不支持开放世界通用理论发现的完成主张。
- 已有递归计划、实验价值、知识范围和研究预算分配主要采用有限启发式；跨任务策略学习与自主重组问题结构仍是持续研究内容。
- 状态预测目前读取实际已经观察到的历史输出；没有反馈的自由滚动预测是另一种任务，需相应环境与结果。
- 原始文档列出的广泛先验具有不同数据与操作要求，当前实现覆盖其中可执行的一部分。自然语言名称齐全不能替代其发现与应用能力。
