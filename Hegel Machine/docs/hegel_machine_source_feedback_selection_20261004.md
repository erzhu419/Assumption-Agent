# 待执行研究的来源反馈重排（0.181.0）

## 与 0.181.0 的衔接

本文件前半部分是 0.181.0 的来源反馈主线：实测回报进入待执行 successor 的排序和条件限定撤回。当前代码仍在同一未发布 0.181.0 主线中做增量续研，新增的响应签名（均值、幅度和一次拟合残差）以及 `provisional`→`confirmed` 的重复确认，都是对这条回报链的输入条件收紧，不是另一套 Agent 或另一条知识库。

`KnowledgeLibrary.from_dict` 可以读取旧 JSON，但 0.180／早期 0.181 收据中的 `research_return.condition` 没有 `response_signature`。精确条件比较会让这些旧回报在新签名条件下保持零调度信用；它们仍可审计，不能从旧字段推回签名，因此不做静默迁移。重新使用旧来源必须在当前条件下完成带签名的付费访问。旧收据继续作为 0.180 前置证据，不能直接当作本轮 signed-return 证据。

0.180 已经把普通知识的实测回报写入来源记录，但待执行报价仍按旧的即时预测收益排队。本轮把这条回报接到 UnifiedSession 的采购层：对已排队的普通 successor，按报价时保存的 `transfer_condition` 查找来源回报；正回报只作为即时收益相同时的次级排序，所有来源在同一条件下被否定时撤回该候选。没有重新筛选、重新购买观测，也没有把来源回报换算成新的预测损失。JSON 恢复不会重复产生事件。

新增10项调度测试，连同来源回传、回访、投资和组合相关回归共 **86项聚焦测试通过**；来源反馈两组定向测试现为 **18项通过**。新增的真实 staging 从 `source_competition` 产生一个实际失败的 successor 和一个由真实 refit、真实 continuation 产生正回报的 successor，把两者放进同一待执行队列；刷新后坏来源被撤回，正来源被保留并取得正分数。刷新没有重筛、重开实验室或消耗计算。

用冻结的0.180源码作基线，使用两组相同已付前缀和相同资源上限做离线运行。三来源三后继组中，候选版在第一次真实来源回报后对两个尚未执行报价产生了两次零成本 `refresh_source_feedback` 事件；基线没有该事件。两版执行顺序、终测误差和资源账相同。单来源组没有可重排的后续竞争。

这证明了反馈已经进入待执行采购状态，并在一个反馈先于执行的真实正／负混合队列中改变了可执行动作：错误来源不再购买，正来源仍可被选择。它修复了“回报只写账、不影响未来动作”的机制缺口。该 staging 是局部行动分叉和来源条件撤回的证据，还没有覆盖固定总预算下的后续任务质量、确认命中率或稳定长期净收益。

小型 matched no-return 收据给出同一队列的直接对照：保留回报的 candidate 在刷新后只留下 `concept_0002`（正回报分数约 0.01075）并选择它；删除回报的 arm 保留两个报价，首访选择原失败的 `concept_0001`，并把正来源作为伴随项。两臂重排的 screening 费用均为 0，调度搜索只分别消耗 1／4 个账本计算单位；这说明差异来自已测回报进入调度，而不是新增观测或更大的候选搜索。

随后把这两个选择用同一执行上限真正跑了一次：两臂都通过 `UnifiedResearchSession._perform_revisit`，各付 24 行观测、0 测量、120 计算和5次查询。保留回报的一臂执行 `concept_0002`，完成且 later 未见轨迹损失为 `9.73e-20`；删除回报的一臂执行 `concept_0001`，状态为 unresolved，later 损失为 `2.75e-3`。这是从来源回报到采购、执行、未见质量的完整局部因果链，结果收录于[同预算执行收据](../artifacts/source_feedback_same_budget_20261004/)。

进一步跑了 2 个条件边界 × 2 个任务 ID × 3 个声明 seed，共每臂 12 次。匹配条件下，反馈臂 6/6 撤回坏来源并选中 `concept_0002`，6/6 完成；窄边界条件下回报条件不匹配，反馈臂保留并选中 `concept_0001`，与条件作用域一致。无回报臂 12/12 都选坏来源且没有完成。所有试次仍为 24 行观测、0 测量、120 计算；这验证了条件限定的撤回边界，但三个 seed 只是同一确定性 fixture 的重复，不能当作独立随机环境。详见[多条件收据](../artifacts/source_feedback_multitask_20261004/)。

随后把同一真实 fixture 的已付前缀扩成 5 个条件、5 个 seed 和两个来源，共 50 条记录。`single_query00` 下坏来源五次都是负 paired gain 并被撤回；另外四个条件下坏来源都出现正 paired gain，其中 `initial` 的五次最终仍为 `unresolved`，收据把它们标成 `provisional`。好来源五个条件均为正回报并完成，标成 `confirmed`。这个边界直接说明：来源回报必须带着条件和确认状态使用，单次正回报不能被当作可迁移的有效确认。详见[条件边界收据](../artifacts/source_feedback_condition_boundary_20261004/)。

本轮又把固定 fixture 提升为真实参数化任务族：保持已付前缀、来源概念和执行上限不变，只改变转移系数或加入噪声，三种机制、两 seed、两臂共 12 条记录。改变当前输入系数时，旧的负回报曾经会被错误迁移；加入 paid-response signature 后，旧条件不再匹配，反馈臂与 matched arm 都选择当前机制真正适配的 `concept_0001`，两臂未见损失均低于 `1e-10`。原始机制仍复现反馈臂选择 `concept_0002`、matched arm 选择坏来源的差异。噪声机制的两臂都选择 `concept_0001`、保持 `unresolved` 且不触发旧负回报，说明一次拟合的响应残差可以先阻止未经重复确认的错误撤回；它仍没有给噪声机制正向确认。详见[参数化任务族收据](../artifacts/source_feedback_task_family_20261004/)。

本轮把这条“未经重复确认不产生正向信用”的规则接入正式来源回报：对含有非零响应残差的条件，第一次已完成访问记录为 `provisional`，`return_priority` 保持零；同条件第二次、使用不同响应抽样的已完成访问会把两条记录一起提升为 `confirmed`，并开始提供来源信用。两次访问的状态收据已跑通，没有调用实验室或外部模型；它验证的是状态和调度接口，尚不是长期任务收益。详见[重复确认收据](../artifacts/source_feedback_confirmation_20261004/)。

2026-10-04 审计发现的跨访问价值门现已修复：确认与撤回使用同一非零阈值，第二次近零收益不会确认此前 provisional 历史，未保留候选的近零负收益也不会撤回报价；对应跨状态回归通过。具体程序的来源回报读取同时按 canonical program 隔离，原不同程序间的 staging 分叉不再作为当前选择效应。新正常入口窄链及真实来源删除效果见[修复结果](hegel_machine_narrow_cycle_repair_20261004.md)，此前实验数字保留为各自代码状态的记录。

随后在一个共享 `UnifiedSession` 中跑了六任务固定预算序列：原始机制、系数变化和含噪机制各重复两次，反馈臂和删除回报臂使用相同任务顺序、筛选报价和总资源上限。两臂都消耗 246 行观测、0 测量和 40,434 计算；反馈臂在两个原始机制任务中选择 `concept_0002`，对应未见损失约 `2.90e-20`，删除回报臂选择 `concept_0001`，损失 `8.31e-4`。系数变化两臂都选择 `concept_0001` 并接近零误差；含噪任务保持 `unresolved`，没有把噪声响应升级为正向来源信用。详见[共享预算长序列收据](../artifacts/source_feedback_long_horizon_20261004/)。

最后跑了固定种子下 8 个独立随机机制、两个兼容锚点的十任务保留／删除对照。为避免撤回报价后队列变短造成额外研究，两臂使用每任务共同的最小资源上限。两臂总账均为 330 行观测、1,290 计算；两个锚点复现反馈臂选择 `concept_0002`、删除臂选择 `concept_0001`，八个随机机制的来源选择和未见损失完全相同。因此它支持局部兼容锚点上的行动分叉，但没有证明随机任务上的稳定长期净收益或普遍贡献。此前自适应队列版本报告的 402／82,455 对 390／58,560 及 `0.52309` 退化，现保留为资源分配混杂的协议负例，不作为知识退化证据。详见[随机保留／删除对照](hegel_machine_source_feedback_random_retention_20261004.md)。

随后做了同一来源队列的四臂归因：先通过真实 continuation 取得 `concept_0002` 的 `confirmed` 正回报，再冻结 8 个报价和共同执行上限，分别保留全部、删除坏来源、删除好来源和删除两者。自然四臂的实际选择与未见损失完全相同，因为两个候选的即时预测收益本身略有差异；同一前缀下的来源反事实重放则显示，原始机制由 `concept_0002` 拟合、系数变化由 `concept_0001` 拟合，含噪机制两来源都未决。进一步的 tie-controlled 对照删除坏回报并归一两个即时收益，只隔离来源反馈的次级排序：保留好回报时两个原始机制任务选择 `concept_0002`，删除时选择 `concept_0001`，未见损失约 `2.90e-20` 对 `8.31e-4`；系数变化和含噪任务没有错误获得该信用。这完成了来源质量读数和受控选择效应，但自然多来源归因、错误撤回的整链收益和长期净收益仍未完成。详见[来源归因收据](hegel_machine_source_feedback_attribution_20261004.md)。

## Limitations

当前排序只在即时预测收益相同时使用来源反馈；不同即时收益之间仍由当前任务的预测损失决定。同预算执行和六任务固定预算序列已经形成从反馈、动作到未见质量的局部链，多条件重复也确认了条件不匹配时不会撤回。新的 50 条边界记录还显示，正 paired gain 可能伴随 `unresolved`，所以来源分数不能绕过独立确认状态。参数化任务族现已用响应均值、幅度和一次拟合残差阻止已观察到的系数迁移和噪声负回报迁移；重复确认状态也已接入。共同上限的独立随机序列只显示局部兼容锚点收益，随机机制没有来源选择或未见质量分叉；四臂归因也没有在当前 fixture 产生行动分叉，因此多知识交互的稳定长期净收益、贡献归因和完整普通 Code／同一 LLM 模块消融对照仍未完成。早期自适应队列结果因资源分配混杂而降级为协议负例。下一步应构造坏来源不主导撤回、两个来源即时收益接近的多来源同预算对照，并把独占贡献、共享拟合成本和撤回后的未见收益放在同一主终点中。

旧 0.180／早期 0.181 收据没有响应签名，当前实现会保留其历史记录但不给新签名条件调度信用；这是一条明确的衔接边界，不是数据丢失。随机保留／删除对照进一步显示，局部兼容锚点收益不足以证明总成本或长期净收益改善。
