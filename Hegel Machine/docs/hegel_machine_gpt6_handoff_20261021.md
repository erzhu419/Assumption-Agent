# Hegel Machine：供 GPT6 评审的项目现状、问题与已完成工作

更新：2026-10-21。对照起点为 `5c945310e0bd961639192ddb13f7bcb2554419b6`，本说明随之后的累计实现提交。分支为 `codex/hegel-cognitive-mainline`。目的：说明当前系统实际做到了哪里、什么失败了，以及下一步需要判断什么。

## 1. 当前结论

项目已具备可执行的问题语义、理论匹配、有限问题生成与实验选择、跨 Episode 对象归纳、冻结安装、真实父稿绑定、强旧档案比较及评分复用。最近补齐了“反例条件与父参数联合关系没有真正进入低维拟合”的搜索缺口。

**尚未完成的核心目标：当前系统从来源证据自主形成一项有独有用途的对象，冻结后在独立后继中改善真实研究、预测或总成本。** 当前工程机制有实际运行证据；当前 PR3 对象的独立科学增益仍没有正证据。

最新历史对照保留完整旧能力，双方共同旧搜索扩到192、总计算上限同为100万。新增稀疏联合搜索有723个结构实际拟合，1446个程序全部未通过训练及留出检查，零合格新关系。30个对象可执行内容没有变化，没有启动新的对象留删或付费实验。

## 2. 项目要解决什么

目标不是增加假设名字、问题节点或候选数量，而是形成可持续的研究链：

`实际来源 → 提出可执行对象 → 实测支持／反例 → 修订与保留 → 冻结 → 独立后继消费 → 答案、风险、覆盖与完整成本`

比较对象为强普通可执行档案，不能以删旧方法、禁用旧组合或改变原阈值来获得增益。旧语言能表达一个对象，不意味着这个对象没有研究价值；其有限计算下的检索、生成或验证效率可以有价值，但需要实际测量。

当前分开保留两条来源：实际 Luna/Python 作者研究；有限原生 Program 自动生成。两者不能合并为“同一个模型已自主发现”。

## 3. 当前假设、问题和归纳对象是什么

| 对象 | 具体形式与含义 |
|---|---|
| 可执行假设 | 原生 `Program(op, value, name, lag, children, definition)`，或带真实源码、参数、拟合视图和依赖的 Python `fit/predict`。文字解释只有被编译为实际预测／操作后，才有相应可执行后果。 |
| 理论实例 | 索引中的 ID、版本、角色／时间／单位、输出单位、上下文、来源与支持。相同骨架、参数族、有限预测相同、已获科学支持分别记录。 |
| 研究问题 | 稳定 ID、`meaning_version`、查询语义／表达式、答案类型、答案出处、父用途、理论目标与未决义务。所求变化保留旧语义与答案；更换拟合算法不自动构成新问题。 |
| 旧模板对象 | `AbstractTemplate` 及有限参数洞，表达现有程序族；不能把一个新 ID 当成新理论。 |
| 共同构造对象 | `program_context_relation` 保存共同 after 构造；它不自动说明如何把 before 修成 after。 |
| 修订对象 | `program_revision_relation` 保存 before 模式、after 定义、共享洞、父绑定、属性假说、真实触发／反例、源重构和剩余义务。代表对象有22洞／15父洞，或18洞／11父洞，均有7个开放洞。 |
| 参数修订关系 | `parameter_relations[].program` 以 before 常量与已测反例条件为输入，预测原 after 常量。after 常量是监督目标，世界响应不是这个拟合器的标签。通过来源检查仅形成经验候选。 |

复用时先查类型、角色、时间、上下文和父模式，再结合当前已付证据检验。有限预测分组只表示所列计划／轨迹上的行为相同，不证明任意未来下等价。反例可以限制适用范围或触发修订；不应把一个局部失败升级为整条历史理论谱失效。

系统已有由查询未决、失配、合同缺失和父用途生成研究任务的入口，但尚没有证明一个通用作者能稳定判断何时开子假设、何时保留旧假设并生成有效新结构。此处仍需区分宿主工具可用与作者实际采用。

## 4. 实际主线与累计实现

### 4.1 PR1：可执行问题语义

已接语义版本、查询编译、模型／实测读出、答案绑定、父用途、UNKNOWN、历史答案及未完成作者义务的恢复。局部问题完成后可返回父题；原 assignment 和使命不因局部改写丢失。

这是有限查询语言的实现，不是通用自然语言数学证明器。

### 4.2 PR2：匹配、问题生成和选择

已把 typed 理论匹配、角色／参数绑定、有限预测分组、问题生成、任务相关区分评分及计划准备接入 Common 和 Registered 主线。

- 候选×计划分别保留可计算性，部分未知不再无条件封锁所有合法探索。
- 并列认知结论保留；显式冻结策略可以从合法物理动作中选择一个执行，不虚构唯一最优。
- 任务采纳与研究比较池分开；研究分歧不直接替换已采纳预测器。
- 原802个 Python 稿加6个 native，共808个普通旧稿进入对应完整比较；失败／未知列不静默删除。
- 保存的完整同条件评分按引用复用，避免同数据、同模型、同拟合现场再次评分；缺完整依据的旧记录不伪装缓存命中。

G 是当前有限池／计划上的区分启发式，不是已校准的后验信息量、EVSI或科学真值。

### 4.3 PR3：真实来源、修订与冻结消费

已接多来源身份、自动聚合、真实 retention 的 before/after、来源失败及费用、精确重构、已付残差触发、冻结库安装、父洞固定、开放洞的旧语法／整稿拟合、游标和比较预算预留。

之前72条 Program 新增不能凭空补成72次有真实父稿的修订；最终只从两条物理来源恢复11次实际换稿。旧来源新增 ID、同源副本、相同谱系不能增加独立来源数。

有限原生作者已进入正式 runner，生成稿通过已有 exporter 加入普通强池，经历原比较和采纳；失败的研究 before 与真正已采纳父稿分别标注，排名第一不等于实际父稿。原生 pilot 的来源未通过确认／提交，源失败仍保留，不能用后续接线把它改成成功。

### 4.4 当前执行链

`Common._execute(research_route)` → 问题／使命 → 冻结召回与 typed matching → 查询检查 → PR2预测分组／G／计划 → 父 pending。

Registered `_before_model_turn` 使用上述主线；普通／native候选经原 `research_choice` 比较与采纳。来源由 `research_episodes` 接入 `theory_consolidation`，修订构造由 `revision_relations` 执行，冻结后仍用原父绑定、世界检查和后继选择。

## 6. source006：作者研究反复卡在哪

039在原125轨迹／3029行固定五折上MSE为1.9482443501，对原ExtraTrees的2.7008645182改善27.87%。041扩展历史／交互特征后为2.4148014428，五折均差于039；它是确实执行的负结果。

10月19日23:57最后一轮主动未决，新增三组实验共176行，有购测前冻结预测和逐批重拟合；没有比039更好的新结构候选、没有进入原五折的新结构比较、没有新独立确认。

发生过可核实的分臂错误：trial043第二臂漏加轨迹预测偏移。039正确第二臂MSE为0.2943507982，041为0.2854022021；旧笔记写成13.2084／13.4928，并影响后续决策。框架总体评分正确，旧错误解释留档且已纠正。

更核心的断点是：实验约束和竞争解释没有稳定变成新可执行结构，实际预测仍主要用旧算法。机制尚未唯一确定不应成为禁止试验可检验修订的理由；也不能由两条后缀输出相同宣称隐藏状态完全相同。

这条 Python 作者问题与当前最能自动归纳的 native Program 来源不是同一表示通道，预测列适配不能自动把任意Python反编译成修订规则。
