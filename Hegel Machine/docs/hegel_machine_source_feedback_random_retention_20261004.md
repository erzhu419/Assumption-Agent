# 独立随机机制下的来源保留与删除对照（0.181.0续研）

本轮沿用 0.181.0 的来源反馈接口，新增一个同预算、多任务的保留／删除对照。任务顺序、每题上限、初始报价和转移参数种子完全相同；反馈臂保留并刷新来源回报，删除臂每次访问后删除 `research_return`。除一个可重复的兼容锚点外，另外 8 个任务的当前系数和噪声由固定种子独立抽取，最后再次访问兼容锚点，用来检查知识贡献是否能跨过随机任务而持续发挥作用。

运行命令：

```bash
PYTHONPATH=src:tests python3 scripts/run_source_feedback_random_retention.py
```

两臂均完成 10 个访问，外部模型调用为 0。动作在两个兼容锚点分叉：反馈臂均选择 `concept_0002`，未见损失约 `2.90e-20`；删除臂均选择 `concept_0001`，未见损失约 `8.31e-4`。8 个独立随机机制没有发生来源选择分叉，说明响应签名没有把锚点的回报错误迁移到这些机制。

冻结共同上限后，两臂总账相同：各为 330 行观测、1,290 计算；十个任务的实际访问均为 24 行观测、120 计算。两个兼容锚点仍复现反馈臂选择 `concept_0002`、删除臂选择 `concept_0001`，但八个独立随机机制的来源选择和未见损失完全相同（包括 `random_mechanism_4` 的 `0.0002147`）。因此本轮只支持兼容锚点上的局部行动分叉，不支持随机任务上的稳定净收益或普遍贡献。

此前自适应队列版本曾报告反馈臂多出研究并在一个随机任务上退化；复核发现撤回报价后队列变短，使剩余任务获得了不同的访问上限。该版本是资源分配混杂的协议负例，不能作为知识导致退化的因果证据；本报告以共同上限的重跑结果为准。

与 0.181.0 的关系是同一未发布主线的增量续研：0.181.0 已完成来源回报进入待执行选择；本轮只扩展独立机制的因果保留／删除证据，没有改写基础版本号，也没有重建旧报告中的结果。

## 与旧 0.180／早期 0.181 收据的边界

旧收据的 `research_return.condition` 没有 `response_signature`。当前条件包含响应均值、幅度和留一残差，精确条件比较会让旧回报加载后保持可审计，但对新条件给出零调度信用。这个结果是有意的安全边界：旧条件无法从保存内容反推出新的响应签名，所以不做静默迁移；要重新使用旧来源，必须在当前条件下完成一次带签名的付费访问。`source_feedback_selection_20261004` 中的旧收据应继续作为 0.180 前置证据阅读，不能冒充本轮 signed-return 收据。

## 下一步

下一步不是继续放大固定锚点，而是把随机序列扩展为多知识、多来源的同预算因果对照，并记录每一份知识的独占贡献、共同拟合成本、错误迁移撤回和未见任务收益。验收条件应同时要求质量改善、追加成本受控和负迁移不增加；只出现局部锚点收益时，保留失败样本，不提升主线版本。
