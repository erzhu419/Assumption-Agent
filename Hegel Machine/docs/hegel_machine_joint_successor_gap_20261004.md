# 真实后继序列中的联合候选缺口（20261004）

直接互补来源 fixture 已经验证 `current-term + lag-term` 的联合程序可以取得两个正边际贡献，并在机制变化后只撤回联合 binding。这个结果覆盖的是来源回报与联合归因接口，不等于真实 successor scheduler 已经能从两个 singleton 候选自主提出新的联合程序。

此前尝试把无条件 pairwise 联合候选接入 `_successor_candidates`，确实在普通后继 fixture 中改变了访问顺序；另一版多源研究程序搜索还在来源回传筛选中造成持续高 CPU。两条宽搜索路径均已移除。当前已改为窄资格路径：只在同一已付响应上至少两个不同来源的 singleton 已完成测量、最佳 singleton 仍有残差且两源 residual fit 严格改善时生成联合候选；它复用原有报价、确认和撤回逻辑，普通 singleton 队列保持原顺序。

因此联合来源的资格筛选和 successor 报价入口已经存在；“真实新响应上的联合确认、失败后的联合撤回、多任务独占贡献和长期累计收益”仍是未完成主线。下一步应在冻结的多任务序列中验证该窄路径，而不是扩大候选 grammar。
