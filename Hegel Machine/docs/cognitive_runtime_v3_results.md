# 认知主线 0.5.0：实验价值、修订选择与迁移

日期：2026-09-08。代码和预算在首次运行 `forward` 之前确定。

本轮针对 0.4.0 的实际失败改写学习算法。Agent 现在可以联合构造历史、非线性和交互表示，学习历史不足时的启动预测，用新的代表轨迹比较修订，并根据已测得的迁移经验安排后续结构拟合。

**新任务的三种子平均平方误差从 0.861056 降到 0.284248，错误采纳从 41/81 降到 7/61。** 观测支出增加 16.7%，候选计算增加 1.8%；更强联合组合和风险选择仍是主要短板。

## 1. 从失败到实际改动

旧版本在固定相位和共线输入上容易把目标自相关当作输入延迟，也会在定向探测中漏掉交互。旧 `confirmation` 种子 23 中，c02、c07、c08、c09 四个任务占平方损失的 98.47%。本轮把这批已读结果作为开发依据。

| 问题 | 当前实际行为 | 代码 |
|---|---|---|
| 大预测分歧未必有任务价值 | 比较查询后预期预测／行动风险下降与观测成本，保留控制覆盖探索 | `probing.py` |
| 固定相位和输入共线误导选择 | 各输入独立分层取样，新轨迹在本轮候选拟合后获取 | `selection.py` |
| 修订由局部样本决定，父模型过早退出 | 累计代表观测与新轨迹共同决定采用，当前与父模型继续竞争 | `controller.py` |
| 逐种修复难以发现联合机制 | 根据残差逐项选择并联合拟合当前、平方、交互与历史坐标 | `sparse_search.py` |
| 正确历史规律仍在起始行丢失当前信息 | 使用 `if(available(k), mature, startup)`，从实际启动观测学习另一分支 | `language.py`、`selection.py` |
| 模板按插入顺序消耗预算 | 完整轨迹筛选、短名单拟合；相同结构共享当次拟合，相同程序共享评分并保留来源 | `memory.py`、`abstractions.py` |
| 计划投入不受实际收益影响 | 在 episode 内按新轨迹改善与生成成本调整下一轮分配 | `selection.PlanAllocation` |
| 适配成功可能错误支持源规律 | 具体规律的作用域与重拟合模板的使用分别记录；实际迁移结果影响下一任务排序 | `memory.py` |

历史阈值的迁移还修复了一个实际运行错误：完整条件程序能在启动行执行，不意味着其历史子式也能单独执行。阈值拟合现在从该子式可执行的行取候选，完整程序仍在所有行上计分。

同一程序由多个计划或模板产生时，预测可以共享；收益仍按真实来源归属。回顾式选择对照仍测量新数据并更新计划与迁移经验，只改变选择所用的证据，避免把几个机制的停用混为一项效果。

## 2. 比较设计

保存的 0.4.0 认知包位于 `artifacts/cognition_v2_reference/`，作为独立旧算法比较对象。0.5.0 修改了控制器、候选搜索以及启动表达能力；因此总版本差异不能只归因于实验选择。消融进一步分开几项贡献。

| 配置 | 与完整 0.5.0 的区别 |
|---|---|
| `reference_v2` | 保存的完整 0.4.0 算法 |
| `cognitive_v3` | 完整 0.5.0 |
| `raw_disagreement` | 定向探测使用原始预测分歧 |
| `retrospective_selection` | 修订选择只使用本轮查询前证据；新数据仍进入反馈和下一轮拟合 |
| `without_warm_start` | 候选生成不增加学得的启动分支 |
| `without_knowledge` | 每个任务自行学习，禁用知识检索与积累 |
| `erase_specific_concept` | 首次迁移前删除实际获得的第一条概念及其派生内容 |

每个 episode 的上限一致：96 个观测点、24,000 个候选计算单位、5 轮研究。开发序列 17 个 episode，种子 7、11、19；旧组合序列 12 个 episode，种子 23、47、83；新 `forward` 序列 12 个 episode，种子 101、211、307。新序列增加四步历史、更强非线性与交互组合、角色变化、无关迟滞和同一任务的机制反例。

三组、七臂共执行 861 个配置—任务 episode。所有算法使用同种子环境、共同初始和目录观测、相同最终评价行和预算上限。自适应查询可以不同。比较脚本按开发、旧组合、新分区顺序执行；本次首读 forward 后保持学习代码不变。

## 5. 实际程序与剩余失败

旧组合种子 23 中，三步历史、历史与非线性组合、非线性与交互组合分别形成了以下程序。为方便阅读，下面将 AST 写成普通代数形式；数值系数是运行内从观测拟合的结果。

```text
c02: if available(3): 0.4*x + 1.6*lag(x,3)
     else:            0.4*x

c08: if available(3): 0.3*x + 1.2*x*x + 0.8*lag(x,3)
     else:            0.3*x + 1.2*x*x

c09: 0.8*x*x + 1.3*x*z
```

新分区种子 101 的 f02 学到了 `0.55*x - 1.210548*lag(x,4)` 与 `0.55*x` 启动分支。之后同一 f02 机制变化时，最终程序变成 `0.55*x + 1.2*lag(x,2)` 与对应启动分支，三个种子都取得接近零的最终预测误差。三条序列都实际撤销了此前的 `concept_0002`，再将替代程序写入知识库。

**强联合组合 f09 仍未解决。** 三个种子的平方误差分别是 1.300738、3.508856、3.209075，占新分区剩余平方损失的 **85.5%**。真实生成式同时含当前线性、平方、交互和二阶历史；当前语言能表达这四项，但三条最终程序均遗漏部分内容或引入错误历史。三次均在约 23,700 个计算单位、51 条观测处停止，后续研究应集中在有限样本下的组合拟合、候选保留和搜索投入。

**f03/101 暴露了获得证据以后仍未充分利用的问题。** 初始 `x=z` 允许 `0.5*x + 0.5*z - 1.087137*x*x` 拟合训练数据。之后已经取得各变量独立变化的观测，却仍保留这一模型，最终平方误差为 0.849793；末轮取得新观测后没有剩余预算进行下一次修订比较。这个失败与“没有进行解耦实验”不同，应进一步改善重新拟合和查询／比较之间的资源分配。

**f07 的预测正确，但机制仍不可辨识。** 三个种子都选择了输出历史形式。真实输入历史规律为 `y[t] = 0.55*r[t] + d*r[t-4]`，所选形式为 `0.55*r[t] + (d/0.55)*y[t-4]`。每段前四步只有当前输入项，因此两式在重置后的八步轨迹上严格等效；本次最终评测正是 24 段八步轨迹。由生成式可推得第九步起会出现额外的 `(d*d/0.55)*r[t-8]`，这属于代数推导，未作额外运行。当前接口上的成功应记为有限时域预测成功。

**风险选择还不稳定。** 旧组合 c04 的种子 47 中，完整版本 pinball 损失为 0.737788，无启动表示为 0.299318；新分区风险覆盖随种子从 0 到约 0.885 变化。平方误差改善没有消除稀少尾部观测对模型选择的影响。

本轮首读后保持实现不变，以上失败也保留在原始报告中。下一阶段的开发目标由这些具体行为决定：优先解决完整组合被挤出预算、已获得区分证据未转成修订，以及短时域等效规律的区分。

## Limitations

- 开发和旧 `confirmation` 已用于诊断。本轮 forward 是实现确定后的首次读取，生成器仍公开且与旧任务共享基本机制；以后据其结果修改系统时，它也成为开发依据。
- 前瞻选择参考的是公开控制范围。有限候选上的任务价值估计和损失离散余量均为启发式，不能代替未知实际分布或统计显著性证明。
- 程序语言、坐标集合、历史深度上限和计划族由开发者提供；运行内学到的是这些能力中的选择与组合。开放世界理论、任意传感器和更长代际积累仍需扩展与实证。
- 误接受与误回退只比较实际记录的程序对，以最终预测损失为准；没有回退事件时相应错误率无分母，不能解释为已证明回退可靠。复杂度和风险行动的全部取舍不在该指标中。
- 每组只有三个 suite 种子。区间按种子重采样，评价行不能充当独立重复。计算单位、墙钟时间和观测量分别比较，预算上限相同不表示实际用量相同。
- `worst_case_loss` 是每行所学区间两端行动损失的最大值再取均值；零宽 nominal 区间会得到 0，不能把它解释为真实测试最坏损失或尾部风险。风险质量以独立测试的实际行动损失和覆盖一起判断。
