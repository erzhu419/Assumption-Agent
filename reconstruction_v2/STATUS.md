# Reconstruction V2 Status

## Implemented

- Three typed hypothesis kinds: task, policy, and evaluator.
- Structured `HypothesisProgram` with trigger, anti-trigger, action DAG, expected effect, verifier, fallback, lineage, and evaluator epoch.
- Runtime actions that actually enable, disable, and prioritize lanes or inject executable operator steps.
- Baseline preservation in the internal lane runtime; external SkillLearn trials use pre-execution abstention plus a paired harm gate rather than post-verifier rollback.
- JSON-only model proposal and repair requests on the protocol-owned `gpt-5.4-mini` route.
- Active v3.4 single-provider routing through ruoli `gpt-5.4-mini`, with a per-run circuit breaker and provider provenance.
- A route policy embedded in experiment plans, provider fingerprints, and fairness fingerprints so every raw/agent arm uses one model and provider mode.
- Protocol-bound Codex custom Responses-provider commands for v3.4, with `/v1` normalization, ignored user config, ephemeral turns, authoritative hosted-web disable, and no credential in command/event provenance.
- Direct schema-constrained proposal requests through `OpenAICompatibleProposalModel`; the API key is read from environment for the Authorization header and is never persisted.
- SkillLearn task trials use the protocol-bound Codex custom provider inside the task container; proposal transport and trial execution remain distinct.
- Recursive validation that asks the proposal model for a child repair after failed checks.
- Same-task policy-off/policy-on counterfactual execution.
- Protocol-owned promotion from paired validation effect, harm, activation, and cost rather than failure frequency; candidate-declared limits may only tighten the frozen contract.
- Archive nodes representing complete active-program configurations.
- Frozen evaluator epochs, anchor lower-bound challenger comparison, and selective score invalidation.
- Train/validation/sealed-test access guard.
- SkillLearnBench inventory, instance-holdout and family-out manifests.
- Offline-ready 86-item paper subset preserving the earlier split assignment, plus manifest-scoped credential, verifier-payload, and offline-profile hard preflight.
- Backend-specific compiler from promoted hypothesis programs to SkillLearnBench-compatible `SKILL.md` files: four prompt/self-check operations lower explicitly and six unsupported typed operations fail closed.
- SkillLearnBench trial contracts and a sanitized adapter around the upstream Docker verifier runner.
- Failed train-only trials converted into semantic residuals with task instructions available to proposal but absent from persistent logs and runtime triggers.
- Validation and sealed-test compiler targeting, including family-out transfer to unseen validation families.
- Deterministically balanced policy-off/policy-on execution order with provider and budget fingerprints.
- Promotion blockers for invalid endpoint/container rows, provider mismatch, and budget mismatch.
- A guarded `skilllearn_experiment` dry-run/execute CLI with a model health probe before expensive trials.
- Bounded multi-generation evolution with aggregate promotion feedback, behavior deduplication, rejection status, and consecutive-non-promotion early stopping.
- Paper protocol lock, recursive/no-recursive archive freeze, content-hashed compiled controls, resumable matched controls, sealed-access journal, and item-clustered paper statistics.
- Post-agent verifier injection: `/tests` is absent while the model acts and copied into the container only after agent exit.
- Content-addressed per-item base images with oracle skills excluded, plus one digest-pinned, read-only `codex-cli 0.144.1` runtime volume binding the action-supervisor content hash.
- Zero-model-cost all-manifest image/offline-verifier cache-only prewarm with bounded retries and a v4 receipt binding the manifest, exact shared runtime/supervisor, images, and verifier profiles; sealed scoring and agent execution remain disabled.
- Explicit dependency preparation for a missing shared runtime, separately authorized with `--allow-network-download` and unable to produce paper evidence.
- Bounded four-worker train/counterfactual/control execution across items, with every same-item variant sequence kept serial.
- Runner-local deep copies of the upstream agent registry, eliminating parallel provider setup/restore races.
- No-fixed-timeout policy for active agent/verifier stages and the trial-container lifetime, with legacy timeout results classified as invalid evidence.
- Structured Codex terminal-error detection over the complete trace, with fatal provider labels taking priority over earlier generic stream errors, a shared provider-failure circuit, and all-valid training evidence before proposal.
- Shared first-generation evidence and root checkpoint for the recursive versus no-recursive causal ablation.
- Behavior-identical validation replay across paired ablation arms, preventing model resampling variance from appearing as a recursive-repair effect.
- Exact-request root proposal replay across generations and arms, so identical search state cannot produce different roots through model resampling.
- Behavior-identical training replay across generations and arms, so an unchanged incumbent reuses exact train evidence with zero new task executions.
- Same-request invalid-only clean replacement for train and validation trials, with a protocol-frozen attempt budget, backoff, and one-worker retry queue.
- Hard runtime trigger vocabulary with context-only instruction fields rejected programmatically.
- Train-only evaluation of every proposed root and deterministic support/complexity selection of the sole validation candidate.
- Separate aggregate and selected-candidate recursion counts, depths, and repair-candidate provenance.
- Runtime-kind guard: evaluator hypotheses cannot masquerade as compiled agent skills and require a separate anchored epoch challenger.
- Per-item compiled skill routing, preventing a trigger match on one item from leaking to sibling items in the same family.
- Trial provenance for base image key/ID, runtime key/version, cache reuse, withheld verifier mount, and post-agent verifier materialization.
- Provider-only container egress, pinned endpoint host mapping without external DNS, fail-closed prebuilt dependency caches, a v3.4 64 MiB network fuse, and `--network none` verifier/runtime verification.
- Protocol-owned Codex execution treatment: low reasoning/verbosity, 32,768-token `body_after_prefix` compaction, the effective 10,000-token tool-output limit, request compression, canonical `web_search="disabled"`, and policy hashes in requests, fingerprints, replay identities, records, and reports.
- Executable `codex_action_start_v1` budget: the supervisor owns and truncates the current trace, binds a random per-attempt nonce and full trace hash, conservatively counts malformed starts, stops the process group at the limit, and removes all live tasks created after the dedicated container baseline before verifier injection. The task/TID scan also catches `setsid` descendants and live worker threads behind zombie leaders; incomplete scans fail closed. Natural completion requires valid token usage; all v3.4 arms use action starts for promotion cost.
- Per-attempt model audit events; non-retryable HTTP authentication errors stop after one request.
- Candidate-local recursive-repair failure isolation and terminal root-proposal failure reports; any such failure blocks that generation's validation and promotion claim.
- Structured in-memory or JSONL events for proposal, validation, runtime, counterfactual, promotion, archive, evaluator transition, and benchmark compilation.

## Evidence Scope

The current 184-test full offline suite proves that the learning loop is connected, that a promoted hypothesis changes future internal runtime behavior, and that the same lifecycle works against SkillLearnBench's real inventory with a fake external trial backend. It additionally covers evaluator-owned threshold composition, strict paper-protocol and freeze provenance, backend-specific action lowering, hidden-verifier non-exposure, lowered-treatment replay identity, observed versus declared fallback semantics, stable filtering of the offline-ready manifests without re-splitting, immutable v3.1-v3.3 mappings, and the active v3.4 model-only/action-budget contract. The model-free readiness audit passes 7/7 active profiles, 15/15 train-family probes, and an all-selected-item static preflight with `blockers=[]`. V3.4 now has a passing 86/86 v4 cache-only prewarm receipt bound to its runtime/supervisor. These checks do not prove real benchmark improvement.

V3.1-v3.3 are immutable evidence whose historical receipts remain verifiable under their declared legacy schemas; they are not promised to be backward-executable under the current commit.

The active paper path has one execution contract. Before any development, freeze, validation-control, or sealed-control model work, it revalidates the lock content, protocol/evolution/promotion mappings, readiness and v4 prewarm receipts, model/provider/origin, egress and network budget, provider readiness, benchmark payload fingerprint, code fingerprint, clean scoped Git state, and locked commit. Agent ID, action budget, workers, retries, trigger support, generation budget, and candidate count come only from the protocol.
