## 结论

这个方向可行，而且比继续微调当前 UAO recipe、RRF、关键词或 gate 更接近真正
缺失的“假设形成机制”。但不能照原始文档直接开正式 study；必须先把它从
“漂亮的数学描述”收缩为可执行、可证伪的结构绑定器。

总体判断：

| 层面 | 判断 |
|---|---|
| 核心思想 | 正确，值得继续 |
| 数学方向 | 基本正确，但形式堆得过多 |
| 工程规格 | 数据结构较完整，最困难的结构抽取仍欠定义 |
| 直接修复当前 RAW-EQ | 可能性较低，WikiSQL EQ 已接近饱和 |
| 作为新论文方向 | 有潜力，但创新不能只写成“范畴论+22条假设” |

## 1. 22条/13条到底用过没有

“完全没有使用”需要分开看：

- QuAC/L5 的 RJMC 没有使用22条或13条，只用了
  `same_section / adjacent_window / entity_chain` 三种人工冻结关系。
- WikiSQL UAO 使用了22条本体，但只开放了四个手写 recipe：
  T02、T05、T08、T18，最后 TRAIN 选择了 T05“低阶交互”和
  T18“稀疏污染”。
- 13条现在主要是22条的旧别名映射，例如单调性映射到 T17、守恒映射到
  T15、对称性映射到 T14。
- 旧版做过 category/structural morphism，但前端本质上依赖
  `ROLE_MARKERS`、`INVARIANT_MARKERS` 等关键词命中。它先通过词找到角色，
  再生成看起来很结构化的图，因此仍容易退化成“结构词汇情景库”。

更准确的结论是：

> 22条的名字、registry 和少量手写 operator 已接入；但“从数据发现关系定律—
> 绑定角色—验证约束—编译行动”尚未真正接入。

这正是 GSCL 可以补的缺口。

## 2. “广义对位”的核心理解

相似度通常给出：

\[
s(x,y).
\]

但结构假设分别要求：

- 对称/等变：某个变换前后结构保持；
- 单调：有序变量之间方向保持；
- 守恒：多个流入、流出和边界项共同满足平衡；
- 互补：两个证据联合产生单独证据没有的增益；
- 组合性：两条路径组合后应与另一条路径一致。

它们不是22种“相似”，而是不同元数、方向和代数性质的关系定律。

HippoRAG 也不只是词语相似度。它使用 OpenIE/知识图谱和 Personalized
PageRank 做关联传播；问题在于最终主要仍形成关联、可达性或 proximity，
而不是验证“这里满足守恒”“这条映射保持单调方向”等定律
（[HippoRAG](https://arxiv.org/abs/2405.14831)）。

范畴论适合表达对象、带类型态射、组合和交换图，是“约束如何连接到实现”的
语言，但不会自动从文本发现守恒或单调性
（[Categorical Deep Learning](https://arxiv.org/abs/2402.15332)）。因此：

> 范畴论应当是 schema/编译语言；真正的推断器应当是带属性的有向超图、
> 约束求解和可执行 residual。

守恒等 n 元规律也不应强塞进普通二元边；超图适合表达高阶关系
（[HyperSAGE](https://arxiv.org/abs/2010.04558)）。

## 3. 原规格最有价值的部分

应当保留：

1. `StructuralEpisode → LawBinding → HypothesisClaim → TreatmentProgram`
   的分层；
2. embedding 只能召回候选，不能证明结构成立；
3. 每个绑定必须保留 evidence span、unknown 和 counterevidence；
4. role-swap、sign-flip、entity-renaming、低语义重叠正例和高语义重叠负例；
5. 证据不足时必须 abstain；
6. 结构对应不能直接改 policy，仍需经过现有离线 paired validation。

这些不是多补几个效果 gate，而是在防止系统再次退化成关键词匹配。

关系类比与表面相似的区别已有明确研究基础，但仍是困难问题：

- [SCAR](https://aclanthology.org/2023.findings-emnlp.160/) 评估科学类比中的
  结构归纳；
- [ARN](https://aclanthology.org/2024.tacl-1.59/) 区分 surface、
  relational 和 system mappings；
- [AnaloBench](https://aclanthology.org/2024.emnlp-main.725/) 显示长上下文
  中的类比检索仍然困难。

所以论文不能声称“首次超越相似度做结构类比”。创新必须是：

> 把 universal-law ontology 编译为有证据绑定、可执行 residual、反事实检验
> 和下游 action，并证明 retained utility。

## 4. 原规格必须修改的地方

### 4.1 结构抽取是主要问题

Stage 1“结构抽取”写得最短，但它占整个问题的主要难度。如果只是让 LLM
输出：

```text
disturbance = ...
response = ...
controlled_quantity = ...
```

然后下游验证它自己生成的图，系统仍可能形成自证循环。必须要求：

- 每个对象、方向、单位和顺序绑定原始证据跨度；
- 明确 `observed / inferred / unknown`；
- 关系 residual 由确定性函数计算；
- 抽取器和 verifier 分离；
- verifier 不接受自然语言“本质相似”；
- role/sign permutation 必须改变结果。

### 4.2 数学表述必须收紧

- 近似带分数映射不能直接称为 functor，应称为
  `partial typed structure-preserving correspondence`。
- `p(a|D) ∝ p(D|a)p(a)e^{-λv}` 可能重复计算 violation；应明确令
  \(p(D|a)\propto e^{-\beta v}\)，或使用统一 MDL/support score。
- 正交性依赖指定内积和表示基，不能作为无条件世界定律。
- 低频/平滑性依赖预先声明的图或度量。
- 守恒必须声明系统边界、单位和未观测流。
- Le Chatelier–Lenz 适合作为直觉示例，但不宜作为第一项硬验收：原规格中的
  严格幅度收缩并非两个定律在所有条件下都保证。第一阶段应优先使用形式明确的
  order、balance、involution 和 path-composition。

第一版也不应同时引入 `Rel + allegory + enriched category + operad + sheaf`。
有限 typed hypergraph 加约束 residual 已经足够。

## 5. 能否补当前 RAW-EQ

理论上能，现实上不应把 WikiSQL EQ 当成 GSCL 的首个证明场。

安全 aggregate 诊断显示：

- EQ 共24项；
- RAW utility 已是49，理论上限51；
- Agent 也是49；
- Agent 只改变了3项，全部净平；
- 整个 family 只剩2个 utility 单位的总 headroom；
- 选中的 T05/T18 在 TRAIN 上的 EQ 净增益原本就是0。

所以当前 RAW-EQ=0 不是“差一点发现一个大机制”，而是一个接近饱和、极难无损
提高的 family。不能在已消费 cohort 上为 EQ 定制 law 或新增 gate。GSCL 应在
新的、TRAIN 显示有真实 headroom 的来源上测量。

## 6. 建议的可执行版本

第一版只实现五类结构定律：

- T14：involution / symmetry / equivariance；
- T17：order / monotonicity；
- T15：conservation / balance；
- T09：composition / path consistency；
- T05/T06：complementarity / interaction / nonredundancy。

同时：

- T01/T02 等只作为搜索复杂度先验；
- T19–T22 只管理 abstention、证伪和 promotion；
- 不把全部22条做成关系通道。

工程上复用现有 `meta_assumption.py` 的 claim、probe、compiler 和 receipt，
只新增：

```text
StructuralEpisode
ExecutableLawSchema
LawBinding
StructuralCorrespondence
```

实验不再开一串正式版本：

1. 建立一个可反复迭代、非评分的离线 qualification harness，覆盖结构抽取、
   五类 residual、硬负例、旧关键词层和 semantic-only ablation；
2. 用 SCAR/ARN/合成变换验证结构识别；全部使用本地冻结模型和离线 gold，
   不用在线评价；
3. 全绿后才冻结一次 fresh downstream study：
   Agent/RAW/official HippoRAG 三臂，选择 TRAIN-only 已证明不饱和且结构关系
   能改变候选集的来源；
4. 必须有 `same candidates + remove law verifier`、shuffled law、
   role-swap/sign-flip 等因果 ablation，证明收益来自结构定律，而不是更长
   prompt 或更大模型。

## 最终判断

> 值得做，而且是目前最合理的新方向。它不能保证补上已消费 WikiSQL 的
> RAW-EQ，但能真正补上当前 Assumption Agent“有假设本体、没有关系定律
> 发现器”的架构缺口。只有完成证据绑定、可执行 residual、反事实拒绝和下游
> retained effect，它才是论文级的新方法；如果只是把22条变成图标签或
> prompt，它会重演旧版失败。

## 7. 第一次真实长叙事执行后的修正

同一个非评分 harness 随后接通了 program-owned closed-choice extractor、CPU
MiniLM、四个 intrinsic arms 与 late-label scorer barrier。公开合成 qualification
可以完整执行，但第一次 ARN public intrinsic attempt 在评分前终止，并给出了比
“是否胜过 baseline”更基础的反证：

- 871 个 item 共需要 2,613 个 query/choice StructuralEpisode；
- closed-choice extractor 只形成 41 个有效 decision；
- 2,539 个 story 因 v1 span catalog 的 32-token 上限在模型前失败；
- 可进入后续阶段的 story 仍会因为 v1 wire 固定为 1 generator + 2 objects，
  无法覆盖多句叙事而被独立 parser 拒绝；
- 最终 871/871 item 在 semantic-only、legacy-keyword、flat-label/no-verifier
  与 full GSCL 四臂中全部为共同 `ARM_RUNTIME_ERROR`；
- prediction barrier、label-open 与 offline scorer 均未发生。

MiniLM 终止信息本身是一个 path-sensitive comparator 误报：正式与资格化
runtime 除 target manifest 的绝对路径外逐字段、逐字节相同。但即使修正这个
比较，四臂仍会共同全错，因此本轮正确分类是
`implementation-invalid / intrinsic efficacy unknown`，而不是负效果或正效果。

这次反证使原建议进一步收紧。可执行第一版不能是“把短文本三元组 extractor
直接放大到 benchmark”，必须改为：

1. 长叙事先做确定性、层级、句级分块，再在有界候选中选择；
2. wire 表达多个 sentence-grounded generators/objects，而不是强行把整篇文本
   压成一个二元关系；
3. 模型仍只排序 program-owned typed choices，不能生成字段、ID 或 primitive；
4. 显存计算只保留 teacher-forced answer positions 的 logits；
5. catalog、context、tokenizer、model、parser 和 verifier 错误必须分型；
6. 先用 source-free 长文本/多句/反事实 fixtures 证明 coverage 与拒绝能力，再做
   label-blind public-input compatibility；本次已用于 postmortem 的 ARN 输入不再
   称为 untouched 效果 cohort。

因此，真实执行没有否定“广义结构对应”方向；它否定的是当前过窄的单
generator 短文本实现。方向仍然可行，但论文级机制必须把“关系的元数、句级
覆盖和组合结构”落实到 extractor 表达空间，而不能只在下游 residual 中写出
多元定律。
